# Aula 8 - Packages, modulos, imports e organizacao de projetos

Package é a fronteira de organização em Go: o que é exportado é contrato, o que não é, é liberdade. Módulos e imports bem desenhados são arquitetura em miniatura, conferida pelo compilador.

---

## Nesta aula

Entender como Go organiza codigo em packages e modulos, como `import` funciona, como criar projetos com `go mod`, como a visibilidade entre arquivos e packages realmente opera e como estruturar um projeto pequeno de forma previsivel e escalavel. Você vai aprender a criar módulos (`go mod`), organizar pacotes com imports, distinguir pacote interno de biblioteca, e prever ciclos de import.
---

## 1. Por que modularizar em Go?

Nas aulas anteriores, quase todo exemplo cabia em um unico arquivo. Isso ajuda no inicio, mas software real cresce.

Sem modularizacao, surgem problemas classicos:

- responsabilidades misturadas;
- reuso ruim;
- testes mais dificeis;
- manutencao mais lenta;
- acoplamento alto.

Go responde a isso com duas camadas diferentes:

- **package**: unidade de codigo em nivel de linguagem;
- **modulo**: unidade de versionamento e dependencia em nivel de projeto.

---

## 2. O que e um package?

Package e um conjunto de arquivos Go que pertencem ao mesmo namespace e normalmente vivem no mesmo diretorio.

Exemplo conceitual:

```text
calculadora/
|- soma.go
`- subtracao.go
```

Se ambos comecam com:

```go
package calculadora
```

ao mesmo package.

### 2.1 Consequencia pratica

Arquivos do mesmo package compartilham:

- namespace do package;
- acesso a identificadores nao exportados daquele package;
- compilacao conjunta como unidade logica.

Isso significa que separar em varios arquivos nao quebra o pacote em varios espacos de nomes independentes.

---

## 3. O que e um modulo?

Modulo e a unidade introduzida por `go.mod`.

Voce cria assim:

```bash
go mod init exemplo.com/curso-go
```

Isso gera um arquivo `go.mod` que define a identidade do modulo.

Exemplo:

```go
module exemplo.com/curso-go

go 1.24
```

### 3.1 Para que modulo existe?

Modulo resolve principalmente:

- nome do projeto para imports;
- gerenciamento de dependencias;
- reproducibilidade de build;
- versionamento entre pacotes.

Pense em `go.mod` como o ponto em que o projeto ganha identidade formal dentro do ecossistema Go.

---

## 4. Imports

Exemplo:

```go
import "fmt"
```

Isso importa um package da biblioteca padrao.

Em projeto proprio, algo como:

```go
import "exemplo.com/curso-go/matematica"
```

### 4.1 Import path

- **Import path**: caminho textual que identifica um package dentro do ecossistema.

Em Go, o import se ancora no modulo e segue pelos subdiretorios.

---

## 5. Estrutura de projeto simples

Exemplo:

```text
curso-go/
|- go.mod
|- main.go
`- matematica/
   `- soma.go
```

`go.mod`:

```go
module exemplo.com/curso-go

go 1.24
```

`matematica/soma.go`:

```go
package matematica

func Somar(a, b int) int {
    return a + b
}
```

`main.go`:

```go
package main

import (
    "fmt"
    "exemplo.com/curso-go/matematica"
)

func main() {
    fmt.Println(matematica.Somar(10, 20))
}
```

---

## 6. Exportacao por maiuscula

Ja vimos a regra, mas aqui ela ganha papel estrutural.

- `Somar` com `S` maiusculo e exportada;
- `somarInterno` com `s` minusculo fica visivel apenas no package.

Isso substitui parte de mecanismos de visibilidade mais verbosos de outras linguagens.

**Comparacao:**

- C nao tem esse sistema de exportacao semantica no nome.
- C++ usa `public`, `private`, `protected` dentro de classes.
- Rust usa `pub`.
- Go usa capitalizacao como regra simples e direta.

---

## 7. Um diretorio, um package

Regra pratica importante:

- normalmente, um diretorio corresponde a um package.

Nao misture arbitrariamente varios packages no mesmo diretorio comum de codigo fonte. Isso tende a gerar confusao e complica o modelo mental.

Tambem e importante entender:

- o nome do package nao precisa ser igual ao nome do modulo;
- mas costuma haver relacao clara entre o caminho do diretorio e o import path.

---

## 8. `go mod tidy`

Depois de mexer em dependencias, rode:

```bash
go mod tidy
```

Esse comando:

- adiciona dependencias necessarias;
- remove dependencias nao utilizadas;
- ajuda a manter `go.mod` e `go.sum` coerentes.

Faz parte do fluxo normal de projeto em Go.

---

## 9. `main` vs biblioteca

`package main` gera executavel.

Outros packages normalmente servem como bibliotecas internas ou externas.

Exemplo mental:

- `main`: ponto de entrada;
- `matematica`, `config`, `httpclient`: packages de apoio.

Essa separacao ajuda a evitar que toda a logica fique presa dentro do arquivo principal.

---

## 10. Comandos exatos para executar

Criar modulo:

```bash
go mod init exemplo.com/curso-go
```

Rodar projeto:

```bash
go run .
```

Compilar projeto:

```bash
go build .
```

Ajustar dependencias:

```bash
go mod tidy
```

Formatar tudo no diretorio atual:

```bash
go fmt ./...
```

---

## 11. Exemplo completo da aula

```go
// arquivo: matematica/soma.go
package matematica

func Somar(a, b int) int {
    return a + b
}
```

```go
// arquivo: main.go
package main

import (
    "fmt"
    "exemplo.com/curso-go/matematica"
)

func main() {
    resultado := matematica.Somar(15, 25)
    fmt.Println(resultado)
}
```

### Explicacao linha por linha

- `package matematica`: define o package da biblioteca.
- `func Somar(...)`: exporta a funcao para outros packages.
- `import "exemplo.com/curso-go/matematica"`: importa o package pelo caminho do modulo.
- `resultado := matematica.Somar(...)`: acessa simbolo exportado com prefixo do package.
- `go run .`: compila e executa o projeto inteiro a partir do diretorio atual.

## 12. Erros Comuns e Anti-Padroes

1. **Confundir package com modulo**: eles operam em niveis diferentes.
2. **Esquecer `go mod init` em projeto novo**: isso dificulta imports locais organizados.
3. **Exportar tudo sem criterio**: API publica desnecessaria aumenta acoplamento.
4. **Misturar responsabilidades demais em `main`**: o package principal deve coordenar, nao concentrar tudo.
5. **Usar nomes de package pouco claros**: isso piora legibilidade do import.
6. **Nao rodar `go mod tidy`**: dependencias ficam sujas e confusas.
