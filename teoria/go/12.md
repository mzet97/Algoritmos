# Aula 12 - Generics em Go

---

## Objetivo da Aula

Entender como generics funcionam em Go com type parameters e restricoes, por que foram adicionados tardiamente na linguagem e em quais casos melhoram reuso sem destruir clareza. Ao final, voce deve conseguir escrever funcoes e tipos genericos simples de forma idiomatica, sabendo quando evitar abstracao excessiva.

---

## 1. Por que generics existem?

Antes de generics, havia dois caminhos comuns para reuso mais abstrato em Go:

- duplicar codigo para tipos diferentes;
- usar `interface{}` ou, no Go moderno, `any`.

Duplicacao demais aumenta manutencao.

Uso excessivo de `any` perde seguranca de tipo e empurra erros para runtime.

Generics entram para resolver esse meio-termo:

- reuso parametrizado;
- preservacao de informacao de tipo;
- codigo mais geral sem cair em tipagem totalmente apagada no nivel da API.

---

## 2. O que e um type parameter?

Type parameter e um parametro de tipo declarado entre colchetes.

Exemplo:

```go
func Identidade[T any](valor T) T {
    return valor
}
```

- `T` e um parametro de tipo.
- `any` e a restricao mais ampla.
- `Identidade` aceita varios tipos, mantendo o mesmo tipo na entrada e na saida.

Uso:

```go
fmt.Println(Identidade[int](10))
fmt.Println(Identidade[string]("go"))
```

Em muitos casos, o compilador infere o tipo automaticamente.

---

## 3. O que e uma restricao?

Restricao define quais tipos sao aceitos por um type parameter.

```go
func Imprimir[T any](v T) {
    fmt.Println(v)
}
```

Aqui a restricao e ampla: qualquer tipo.

Mas nem sempre isso basta.

Se voce quer somar ou comparar, precisa de tipos que suportem essas operacoes.

---

## 4. `comparable`

Go fornece a restricao predefinida `comparable`.

Ela indica tipos que podem ser comparados com `==` e `!=`.

Exemplo:

```go
func Iguais[T comparable](a, b T) bool {
    return a == b
}
```

Isso e util para:

- comparacao generica;
- chaves de estruturas auxiliares;
- verificacoes simples com preservacao de tipo.

---

## 5. Type sets e restricoes customizadas

Voce tambem pode definir interfaces usadas como restricoes.

```go
type Numero interface {
    ~int | ~int64 | ~float64
}
```

Isso representa um conjunto de tipos permitidos.

- `~int` significa tipos cujo tipo subjacente e `int`.

Agora:

```go
func Somar[T Numero](a, b T) T {
    return a + b
}
```

### 5.1 Por que isso importa?

Porque algumas operacoes so fazem sentido para certos grupos de tipos.

O compilador precisa saber quais operadores sao validos para `T`.

---

## 6. Slice generico

Exemplo muito util:

```go
func Contem[T comparable](valores []T, alvo T) bool {
    for _, v := range valores {
        if v == alvo {
            return true
        }
    }
    return false
}
```

Uso:

```go
fmt.Println(Contem([]int{1, 2, 3}, 2))
fmt.Println(Contem([]string{"a", "b"}, "c"))
```

Essa e uma boa ilustracao de ganho real de reuso com seguranca.

---

## 7. Tipos genericos

Nao sao so funcoes. Tipos tambem podem ser genericos.

```go
type Caixa[T any] struct {
    Valor T
}
```

Uso:

```go
c1 := Caixa[int]{Valor: 10}
c2 := Caixa[string]{Valor: "Go"}
```

Isso ajuda quando voce quer estruturar dados parametrizados sem perder tipo concreto.

---

## 8. Generics nao substituem interfaces em tudo

Esse ponto e muito importante.

- interfaces modelam comportamento;
- generics modelam parametrizacao por tipo.

Se o problema e polimorfismo por comportamento em runtime, interface continua sendo ferramenta central.

Se o problema e escrever algoritmo ou estrutura reutilizavel preservando tipo, generics pode ser melhor.

### 8.1 Regra mental

Pergunte:

- preciso de comportamento comum entre tipos diferentes? interface.
- preciso de algoritmo parametrizado por tipo? generic.

---

## 9. Quando generics pioram o codigo?

Quando viram exibicao de abstracao.

Sinais de exagero:

- nomes muito abstratos e vagos;
- varias camadas genericas sem ganho real;
- restricoes complicadas para resolver problema simples;
- perda de legibilidade para economizar poucas linhas.

Go adicionou generics com bastante conservadorismo exatamente para nao empurrar a linguagem para meta-abstracao excessiva.

## 11. Exemplo completo da aula

```go
package main

import "fmt"

type Numero interface {
    ~int | ~int64 | ~float64
}

type Caixa[T any] struct {
    Valor T
}

func Somar[T Numero](a, b T) T {
    return a + b
}

func Contem[T comparable](valores []T, alvo T) bool {
    for _, v := range valores {
        if v == alvo {
            return true
        }
    }
    return false
}

func main() {
    fmt.Println(Somar(10, 20))
    fmt.Println(Somar(1.5, 2.5))

    fmt.Println(Contem([]int{1, 2, 3}, 2))
    fmt.Println(Contem([]string{"ana", "bruno"}, "carla"))

    caixa := Caixa[string]{Valor: "conteudo"}
    fmt.Println(caixa.Valor)
}
```

### Explicacao linha por linha

- `type Numero interface { ... }`: define restricao customizada por conjunto de tipos.
- `type Caixa[T any] struct`: define tipo parametrizado.
- `func Somar[T Numero](...)`: generic com operacao valida para tipos numericos escolhidos.
- `func Contem[T comparable](...)`: generic que depende de comparacao `==`.
- `Somar(10, 20)`: usa inferencia de tipo pelo compilador.
- `Caixa[string]{...}`: instancia tipo generico com `string`.

## 12. Erros Comuns e Anti-Padroes

1. **Usar generic quando uma funcao concreta bastaria**: abstracao demais custa leitura.
2. **Trocar interface por generic sem criterio**: elas resolvem problemas diferentes.
3. **Usar `any` em tudo e chamar isso de generic sofisticado**: voce pode perder o principal beneficio.
4. **Criar restricoes confusas cedo demais**: mantenha o desenho simples.
5. **Esquecer que nem todo operador vale para todo tipo**: a restricao precisa refletir isso.
6. **Tentar importar metaprogramacao pesada de C++ templates**: Go foi desenhada para ser mais contida.
