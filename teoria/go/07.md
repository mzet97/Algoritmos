# Aula 7 - Tratamento de erros, `error`, `panic`, `recover` e `defer`

Erro em Go é valor, `panic` é último recurso e `defer` é a rede que garante a limpeza. Tratar erro como parte do fluxo — e não como exceção à espreita — muda o formato de cada função que você escreve.

---

## Nesta aula

Entender como Go trata falhas sem depender de excecoes classicas, como usar o tipo `error`, quando `panic` faz sentido, o que `recover` realmente faz e por que `defer` e tao importante para limpeza de recursos. Você vai aprender a retornar erros como valores (`error`), distinguir `panic` de erro, usar `defer`/`recover` apenas na fronteira adequada, e envolver erros com `%w`/`errors.Is`/`errors.As`.
---

## 1. Filosofia de erro em Go

Go trata erro como valor.

Essa frase e famosa porque define o modelo mental da linguagem:

> erros comuns fazem parte do fluxo normal e devem ser representados explicitamente.

Em vez de esconder falhas em mecanismo excepcional implicito, Go geralmente devolve um segundo valor do tipo `error`.

---

## 2. O que e `error`?

`error` e uma interface da biblioteca padrao.

Conceitualmente, pense assim:

```go
type error interface {
    Error() string
}
```

Qualquer valor que implemente `Error() string` satisfaz `error`.

### 2.1 Exemplo simples

```go
package main

import (
    "errors"
    "fmt"
)

func dividir(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("divisao por zero")
    }
    return a / b, nil
}

func main() {
    resultado, err := dividir(10, 0)
    if err != nil {
        fmt.Println("erro:", err)
        return
    }

    fmt.Println(resultado)
}
```

- `nil` significa ausencia de erro.
- `err != nil` e o teste idiomatico mais comum da linguagem.

---

## 3. Por que Go usa `valor, err`?

Porque varios problemas em programas reais sao esperados:

- arquivo pode nao existir;
- rede pode falhar;
- entrada pode estar invalida;
- dado externo pode vir corrompido.

Esses casos nao sao "impossiveis". Sao parte da realidade operacional.

Ao forcar tratamento explicito, Go favorece visibilidade do caminho de falha.

**Comparacao com C/C++/Rust:**

- C muitas vezes usa codigos de retorno e `errno`.
- C++ costuma usar excecoes ou codigos de erro, dependendo do estilo.
- Rust usa `Result<T, E>` de forma tipada.
- Go usa tipicamente `valor, error`.

---

## 4. Criando erros

### 4.1 `errors.New`

```go
err := errors.New("entrada invalida")
```

### 4.2 `fmt.Errorf`

```go
err := fmt.Errorf("usuario %s nao encontrado", nome)
```

`fmt.Errorf` e util quando voce quer interpolar contexto textual na mensagem.

---

## 5. Encadeando contexto

Em software real, erro sem contexto perde valor diagnostico.

```go
func carregarConfiguracao(caminho string) error {
    return fmt.Errorf("falha ao carregar configuracao em %s", caminho)
}
```

Mais adiante, voce pode acumular contexto em camadas diferentes do sistema.

O objetivo nao e produzir mensagem dramatica, mas sim mensagem operacionalmente util.

## 6. `defer`

`defer` agenda uma chamada para o momento em que a funcao atual estiver saindo.

```go
package main

import "fmt"

func main() {
    fmt.Println("inicio")
    defer fmt.Println("fim")
    fmt.Println("meio")
}
```

Saida:

```text
inicio
meio
fim
```

### 6.1 Para que `defer` existe?

Principalmente para limpeza de recursos:

- fechar arquivo;
- liberar conexao;
- destravar mutex;
- registrar fim de operacao.

Exemplo classico:

```go
arquivo, err := os.Open("dados.txt")
if err != nil {
    return err
}
defer arquivo.Close()
```

Assim, o fechamento fica proximo da abertura, reduzindo risco de esquecer limpeza em multiplos caminhos de retorno.

---

## 7. `panic`

`panic` interrompe o fluxo normal e inicia desembrulho da pilha.

```go
panic("estado impossivel")
```

- **Pilha**: cadeia de chamadas de funcao em execucao.

Quando ocorre `panic`, a linguagem executa `defer`s pendentes da goroutine atual enquanto sobe pela pilha.

### 7.1 Quando `panic` faz sentido?

Use `panic` para falhas graves ou invariantes quebradas, por exemplo:

- estado impossivel em codigo interno;
- bug de programacao;
- inicializacao essencial sem recuperacao local plausivel.

Nao use `panic` como substituto de erro de validacao comum.

---

## 8. `recover`

`recover` permite capturar um `panic`, mas so quando chamado dentro de uma funcao adiada por `defer`.

```go
package main

import "fmt"

func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("panic recuperado:", r)
        }
    }()

    panic("algo deu muito errado")
}
```

### 8.1 O que `recover` nao deve virar

`recover` nao e desculpa para esconder bugs indiscriminadamente.

Ele costuma fazer mais sentido em:

- bordas de servidor;
- workers concorrentes;
- infraestrutura que precisa evitar derrubar o processo inteiro por uma falha isolada.

---

## 9. Fluxo normal vs falha grave

Modelo pratico:

- erro esperado de negocio ou I/O: `error`;
- falha interna irrecuperavel ou estado impossivel: `panic`;
- isolamento de dano em fronteiras do sistema: `recover` com cuidado.

Essa distincao melhora confiabilidade e legibilidade do codigo.

## 11. Exemplo completo da aula

```go
package main

import (
    "errors"
    "fmt"
)

func dividir(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("divisao por zero")
    }
    return a / b, nil
}

func execucaoProtegida() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("recover capturou:", r)
        }
    }()

    panic("falha grave de exemplo")
}

func main() {
    resultado, err := dividir(10, 2)
    if err != nil {
        fmt.Println("erro:", err)
        return
    }

    fmt.Println("resultado:", resultado)

    defer fmt.Println("encerrando main")
    execucaoProtegida()
}
```

### Explicacao linha por linha

- `func dividir(...) (float64, error)`: retorna valor e erro explicitamente.
- `errors.New(...)`: cria um erro simples.
- `if err != nil`: testa falha no caminho idiomatico.
- `defer func() { ... }()`: agenda funcao anonima para o fim da funcao atual.
- `recover()`: captura o valor do `panic` durante o desempilhamento.
- `panic(...)`: interrompe fluxo normal por falha grave.
- `defer fmt.Println(...)`: mostra que `defer` ainda roda na saida da funcao.

---

## 12. Erros Comuns e Anti-Padroes

1. **Usar `panic` para erro comum de validacao**: isso piora robustez.
2. **Ignorar `err` sem justificativa**: falhas silenciosas custam caro.
3. **Perder contexto ao propagar erro**: mensagem pobre atrapalha diagnostico.
4. **Esquecer `defer` para fechar recursos**: isso causa vazamento logico de recurso.
5. **Usar `recover` para esconder bug estrutural**: isso mascara problema real.
6. **Tratar `nil` como detalhe menor**: em Go, checagem explicita de erro e parte do fluxo normal.
