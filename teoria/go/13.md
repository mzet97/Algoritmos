# Aula 13 - Arquivos, I/O, `io`, `bufio`, `os`, `path/filepath` e serializacao

Arquivo, rede e serialização passam pela mesma interface `io` de poucos métodos. Em Go, I/O idiomático é composição de leitores e escritores pequenos — e erro tratado em cada fronteira.

---

## Nesta aula

Entender como Go lida com entrada e saida de dados em arquivos e fluxos, como usar `os`, `io`, `bufio` e `path/filepath`, e como serializar dados em formatos comuns como JSON. Você vai aprender a ler/escrever arquivos com `os`/`io`/`bufio`, percorrer árvores com `filepath`, serializar (JSON/CSV), e prever erros de caminho, permissão e encoding.
---

## 1. O que e I/O?

I/O significa input/output, ou seja, entrada e saida.

Na pratica, isso inclui:

- ler arquivo;
- escrever arquivo;
- copiar bytes entre origem e destino;
- interagir com stdin e stdout;
- lidar com rede e dispositivos.

Em sistemas, I/O costuma ser mais lento do que operacoes puramente em CPU e memoria.

Por isso, bibliotecas de I/O existem para organizar fluxo, bufferizacao e tratamento de erro.

---

## 2. `os`

O package `os` oferece acesso a recursos do sistema operacional.

Exemplos de uso:

- abrir arquivo;
- criar arquivo;
- remover arquivo;
- ler argumentos do processo;
- obter variaveis de ambiente.

Leitura simples de arquivo inteiro:

```go
dados, err := os.ReadFile("dados.txt")
if err != nil {
    return
}
fmt.Println(string(dados))
```

Escrita simples:

```go
err := os.WriteFile("saida.txt", []byte("ola"), 0644)
```

- `0644` representa permissoes do arquivo em estilo Unix.

---

## 3. `io`

`io` e um package central porque define interfaces fundamentais para fluxo de dados, como:

- `io.Reader`;
- `io.Writer`;
- `io.Closer`.

Conceitualmente:

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
```

Isso e poderoso porque varios componentes diferentes podem participar do mesmo ecossistema de leitura e escrita.

### 3.1 Por que isso importa?

Porque um arquivo, um buffer em memoria e uma conexao de rede podem compartilhar a mesma ideia de leitura e escrita, mesmo sendo recursos fisicamente diferentes.

Interfaces pequenas tornam o ecossistema composivel.

---

## 4. `bufio`

`bufio` adiciona bufferizacao sobre readers e writers.

- **Bufferizacao**: acumular dados em memoria para reduzir quantidade de operacoes de I/O subjacentes.

Isso costuma melhorar eficiencia e tambem fornece utilitarios convenientes, como leitura por linha.

Exemplo:

```go
arquivo, err := os.Open("dados.txt")
if err != nil {
    return
}
defer arquivo.Close()

scanner := bufio.NewScanner(arquivo)
for scanner.Scan() {
    fmt.Println(scanner.Text())
}
if err := scanner.Err(); err != nil {
    fmt.Println("erro:", err)
}
```

---

## 5. `path/filepath`

Esse package ajuda a manipular caminhos de forma portavel entre sistemas operacionais.

Exemplos:

```go
caminho := filepath.Join("dados", "entrada.txt")
base := filepath.Base(caminho)
dir := filepath.Dir(caminho)
```

Por que usar isso em vez de concatenar string manualmente?

Porque separadores de caminho variam entre sistemas, e o package trata isso corretamente.

No Windows, por exemplo, o separador visual mais comum difere do Unix.

---

## 6. Leitura em streaming vs arquivo inteiro

Duas estrategias comuns:

- ler tudo de uma vez com `os.ReadFile`;
- ler progressivamente com `io.Reader` ou `bufio.Scanner`.

Use leitura total quando:

- o arquivo e pequeno;
- a simplicidade importa mais;
- voce realmente precisa do conteudo inteiro em memoria.

Use streaming quando:

- o arquivo pode ser grande;
- voce quer processar por partes;
- quer controlar melhor uso de memoria.

Isso conecta diretamente com custo de heap e pressao no garbage collector.

## 7. Serializacao com JSON

Serializar e transformar uma estrutura em representacao externa.

Em Go, `encoding/json` e muito comum.

Exemplo:

```go
type Usuario struct {
    Nome  string `json:"nome"`
    Idade int    `json:"idade"`
}
```

- **Tag de struct**: metadado textual associado ao campo, usado por bibliotecas como `encoding/json`.

Gerando JSON:

```go
u := Usuario{Nome: "Ana", Idade: 30}
dados, err := json.Marshal(u)
```

Lendo JSON:

```go
var u Usuario
err := json.Unmarshal(dados, &u)
```

### 7.1 Exportacao importa aqui

Campos precisam ser exportados, isto e, com inicial maiuscula, para que `encoding/json` os enxergue por padrao.

---

## 8. `Marshal` vs `Unmarshal`

- `Marshal`: converte valor Go em bytes externos.
- `Unmarshal`: converte bytes externos em valor Go.

Isso aparece o tempo todo em backend, configuracao, APIs e persistencia leve.

## 10. Exemplo completo da aula

```go
package main

import (
    "bufio"
    "encoding/json"
    "fmt"
    "os"
    "path/filepath"
)

type Usuario struct {
    Nome  string `json:"nome"`
    Idade int    `json:"idade"`
}

func main() {
    caminho := filepath.Join("dados", "usuarios.txt")
    fmt.Println("caminho:", caminho)

    u := Usuario{Nome: "Ana", Idade: 30}
    dadosJSON, err := json.Marshal(u)
    if err != nil {
        fmt.Println("erro ao serializar:", err)
        return
    }

    fmt.Println(string(dadosJSON))

    arquivo, err := os.Open("13_exemplo.go")
    if err != nil {
        fmt.Println("erro ao abrir arquivo:", err)
        return
    }
    defer arquivo.Close()

    scanner := bufio.NewScanner(arquivo)
    for scanner.Scan() {
        fmt.Println(scanner.Text())
        break
    }

    if err := scanner.Err(); err != nil {
        fmt.Println("erro ao ler:", err)
    }
}
```

### Explicacao linha por linha

- `filepath.Join(...)`: monta caminho portavel.
- `json.Marshal(u)`: serializa a struct para JSON.
- `os.Open(...)`: abre arquivo para leitura.
- `defer arquivo.Close()`: garante fechamento do recurso.
- `bufio.NewScanner(arquivo)`: cria leitor por linhas.
- `scanner.Scan()`: avanca linha por linha.
- `scanner.Err()`: verifica erro de leitura.

## 11. Erros Comuns e Anti-Padroes

1. **Ler arquivo gigante inteiro sem necessidade**: isso aumenta uso de memoria.
2. **Esquecer `Close()`**: recurso aberto pode permanecer ocupado.
3. **Concatenar caminhos manualmente**: `filepath.Join` e mais seguro e portavel.
4. **Ignorar erro de `scanner.Err()`**: leitura pode falhar no meio do processo.
5. **Esperar JSON preencher campos nao exportados**: campos minusculos nao sao vistos por padrao.
6. **Misturar bytes e string sem pensar em custo e semantica**: conversoes tem impacto e significado.
