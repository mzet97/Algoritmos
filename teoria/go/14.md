# Aula 14 - Testes, benchmarks, profiling e ferramentas da toolchain

---

## Objetivo da Aula

Entender como validar comportamento, medir desempenho e investigar custo em Go usando `go test`, testes unitarios, benchmarks, coverage, `go vet` e uma primeira visao de profiling. Ao final, voce deve conseguir integrar verificacao e observabilidade basica ao fluxo normal de desenvolvimento, sem tratar testes e medicao como etapa secundaria.

---

## 1. Por que a toolchain importa tanto em Go?

Uma das forcas da linguagem e o ecossistema coeso.

Em vez de depender de combinacoes fragmentadas de ferramentas externas, Go oferece um fluxo forte com:

- `go test`;
- `go fmt`;
- `go vet`;
- benchmarks integrados;
- coverage;
- suporte a profiling.

Isso reduz atrito e ajuda a padronizar engenharia no time.

---

## 2. Testes em Go

Arquivos de teste usam o sufixo `_test.go`.

Funcoes de teste seguem a forma:

```go
func TestAlgo(t *testing.T)
```

Exemplo:

```go
package matematica

import "testing"

func Soma(a, b int) int {
    return a + b
}

func TestSoma(t *testing.T) {
    got := Soma(2, 3)
    want := 5

    if got != want {
        t.Fatalf("esperado %d, obtido %d", want, got)
    }
}
```

### 2.1 O que `testing.T` faz?

Ele fornece contexto do teste e operacoes para:

- falhar;
- registrar mensagens;
- controlar subtestes;
- marcar helper.

---

## 3. Rodando testes

```bash
go test ./...
```

Esse comando executa testes do modulo inteiro abaixo do diretorio atual.

Rodar um package especifico:

```bash
go test ./matematica
```

Rodar com verbosidade:

```bash
go test -v ./...
```

---

## 4. Coverage

Coverage mede quanto do codigo foi exercitado pelos testes.

Comando:

```bash
go test -cover ./...
```

Isso nao significa prova absoluta de corretude, mas ajuda a enxergar buracos de verificacao.

Use coverage como sinal, nao como fetiche numerico.

---

## 5. Benchmarks

Benchmark mede desempenho de um trecho de codigo de forma estruturada.

Forma basica:

```go
func BenchmarkAlgo(b *testing.B)
```

Exemplo:

```go
func BenchmarkSoma(b *testing.B) {
    for i := 0; i < b.N; i++ {
        Soma(10, 20)
    }
}
```

- `b.N` e ajustado pela ferramenta para obter medicao util.

Rodar benchmarks:

```bash
go test -bench=. ./...
```

---

## 6. `go vet`

`go vet` faz analise estatica para detectar suspeitas comuns.

Comando:

```bash
go vet ./...
```

Ele nao substitui compilacao nem testes, mas ajuda a capturar erros conceituais e padroes perigosos.

Pense nele como uma camada de saneamento tecnico automatizado.

---

## 7. Profiling e pprof

Profiling e o processo de observar onde tempo e memoria estao sendo gastos.

Go oferece integracao forte com `pprof`.

- **pprof**: conjunto de ferramentas para inspecao de perfil de CPU, heap, goroutines e outros aspectos do runtime.

Sem entrar em toda a profundidade ainda, o ponto importante e:

- nao otimize no escuro;
- meca antes;
- encontre hotspots reais;
- so depois ajuste alocacao, algoritmo ou concorrencia.

---

## 8. Teste, benchmark e profile sao coisas diferentes

- teste responde: esta correto?
- benchmark responde: quao rapido ou caro esta?
- profile responde: onde o custo esta concentrado?

Misturar essas perguntas gera engenharia ruim.

Cada ferramenta responde a uma dimensao diferente do problema.

---

## 9. Race detector no fluxo de qualidade

Como vimos na aula anterior, codigo concorrente deve ser verificado com:

```bash
go test -race ./...
```

Isso merece entrar no fluxo normal de projetos que usam goroutines e estado compartilhado.

## 11. Exemplo completo da aula

```go
// arquivo: matematica/soma.go
package matematica

func Soma(a, b int) int {
    return a + b
}
```

```go
// arquivo: matematica/soma_test.go
package matematica

import "testing"

func TestSoma(t *testing.T) {
    got := Soma(2, 3)
    want := 5

    if got != want {
        t.Fatalf("esperado %d, obtido %d", want, got)
    }
}

func BenchmarkSoma(b *testing.B) {
    for i := 0; i < b.N; i++ {
        Soma(10, 20)
    }
}
```

### Explicacao linha por linha

- `*_test.go`: arquivo especial descoberto por `go test`.
- `TestSoma(...)`: teste unitario convencional.
- `t.Fatalf(...)`: falha o teste e interrompe execucao daquele caso.
- `BenchmarkSoma(...)`: benchmark reconhecido pela toolchain.
- `for i := 0; i < b.N; i++`: repeticao controlada pelo framework.

## 12. Erros Comuns e Anti-Padroes

1. **Confiar apenas em compilar**: build verde nao garante corretude.
2. **Escrever benchmark sem pensar em alocacao e setup**: medicao pode ficar contaminada.
3. **Usar coverage como objetivo absoluto**: numero alto nao substitui qualidade de caso.
4. **Ignorar `go vet`**: varias suspeitas uteis passam despercebidas.
5. **Otimizar antes de medir**: isso gera trabalho aleatorio.
6. **Nao usar `-race` em codigo concorrente**: voce perde protecao importante.
