# Aula 5 - Maps e structs

Map e struct são como Go modela o mundo sem classes: dados agrupados com comportamento ao lado, não dentro de hierarquia. A escolha entre um e outro decide a forma de quase todo o código que você vai escrever.

---

## Nesta aula

Aprender a modelar dados em Go com `map` e `struct`, entendendo quando usar associacao por chave e quando usar campos nomeados, como inicializar, ler, escrever, verificar existencia e compor modelos simples. Você vai aprender a usar maps com verificação de existência (vírgula-ok), definir structs com tags, distinguir valor de ponteiro como receptor, e prever o pânico de escrita em map nil.
---

## 1. O que e um `map`?

`map` e uma estrutura que associa chaves a valores.

Exemplo:

```go
idades := map[string]int{
    "Ana":   30,
    "Bruno": 25,
}
```

- chave: `string`;
- valor: `int`.

Modelo mental:

- em vez de acessar por posicao numerica como em slice;
- voce acessa por uma chave.

Isso e util para:

- tabelas de configuracao;
- indices por nome;
- caches simples;
- contadores por categoria.

---

## 2. Criando e acessando `map`

```go
package main

import "fmt"

func main() {
    idades := map[string]int{
        "Ana":   30,
        "Bruno": 25,
    }

    fmt.Println(idades["Ana"])
}
```

### 2.1 Inserindo e atualizando

```go
idades["Carla"] = 40
idades["Ana"] = 31
```

### 2.2 Removendo

```go
delete(idades, "Bruno")
```

- `delete` remove a chave, se existir.

---

## 3. Testando existencia no `map`

Esse ponto e central em Go.

```go
idade, ok := idades["Daniel"]
fmt.Println(idade, ok)
```

- `idade` recebe o valor encontrado ou zero value do tipo;
- `ok` informa se a chave existia.

Por que isso e importante?

Porque o zero value sozinho pode ser ambiguo.

Se o valor do map for `int`, `0` pode significar:

- chave ausente;
- chave presente com valor `0`.

O segundo retorno resolve essa ambiguidade.

---

## 4. O que e uma `struct`?

`struct` e um tipo composto com campos nomeados.

```go
type Pessoa struct {
    Nome  string
    Idade int
}
```

- **Struct**: tipo que agrupa varios campos relacionados sob um mesmo nome semantico.

Comparacao:

- Em C, a ideia lembra `struct`.
- Em Go, `struct` tambem e um tipo central para modelagem de dominio.
- Em vez de classes pesadas, Go favorece composicao e tipos simples.

---

## 5. Criando valores de `struct`

### 5.1 Literal nomeado

```go
p := Pessoa{
    Nome:  "Marina",
    Idade: 28,
}
```

Essa forma e a mais clara e segura no dia a dia.

### 5.2 Acesso a campos

```go
fmt.Println(p.Nome)
fmt.Println(p.Idade)
```

### 5.3 Modificando campo

```go
p.Idade = 29
```

---

## 6. `struct` vs `map`

Essa decisao aparece o tempo todo.

Use `struct` quando:

- os campos sao conhecidos e estaveis;
- o dado tem significado semantico claro;
- voce quer tipos mais seguros e documentacao implita no proprio modelo.

Use `map` quando:

- o conjunto de chaves e dinamico;
- os campos podem variar em quantidade;
- o problema e naturalmente de associacao por chave.

### 6.1 Exemplo de escolha ruim

Ruim para entidade fixa:

```go
usuario := map[string]string{
    "nome":  "Ana",
    "email": "ana@site.com",
}
```

Melhor:

```go
type Usuario struct {
    Nome  string
    Email string
}
```

Com `struct`, o compilador ajuda mais e o codigo expressa melhor a intencao.

---

## 7. Zero values em `map` e `struct`

### 7.1 `map`

Um `map` declarado sem `make` ou literal fica `nil`.

```go
var contadores map[string]int
fmt.Println(contadores == nil)
```

Voce pode ler de `map` nil, mas nao pode gravar:

```go
// contadores["x"] = 1 // panic em runtime
```

Para criar um `map` vazio e pronto para uso:

```go
contadores = make(map[string]int)
```

### 7.2 `struct`

Uma `struct` tem zero values validos para todos os campos:

```go
type Config struct {
    Host   string
    Porta  int
    Ativo  bool
}

var cfg Config
fmt.Println(cfg)
```

Isso produz uma instancia valida do tipo, com cada campo em seu zero value.

---

## 8. Compondo modelos simples

Vamos unir `struct` e `map`.

```go
type Produto struct {
    Nome  string
    Preco float64
}

estoque := map[string]Produto{
    "sku-1": {Nome: "Teclado", Preco: 199.90},
    "sku-2": {Nome: "Mouse", Preco: 89.90},
}
```

Aqui:

- o `map` organiza itens por chave dinamica (`sku`);
- a `struct` define a forma de cada item.

Esse padrao aparece o tempo todo em backend, CLIs e sistemas internos.

## 10. Exemplo completo da aula

```go
package main

import "fmt"

type Pessoa struct {
    Nome  string
    Idade int
}

func main() {
    idades := map[string]int{
        "Ana":   30,
        "Bruno": 25,
    }

    idades["Carla"] = 40

    idade, ok := idades["Ana"]
    if ok {
        fmt.Println("idade de Ana:", idade)
    }

    p := Pessoa{
        Nome:  "Marina",
        Idade: 28,
    }

    fmt.Println("pessoa:", p)
    fmt.Println("nome:", p.Nome)

    p.Idade = 29
    fmt.Println("idade atualizada:", p.Idade)
}
```

### Explicacao linha por linha

- `map[string]int{...}`: cria associacao entre nomes e idades.
- `idades["Carla"] = 40`: insere novo par chave/valor.
- `idade, ok := idades["Ana"]`: consulta com verificacao de existencia.
- `type Pessoa struct { ... }`: define um tipo estruturado.
- `Pessoa{Nome: ..., Idade: ...}`: inicializa struct por campos nomeados.
- `p.Nome`: acessa campo da struct.
- `p.Idade = 29`: altera o campo.

## 11. Erros Comuns e Anti-Padroes

1. **Usar `map` para tudo**: quando os campos sao fixos, `struct` geralmente e melhor.
2. **Esquecer o segundo retorno de leitura do `map`**: voce pode confundir ausencia com zero value legitimo.
3. **Escrever em `map` nil**: isso falha em runtime.
4. **Criar `struct` sem nome sem necessidade**: literais anonimos tem seu lugar, mas tipos nomeados comunicam melhor.
5. **Modelar entidade importante como `map[string]any` cedo demais**: isso joga fora seguranca de tipos.
6. **Abusar de dinamismo quando o dominio e estavel**: Go favorece modelos explicitos e previsiveis.
