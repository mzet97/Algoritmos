# Aula 16 - Redes, HTTP, clientes, servidores e backend idiomatico

---

## Objetivo da Aula

Entender como Go trabalha com rede e HTTP usando a biblioteca padrao, como montar clientes e servidores simples, como handlers se encaixam no modelo de backend idiomatico e como `context`, I/O e concorrencia aparecem naturalmente nesse tipo de software. Ao final, voce deve conseguir ler o esqueleto de um servico HTTP em Go e construir um servidor pequeno com clareza estrutural.

---

## 1. Por que HTTP importa tanto em Go?

Grande parte do uso profissional de Go envolve:

- APIs HTTP;
- servicos internos;
- proxies;
- gateways;
- ferramentas de infraestrutura com endpoints de observabilidade.

Go se tornou forte nisso porque combina:

- runtime eficiente;
- concorrencia pratica;
- biblioteca padrao robusta;
- deploy simples com binario unico na maioria dos casos.

---

## 2. `net/http`

O package central para HTTP em Go e `net/http`.

Ele oferece dois lados importantes:

- cliente HTTP;
- servidor HTTP.

Isso significa que a mesma biblioteca padrao cobre tanto consumo quanto exposicao de servicos.

### 2.1 O que e um handler?

Handler e algo capaz de responder a uma requisicao HTTP.

Conceitualmente, pense no contrato principal assim:

```go
func(w http.ResponseWriter, r *http.Request)
```

- `http.ResponseWriter`: interface usada para escrever status, headers e corpo da resposta.
- `*http.Request`: representa a requisicao recebida.

---

## 3. Servidor HTTP minimo

```go
package main

import (
    "fmt"
    "net/http"
)

func olaHandler(w http.ResponseWriter, r *http.Request) {
    fmt.Fprintln(w, "ola, Go HTTP")
}

func main() {
    http.HandleFunc("/", olaHandler)
    http.ListenAndServe(":8080", nil)
}
```

### 3.1 O que acontece aqui?

- `http.HandleFunc("/", olaHandler)`: registra rota e handler.
- `http.ListenAndServe(":8080", nil)`: abre socket, aceita conexoes e despacha requisicoes.

Ponto importante:

> o servidor HTTP ja lida naturalmente com concorrencia entre requisicoes.

Cada requisicao pode ser tratada em execucao concorrente pelo runtime.

---

## 4. `Request` e `ResponseWriter`

`*http.Request` carrega informacoes como:

- metodo HTTP;
- URL;
- headers;
- body;
- contexto da requisicao.

Exemplo:

```go
func handler(w http.ResponseWriter, r *http.Request) {
    fmt.Println(r.Method)
    fmt.Println(r.URL.Path)
}
```

`ResponseWriter` permite:

- escrever corpo;
- definir header;
- ajustar status code.

Exemplo:

```go
w.Header().Set("Content-Type", "application/json")
w.WriteHeader(http.StatusCreated)
w.Write([]byte(`{"ok":true}`))
```

## 5. JSON em APIs

Como vimos na aula de serializacao, JSON aparece o tempo todo em backend.

Resposta JSON simples:

```go
type Mensagem struct {
    Texto string `json:"texto"`
}

func handler(w http.ResponseWriter, r *http.Request) {
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(Mensagem{Texto: "ok"})
}
```

### 5.1 Por que `json.NewEncoder(w)`?

Porque ele escreve direto no fluxo de saida sem exigir buffer intermediario explicito para casos simples.

---

## 6. Lendo JSON de entrada

Exemplo:

```go
type Pedido struct {
    Nome string `json:"nome"`
}

func handler(w http.ResponseWriter, r *http.Request) {
    defer r.Body.Close()

    var p Pedido
    if err := json.NewDecoder(r.Body).Decode(&p); err != nil {
        http.Error(w, "json invalido", http.StatusBadRequest)
        return
    }
}
```

- `r.Body` e um fluxo de leitura.
- `Decode(&p)` preenche a struct.

Aqui reaparecem `io.Reader`, tratamento de erro e limpeza de recurso.

## 7. Cliente HTTP

Go tambem facilita consumo de servicos.

Exemplo basico:

```go
resp, err := http.Get("http://localhost:8080/")
if err != nil {
    return
}
defer resp.Body.Close()
```

Mas em software real, prefira `http.Client` com timeout configurado.

```go
client := http.Client{
    Timeout: 2 * time.Second,
}
```

### 7.1 Por que evitar dependencia cega de `http.Get`?

Porque timeout e controle de transporte importam muito em producao.

Sem timeout, uma chamada pode esperar indefinidamente em certas falhas.

---

## 8. `context` em requisicoes HTTP

Cada requisicao traz um contexto:

```go
ctx := r.Context()
```

Se o cliente desconectar ou a requisicao for cancelada, esse contexto reflete isso.

Para chamadas de saida, voce pode propagar contexto:

```go
req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
```

Isso conecta a aula anterior diretamente ao backend real.

## 9. Estrutura idiomatica de servico pequeno

Mesmo sem framework externo, uma organizacao minima razoavel costuma separar:

- `main`: bootstrap do processo;
- camada HTTP: handlers;
- camada de servico: regras de negocio;
- camada de acesso externo: banco, fila, APIs.

Isso ajuda a evitar que o handler vire um bloco monolitico com tudo misturado.

## 11. Exemplo completo da aula

```go
package main

import (
    "encoding/json"
    "log"
    "net/http"
    "time"
)

type Mensagem struct {
    Texto string `json:"texto"`
}

func olaHandler(w http.ResponseWriter, r *http.Request) {
    resposta := Mensagem{Texto: "ola do servidor Go"}
    payload, err := json.Marshal(resposta)
    if err != nil {
        http.Error(w, "falha ao serializar resposta", http.StatusInternalServerError)
        return
    }
    w.Header().Set("Content-Type", "application/json")
    if _, err := w.Write(append(payload, '\n')); err != nil {
        log.Printf("falha ao escrever resposta: %v", err)
    }
}

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("/ola", olaHandler)

    server := &http.Server{
        Addr:              "127.0.0.1:8080",
        Handler:           mux,
        ReadHeaderTimeout: 2 * time.Second,
        ReadTimeout:       5 * time.Second,
        WriteTimeout:      5 * time.Second,
        IdleTimeout:       30 * time.Second,
    }
    log.Println("servidor local em http://127.0.0.1:8080")
    if err := server.ListenAndServe(); err != nil {
        log.Fatal(err)
    }
}
```

### Explicacao linha por linha

- `http.NewServeMux()`: cria roteador simples da biblioteca padrao.
- `mux.HandleFunc(...)`: associa rota a handler.
- `w.Header().Set(...)`: define metadado da resposta HTTP.
- `json.Marshal(...)`: serializa antes de enviar cabecalhos; depois de iniciar uma resposta, nao e possivel trocar seu status por `500`.
- `server.ListenAndServe()`: inicia servidor apenas no loopback, com limites basicos de tempo para este laboratorio. Para expor o servico a rede, revise TLS, autenticacao, limites de corpo e shutdown; veja a Aula 20.
- `log.Fatal(err)`: registra erro fatal e encerra o processo.

## 12. Erros Comuns e Anti-Padroes

1. **Ignorar timeout em cliente HTTP**: isso abre caminho para travamentos longos.
2. **Nao fechar `resp.Body`**: recurso de rede pode ficar preso mais tempo que o necessario.
3. **Misturar regra de negocio pesada dentro do handler**: isso reduz testabilidade.
4. **Escrever JSON manualmente como string sem necessidade**: encoder reduz erros mecanicos.
5. **Ignorar `r.Context()`**: cancelamento do cliente deixa de se propagar.
6. **Assumir que backend precisa de framework pesado desde o inicio**: a biblioteca padrao ja cobre muita base.
