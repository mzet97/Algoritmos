# Aula 9 - Ponteiros, memoria, escape analysis e modelo de alocacao

Ponteiro em Go não faz aritmética, mas decide onde o valor mora — e a escape analysis decide por você mais vezes do que você imagina. Entender o modelo de alocação é entender o custo real do seu programa.

---

## Nesta aula

Entender como Go lida com enderecos, copias e compartilhamento por meio de ponteiros, como stack e heap entram no modelo conceitual da linguagem e por que escape analysis influencia custo de alocacao e garbage collector. Você vai aprender a distinguir ponteiro de referência de slice, explicar escape analysis e o modelo de alocação (stack vs. heap), e prever quando um valor escapa para o heap.
---

## 1. Por que estudar memoria em Go?

Go abstrai muita coisa, mas nao elimina custo de memoria.

Para escrever codigo de alto desempenho e necessario entender:

- quando ha copia de valores;
- quando ha compartilhamento indireto;
- quando um valor pode ir para heap;
- como isso afeta garbage collector e custo operacional.

Go nao exige gerenciamento manual como C, mas continua recompensando um modelo mental correto.

---

## 2. O que e um ponteiro?

Ponteiro e um valor que guarda o endereco de outro valor.

Exemplo:

```go
package main

import "fmt"

func main() {
    x := 10
    p := &x

    fmt.Println(x)
    fmt.Println(p)
    fmt.Println(*p)
}
```

- `&x`: endereco de `x`.
- `p`: ponteiro para `int`.
- `*p`: dereferencia o ponteiro, acessando o valor apontado.

### 2.1 Diferenca em relacao a C

Go tem ponteiros, mas o modelo e mais restrito que C:

- nao ha aritmetica de ponteiros no uso normal;
- o sistema de tipos e mais protegido;
- o garbage collector continua responsavel pelo ciclo de vida de memoria alocada.

Isso reduz varias classes de erro comuns de baixo nivel.

---

## 3. Modificando valor via ponteiro

```go
package main

import "fmt"

func dobrar(n *int) {
    *n = *n * 2
}

func main() {
    valor := 10
    dobrar(&valor)
    fmt.Println(valor)
}
```

Agora a funcao consegue alterar o valor original.

Esse e o contraste com a aula de passagem por valor.

- sem ponteiro: a funcao recebe copia;
- com ponteiro: a funcao acessa o valor original indiretamente.

---

## 4. Ponteiro para `struct`

Isso aparece o tempo todo em Go.

```go
type Conta struct {
    Saldo int
}

func depositar(c *Conta, valor int) {
    c.Saldo += valor
}
```

Quando o compilador ve `c.Saldo`, ele automaticamente faz a dereferencia necessaria.

Ou seja, voce nao precisa escrever `(*c).Saldo` toda hora, embora isso seja conceitualmente o que esta acontecendo.

---

## 5. `new` e `make`

Essas duas palavras confundem muita gente.

### 5.1 `new`

`new(T)` aloca um valor zero de tipo `T` e devolve `*T`.

```go
p := new(int)
fmt.Println(*p)
```

### 5.2 `make`

`make` e usado para inicializar tipos internos especiais como:

- slice;
- map;
- channel.

```go
numeros := make([]int, 5)
idades := make(map[string]int)
```

Regra pratica:

- `new` devolve ponteiro para zero value de um tipo comum;
- `make` prepara estruturas com runtime interno proprio.

---

## 6. Stack e heap no modelo conceitual

Modelo simplificado:

- **Stack**: area tipicamente usada para frames de funcao e valores locais de vida curta.
- **Heap**: area usada para valores cuja vida util ultrapassa o escopo local imediato ou cuja organizacao exige alocacao mais flexivel.

Em Go, voce nao escolhe manualmente stack ou heap na maior parte do tempo. O compilador decide com base em analise.

---

## 7. Escape analysis

Escape analysis e a analise feita pelo compilador para decidir se um valor pode ficar na stack ou precisa "escapar" para heap.

Exemplo conceitual:

```go
func criar() *int {
    x := 10
    return &x
}
```

`x` nasceu dentro da funcao, mas seu endereco sai dali. Logo, o compilador precisa garantir que esse valor continue vivo apos o retorno. Na pratica, isso leva o valor para heap.

### 7.1 Por que isso importa?

Porque alocacoes em heap tendem a:

- custar mais;
- aumentar trabalho do garbage collector;
- influenciar latencia e throughput em software intenso.

### 7.2 Como inspecionar

Voce pode pedir indicios ao compilador:

```bash
go build -gcflags="-m" .
```

Isso nao e leitura trivial no inicio, mas e uma ferramenta importante para estudo de performance.

---

## 8. Nem todo ponteiro implica heap

Ponto importante para evitar mito comum:

> usar ponteiro nao significa automaticamente heap.

A decisao depende do escape analysis.

Da mesma forma:

> valores sem ponteiro tambem podem ir para heap, dependendo do contexto.

Entao o modelo correto e:

- ponteiro e mecanismo de indirecao;
- heap e decisao de alocacao;
- uma coisa influencia a outra, mas nao sao sinonimos.

---

## 9. Copia de valor vs compartilhamento

Se voce passa uma `struct` por valor, ha copia.

Se voce passa `*Struct`, ha compartilhamento indireto do mesmo valor subjacente.

Essa decisao afeta:

- custo de copia;
- mutabilidade observavel;
- acoplamento entre funcoes;
- concorrencia futura.

Para tipos pequenos, copiar pode ser barato e simples.

Para tipos grandes ou mutaveis, ponteiro pode fazer sentido.

## 11. Exemplo completo da aula

```go
package main

import "fmt"

type Conta struct {
    Saldo int
}

func depositar(c *Conta, valor int) {
    c.Saldo += valor
}

func criarNumero() *int {
    x := 42
    return &x
}

func main() {
    valor := 10
    p := &valor

    fmt.Println("valor:", valor)
    fmt.Println("ponteiro:", p)
    fmt.Println("conteudo apontado:", *p)

    conta := Conta{Saldo: 100}
    depositar(&conta, 50)
    fmt.Println("saldo:", conta.Saldo)

    numero := criarNumero()
    fmt.Println("numero criado:", *numero)
}
```

### Explicacao linha por linha

- `p := &valor`: pega endereco de `valor`.
- `*p`: le o valor apontado.
- `depositar(c *Conta, ...)`: recebe ponteiro para modificar a `struct` original.
- `c.Saldo += valor`: acesso com dereferencia implicita pelo compilador.
- `return &x`: faz o endereco sair da funcao, permitindo escape para heap.

## 12. Erros Comuns e Anti-Padroes

1. **Trazer aritmetica de ponteiros do C para Go**: esse nao e o modelo idiomatico da linguagem.
2. **Achar que ponteiro sempre significa heap**: depende de escape analysis.
3. **Usar ponteiro em todo lugar sem motivo**: isso piora legibilidade e pode aumentar acoplamento.
4. **Copiar `struct` grande sem perceber custo**: entender tamanho e semantica importa.
5. **Confundir `new` com `make`**: eles resolvem problemas diferentes.
6. **Ignorar impacto de heap no garbage collector**: performance real depende disso.
