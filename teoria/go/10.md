# Aula 10 - Concorrencia com goroutines, channels e `select`

---

## Objetivo da Aula

Entender o modelo de concorrencia de Go com goroutines, channels e `select`, distinguindo concorrencia de paralelismo, comunicacao de sincronizacao e compartilhamento por memoria de coordenacao por mensagens. Ao final, você deverá: criar goroutines, comunicar por channels, usar `select` com timeout/cancelamento, e prever vazamento de goroutine e deadlock simples.
Mediremos com níveis de proficiência:
- **Nível 1 — Recordar:** `definir goroutine, channel (buffered/unbuffered) e `select``;
- **Nível 2 — Aplicar:** `diagnosticar deadlock e vazamento de goroutine e corrigir`;
- **Nível 3 — Projetar:** `projetar um pipeline concorrente justificando buffer, `select` e encerramento`.
---

## 1. Concorrencia vs paralelismo

Esses dois termos sao parentes, mas nao sao identicos.

- **Concorrencia**: estruturar varias atividades em progresso no mesmo intervalo logico.
- **Paralelismo**: executar literalmente varias atividades ao mesmo tempo em multiplos nucleos ou CPUs.

Um programa pode ser concorrente sem ser paralelo.

Go foi desenhada para tornar concorrencia uma parte natural da linguagem.

---

## 2. O que e uma goroutine?

Goroutine e uma execucao concorrente muito mais leve que uma thread tradicional do sistema operacional.

Voce cria com `go` antes da chamada de funcao.

```go
package main

import (
    "fmt"
    "time"
)

func tarefa() {
    fmt.Println("rodando em concorrencia")
}

func main() {
    go tarefa()
    time.Sleep(100 * time.Millisecond)
}
```

### 2.1 Por que elas sao importantes?

Porque permitem estruturar muitas tarefas concorrentes com menos custo do que o modelo de thread pesada por tarefa.

Ponto mental importante:

- goroutine nao e a mesma coisa que thread do SO;
- o runtime de Go multiplexa goroutines sobre threads reais.

---

## 3. O scheduler de Go

O runtime decide quando e onde executar goroutines.

Nao vamos entrar em todos os detalhes internos agora, mas o modelo pratico e:

- voce descreve concorrencia em goroutines;
- o scheduler distribui trabalho sobre threads do sistema;
- a quantidade de paralelismo efetivo depende de recursos da maquina e configuracao do runtime.

Isso separa a estrutura logica da concorrencia dos detalhes brutos de thread management.

---

## 4. O que e um channel?

Channel e um mecanismo tipado de comunicacao entre goroutines.

```go
ch := make(chan int)
```

- `chan int`: canal que transporta valores `int`.

Envio:

```go
ch <- 10
```

Recebimento:

```go
valor := <-ch
```

### 4.1 Por que isso existe?

Para coordenar concorrencia trocando dados explicitamente, em vez de depender sempre de memoria compartilhada com locks em todo lugar.

Frase famosa do ecossistema Go:

> nao compartilhe memoria para se comunicar; comunique-se para compartilhar memoria.

Ela nao e regra absoluta, mas resume a filosofia idiomatica.

---

## 5. Channel sem buffer

Channel sem buffer sincroniza envio e recebimento.

```go
package main

import "fmt"

func main() {
    ch := make(chan string)

    go func() {
        ch <- "mensagem pronta"
    }()

    msg := <-ch
    fmt.Println(msg)
}
```

Nesse caso:

- o envio espera receptor pronto;
- o recebimento espera emissor pronto.

Isso cria sincronizacao natural.

---

## 6. Channel com buffer

Com buffer, alguns valores podem ser enfileirados sem bloqueio imediato.

```go
ch := make(chan int, 2)
ch <- 10
ch <- 20
```

- capacidade `2` significa espaco para dois elementos antes de bloquear o proximo envio.

Canais com buffer sao uteis, mas tambem exigem cuidado para nao esconder problemas de coordenacao.

---

## 7. `select`

`select` espera entre varias operacoes de canal.

```go
select {
case msg := <-ch1:
    fmt.Println("ch1:", msg)
case msg := <-ch2:
    fmt.Println("ch2:", msg)
default:
    fmt.Println("nenhum canal pronto")
}
```

Isso e muito util quando voce precisa:

- responder ao primeiro evento disponivel;
- combinar timeout e trabalho;
- reagir a varias fontes concorrentes.

---

## 8. Fechando canal

Voce pode fechar um canal com `close(ch)` quando nao havera mais envios.

```go
close(ch)
```

Recebimento com teste:

```go
valor, ok := <-ch
```

- `ok == false` indica canal fechado e sem mais valores pendentes.

Ponto importante:

- quem envia geralmente e quem fecha;
- fechar canal do lado errado pode causar bugs e `panic`.

---

## 9. Concorrencia nao elimina bugs automaticamente

Go facilita concorrencia, mas nao torna problemas invisiveis.

Voce ainda pode ter:

- deadlock;
- goroutine vazando trabalho infinito;
- canal nunca consumido;
- ordem inesperada de execucao;
- condicoes de corrida quando compartilha memoria sem coordenacao adequada.

Ferramenta importante para mais tarde:

```bash
go test -race ./...
```

O race detector ajuda a encontrar acessos concorrentes inseguros.

## 11. Exemplo completo da aula

```go
package main

import (
    "fmt"
    "time"
)

func produtor(ch chan string) {
    time.Sleep(200 * time.Millisecond)
    ch <- "dados prontos"
}

func main() {
    ch := make(chan string)

    go produtor(ch)

    select {
    case msg := <-ch:
        fmt.Println("recebido:", msg)
    case <-time.After(1 * time.Second):
        fmt.Println("timeout")
    }
}
```

### Explicacao linha por linha

- `ch := make(chan string)`: cria canal sem buffer para `string`.
- `go produtor(ch)`: inicia uma goroutine concorrente.
- `time.Sleep(...)`: simula trabalho demorado.
- `ch <- "dados prontos"`: envia valor ao canal.
- `select { ... }`: espera entre o canal de dados e o timeout.
- `time.After(...)`: gera um canal que dispara apos o intervalo.

---

## 12. Erros Comuns e Anti-Padroes

1. **Confundir goroutine com thread do SO**: o runtime faz o multiplexing.
2. **Iniciar goroutine e deixar `main` terminar cedo demais**: o programa pode encerrar antes do trabalho acabar.
3. **Usar channel sem pensar no bloqueio**: envio e recebimento podem travar.
4. **Fechar canal do lado errado**: isso pode gerar `panic`.
5. **Achar que concorrencia sempre acelera tudo**: depende do problema e do custo de coordenacao.
6. **Ignorar race conditions em memoria compartilhada**: channels ajudam, mas nao eliminam todos os riscos.
