# Aula 15 - `context`, cancelamento, timeouts e codigo concorrente robusto

---

## Objetivo da Aula

Entender como `context` permite carregar cancelamento, deadline, timeout e metadados de requisicao entre camadas de software em Go. Ao final, voce deve conseguir interromper trabalho concorrente de forma cooperativa, evitar goroutines abandonadas e escrever APIs mais robustas para backend e infraestrutura.

---

## 1. Por que `context` existe?

Em software concorrente e distribuido, uma tarefa raramente vive isolada.

Exemplos reais:

- cliente HTTP desistiu da requisicao;
- timeout de operacao expirou;
- servidor esta desligando;
- pipeline interno nao precisa mais continuar;
- varias goroutines filhas devem parar juntas.

Sem um mecanismo comum, cada API inventaria seu proprio jeito de cancelar trabalho.

`context` existe para padronizar esse controle.

---

## 2. O que e `context.Context`?

`context.Context` e uma interface da biblioteca padrao que carrega principalmente:

- sinal de cancelamento;
- deadline ou timeout;
- valores de escopo de requisicao.

Pense nele como um canal de controle que atravessa chamadas e goroutines relacionadas.

### 2.1 O que ele nao e

`context` nao deve virar saco de parametros arbitrarios de negocio.

Ele serve para controle de ciclo de vida e metadados de requisicao, nao para substituir argumentos normais.

---

## 3. Contexto base

Os contextos base mais comuns sao:

- `context.Background()`;
- `context.TODO()`.

Exemplo:

```go
ctx := context.Background()
```

- `Background` e raiz tipica para aplicacoes.
- `TODO` e marcador temporario quando voce ainda nao decidiu o contexto certo.

---

## 4. Cancelamento com `WithCancel`

```go
ctx, cancel := context.WithCancel(context.Background())
defer cancel()
```

Agora existe um contexto derivado que pode ser cancelado explicitamente.

Dentro de uma goroutine, voce pode observar:

```go
select {
case <-ctx.Done():
    fmt.Println("cancelado")
    return
default:
}
```

- `Done()` devolve um canal fechado quando o contexto e cancelado.

---

## 5. Timeout com `WithTimeout`

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()
```

Depois do prazo, o contexto e cancelado automaticamente.

Isso e muito util em:

- chamadas HTTP;
- acesso a banco;
- tarefas internas com SLA;
- operacoes que nao podem esperar indefinidamente.

---

## 6. Deadline com `WithDeadline`

`WithDeadline` e parecido com `WithTimeout`, mas usa um instante absoluto.

```go
deadline := time.Now().Add(2 * time.Second)
ctx, cancel := context.WithDeadline(context.Background(), deadline)
```

Use quando voce ja tem um horario limite definido.

---

## 7. Verificando cancelamento

Padrao comum dentro de loop ou trabalho concorrente:

```go
select {
case <-ctx.Done():
    return ctx.Err()
default:
}
```

- `ctx.Err()` costuma devolver algo como `context.Canceled` ou `context.DeadlineExceeded`.

Esse modelo e cooperativo.

Isto e, o trabalho precisa checar o contexto e encerrar de forma consciente.

---

## 8. `WithValue` e cuidado de projeto

Existe tambem:

```go
ctx = context.WithValue(ctx, chave, valor)
```

Isso deve ser usado com disciplina.

Uso apropriado:

- metadados de requisicao;
- identificador de tracing;
- informacao transversal de infraestrutura.

Uso ruim:

- passar regra de negocio arbitraria;
- esconder dependencia importante da funcao;
- transformar contexto em mapa global disfarcado.

---

## 9. Evitando goroutine leak

Uma goroutine leak acontece quando uma goroutine continua viva sem necessidade, aguardando algo que nunca vira ou executando trabalho abandonado.

`context` ajuda a evitar isso porque fornece um caminho uniforme para sinalizar parada.

Em servicos concorrentes, isso e fundamental para:

- shutdown limpo;
- economia de recursos;
- previsibilidade operacional;
- controle de latencia.

---

## 10. Assinatura idiomatica

Em funcoes que aceitam contexto, o padrao idiomatico e:

```go
func Processar(ctx context.Context, entrada string) error
```

Regras praticas:

- `ctx` costuma ser o primeiro parametro;
- nao armazene contexto em struct por impulso;
- propague para chamadas descendentes relevantes;
- respeite cancelamento sempre que fizer sentido.

## 12. Exemplo completo da aula

```go
package main

import (
    "context"
    "fmt"
    "time"
)

func trabalhar(ctx context.Context) error {
    for {
        select {
        case <-ctx.Done():
            return ctx.Err()
        case <-time.After(300 * time.Millisecond):
            fmt.Println("trabalhando...")
        }
    }
}

func main() {
    ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
    defer cancel()

    err := trabalhar(ctx)
    fmt.Println("fim:", err)
}
```

### Explicacao linha por linha

- `context.WithTimeout(...)`: cria contexto com cancelamento automatico por tempo.
- `defer cancel()`: libera recursos associados ao contexto derivado.
- `select { ... }`: espera entre cancelamento e progresso de trabalho.
- `<-ctx.Done()`: observa sinal de encerramento.
- `ctx.Err()`: explica por que o contexto terminou.
- `time.After(...)`: simula passagem de tempo e trabalho periodico.

---

## 13. Erros Comuns e Anti-Padroes

1. **Ignorar `ctx.Done()` em trabalho potencialmente longo**: isso dificulta cancelamento cooperativo.
2. **Nao chamar `cancel()` quando apropriado**: recursos podem ficar vivos mais tempo que o necessario.
3. **Usar `context` para passar qualquer dado arbitrario**: isso degrada design da API.
4. **Esconder dependencia importante em `WithValue`**: parametro explicito costuma ser melhor.
5. **Nao propagar contexto para operacoes descendentes**: o cancelamento perde efeito.
6. **Criar goroutines sem estrategia de encerramento**: isso favorece leaks e shutdown ruim.
