# Aula 4 - Classes, `struct`, encapsulamento, construtores, destrutores e RAII

---

## Objetivo da Aula

Entender como C++ organiza dados e comportamento com classes e `struct`, como encapsulamento ajuda a proteger invariantes, qual o papel de construtores e destrutores, e por que RAII e um dos pilares centrais da linguagem. Ao final, voce devera: escrever uma classe cuja invariante sobrevive a todos os metodos publicos; prever a ordem de construcao/destruicao antes de rodar; e explicar por que RAII dispensa `finally`.

### Como ler esta aula (tres niveis)

- **Fundamental:** classe, construtor, destrutor, `const` em metodo.
- **Intermediario:** encapsulamento como invariante, ordem de destruicao.
- **Aprofundamento (opcional):** excecoes e a garantia basica (aula 09 retoma).

## 2. Classe e `struct`

Em C++, tanto `class` quanto `struct` podem ter:

- dados;
- funcoes membro;
- construtores;
- destrutores;
- modificadores de acesso.

### 2.1 Diferenca principal

A diferenca padrao e:

- em `struct`, membros sao `public` por padrao
- em `class`, membros sao `private` por padrao

Exemplo:

```cpp
struct Ponto {
    int x;
    int y;
};
```

```cpp
class Conta {
    int saldo;
};
```

### 2.2 Entao `struct` em C++ nao e igual a C?

Nao exatamente.

Em C++, `struct` pode ter:

- metodos;
- construtores;
- heranca;
- operadores.

Ou seja:

- `struct` em C++ participa do object model da linguagem.

---

## 3. Encapsulamento

Encapsular significa controlar:

- o que e interno;
- o que pode ser acessado de fora;
- como o objeto protege sua consistencia.

Exemplo:

```cpp
class Conta {
private:
    int saldo;
};
```

Aqui o usuario da classe nao pode mexer diretamente em `saldo`.

### 3.1 Por que isso importa?

Porque sem encapsulamento:

- qualquer codigo pode quebrar invariantes;
- estado invalido aparece com facilidade;
- manutencao piora.

### 3.2 Invariante

Invariante e uma regra que o objeto quer manter sempre verdadeira.

Exemplo:

- saldo nao pode ficar negativo sem politica explicita

---

## 4. Construtores

Construtor e uma funcao especial chamada quando o objeto nasce.

Exemplo:

```cpp
class Conta {
public:
    Conta() : saldo(0) {}

private:
    int saldo;
};
```

### 4.1 O que esta acontecendo?

- `Conta()` e o construtor
- `: saldo(0)` e lista de inicializacao
- o objeto nasce com `saldo` coerente

### 4.2 Por que nao inicializar no corpo apenas?

Em C++, a lista de inicializacao e o mecanismo correto e importante para:

- membros `const`
- referencias
- eficiencia
- ordem real de inicializacao

---

## 5. Destrutores

Destrutor e uma funcao especial chamada quando o objeto morre.

Exemplo:

```cpp
~Conta() {
    std::cout << "Conta destruida\n";
}
```

### 5.1 Quando isso roda?

Para objeto automatico:

- ao sair do escopo

Para objeto em heap via `new`:

- quando `delete` e chamado corretamente

Mais tarde veremos por que depender de `new`/`delete` manual demais e perigoso.

---

## 6. RAII

- **RAII**: Resource Acquisition Is Initialization.

Esse e um dos conceitos mais importantes de C++.

### 6.1 O que significa?

Aquisicao de recurso deve estar ligada ao nascimento do objeto, e liberacao do recurso deve estar ligada a morte do objeto.

Recurso pode ser:

- memoria;
- arquivo;
- socket;
- mutex;
- handle do sistema;
- qualquer coisa que precise cleanup.

### 6.2 Por que isso e poderoso?

Porque transforma cleanup em propriedade do lifetime do objeto.

Ou seja:

- objeto nasceu, recurso foi adquirido
- objeto morreu, recurso foi liberado

Isso reduz:

- leaks;
- caminhos de erro sem cleanup;
- codigo manual repetitivo.

### 6.3 Comparacao com C

Em C, esse padrao costuma ser disciplinar e manual:

- `init`
- `goto cleanup`
- `free`
- `close`

Em C++, RAII coloca isso no proprio object model.

## 7. Exemplo completo da aula

```cpp
#include <iostream>
#include <string>

class Logger {
public:
    Logger(const std::string& nome) : nome_(nome) {
        std::cout << "Logger criado: " << nome_ << "\n";
    }

    ~Logger() {
        std::cout << "Logger destruido: " << nome_ << "\n";
    }

    void log(const std::string& mensagem) const {
        std::cout << "[" << nome_ << "] " << mensagem << "\n";
    }

private:
    std::string nome_;
};

class Contador {
public:
    Contador(int valor_inicial) : valor_(valor_inicial) {}

    void incrementar() {
        valor_++;
    }

    int valor() const {
        return valor_;
    }

private:
    int valor_;
};

int main() {
    Logger logger("app");
    logger.log("inicio");

    Contador c(10);
    c.incrementar();
    c.incrementar();

    std::cout << "valor atual: " << c.valor() << "\n";
    logger.log("fim");

    return 0;
}
```

---

## 8. O que esse exemplo mostra?

### 8.1 `Logger`

Mostra:

- construtor;
- destrutor;
- membro privado;
- metodo `const`;
- RAII ligado ao lifetime automatico.

### 8.2 `Contador`

Mostra:

- objeto com estado interno;
- encapsulamento;
- metodo que modifica;
- metodo de leitura que nao modifica.

### 8.3 `int valor() const`

O `const` no fim do metodo significa:

- este metodo promete nao modificar o estado observavel do objeto

Isso e muito importante em C++.

---

## 9. Linha por linha do ponto central

Trecho:

```cpp
Logger(const std::string& nome) : nome_(nome) {
    std::cout << "Logger criado: " << nome_ << "\n";
}
```

- `Logger(...)`: construtor
- `const std::string& nome`: recebe string sem copiar desnecessariamente e sem permitir modificacao
- `: nome_(nome)`: inicializa o membro `nome_`
- corpo: faz efeito colateral de log

Trecho:

```cpp
~Logger() {
    std::cout << "Logger destruido: " << nome_ << "\n";
}
```

- destrutor
- chamado automaticamente ao sair do escopo para objeto automatico

Esse "automaticamente" e parte do coracao de RAII.

---

## 10. O que acontece em memoria?

No `main`, os objetos `logger` e `c` vivem na stack frame como objetos automaticos.

Mas eles podem conter internals mais complexos.

Por exemplo:

- `std::string` frequentemente administra memoria dinamica internamente

Mesmo assim, para o usuario de `Logger`, a historia fica simples:

- objeto nasceu corretamente
- objeto morre corretamente

### 10.1 O ponto essencial

RAII nao significa "sem recurso".

Significa:

- recurso acoplado ao lifetime do objeto

## 11. `public`, `private` e design

Exemplo:

```cpp
class Conta {
public:
    void depositar(int valor);
    int saldo() const;

private:
    int saldo_;
};
```

### 11.1 O que isso expressa?

- `public`: interface externa
- `private`: detalhe interno

### 11.2 Regra pratica

Prefira:

- expor operacoes;
- esconder representacao interna.

Isso deixa a classe mais evoluivel.

## 12. `struct` ainda e util?

Sim.

Em C++ moderno, `struct` e muito comum para:

- tipos simples de dados;
- agregados;
- pequenos objetos com semantica mais aberta;
- DTOs e configuracoes pequenas.

Use `class` quando quiser enfatizar:

- encapsulamento;
- invariantes;
- interface mais fechada.

Use `struct` quando quiser enfatizar:

- dados simples;
- organizacao mais aberta.

## 14. Comparacao com C, Rust, Go e Python

- Em C, `struct` agrupa dados, mas nao participa do mesmo modelo de construtores, destrutores e RAII.
- Em Rust, `struct` e `Drop` lembram um pouco o acoplamento de recurso ao lifetime, mas com regras de ownership diferentes.
- Em Go, `struct` existe, mas nao ha destrutor equivalente e o cleanup nao segue o mesmo modelo.
- Em Python, classes sao muito mais dinamicas e o lifetime nao e controlado do mesmo modo previsivel.

C++ aposta forte na ideia de:

- objeto com lifetime deterministico;
- cleanup automatico ao sair do escopo.

Esse e um diferencial enorme da linguagem.

## 15. Erros comuns e anti-padroes

1. **Achar que classe serve so para "orientacao a objetos classica"**.
2. **Expor membros internos sem necessidade**.
3. **Inicializar membros no corpo quando a lista de inicializacao seria o lugar correto**.
4. **Ignorar destrutor ao lidar com recurso real**.
5. **Usar `new` cedo demais em vez de entender lifetime automatico primeiro**.
6. **Esquecer `const` em metodos que nao deveriam modificar o objeto**.
