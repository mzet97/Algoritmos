# Aula 31 - Esboco didatico de servidor TCP com `poll` em C++

## 4. Estado por conexao

Um servidor event-driven serio precisa lembrar mais do que:

- "tenho um socket"

Ele precisa manter:

- identificador da conexao;
- buffer de entrada;
- buffer de saida;
- offset de escrita;
- flag de fechamento;
- metadados operacionais.

### 4.1 Modelo inicial

```cpp
struct Connection {
    int fd = -1;
    std::string input_buffer;
    std::string output_buffer;
    std::size_t write_offset = 0;
    bool closing = false;
    std::uint64_t id = 0;
};
```

---

## 5. Framing por linha

Protocolos baseados em texto frequentemente usam:

- `\n`

Isso parece simples, mas nao significa que um `recv` entrega:

- exatamente uma linha

Pode vir:

- meia linha;
- duas linhas;
- uma linha e meia;
- nada util ainda.

### 5.1 Consequencia

Voce precisa de:

- buffer incremental;
- parser que consome o que ja ficou completo;
- permanencia do resto no estado da conexao.

---

## 6. Escrita parcial

Mesma ideia do lado de saida.

Um `send` ou `write` pode:

- escrever tudo;
- escrever parte;
- nao escrever agora.

### 6.1 Consequencia

O servidor precisa manter:

- buffer de saida persistente;
- offset de progresso;
- tentativa futura de flush.

## 7. Observabilidade minima

Da Aula 27, trazemos a ideia de que servidor sem sinais operacionais vira caixa preta.

Mesmo em projeto pequeno, vale ter:

- log de inicializacao;
- log de conexao aberta;
- log de fechamento;
- log de erro de leitura/escrita;
- contador simples de requests processadas;
- contador de conexoes ativas.

## 8. Exemplo completo da aula

Este exemplo e didatico, usa APIs de sockets do **Linux** e escuta apenas em
`127.0.0.1`. `poll` avisa que ha atividade, mas os sockets continuam
bloqueantes: `accept`, `recv` ou `send` ainda podem parar o loop. Portanto,
nao use este codigo com clientes nao confiaveis ou em uma interface publica.

Ele mostra:

- accept;
- `poll`;
- buffer por conexao;
- parser por linha;
- respostas simples;
- flush parcial;
- limpeza correta.

```cpp
#include <arpa/inet.h>
#include <cerrno>
#include <cstdint>
#include <cstring>
#include <iostream>
#include <string>
#include <unordered_map>
#include <vector>

#include <netinet/in.h>
#include <poll.h>
#include <sys/socket.h>
#include <unistd.h>

struct Connection {
    int fd = -1;
    std::string input_buffer;
    std::string output_buffer;
    std::size_t write_offset = 0;
    bool closing = false;
    std::uint64_t id = 0;
};

class Server {
public:
    explicit Server(int port) : port_(port) {}

    bool init() {
        listen_fd_ = ::socket(AF_INET, SOCK_STREAM, 0);
        if (listen_fd_ < 0) {
            log_error("socket");
            return false;
        }

        int opt = 1;
        if (::setsockopt(listen_fd_, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt)) < 0) {
            log_error("setsockopt");
            return false;
        }

        sockaddr_in addr{};
        addr.sin_family = AF_INET;
        addr.sin_addr.s_addr = htonl(INADDR_LOOPBACK);
        addr.sin_port = htons(static_cast<std::uint16_t>(port_));

        if (::bind(listen_fd_, reinterpret_cast<sockaddr*>(&addr), sizeof(addr)) < 0) {
            log_error("bind");
            return false;
        }

        if (::listen(listen_fd_, 128) < 0) {
            log_error("listen");
            return false;
        }

        std::cout << "[INFO] listening on port " << port_ << "\n";
        return true;
    }

    void run() {
        while (true) {
            std::vector<pollfd> fds;
            fds.push_back({listen_fd_, POLLIN, 0});

            std::vector<int> client_order;
            client_order.reserve(connections_.size());

            for (auto& [fd, conn] : connections_) {
                short events = POLLIN;
                if (!conn.output_buffer.empty()) {
                    events |= POLLOUT;
                }
                fds.push_back({fd, events, 0});
                client_order.push_back(fd);
            }

            int rc = ::poll(fds.data(), static_cast<nfds_t>(fds.size()), -1);
            if (rc < 0) {
                log_error("poll");
                continue;
            }

            if (fds[0].revents & POLLIN) {
                accept_client();
            }

            for (std::size_t i = 1; i < fds.size(); i++) {
                int fd = client_order[i - 1];
                auto it = connections_.find(fd);
                if (it == connections_.end()) {
                    continue;
                }

                if (fds[i].revents & (POLLERR | POLLHUP | POLLNVAL)) {
                    close_connection(fd, "poll error/hup");
                    continue;
                }

                if (fds[i].revents & POLLIN) {
                    if (!handle_read(it->second)) {
                        close_connection(fd, "read failure");
                        continue;
                    }
                }

                auto again = connections_.find(fd);
                if (again == connections_.end()) {
                    continue;
                }

                if (fds[i].revents & POLLOUT) {
                    if (!handle_write(again->second)) {
                        close_connection(fd, "write failure");
                        continue;
                    }
                }

                again = connections_.find(fd);
                if (again != connections_.end() &&
                    again->second.closing &&
                    again->second.output_buffer.empty()) {
                    close_connection(fd, "graceful close");
                }
            }
        }
    }

    ~Server() {
        for (auto& [fd, conn] : connections_) {
            (void)conn;
            ::close(fd);
        }

        if (listen_fd_ >= 0) {
            ::close(listen_fd_);
        }
    }

private:
    void accept_client() {
        int client_fd = ::accept(listen_fd_, nullptr, nullptr);
        if (client_fd < 0) {
            log_error("accept");
            return;
        }

        Connection conn;
        conn.fd = client_fd;
        conn.id = next_id_++;
        connections_.emplace(client_fd, std::move(conn));
        std::cout << "[INFO] client accepted id=" << connections_[client_fd].id
                  << " active=" << connections_.size() << "\n";
    }

    bool handle_read(Connection& conn) {
        char buffer[1024];
        ssize_t n = ::recv(conn.fd, buffer, sizeof(buffer), 0);
        if (n == 0) {
            return false;
        }

        if (n < 0) {
            log_error("recv");
            return false;
        }

        conn.input_buffer.append(buffer, static_cast<std::size_t>(n));

        constexpr std::size_t max_input = 8192;
        if (conn.input_buffer.size() > max_input) {
            queue_response(conn, "ERR input too large\n");
            conn.closing = true;
            return true;
        }

        consume_lines(conn);
        return true;
    }

    void consume_lines(Connection& conn) {
        while (true) {
            std::size_t pos = conn.input_buffer.find('\n');
            if (pos == std::string::npos) {
                return;
            }

            std::string line = conn.input_buffer.substr(0, pos);
            conn.input_buffer.erase(0, pos + 1);

            if (!line.empty() && line.back() == '\r') {
                line.pop_back();
            }

            handle_command(conn, line);
            requests_total_++;
        }
    }

    void handle_command(Connection& conn, const std::string& line) {
        if (line == "PING") {
            queue_response(conn, "PONG\n");
            return;
        }

        if (line.rfind("ECHO ", 0) == 0) {
            queue_response(conn, line.substr(5) + "\n");
            return;
        }

        if (line == "QUIT") {
            queue_response(conn, "BYE\n");
            conn.closing = true;
            return;
        }

        queue_response(conn, "ERR unknown command\n");
    }

    void queue_response(Connection& conn, const std::string& msg) {
        constexpr std::size_t max_output = 8192;
        if (conn.output_buffer.size() + msg.size() > max_output) {
            conn.closing = true;
            return;
        }

        conn.output_buffer += msg;
    }

    bool handle_write(Connection& conn) {
        while (conn.write_offset < conn.output_buffer.size()) {
            const char* data = conn.output_buffer.data() + conn.write_offset;
            std::size_t remaining = conn.output_buffer.size() - conn.write_offset;

            // Linux: evita que um cliente desconectado termine o processo via SIGPIPE.
            ssize_t n = ::send(conn.fd, data, remaining, MSG_NOSIGNAL);
            if (n < 0) {
                log_error("send");
                return false;
            }

            if (n == 0) {
                return false;
            }

            conn.write_offset += static_cast<std::size_t>(n);
        }

        conn.output_buffer.clear();
        conn.write_offset = 0;
        return true;
    }

    void close_connection(int fd, const char* reason) {
        auto it = connections_.find(fd);
        if (it == connections_.end()) {
            return;
        }

        std::cout << "[INFO] client closed id=" << it->second.id
                  << " reason=" << reason
                  << " active_before=" << connections_.size()
                  << " requests_total=" << requests_total_
                  << "\n";

        ::close(fd);
        connections_.erase(it);
    }

    void log_error(const char* what) {
        std::cerr << "[ERROR] " << what << " errno=" << errno
                  << " message=" << std::strerror(errno) << "\n";
    }

    int port_;
    int listen_fd_ = -1;
    std::unordered_map<int, Connection> connections_;
    std::uint64_t next_id_ = 1;
    std::uint64_t requests_total_ = 0;
};

int main() {
    Server server(8080);
    if (!server.init()) {
        return 1;
    }

    server.run();
    return 0;
}
```

## 9. O que esse exemplo ensina?

### 9.1 `Server`

Centraliza:

- socket de escuta;
- tabela de conexoes;
- loop principal;
- logs simples.

### 9.2 `Connection`

Guarda tudo que precisa sobreviver entre eventos:

- bytes incompletos;
- resposta pendente;
- estado de fechamento.

### 9.3 `consume_lines`

Mostra parser incremental:

- consome o que ja formou linha;
- preserva resto.

### 9.4 `handle_write`

Guarda o progresso de uma escrita parcial:

- usa `write_offset`;
- continua de onde parou. Como `send` ainda e bloqueante, o `while` pode
  parar o loop inteiro ate haver espaco no buffer do peer.

### 9.5 `closing`

Ajuda a fazer encerramento gracioso:

- termina flush;
- fecha depois.

## 10. O que esta simplificado aqui?

Muita coisa.

Este projeto ainda nao cobre, por exemplo:

- non-blocking mode completo;
- tratamento fino de `EAGAIN`;
- signal handling;
- timeouts por conexao;
- autenticacao;
- TLS;
- fila real de varias mensagens;
- parser binario;
- backpressure mais sofisticado;
- thread pool para trabalho CPU-bound.

### 10.1 Limites de seguranca do esboco

Mesmo em loopback, um cliente pode manter a conexao aberta e parar de ler;
`send` bloqueante pode entao travar todos os clientes. `poll` nao elimina esse
risco. `MSG_NOSIGNAL` evita a terminacao por `SIGPIPE` no Linux, mas nao evita
bloqueio ou outros erros de escrita. O limite de 8192 bytes e **por buffer**,
nao limita o numero de conexoes, CPU ou memoria total. Para servir entrada nao
confiavel, a proxima etapa precisa configurar listener e clientes como nao
bloqueantes, tratar `EAGAIN`/`EWOULDBLOCK`, limitar conexoes e impor prazos
de leitura e escrita. Revisar tambem a politica de backpressure antes de
expor o servico fora da maquina.

## 12. Como esse projeto conversa com as Aulas 28 e 30?

O hot path real em servidor pequeno costuma passar por:

- parsing;
- copia de buffer;
- flush de escrita;
- tabela de conexoes;
- logs.

Com carga maior, passa a importar:

- localidade dos dados;
- padrao de acesso aos buffers;
- custo de formatacao de logs;
- contencao em estruturas globais;
- desenho de containers.

Ou seja:

- arquitetura primeiro;
- profiling depois;
- micro-otimizacao por ultimo.

## 13. Comparacao com C, Rust, Go e Python

- Em C, a mesma arquitetura seria ainda mais manual, com menos RAII e mais responsabilidade explicita de cleanup.
- Em Rust, ownership e tipos ajudariam bastante a modelar conexoes e estado com mais seguranca.
- Em Go, goroutines e netpoll do runtime esconderiam boa parte da mecanica do event loop.
- Em Python, `asyncio` e frameworks tornariam a expressao mais curta, mas com outro custo e outro grau de controle.

C++ fica num ponto interessante:

- proximo da API nativa;
- forte para modelar estado;
- bom para wrappers e RAII;
- perigoso se esconder demais o mecanismo real.

## 15. Evolucoes saudaveis

Boas proximas melhorias:

1. colocar sockets em non-blocking mode
2. tratar `EAGAIN`/`EWOULDBLOCK` em `accept`, `recv` e `send`, com retry futuro
3. separar parser e protocolo em modulos
4. trocar string unica por fila de saida
5. introduzir timeouts
6. adicionar metricas e tracing mais formais
7. descarregar trabalho pesado para pool
8. limitar conexoes, tempo e trabalho por iteracao e testar cliente lento

## 17. Erros comuns e anti-padroes

1. **Assumir que um `recv` entrega exatamente uma linha inteira**.
2. **Esquecer que escrita parcial exige estado persistente**.
3. **Misturar parser, protocolo e I/O no mesmo bloco sem fronteira minima**.
4. **Nao impor limite de buffer por conexao**.
5. **Fechar conexao sem limpar estado ou sem flush planejado**.
6. **Achar que "funcionou com um cliente" significa arquitetura pronta para producao**.
7. **Otimizar antes de estabilizar corretude e visibilidade operacional**.
