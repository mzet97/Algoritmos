# Aula 3 - Funcoes, sobrecarga, namespaces, escopo e organizacao basica do codigo

---

## Objetivo da Aula

Entender como declarar e definir funcoes em C++, como a sobrecarga funciona, para que servem namespaces, como escopo controla visibilidade de nomes, e como comecar a organizar codigo em arquivos e modulos pequenos. Ao final, voce devera: explicar por que a chamada resolve para uma sobrecarga e nao outra; prever o que cada namespace qualifica antes de compilar; e separar declaracao de definicao sem erro de linkagem.

### Como ler esta aula (tres niveis)

- **Fundamental:** funcao, sobrecarga, `std::`, escopo.
- **Intermediario:** declaracao vs definicao, ODR na pratica.
- **Aprofundamento (opcional):** mangling e resolucao de sobrecarga (aula 12a mede o custo).

## 2. O que e uma funcao?

Uma funcao e um bloco nomeado de codigo que:

- pode receber entradas;
- pode produzir saida;
- pode encapsular logica;
- pode ser reutilizado em varios pontos.

Exemplo simples:

```cpp
int quadrado(int x) {
    return x * x;
}
```

### 2.1 Partes da funcao

- tipo de retorno: `int`
- nome: `quadrado`
- parametro: `int x`
- corpo: bloco entre chaves

---

## 3. Declaracao vs definicao

Em C++ isso vai aparecer o tempo todo.

Declaracao:

```cpp
int quadrado(int x);
```

Definicao:

```cpp
int quadrado(int x) {
    return x * x;
}
```

### 3.1 Diferenca conceitual

- declaracao diz que a entidade existe com certa assinatura
- definicao fornece a implementacao

Mais tarde isso sera fundamental para:

- headers
- multiplos arquivos
- linkagem
- ODR

---

## 4. Parametros e retorno

Exemplo:

```cpp
double media(double a, double b) {
    return (a + b) / 2.0;
}
```

Aqui:

- `a` e `b` entram por valor
- a funcao retorna um `double`

### 4.1 Passagem por valor

No modelo inicial:

- a funcao recebe copia dos argumentos

Isso e simples e seguro para tipos pequenos.

### 4.2 Mais tarde

Para objetos grandes, vamos discutir:

- `const T&`
- movimento
- ownership

---

## 5. Sobrecarga

C++ permite varias funcoes com o mesmo nome, desde que as assinaturas sejam diferentes.

Exemplo:

```cpp
int soma(int a, int b) {
    return a + b;
}

double soma(double a, double b) {
    return a + b;
}
```

### 5.1 O que muda aqui?

O nome e o mesmo:

- `soma`

Mas os tipos dos parametros mudam.

O compilador escolhe a funcao apropriada com base na chamada.

### 5.2 Por que isso existe?

Para permitir:

- interfaces mais naturais;
- reuso de nomes;
- codigo generico mais expressivo.

### 5.3 Comparacao com C

Em C, isso nao existe da mesma forma.

Voce frequentemente precisaria criar nomes como:

- `soma_int`
- `soma_double`

---

## 6. Escopo

Escopo responde:

- onde um nome pode ser usado?

Exemplo:

```cpp
int x = 10;

if (x > 0) {
    int y = 20;
}
```

Aqui:

- `x` existe no escopo mais externo
- `y` existe apenas dentro do bloco do `if`

### 6.1 Por que isso importa?

Porque escopo ajuda a:

- limitar visibilidade;
- evitar confusao;
- reduzir colisao de nomes;
- controlar lifetime de variaveis automaticas.

---

## 7. Namespaces

Namespace e um mecanismo para agrupar nomes e evitar conflito.

Exemplo:

```cpp
namespace matematica {
    int dobro(int x) {
        return x * 2;
    }
}
```

Uso:

```cpp
int valor = matematica::dobro(5);
```

### 7.1 `::`

Esse operador e o operador de resolucao de escopo.

Ele indica:

- "procure esse nome dentro desse namespace ou escopo"

### 7.2 Por que isso existe?

Porque projetos grandes acumulam nomes.

Sem namespace, colisao vira problema rapidamente.

### 7.3 Regra pratica

Entenda bem `std::alguma_coisa`.

Isso quer dizer:

- nome `alguma_coisa` dentro do namespace `std`

---

## 8. `using namespace`?

Voce vera por ai:

```cpp
using namespace std;
```

No comeco pode parecer conveniente.

Mas didaticamente e tecnicamente, prefira:

```cpp
std::cout
std::string
std::vector
```

### 8.1 Por que evitar no comeco?

- esconde de onde o nome veio;
- aumenta chance de conflito;
- piora leitura em codigo maior.

## 9. Exemplo completo da aula

```cpp
#include <iostream>

namespace matematica {
    int soma(int a, int b) {
        return a + b;
    }

    double soma(double a, double b) {
        return a + b;
    }

    int quadrado(int x) {
        return x * x;
    }
}

void imprimir_resultado(const char* nome, int valor) {
    std::cout << nome << ": " << valor << "\n";
}

void imprimir_resultado(const char* nome, double valor) {
    std::cout << nome << ": " << valor << "\n";
}

int main() {
    int a = matematica::soma(2, 3);
    double b = matematica::soma(2.5, 3.5);
    int c = matematica::quadrado(7);

    imprimir_resultado("soma int", a);
    imprimir_resultado("soma double", b);
    imprimir_resultado("quadrado", c);

    if (c > 40) {
        int limite_local = 100;
        std::cout << "limite local: " << limite_local << "\n";
    }

    return 0;
}
```

---

## 10. O que esse exemplo mostra?

### 10.1 Namespace `matematica`

Agrupa funcoes relacionadas e evita jogar tudo no escopo global.

### 10.2 Sobrecarga de `soma`

Temos duas funcoes chamadas `soma`:

- uma para `int`
- outra para `double`

### 10.3 Sobrecarga de `imprimir_resultado`

Mesmo padrao:

- um nome
- implementacoes para tipos diferentes

### 10.4 Escopo local

`limite_local` so existe dentro do bloco `if`.

---

## 11. Linha por linha da ideia mais importante

Trecho:

```cpp
double soma(double a, double b) {
    return a + b;
}
```

- `double`: a funcao devolve `double`
- `soma`: nome
- `(double a, double b)`: assinatura dos parametros
- `return a + b;`: resultado

Quando voce chama:

```cpp
matematica::soma(2.5, 3.5)
```

o compilador prefere a sobrecarga compativel com `double`.

---

## 12. O que acontece em memoria e execucao?

Cada chamada de funcao cria um novo contexto de execucao.

Conceitualmente, isso envolve:

- parametros;
- endereco de retorno;
- variaveis locais;
- possivel stack frame.

Ainda nao precisamos entrar em ABI profunda.

Mas o modelo mental correto e:

- funcao nao e so "atalho textual"
- ha custo operacional e contexto de chamada

### 12.1 Comparacao com Python e Go

- Em Python, a chamada tambem cria contexto, mas num runtime muito mais alto nivel.
- Em Go, a chamada tambem existe, mas a linguagem esconde mais detalhes operacionais do iniciante.
- Em C++, custo e layout da chamada podem importar bastante em codigo critico.

## 13. Organizacao basica do codigo

Mesmo antes de multiplos arquivos, vale criar disciplina:

- funcoes pequenas;
- nomes coerentes;
- logica separada por responsabilidade;
- evitar `main` gigante.

### 13.1 Padrao saudavel no comeco

- funcoes puras para calculo quando possivel;
- funcoes de I/O separadas;
- namespace para agrupar dominio.

## 15. Erros comuns e anti-padroes

1. **Escrever tudo dentro de `main`**.
2. **Confundir declaracao com definicao**.
3. **Usar `using namespace std;` sem criterio logo no inicio**.
4. **Criar sobrecargas ambiguas ou confusas**.
5. **Usar nomes genericos demais em escopo global**.
6. **Ignorar escopo local e reaproveitar nomes de forma baguncada**.

---

## 16. Comparacao com C, Rust, Go e Python

- Em C, nao ha sobrecarga de funcoes por assinatura.
- Em Rust, nomes e modulos seguem outra estrutura, e sobrecarga tradicional nao existe da mesma forma.
- Em Go, o sistema de packages organiza nomes, mas sobrecarga nao e um recurso da linguagem.
- Em Python, modulos e funcoes existem, mas a resolucao e dinamica e o custo mental e diferente.

C++ oferece:

- sobrecarga;
- namespaces;
- mais estrutura estatica;

mas cobra:

- mais atencao a resolucao de nomes;
- assinaturas;
- organizacao correta.
