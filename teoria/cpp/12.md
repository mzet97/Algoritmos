# Aula 12 - Headers, multiplos arquivos, templates em headers, ODR, linkagem e ABI

---

## Nesta aula

Entender como projetos C++ se organizam em headers e source files, por que templates costumam viver em headers, o que e ODR, como a linkagem junta varias translation units e por que ABI importa para compatibilidade binaria. Você vai aprender a montar um projeto com varios arquivos que compila via objetos separados; diagnosticar um erro de ODR/linkagem lendo a mensagem; e explicar por que template mora em header.

## 2. Header e source file

Em C++ e comum separar:

- declaracoes em `.h` ou `.hpp`
- definicoes em `.cpp`

Exemplo conceitual:

- `math_utils.h`
- `math_utils.cpp`
- `main.cpp`

### 2.1 Header

Header costuma expor:

- tipos;
- assinaturas;
- constantes;
- templates;
- contratos publicos.

### 2.2 Source file

Arquivo `.cpp` costuma conter:

- implementacao concreta;
- detalhes internos;
- funcoes helper privadas ao arquivo.

---

## 3. Include guards

Header nao deve ser incluido repetidamente sem protecao.

Exemplo:

```cpp
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int soma(int a, int b);

#endif
```

### 3.1 Por que isso existe?

Para evitar multiplas inclusoes do mesmo conteudo na mesma translation unit.

### 3.2 `#pragma once`

Tambem e muito usado:

```cpp
#pragma once
```

Mas include guard tradicional continua importante de entender.

---

## 4. Translation unit

Depois do preprocessor, cada `.cpp` vira uma translation unit separada.

Exemplo:

- `main.cpp` com includes processados
- `math_utils.cpp` com includes processados

Cada uma e compilada separadamente em objeto intermediario.

Depois o linker junta tudo.

---

## 5. Declaracao, definicao e linker

Se voce declara:

```cpp
int soma(int a, int b);
```

e chama `soma`, mas nunca fornece definicao real:

- compila;
- mas o linker falha.

### 5.1 Por que?

Porque o compilador acredita na declaracao.

Quem precisa provar que a implementacao existe no final e:

- o linker.

---

## 6. Exemplo completo da aula

### 6.1 `math_utils.h`

```cpp
#ifndef MATH_UTILS_H
#define MATH_UTILS_H

int soma(int a, int b);
int dobro(int x);

template <typename T>
T quadrado(T x) {
    return x * x;
}

#endif
```

### 6.2 `math_utils.cpp`

```cpp
#include "math_utils.h"

int soma(int a, int b) {
    return a + b;
}

int dobro(int x) {
    return x * 2;
}
```

### 6.3 `main.cpp`

```cpp
#include <iostream>

#include "math_utils.h"

int main() {
    std::cout << "soma = " << soma(2, 3) << "\n";
    std::cout << "dobro = " << dobro(10) << "\n";
    std::cout << "quadrado = " << quadrado(6) << "\n";
    return 0;
}
```

---

## 7. Por que o template esta no header?

Esse e um ponto central.

`quadrado` e template.

Na maioria dos casos, o compilador precisa ver a definicao do template no ponto de uso para instanciar codigo concreto.

Por isso, templates frequentemente ficam:

- no header

### 7.1 Comparacao com funcao comum

Funcao comum pode ser:

- declarada no header;
- definida no `.cpp`

Template normalmente precisa ter a definicao visivel no header.

---

## 8. ODR

- **ODR**: One Definition Rule.

Intuicao:

- certas entidades nao podem ter multiplas definicoes conflitantes no programa.

### 8.1 Por que isso importa?

Porque projetos grandes podem:

- definir a mesma funcao em mais de um lugar;
- repetir objeto global;
- introduzir inconsistencias discretas entre translation units.

### 8.2 Resultado

Pode haver:

- erro de link;
- comportamento indefinido;
- bug sutil e dificil de diagnosticar.

---

## 9. Linkagem

Linkagem responde:

- como nomes definidos em um arquivo se conectam a usos em outro?

### 9.1 Fluxo simplificado

1. cada `.cpp` vira objeto intermediario
2. linker resolve simbolos
3. binario final e gerado

### 9.2 Erros tipicos de link

- funcao declarada e nao definida;
- multiplas definicoes;
- objeto nao incluido na linha de build;
- assinatura diferente entre declaracao e definicao.

---

## 10. ABI

- **ABI**: Application Binary Interface.

Ela define aspectos binarios como:

- convencao de chamada;
- layout de certos tipos;
- nome mangling;
- contrato de ligacao entre binarios compilados.

### 10.1 Por que isso importa?

Porque compatibilidade de codigo fonte nao e igual a compatibilidade binaria.

Voce pode ter problemas se:

- compilar partes com configuracoes diferentes;
- misturar toolchains incompativeis;
- mudar layout publico de biblioteca;
- atravessar fronteiras entre C e C++ sem cuidado.

---

## 11. `extern "C"`

Quando interoperamos com C, C++ oferece:

```cpp
extern "C" {
    int soma_c(int a, int b);
}
```

### 11.1 Intuicao

Isso pede ligacao com convencao de C para aquele simbolo, evitando nome mangling de C++ naquele caso.

Mais tarde, na aula de interoperabilidade, voltaremos nisso.

---

## 12. O que acontece em memoria e no build?

Cada translation unit:

- e compilada separadamente;
- gera simbolos;
- inclui seus headers processados.

O linker depois conecta:

- quem declarou e usou;
- quem realmente definiu.

### 12.1 Ponto importante

Header nao "existe em runtime" como entidade especial.

Ele e infraestrutura de compilacao.

---

## 13. Comparacao com C, Rust, Go e Python

- Em C, headers e source files seguem modelo muito parecido, embora C++ adicione templates, ODR mais rica e name mangling.
- Em Rust, modulos e crates seguem outro sistema de organizacao e build, com menos exposicao direta a linker no uso basico.
- Em Go, packages e build tool escondem mais do pipeline do iniciante.
- Em Python, a organizacao modular e muito diferente e o linking binario nao aparece da mesma forma no dia a dia.

C++ cobra que voce entenda:

- preprocessor;
- compilacao separada;
- linkagem;
- ODR;
- ABI.

## 14. Comandos exatos

Compilar em uma linha:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -O0 -g main.cpp math_utils.cpp -o app
```

Compilar em duas etapas:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -O0 -g -c main.cpp -o main.o
g++ -std=c++20 -Wall -Wextra -Wpedantic -O0 -g -c math_utils.cpp -o math_utils.o
g++ main.o math_utils.o -o app
```

Rodar:

```bash
./app
```

## 15. Erros comuns e anti-padroes

1. **Definir funcao nao inline em header incluido por varios `.cpp`**.
2. **Declarar funcao e esquecer definicao real**.
3. **Colocar template so no `.cpp` e esperar que funcione genericamente**.
4. **Ignorar include guard**.
5. **Confundir erro de compilacao com erro de linkagem**.
6. **Achar que compatibilidade de fonte garante compatibilidade binaria**.
