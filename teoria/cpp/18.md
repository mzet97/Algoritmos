# Aula 18 - Redes e programacao de sistemas com C++ sobre APIs nativas

Rede em C++ sobre APIs nativas expõe tudo que frameworks escondem: socket bloqueante, leitura parcial, erro no meio da conexão. Entender essa camada é pré-requisito para avaliar qualquer abstração que venha depois.

---

## Nesta aula

Entender como C++ se apoia em APIs nativas de sistema para trabalhar com sockets, descritores, arquivos e outros recursos de baixo nivel, e como RAII e containers podem melhorar a ergonomia sem esconder o mecanismo real. Ao final, voce deve conseguir enxergar C++ como uma camada de engenharia sobre syscalls e APIs do SO, e nao como substituto magico delas.

Você vai aprender a construir cliente e servidor sobre APIs nativas; distinguir bloqueante de nao bloqueante; e medir o comportamento sob carga.

## 2. C++ nao substitui a API nativa

Para programacao de sistemas, C++ costuma usar diretamente:

- sockets POSIX em Unix-like;
- Winsock no Windows;
- APIs de arquivo e processo do sistema;
- `poll`, `select`, `epoll`, `kqueue` ou equivalentes.

### 2.1 O papel de C++ aqui

C++ ajuda a:

- encapsular recursos em objetos;
- modelar ownership;
- evitar vazamento de FD;
- organizar parser, buffer e estado;
- separar camada de sistema da logica da aplicacao.

---

## 3. RAII para descritores

Um file descriptor ou socket handle e recurso perfeito para RAII.

Exemplo conceitual:

```cpp
class Fd {
public:
    explicit Fd(int fd = -1) : fd_(fd) {}

    ~Fd() {
        if (fd_ >= 0) {
            ::close(fd_);
        }
    }

    Fd(const Fd&) = delete;
    Fd& operator=(const Fd&) = delete;

private:
    int fd_;
};
```

### 3.1 Por que isso e bom?

Porque conecta:

- ownership do descritor;
- cleanup automatico;
- regra dos 5;
- seguranca em face de erro.

---

## 4. Sockets: fluxo minimo

Servidor TCP classico em Unix-like passa por:

1. `socket`
2. `bind`
3. `listen`
4. `accept`
5. `read` ou `recv`
6. `write` ou `send`
7. `close`

Cliente TCP classico passa por:

1. `socket`
2. `connect`
3. `send`
4. `recv`
5. `close`

### 4.1 Moral importante

C++ nao apaga essa sequencia.

Ele ajuda a estrutura-la melhor.

## 5. Exemplo completo da aula

Cliente TCP simples em Unix-like com RAII minimo:

```cpp
#include <arpa/inet.h>
#include <sys/socket.h>
#include <unistd.h>

#include <cerrno>
#include <cstring>
#include <iostream>
#include <string>

class SocketFd {
public:
    explicit SocketFd(int fd = -1) : fd_(fd) {}

    ~SocketFd() {
        if (fd_ >= 0) {
            ::close(fd_);
        }
    }

    SocketFd(const SocketFd&) = delete;
    SocketFd& operator=(const SocketFd&) = delete;

    SocketFd(SocketFd&& other) noexcept : fd_(other.fd_) {
        other.fd_ = -1;
    }

    SocketFd& operator=(SocketFd&& other) noexcept {
        if (this == &other) {
            return *this;
        }

        if (fd_ >= 0) {
            ::close(fd_);
        }

        fd_ = other.fd_;
        other.fd_ = -1;
        return *this;
    }

    int get() const {
        return fd_;
    }

    bool valid() const {
        return fd_ >= 0;
    }

private:
    int fd_;
};

int main() {
    SocketFd sock(::socket(AF_INET, SOCK_STREAM, 0));
    if (!sock.valid()) {
        std::cerr << "socket falhou: " << std::strerror(errno) << "\n";
        return 1;
    }

    sockaddr_in addr{};
    addr.sin_family = AF_INET;
    addr.sin_port = htons(8080);

    if (::inet_pton(AF_INET, "127.0.0.1", &addr.sin_addr) <= 0) {
        std::cerr << "inet_pton falhou\n";
        return 2;
    }

    if (::connect(sock.get(),
                  reinterpret_cast<sockaddr*>(&addr),
                  sizeof(addr)) < 0) {
        std::cerr << "connect falhou: " << std::strerror(errno) << "\n";
        return 3;
    }

    std::string msg = "PING\n";
    ssize_t sent = ::send(sock.get(), msg.data(), msg.size(), 0);
    if (sent < 0) {
        std::cerr << "send falhou: " << std::strerror(errno) << "\n";
        return 4;
    }

    char buffer[256];
    ssize_t n = ::recv(sock.get(), buffer, sizeof(buffer) - 1, 0);
    if (n < 0) {
        std::cerr << "recv falhou: " << std::strerror(errno) << "\n";
        return 5;
    }

    buffer[n] = '\0';
    std::cout << "resposta: " << buffer;

    return 0;
}
```

## 6. O que esse exemplo mostra?

### 6.1 `SocketFd`

Wrapper RAII simples:

- fecha socket no destrutor;
- impede copia;
- permite movimento.

### 6.2 `sockaddr_in`

Struct da API de rede do sistema.

### 6.3 `connect`

Conecta ao servidor.

### 6.4 `send` e `recv`

I/O real de rede.

### 6.5 `std::string` como payload local

C++ ajuda a organizar buffer e texto, mas a chamada final ainda usa a API nativa.

## 7. Leitura parcial, escrita parcial e framing

Ponto crucial:

- rede nao garante mensagem inteira por `recv`
- escrita tambem pode ser parcial

### 7.1 Consequencia

Voce precisa pensar em:

- buffer incremental;
- framing;
- parser;
- retry de envio;
- backpressure.

### 7.2 Erro classico

Assumir:

- "um `recv` == uma mensagem"

Isso e falso.

---

## 8. Blocking vs non-blocking

Sockets podem operar em modo:

- bloqueante;
- nao bloqueante.

### 8.1 Bloqueante

Mais simples para comecar.

### 8.2 Nao bloqueante

Necessario para event loops mais sofisticados.

Ai entram mecanismos como:

- `poll`
- `epoll`
- `select`
- `kqueue`

---

## 9. Wrappers em C++ devem respeitar o mecanismo real

Bom wrapper:

- deixa ownership claro;
- nao mente sobre custo;
- nao esconde erro demais;
- facilita cleanup;
- nao apaga a semantica da API do SO.

Wrapper ruim:

- inventa abstracao confusa;
- mistura parser, socket e protocolo;
- esconde estado de modo perigoso;
- torna debugging mais dificil.

---

## 10. O que acontece em memoria e recursos?

No exemplo:

- o objeto `SocketFd` pode viver na stack;
- o recurso socket pertence ao kernel;
- o inteiro `fd` e apenas handle para esse recurso;
- o destrutor chama `close`, liberando o handle no processo.

### 10.1 Ponto importante

RAII em C++ nao "move o recurso para a linguagem".

Ele so modela melhor:

- posse;
- cleanup;
- erros.

---

## 11. Comparacao com C, Rust, Go e Python

- Em C, o mecanismo e praticamente o mesmo, mas wrappers e cleanup sao mais manuais.
- Em Rust, RAII e tipos mais fortes ajudam bastante, mas o fluxo de sockets e APIs nativas continua equivalente.
- Em Go, a biblioteca padrao esconde boa parte do baixo nivel sob interfaces mais altas.
- Em Python, `socket` e frameworks elevam muito a abstracao, mas o mecanismo do SO continua por baixo.

C++ oferece um meio-termo poderoso:

- proximo do sistema;
- com RAII;
- com containers;
- com custo visivel.

## 13. Erros comuns e anti-padroes

1. **Achar que C++ substitui sockets do SO por magia**.
2. **Esquecer `close` em caminhos de erro quando nao ha RAII**.
3. **Assumir que `recv` devolve mensagem completa**.
4. **Misturar rede, protocolo e regra de negocio no mesmo bloco gigante**.
5. **Escrever wrapper que esconde demais o estado real do recurso**.
6. **Ignorar diferencas entre Unix-like e Windows em camada de sistema**.
