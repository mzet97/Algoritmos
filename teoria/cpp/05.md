# Aula 5 - Copy semantics, move semantics, regra dos 3, 5 e 0

---

## Objetivo da Aula

Entender o que significa copiar um objeto em C++, por que mover pode ser diferente de copiar, quando a linguagem gera operacoes especiais automaticamente, e como a regra dos 3, 5 e 0 ajuda a desenhar tipos robustos. Ao final, voce deve conseguir reconhecer quando um tipo administra recurso e por que isso afeta construtor de copia, atribuicao, movimento e destrutor.

---

## 1. Ponte com a aula anterior

Na Aula 4, vimos:

- classes;
- construtores;
- destrutores;
- encapsulamento;
- RAII.

Agora aparece o problema inevitavel:

- o que acontece quando um objeto e copiado?

Se o objeto administra recurso real, essa pergunta e central.

---

## 2. Copiar nao e sempre trivial

Considere:

```cpp
int a = 10;
int b = a;
```

Aqui a copia e simples.

Mas imagine um objeto que administra:

- memoria dinamica;
- arquivo aberto;
- socket;
- mutex;
- buffer proprio.

Nesse caso, copiar pode significar:

- duplicar recurso?;
- compartilhar recurso?;
- proibir copia?;
- transferir posse?;

C++ leva essas perguntas a serio.

---

## 3. Operacoes especiais de um tipo

Quando um tipo gerencia lifetime, as operacoes mais importantes passam a ser:

- construtor
- destrutor
- construtor de copia
- operador de atribuicao por copia
- construtor de movimento
- operador de atribuicao por movimento

### 3.1 Por que tanta coisa?

Porque o tipo precisa definir comportamento correto quando:

- nasce;
- morre;
- e copiado;
- e sobrescrito por copia;
- e movido;
- e sobrescrito por movimento.

---

## 4. Construtor de copia

Exemplo de assinatura:

```cpp
Buffer(const Buffer& other);
```

Isso significa:

- construir um novo objeto a partir de outro existente

### 4.1 Quando ele roda?

Casos tipicos:

```cpp
Buffer b2 = b1;
Buffer b3(b1);
```

### 4.2 Semantica desejada

Se o tipo tem ownership de memoria, copia correta costuma significar:

- alocar novo recurso;
- copiar conteudo;
- evitar dois objetos tentando destruir o mesmo ponteiro.

---

## 5. Operador de atribuicao por copia

Exemplo de assinatura:

```cpp
Buffer& operator=(const Buffer& other);
```

Isso trata o caso:

```cpp
b2 = b1;
```

### 5.1 Diferenca para construtor de copia

- construtor de copia cria um objeto novo
- atribuicao por copia escreve sobre um objeto ja existente

Essa diferenca e muito importante.

---

## 6. Movimento

Mover e diferente de copiar.

Ideia:

- em vez de duplicar o recurso, transferimos a posse dele

Exemplo conceitual:

- um buffer interno pode ser "roubado" de um objeto temporario para outro

### 6.1 Por que isso existe?

Porque copiar certos recursos custa caro.

Mover pode:

- evitar alocacao extra;
- evitar copia de dados;
- melhorar performance;
- aproveitar temporarios.

### 6.2 Assinaturas tipicas

```cpp
Buffer(Buffer&& other);
Buffer& operator=(Buffer&& other);
```

---

## 7. Lvalue e rvalue, intuicao inicial

Por enquanto, guarde uma intuicao simples:

- lvalue: objeto com identidade nomeada e duradoura
- rvalue: valor temporario ou prestes a ser descartado

Exemplo:

```cpp
Buffer a(10);
Buffer b = a;
Buffer c = Buffer(20);
```

Intuitivamente:

- `a` e lvalue
- `Buffer(20)` e um temporario, entao e rvalue

Mais tarde refinaremos isso.

## 8. Exemplo ruim: dono de ponteiro sem semantica correta

```cpp
class BufferRuim {
public:
    BufferRuim(size_t n) : size_(n), data_(new int[n]) {}

    ~BufferRuim() {
        delete[] data_;
    }

private:
    size_t size_;
    int* data_;
};
```

### 8.1 Qual e o problema?

Parece razoavel.

Mas se o objeto for copiado, a copia padrao do compilador pode fazer:

- copia rasa do ponteiro

Resultado:

- dois objetos com o mesmo `data_`
- dois destrutores chamando `delete[]`
- double delete
- comportamento indefinido

## 9. Exemplo completo da aula

```cpp
#include <algorithm>
#include <cstddef>
#include <iostream>

class IntBuffer {
public:
    explicit IntBuffer(std::size_t size)
        : size_(size), data_(new int[size]) {
        std::fill(data_, data_ + size_, 0);
        std::cout << "construtor size=" << size_ << "\n";
    }

    ~IntBuffer() {
        delete[] data_;
        std::cout << "destrutor size=" << size_ << "\n";
    }

    IntBuffer(const IntBuffer& other)
        : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
        std::cout << "copia size=" << size_ << "\n";
    }

    IntBuffer& operator=(const IntBuffer& other) {
        if (this == &other) {
            return *this;
        }

        int* new_data = new int[other.size_];
        std::copy(other.data_, other.data_ + other.size_, new_data);

        delete[] data_;
        data_ = new_data;
        size_ = other.size_;

        std::cout << "atribuicao por copia size=" << size_ << "\n";
        return *this;
    }

    IntBuffer(IntBuffer&& other) noexcept
        : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
        std::cout << "movimento size=" << size_ << "\n";
    }

    IntBuffer& operator=(IntBuffer&& other) noexcept {
        if (this == &other) {
            return *this;
        }

        delete[] data_;

        data_ = other.data_;
        size_ = other.size_;

        other.data_ = nullptr;
        other.size_ = 0;

        std::cout << "atribuicao por movimento size=" << size_ << "\n";
        return *this;
    }

    int& operator[](std::size_t index) {
        return data_[index];
    }

    const int& operator[](std::size_t index) const {
        return data_[index];
    }

    std::size_t size() const {
        return size_;
    }

private:
    std::size_t size_;
    int* data_;
};

IntBuffer make_buffer() {
    IntBuffer tmp(4);
    tmp[0] = 10;
    tmp[1] = 20;
    tmp[2] = 30;
    tmp[3] = 40;
    return tmp;
}

int main() {
    IntBuffer a(3);
    a[0] = 1;
    a[1] = 2;
    a[2] = 3;

    IntBuffer b = a;
    IntBuffer c = make_buffer();

    b[0] = 99;

    std::cout << "a[0]=" << a[0] << "\n";
    std::cout << "b[0]=" << b[0] << "\n";
    std::cout << "c size=" << c.size() << "\n";

    c = std::move(b);

    std::cout << "c[0]=" << c[0] << "\n";

    return 0;
}
```

---

## 10. O que esse exemplo mostra?

### 10.1 Construtor normal

Cria recurso:

- `new int[size]`

### 10.2 Destrutor

Libera recurso:

- `delete[] data_`

### 10.3 Construtor de copia

Faz deep copy:

- nova memoria
- copia dos elementos

### 10.4 Atribuicao por copia

Substitui o conteudo do objeto atual com copia independente.

### 10.5 Construtor de movimento

Rouba o recurso de `other`:

- transfere ponteiro
- zera o objeto fonte

### 10.6 Atribuicao por movimento

Libera o recurso atual e toma posse do recurso do outro objeto.

---

## 11. Regra dos 3

Se voce precisa escrever manualmente um destes:

- destrutor
- construtor de copia
- atribuicao por copia

entao provavelmente precisa considerar os tres.

### 11.1 Por que?

Porque tipos que gerenciam recurso geralmente nao podem depender de copia rasa padrao.

---

## 12. Regra dos 5

Em C++ moderno, com movimento, a intuicao se expande para cinco operacoes:

- destrutor
- construtor de copia
- atribuicao por copia
- construtor de movimento
- atribuicao por movimento

### 12.1 Regra pratica

Se o tipo administra recurso manualmente, pense nas cinco.

---

## 13. Regra dos 0

Essa e a regra mais elegante quando possivel.

Ideia:

- prefira compor seu tipo com membros que ja gerenciam recurso corretamente

Exemplo:

- `std::string`
- `std::vector`
- smart pointers

Se fizer isso, muitas vezes voce nao precisa escrever nenhuma dessas operacoes especiais.

### 13.1 Exemplo conceitual

```cpp
class BufferSeguro {
private:
    std::vector<int> data_;
};
```

Nesse caso, `std::vector` ja faz o trabalho dificil.

---

## 14. O que acontece em memoria?

No nosso `IntBuffer`:

- o objeto em si pode viver na stack frame
- mas `data_` aponta para memoria dinamica no heap

Esse e exatamente o tipo de situacao em que copia rasa da representacao e perigosa.

Se dois objetos apontarem para o mesmo bloco por acidente:

- o lifetime quebra;
- o destrutor vira bomba.

### 14.1 O ponto central

Quando ha ownership de recurso manual, semantica de copia e movimento vira parte do design do tipo.

---

## 15. `std::move` nao move sozinho

Trecho:

```cpp
c = std::move(b);
```

`std::move` nao move recurso por magia.

Ele faz algo conceitualmente mais proximo de:

- dizer ao compilador: trate isto como candidato a movimento

Se o tipo tiver operacao de movimento adequada, ela podera ser usada.

Sem isso:

- pode cair em copia;
- ou nem compilar em casos mais sofisticados.

---

## 16. Comparacao com C, Rust, Go e Python

- Em C, tudo isso costuma ser manual e disciplinar: `malloc`, `free`, copia explicita, e muito cuidado com ownership.
- Em Rust, movimento faz parte do modelo central da linguagem e ownership e verificado pelo compilador de modo muito mais rigido.
- Em Go, copias e referencias existem em outro modelo, com GC e sem destrutor deterministicamente equivalente.
- Em Python, atribuicao normalmente compartilha referencia de objeto em semantica muito diferente.

C++ fica num meio-termo poderoso e perigoso:

- oferece controle fino;
- mas exige que o tipo seja desenhado corretamente.

## 18. Erros comuns e anti-padroes

1. **Gerenciar ponteiro cru e confiar na copia padrao do compilador sem pensar**.
2. **Escrever destrutor e esquecer construtor de copia e atribuicao por copia**.
3. **Achar que mover e o mesmo que copiar**.
4. **Usar `std::move` sem entender ownership depois da operacao**.
5. **Ignorar a regra dos 0 quando `std::vector` ou `std::string` resolveriam melhor**.
6. **Nao tratar autoatribuicao em operador de atribuicao por copia ou movimento**.
