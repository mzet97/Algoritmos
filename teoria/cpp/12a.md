# Aula 12a - ISA, ABI, modo usuário/kernel e observação do sistema

Entre o seu `main` e a CPU existe um país inteiro: ISA, ABI, modo usuário e kernel, syscalls. Esta ponte observa esse país do espaço de usuário — o mesmo território que o kernel das aulas 33–40 vai construir por dentro.

---

## Nesta aula

Explicar o caminho de um programa C++ entre código-fonte, ABI, instruções, chamadas de sistema e hardware — e investigar cada camada com ferramentas do espaço de usuário, sem sair do C++ padrão mais POSIX. Pré-requisitos: aulas 01 a 12. Não precisa saber Assembly, QEMU nem kernel.

Ao terminar, você deverá medir `sizeof`/`alignof` e explicar padding, cronometrar uma syscall, criar um processo filho e colher sua saída, ler o mapa de memória do próprio processo e distinguir falta de página menor de maior. Tudo em Linux ou WSL; este laboratório é o último degrau antes do kernel emulado.

---

## 1. ISA não é microarquitetura, ABI não é API

A **ISA** define as instruções que o software pode usar; duas CPUs com a mesma ISA executam os mesmos binários com caches, pipelines e latências diferentes. A **ABI** define como o binário conversa: convenção de chamada, layout de structs, mangling de nomes, formato do executável. API quebra em recompilação; ABI quebrada exige recompilar o mundo — por isso trocar `std::string` entre duas libstdc++ incompatíveis corrompe pilha em silêncio.

## 2. Layout: o compilador preenche o que você não declarou

Trecho ilustrativo (declarações isoladas; o programa completo e executável está na seção 4):

```cpp
struct Cheia {
    char  a;   // 1 byte + 7 de preenchimento
    double b;  // 8 bytes, alinhada a 8
    char  c;   // 1 byte + 7 de preenchimento
}; // sizeof == 24, alignof == 8
```

`alignof` revela a exigência; `sizeof` revela o custo. Reordenar para `double, char, char` derruba para 16. Isso não é micro-otimização gratuita: é o motivo de `vector<Cheia>` gastar 50% a mais de cache. Medir `sizeof` antes de culpar o algoritmo é higiene, não premature optimization.

## 3. Modo usuário, syscall e o preço da travessia

`getpid()` quase não faz nada — régua do custo mínimo de chamar o kernel. Em muitos sistemas o kernel atende via vDSO sem troca de modo real; então o número medido é um *teto inferior*, e `read`/`write` custam mais. Declare máquina, kernel e carga junto do número.

## 4. Exemplo completo e executável

O [arquivo-fonte desta aula](exemplos/12a_sistema.cpp) contém exatamente o programa abaixo. Requer Linux ou WSL (usa `fork`, `/proc` e `getrusage`); C++20 é o padrão do núcleo:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror teoria/cpp/exemplos/12a_sistema.cpp -o sistema12a
./sistema12a
```

```cpp
#include <cassert>
#include <chrono>
#include <cstdint>
#include <fstream>
#include <iostream>
#include <string>
#include <sys/resource.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>
#include <vector>

struct Cheia {
    char a;
    double b;
    char c;
};

struct Compacta {
    double b;
    char a;
    char c;
};

// Régua de syscall: um milhao de getpid.
static double medir_getpid(int repeticoes) {
    const auto t0 = std::chrono::steady_clock::now();
    for (int i = 0; i < repeticoes; ++i) {
        volatile pid_t p = getpid();
        (void)p;
    }
    const auto t1 = std::chrono::steady_clock::now();
    return std::chrono::duration<double>(t1 - t0).count() / repeticoes;
}

// Conta regioes totais e executaveis em /proc/self/maps.
static void resumir_mapas(int &total, int &exec) {
    std::ifstream mapas("/proc/self/maps");
    assert(mapas && "sem /proc/self/maps: rode em Linux/WSL");
    std::string linha;
    total = 0;
    exec = 0;
    while (std::getline(mapas, linha)) {
        ++total;
        if (linha.find("r-xp") != std::string::npos) {
            ++exec;
        }
    }
}

int main() {
    static_assert(sizeof(Cheia) == 24, "layout esperado: 1+7+8+1+7");
    static_assert(sizeof(Compacta) == 16, "layout esperado: 8+1+1+6");
    static_assert(alignof(Cheia) == 8, "alinhada a double");
    std::cout << "sizeof(Cheia)=" << sizeof(Cheia)
              << " sizeof(Compacta)=" << sizeof(Compacta) << "\n";

    // 1. Processo filho com codigo de saida conhecido.
    const pid_t filho = fork();
    assert(filho >= 0);
    if (filho == 0) {
        _exit(7);
    }
    int estado = 0;
    assert(waitpid(filho, &estado, 0) == filho);
    assert(WIFEXITED(estado) && WEXITSTATUS(estado) == 7);
    std::cout << "filho colhido: codigo=" << WEXITSTATUS(estado) << "\n";

    // 2. Régua de syscall.
    const int rep = 1000000;
    std::cout << "getpid: " << medir_getpid(rep) * 1e9 << " ns/chamada ("
              << rep << " repeticoes)\n";

    // 3. Mapa de memoria do proprio processo.
    int total = 0, exec = 0;
    resumir_mapas(total, exec);
    std::cout << "regioes mapeadas: " << total << ", executaveis: " << exec << "\n";
    assert(total > 0 && exec > 0);

    // 4. Faltas de pagina: menores (sem I/O) x maiores (com I/O).
    struct rusage antes{}, depois{};
    assert(getrusage(RUSAGE_SELF, &antes) == 0);
    // new[] nao inicializa: as paginas nascem no toque abaixo, uma falta por pagina.
    // (vector(n, 0) zeraria tudo na construcao e estragaria a medicao.)
    const std::size_t tamanho = 8u * 1024u * 1024u;
    unsigned char *bloco = new unsigned char[tamanho];
    const long pagina = sysconf(_SC_PAGESIZE);
    assert(pagina > 0);
    for (std::size_t i = 0; i < tamanho; i += (std::size_t)pagina) {
        bloco[i] = 1; // uma falta menor por pagina nova
    }
    assert(getrusage(RUSAGE_SELF, &depois) == 0);
    std::cout << "faltas menores: " << antes.ru_minflt << " -> " << depois.ru_minflt << "\n";
    std::cout << "faltas maiores: " << antes.ru_majflt << " -> " << depois.ru_majflt << "\n";
    assert(depois.ru_minflt > antes.ru_minflt);
    delete[] bloco;

    // 5. Entrada nao confiavel contida no filho.
    const pid_t f2 = fork();
    assert(f2 >= 0);
    if (f2 == 0) {
        execl("/nao/existe/de/jeito/nenhum", "x", static_cast<char *>(nullptr));
        _exit(127); // execl so retorna em erro
    }
    int e2 = 0;
    assert(waitpid(f2, &e2, 0) == f2);
    assert(WIFEXITED(e2) && WEXITSTATUS(e2) == 127);
    std::cout << "exec falho contido: codigo=" << WEXITSTATUS(e2) << "\n";
    return 0;
}
```

Saída esperada (números variam por máquina e carga):

```text
sizeof(Cheia)=24 sizeof(Compacta)=16
filho colhido: codigo=7
getpid: ~ns/chamada (1000000 repeticoes)
regioes mapeadas: N, executaveis: M (ambos > 0)
faltas menores: A -> B (B > A; espere ~2048 a mais para 8 MiB em páginas de 4 KiB)
faltas maiores: C -> D (D costuma igualar C: memoria anonima nao vem de disco)
exec falho contido: codigo=127
```

Leia com o modelo certo: `static_assert` prova o layout em tempo de compilação para *este* alvo/ABI — em outra plataforma os números podem diferir, e é exatamente por isso que o teste existe. Faltas menores sobem ~2048 porque cada página tocada pela primeira vez é materializada sob demanda; maiores exigem I/O e normalmente não sobem aqui.

### O que a memória faz aqui?

`bloco` aloca 8 MiB no heap (`vector` zera na construção — esse zero inicial já materializa páginas; o laço de toque página a página mede as faltas com granularidade explícita). `/proc/self/maps` mostra faixas virtuais com permissões `rwxp/s`; nada revela quadros físicos — ver a aula C 10a. O filho de `fork` duplica o espaço de endereços (com copy-on-write no Linux moderno: as páginas só são copiadas de verdade ao serem escritas).

## 5. Erros comuns e implicações defensivas

1. **Presumir layout:** `sizeof` varia por ABI. Prove com `static_assert` no alvo.
2. **Esquecer `waitpid`:** zumbis acumulam na tabela de processos. Colha todo filho.
3. **`exit` no filho após `fork`:** descarrega buffers duplicados. Use `_exit` no filho.
4. **Medir syscall sem ambiente:** vDSO, mitigações e carga mudam o número. Anote tudo.
5. **Confundir falta menor com erro:** falta menor é funcionamento normal (página sob demanda).
6. **`execl` com caminho externo:** valide antes; trate retorno como erro, nunca como sucesso parcial.

## 6. Ponte com Python e JavaScript

Python: `struct` do módulo homônimo e `ctypes.sizeof` expõem layout; `os.getpid` e `resource.getrusage` cobrem a régua e as faltas (aula 14a). Node: `process.pid`, `os.cpus()`. Nos três, processo é isolamento com contabilidade e toda travessia custa.
