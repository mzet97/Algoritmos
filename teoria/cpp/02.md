## 2. Tipos basicos em C++: tamanho e limites

Vamos ampliar a base inicial com a tabela que faltava: cada tipo com tamanho em bytes e faixa de valores na maquina de referencia (Linux x86-64, LP64 — mesma referencia da aula de C).

| Tipo | `sizeof` aqui | Minimo | Maximo | Header para medir |
|---|---|---|---|---|
| `bool` | 1 byte | `false` (0) | `true` (1) | `<limits>` |
| `char` | 1 byte | -128 | 127 (nesta plataforma, `char` e com sinal) | `<limits.h>` (`CHAR_MIN`, `CHAR_MAX`) |
| `signed char` | 1 byte | -128 | 127 | `<limits.h>` |
| `unsigned char` | 1 byte | 0 | 255 | `<limits.h>` |
| `short` | 2 bytes | -32768 | 32767 | `<limits>` |
| `unsigned short` | 2 bytes | 0 | 65535 | `<limits>` |
| `int` | 4 bytes | -2147483648 | 2147483647 | `<limits>` (`INT_MIN`, `INT_MAX`) |
| `unsigned int` | 4 bytes | 0 | 4294967295 | `<limits>` (`UINT_MAX`) |
| `long` | 8 bytes aqui, 4 no Windows | -9223372036854775808 | 9223372036854775807 | `<limits>` |
| `unsigned long` | 8 bytes aqui, 4 no Windows | 0 | 18446744073709551615 | `<limits>` |
| `long long` | 8 bytes | -9223372036854775808 | 9223372036854775807 | `<limits>` |
| `unsigned long long` | 8 bytes | 0 | 18446744073709551615 | `<limits>` |
| `float` | 4 bytes | ~-3.4e38 | ~3.4e38 | `<limits>`, `<cfloat>` (`FLT_MIN`, `FLT_MAX`) |
| `double` | 8 bytes | ~-1.8e308 | ~1.8e308 | `<limits>`, `<cfloat>` (`DBL_MIN`, `DBL_MAX`) |
| `long double` | 16 bytes aqui | ~-1.2e4932 | ~1.2e4932 | `<limits>`, `<cfloat>` |

Atencao: `long` nao tem tamanho fixo. Com 8 bytes aqui e LP64; em Windows (LLP64) seria 4 — mesmo codigo-fonte, numero diferente, e nenhum dos dois esta "errado". `char` sozinho tambem pode ser com ou sem sinal conforme a implementacao. Quando precisar de largura exata, use os tipos de `<cstdint>` (`int32_t`, `uint64_t`, ...).

### 2.1 Experimento: medir na sua maquina

```cpp
#include <iostream>
#include <limits>

int main() {
    std::cout << "bool: " << sizeof(bool) << " byte(s)\n";
    std::cout << "char: " << sizeof(char) << " byte(s) "
              << (int)std::numeric_limits<char>::min() << " a "
              << (int)std::numeric_limits<char>::max() << "\n";
    std::cout << "short: " << sizeof(short) << " byte(s) "
              << std::numeric_limits<short>::min() << " a "
              << std::numeric_limits<short>::max() << "\n";
    std::cout << "int: " << sizeof(int) << " byte(s) "
              << std::numeric_limits<int>::min() << " a "
              << std::numeric_limits<int>::max() << "\n";
    std::cout << "long: " << sizeof(long) << " byte(s)\n";
    std::cout << "long long: " << sizeof(long long) << " byte(s)\n";
    std::cout << "unsigned int max: " << std::numeric_limits<unsigned int>::max() << "\n";
    std::cout << "float: " << sizeof(float) << " byte(s) max="
              << std::numeric_limits<float>::max() << "\n";
    std::cout << "double: " << sizeof(double) << " byte(s) max="
              << std::numeric_limits<double>::max() << "\n";
    return 0;
}
```

Saida na maquina de referencia (Linux x86-64, `g++`):

```text
bool: 1 byte(s)
char: 1 byte(s) -128 a 127
short: 2 byte(s) -32768 a 32767
int: 4 byte(s) -2147483648 a 2147483647
long: 8 byte(s)
long long: 8 byte(s)
unsigned int max: 4294967295
float: 4 byte(s) max=3.40282e+38
double: 8 byte(s) max=1.79769e+308
```

Registre compilador, arquitetura e saida: a diferenca entre exigencia do padrao (minimos garantidos) e propriedade da plataforma (o que `sizeof` e `numeric_limits` dizem aqui) e o conteudo do experimento.

### 2.2 Regra pratica

No comeco, prefira clareza:

- `int` para inteiros gerais
- `double` para ponto flutuante
- `bool` para logica
- `char` para caractere simples

So use tipos mais especificos quando houver motivo concreto.

## 3. `const`: imutabilidade por contrato local

`const` indica que um valor nao deve ser modificado por aquele nome.

Exemplo:

```cpp
const int limite = 10;
```

Isso significa:

- `limite` foi inicializado com `10`
- depois disso, nao pode ser alterado por essa variavel

### 3.1 Por que isso existe?

Porque C++ valoriza:

- intencao explicita;
- prevencao de erro;
- otimizacao e raciocinio local melhores.

### 3.2 `const` nao significa "vive em memoria especial"

O principal aqui e contrato semantico:

- "nao mexa nisso"

Onde exatamente o compilador colocara o dado depende do contexto.

## 4. Referencias: alias com sintaxe de valor

Exemplo:

```cpp
int x = 10;
int& ref = x;
```

`ref` e uma referencia para `x`.

Isso significa:

- `ref` e um outro nome para o mesmo objeto
- mexer em `ref` mexe em `x`

### 4.1 Exemplo

```cpp
int x = 10;
int& ref = x;

ref = 99;

std::cout << x << "\n";
```

Saida:

```text
99
```

### 4.2 O que uma referencia nao e?

No modelo da linguagem, referencia nao e um objeto independente como um ponteiro cru.

Ela e melhor entendida como:

- alias nomeado

Mais tarde veremos que, no nivel de implementacao, o compilador pode materializar isso de varias formas.

### 4.3 Comparacao com C

Em C, passagem por referencia costuma ser simulada via ponteiro.

Em C++, referencias tornam isso mais expressivo em muitos casos.

---

## 5. `const` com referencias

Exemplo:

```cpp
int valor = 42;
const int& ref = valor;
```

Aqui:

- `ref` referencia `valor`
- mas nao permite modificar `valor` por esse nome

### 5.1 Por que isso e tao comum?

Porque C++ usa muito:

- `const T&`

para passar objetos sem copiar e sem permitir modificacao.

Hoje basta guardar a intuicao:

- referencia evita copia
- `const` protege contra escrita acidental

## 7. Controle de fluxo

Controle de fluxo responde:

- qual trecho do codigo roda?
- quantas vezes?
- com qual condicao?

### 7.1 `if` e `else`

```cpp
if (idade >= 18) {
    std::cout << "maior de idade\n";
} else {
    std::cout << "menor de idade\n";
}
```

### 7.2 `switch`

```cpp
switch (opcao) {
    case 1:
        std::cout << "listar\n";
        break;
    case 2:
        std::cout << "sair\n";
        break;
    default:
        std::cout << "opcao invalida\n";
        break;
}
```

### 7.3 `for`

```cpp
for (int i = 0; i < 5; i++) {
    std::cout << i << "\n";
}
```

### 7.4 `while`

```cpp
int i = 0;
while (i < 5) {
    std::cout << i << "\n";
    i++;
}
```

## 8. Exemplo completo da aula

```cpp
#include <iostream>

int main() {
    const int limite = 10;
    int soma = 0;

    for (int i = 0; i <= limite; i++) {
        soma += i;
    }

    int resultado = soma;
    int& alias_resultado = resultado;
    const int& leitura = resultado;

    if (resultado > 50) {
        std::cout << "resultado maior que 50\n";
    } else {
        std::cout << "resultado menor ou igual a 50\n";
    }

    alias_resultado += 5;

    std::cout << "resultado: " << resultado << "\n";
    std::cout << "leitura: " << leitura << "\n";

    int dia = 2;
    switch (dia) {
        case 1:
            std::cout << "segunda\n";
            break;
        case 2:
            std::cout << "terca\n";
            break;
        default:
            std::cout << "outro dia\n";
            break;
    }

    return 0;
}
```

---

## 9. O que esse exemplo ensina?

### 9.1 `const int limite = 10;`

- define um valor que nao sera alterado
- ajuda a evitar escrita acidental

### 9.2 `for (int i = 0; i <= limite; i++)`

- `i` nasce na cabeca do loop
- existe so dentro desse escopo do `for`
- o loop acumula a soma de `0` ate `10`

### 9.3 `int& alias_resultado = resultado;`

- `alias_resultado` e um alias de `resultado`
- ambos apontam para o mesmo objeto no sentido semantico da linguagem

### 9.4 `const int& leitura = resultado;`

- `leitura` observa o mesmo valor
- mas nao pode modifica-lo

### 9.5 `alias_resultado += 5;`

- altera `resultado`
- porque nao existe copia, existe alias

---

## 10. O que acontece em memoria?

Conceitualmente:

- `limite`, `soma`, `resultado`, `dia` e `i` sao variaveis automaticas
- vivem na stack frame de `main`
- `alias_resultado` e `leitura` referenciam o mesmo objeto `resultado`

Os bytes exatos variam por plataforma — por isso a secao 2 manda medir com `sizeof` e `numeric_limits` em vez de decorar. O ponto essencial e outro.

E entender:

- valor tem lifetime;
- escopo controla visibilidade;
- referencia compartilha o mesmo objeto;
- `const` restringe modificacao por aquele nome.

## 11. Comparacao com C, Rust, Go e Python

- Em C, referencias nao existem como recurso da linguagem; o padrao equivalente normalmente usa ponteiros.
- Em Rust, referencias tambem existem, mas com regras muito mais fortes de alias e mutabilidade.
- Em Go, variaveis e fluxo sao mais simples sintaticamente, mas nao existe o mesmo ecossistema de referencias e sobrecarga de tipos.
- Em Python, nomes sao referencias para objetos em outro modelo semantico, muito diferente do custo e layout visiveis em C++.

Em C++, o ponto delicado e:

- a sintaxe pode parecer simples;
- mas alias, lifetime e mutabilidade importam desde cedo.

## 13. Erros comuns e anti-padroes

1. **Confundir `=` com `==`**.
2. **Achar que referencia e uma copia**.
3. **Achar que `const` sempre implica memoria imutavel global**.
4. **Esquecer `break` em `switch`**.
5. **Criar logica dificil de ler com muitos `if` aninhados sem necessidade**.
6. **Usar tipos sem pensar em mutabilidade e intencao**.
