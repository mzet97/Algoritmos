# Aula 7 - Templates, genericidade, `auto`, deducao de tipos e `concepts`

---

## Objetivo da Aula

Entender como C++ permite escrever codigo generico com templates, por que `auto` e deducao de tipos existem, e como `concepts` ajudam a restringir genericidade com mensagens e contratos melhores. Ao final, voce deve conseguir reconhecer quando faz sentido generalizar codigo sem cair em abstracao descontrolada.

Na Aula 6, vimos:

Agora vamos para outro pilar de C++:

## 2. O que e template?

Template e um mecanismo de C++ para escrever codigo parametrizado por tipo ou valor em tempo de compilacao.

Exemplo:

```cpp
template <typename T>
T maximo(T a, T b) {
    return (a < b) ? b : a;
}
```

### 2.1 O que isso quer dizer?

- `T` e um parametro de tipo
- a funcao pode ser instanciada para `int`, `double`, `std::string` e outros tipos compativeis

### 2.2 Comparacao com C

Em C, genericidade costuma virar:

- macros;
- `void*`;
- repeticao manual;

Em C++, templates permitem:

- checagem estatica;
- especializacao;
- zero-cost abstractions em muitos casos.

---

## 3. Primeiro exemplo com funcao template

```cpp
#include <iostream>

template <typename T>
T soma(T a, T b) {
    return a + b;
}

int main() {
    std::cout << soma<int>(2, 3) << "\n";
    std::cout << soma<double>(2.5, 3.5) << "\n";
    return 0;
}
```

### 3.1 O que o compilador faz conceitualmente?

Ele instancia versoes concretas com base no uso.

Exemplo:

- `soma<int>`
- `soma<double>`

### 3.2 Isso e polimorfismo dinamico?

Nao.

Aqui a resolucao e estatica em tempo de compilacao.

---

## 4. Deducao de tipo em template

Na maioria dos casos, voce nao precisa escrever o tipo explicitamente.

Exemplo:

```cpp
std::cout << soma(2, 3) << "\n";
std::cout << soma(2.5, 3.5) << "\n";
```

O compilador deduz:

- `T = int`
- `T = double`

### 4.1 Quando isso ajuda?

- reduz ruido;
- deixa chamada mais natural;
- melhora ergonomia do codigo generico.

---

## 5. `auto`

`auto` pede ao compilador que deduza o tipo da variavel a partir da inicializacao.

Exemplo:

```cpp
auto x = 10;
auto y = 3.14;
auto ok = true;
```

### 5.1 Por que isso existe?

Porque certos tipos em C++ podem ser:

- longos;
- dependentes de template;
- desconfortaveis de repetir;

e porque muitas vezes o tipo exato ja esta claro na expressao.

### 5.2 `auto` e "tipo dinamico"?

Nao.

O tipo continua sendo estatico.

`auto` apenas pede:

- deduza o tipo em compilacao

---

## 6. Quando `auto` ajuda e quando atrapalha?

### 6.1 Ajuda quando

- o tipo e obvio no lado direito;
- o tipo e muito verboso;
- voce esta iterando com iteradores;
- o foco conceitual esta no valor, nao no nome enorme do tipo.

### 6.2 Atrapalha quando

- esconde tipo importante para entendimento;
- deixa leitura ambigua;
- mascara copia quando voce queria referencia;
- vira moda em todo lugar sem criterio.

### 6.3 Regra pratica

Use `auto` para reduzir ruido, nao para esconder a modelagem.

## 7. Template de classe

Nao so funcoes podem ser templates.

Exemplo:

```cpp
template <typename T>
class Caixa {
public:
    explicit Caixa(const T& valor) : valor_(valor) {}

    const T& valor() const {
        return valor_;
    }

private:
    T valor_;
};
```

Uso:

```cpp
Caixa<int> a(10);
Caixa<double> b(2.5);
```

---

## 8. O problema da genericidade irrestrita

Templates sao poderosos, mas podem falhar de forma confusa quando o tipo nao satisfaz o que a implementacao espera.

Exemplo:

```cpp
template <typename T>
T dobro(T x) {
    return x + x;
}
```

Isso assume:

- que `T` suporta `operator+`

Se nao suportar, o erro pode ser grande e desagradavel.

E aqui entram os `concepts`.

---

## 9. `concepts`

`concept` permite expressar requisitos para parametros de template de forma mais explicita.

Exemplo:

```cpp
#include <concepts>

template <std::integral T>
T dobro(T x) {
    return x + x;
}
```

### 9.1 O que isso faz?

Restringe a funcao para tipos integrais.

### 9.2 Por que isso e importante?

- documenta melhor o contrato;
- melhora erros de compilacao;
- reduz genericidade sem criterio.

---

## 10. Exemplo completo da aula

```cpp
#include <concepts>
#include <iostream>
#include <string>

template <typename T>
T maximo(T a, T b) {
    return (a < b) ? b : a;
}

template <typename T>
class Caixa {
public:
    explicit Caixa(T valor) : valor_(valor) {}

    const T& valor() const {
        return valor_;
    }

private:
    T valor_;
};

template <std::integral T>
T somar_um(T x) {
    return x + 1;
}

int main() {
    auto a = maximo(10, 20);
    auto b = maximo(2.5, 9.1);
    auto c = maximo(std::string("ana"), std::string("bia"));

    Caixa<int> ci(42);
    Caixa<std::string> cs("cpp");

    std::cout << "a = " << a << "\n";
    std::cout << "b = " << b << "\n";
    std::cout << "c = " << c << "\n";
    std::cout << "ci = " << ci.valor() << "\n";
    std::cout << "cs = " << cs.valor() << "\n";
    std::cout << "somar_um(9) = " << somar_um(9) << "\n";

    return 0;
}
```

---

## 11. O que esse exemplo mostra?

### 11.1 `maximo`

Funcao template simples:

- precisa de tipo comparavel com `<`

### 11.2 `Caixa<T>`

Classe template:

- armazena um valor de tipo parametrizado

### 11.3 `std::integral`

Concept pronto da biblioteca padrao:

- restringe o template a inteiros

### 11.4 `auto`

Evita repetir tipos obvios nas variaveis `a`, `b`, `c`.

---

## 12. O que acontece em memoria?

Template em si nao e "um objeto em memoria".

Ele e um mecanismo de geracao de codigo em compilacao.

Depois da instanciacao:

- `Caixa<int>` e um tipo concreto;
- `Caixa<std::string>` e outro tipo concreto.

Cada um tera layout compativel com seus membros reais.

### 12.1 O ponto importante

Genericidade de C++ muitas vezes e resolvida em compilacao, nao em runtime.

Isso ajuda a explicar por que templates podem ser:

- muito eficientes;
- muito poderosos;
- e tambem muito verbosos em erro quando mal usados.

---

## 13. Template nao e desculpa para abstracao ruim

Fazer algo generico demais pode:

- piorar legibilidade;
- gerar erros confusos;
- aumentar tempo de compilacao;
- esconder requisitos reais.

### 13.1 Regra pratica

So generalize quando houver reuso real ou modelo claro.

Nao transforme toda funcao simples em template por esporte.

---

## 14. Comparacao com C, Rust, Go e Python

- Em C, genericidade costuma ser mais manual, com macro, `void*` ou duplicacao.
- Em Rust, generics tambem sao fortes e constraints por traits lembram o papel conceitual de `concepts`.
- Em Go, generics existem hoje, mas o ecossistema historico foi muito menos dependente disso do que C++.
- Em Python, genericidade e muito mais dinamica, com custo e validacao diferentes.

C++ quer oferecer:

- genericidade forte;
- checagem estatica;
- desempenho;

mas exige criterio para nao virar labirinto.

## 16. Erros comuns e anti-padroes

1. **Usar `auto` como se fosse tipo dinamico**.
2. **Escrever template sem entender quais operacoes o tipo precisa suportar**.
3. **Generalizar codigo sem necessidade real**.
4. **Achar que `concepts` servem so para "embelezar" template**.
5. **Esconder tipos importantes demais com `auto`**.
6. **Confundir instancia de template com polimorfismo virtual**.
