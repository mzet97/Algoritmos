# Aula 17a - Concorrência e SO vistos do espaço de usuário

---

## Objetivo da Aula

Explicar interrupção e escalonamento como o programa os observa (sem implementá-los), medir o custo real de sincronização com múltiplas CPUs e diagnosticar data race com o ThreadSanitizer. Pré-requisitos: aulas 12a, 14 e 17. Não precisa saber kernel, `epoll`, rede nem GPU.

Ao terminar, você deverá distinguir contenção de paralelismo real, escolher `mutex` contra `atomic` com argumento, tratar sinais com o subconjunto seguro e provar ausência de data race com `-fsanitize=thread`.

Esta aula é o módulo CPP-6 do mapa: quem domina a observação aqui carrega o modelo para rede robusta (23a), distribuídos (23b) e medição honesta (30a), onde cada invariante violada vira cliente travado ou dado corrompido.

## 1. Interrupção e escalonamento, do lado de fora

O kernel interrompe seu programa quando quer: fatia de tempo esgotada, I/O pronto, sinal entregue. Você não controla *quando*; controla *o que é seguro fazer quando isso acontece*:

- **Sinais:** o handler executa em contexto assíncrono. Quase tudo é proibido lá dentro (`cout`, `malloc`, `mutex`). O permitido clássico: escrever em `volatile sig_atomic_t` e retornar. O laço principal lê o flag em ponto seguro.
- **Escalonamento:** threads prontas disputam CPUs. Com mais threads que núcleos, o SO alterna; com menos trabalho que o custo da alternância, paralelizar piora.

## 2. Mutex, atômico e o custo de cada um

- `std::mutex`: exclusão para seções críticas de qualquer tamanho. Custa syscall/futex quando há contenção real; sem contenção, é barato.
- `std::atomic<T>`: operações indivisíveis sem lock para casos simples (contadores, flags). `fetch_add` com `memory_order_relaxed` quando só a atomicidade importa; o padrão `seq_cst` quando a *ordem* entre threads importa.
- Contenção não é paralelismo: 8 threads somando no mesmo `atomic` disputam uma linha de cache — o programa fica mais lento que o sequencial e a culpa não é do hardware.

## 3. Data race é comportamento indefinido — detecte, não demonstre

Em C++, acessar a mesma variável de duas threads sem sincronização, com ao menos uma escrita, é *indefinido*: o compilador pode assumir que isso nunca acontece e otimizar em cima. Por isso esta aula **não distribui programa com corrida**: o exemplo é todo sincronizado, e a corrida aparece como exercício controlado sob `-fsanitize=thread`, que denuncia as duas threads e as duas linhas. O relatório do TSan é evidência, não enfeite — mas evidência depende de ambiente: neste WSL (kernel 6.18 + GCC), o TSan aborta até em programa trivial por incompatibilidade de mapeamento de memória, então o WARNING abaixo é padrão documentado, não saída observada aqui. Execute onde seu TSan funcionar e transcreva o seu.

## 4. Exemplo completo e executável

O [arquivo-fonte desta aula](exemplos/17a_concorrencia.cpp) contém exatamente o programa abaixo. Requer Linux (sinais POSIX); C++20 é o padrão do núcleo:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror teoria/cpp/exemplos/17a_concorrencia.cpp -o conc17a
./conc17a
g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror -fsanitize=address,undefined teoria/cpp/exemplos/17a_concorrencia.cpp -o conc17asan && ./conc17asan
```

```cpp
#include <atomic>
#include <cassert>
#include <chrono>
#include <csignal>
#include <iostream>
#include <mutex>
#include <thread>
#include <vector>

// Flag async-signal-safe: o handler so escreve, o laco so le.
volatile std::sig_atomic_t parar = 0;

extern "C" void ao_sinal(int) {
    parar = 1; // unico gesto seguro aqui: escrever o flag
}

static double agora_s() {
    return std::chrono::duration<double>(
               std::chrono::steady_clock::now().time_since_epoch())
        .count();
}

int main() {
    std::signal(SIGINT, ao_sinal);
    std::signal(SIGTERM, ao_sinal);

    // 1. Contador sob mutex: invariante verificada, sem TSan reclamando.
    std::mutex mu;
    long total = 0;
    const int threads = 8, repeticoes = 100000;
    std::vector<std::thread> ts;
    for (int t = 0; t < threads; ++t) {
        ts.emplace_back([&] {
            for (int i = 0; i < repeticoes; ++i) {
                std::lock_guard<std::mutex> g(mu);
                ++total;
            }
        });
    }
    for (auto &t : ts) {
        t.join();
    }
    ts.clear();
    assert(total == (long)threads * repeticoes);
    std::cout << "mutex ok: total = " << total << "\n";

    // 2. Contador atomico: mesma conta, sem lock.
    std::atomic<long> atomico{0};
    for (int t = 0; t < threads; ++t) {
        ts.emplace_back([&] {
            for (int i = 0; i < repeticoes; ++i) {
                atomico.fetch_add(1, std::memory_order_relaxed);
            }
        });
    }
    for (auto &t : ts) {
        t.join();
    }
    ts.clear();
    assert(atomico.load() == (long)threads * repeticoes);
    std::cout << "atomico ok: total = " << atomico.load() << "\n";

    // 3. Escala 1 x N: soma particionada, invariante fechada.
    const long n = 2000000L;
    const int ncpu = (int)std::max(1u, std::thread::hardware_concurrency());
    auto somar_faixa = [](long ini, long fim) {
        long s = 0;
        for (long i = ini; i < fim; ++i) {
            s += i;
        }
        return s;
    };
    const double t0 = agora_s();
    const long seq = somar_faixa(0, n);
    const double t_seq = agora_s() - t0;

    const double t1 = agora_s();
    std::vector<std::thread> ws;
    std::vector<long> parciais((std::size_t)ncpu, 0);
    for (int w = 0; w < ncpu; ++w) {
        ws.emplace_back([&, w] {
            parciais[(std::size_t)w] = somar_faixa(n * w / ncpu, n * (w + 1) / ncpu);
        });
    }
    for (auto &t : ws) {
        t.join();
    }
    long par = 0;
    for (long p : parciais) {
        par += p;
    }
    const double t_par = agora_s() - t1;
    assert(seq == par && seq == n * (n - 1) / 2);
    std::cout << "seq=" << t_seq << "s par(" << ncpu << ")=" << t_par
              << "s razao=" << t_seq / t_par << "x\n";

    // 4. Sinal: o laco respeita o flag sem fazer nada proibido no handler.
    for (int i = 0; i < 3 && !parar; ++i) {
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
    std::cout << "sinal respeitado (rode com timeout -s TERM para testar)\n";
    return 0;
}
```

Saída esperada (tempos variam por máquina e carga):

```text
mutex ok: total = 800000
atomico ok: total = 800000
seq=~s par(N)=~s razao=~x
sinal respeitado (rode com timeout -s TERM para testar)
```

Leia com o modelo certo: a razão seq/par mede *este* laço somável e partível; com contenção real (8 threads no mesmo `atomic`), o paralelo pode perder — meça os dois regimes antes de alegar qualquer coisa (exercício 2).

### O que a memória faz aqui?

`parciais` dá a cada thread sua posição: soma local sem compartilhar linha de cache quente entre escritores (partição, não contenção). O `mutex` serializa o contador; o `atomic` usa instrução indivisível sem lock. `parar` é `sig_atomic_t`: leitura e escrita são indivisíveis mesmo sob interrupção — qualquer outro tipo no handler seria corrida com o próprio sinal.

## 5. Erros comuns e implicações defensivas

1. **Fazer demais no handler:** `cout`, `malloc`, `lock` no handler é corrida com o programa interrompido. Só `sig_atomic_t`.
2. **Copiar `mutex`:** `std::mutex` não é copiável; capturar por valor na lambda não compila por sorte — capture por referência com lifetime garantido pelo `join`.
3. **Achar `-fsanitize=thread` limpo prova correção:** prova ausência de data race. Lógica se prova com invariante.
4. **Medir uma vez:** escalonador, carga e turbo variam. Repita e anote o ambiente.
5. **Confundir contenção com paralelismo:** N threads no mesmo `atomic` disputam; N partições independentes somam. Desenhe antes de escalar.
6. **Ignorar `hardware_concurrency() == 0`:** pode devolver 0 ("não sei"). O `max(1u, ...)` documenta o fallback.

## 6. Ponte com Python, Go e JavaScript

Python teria o GIL no caminho do contador (aula 16a); Go detectaria corrida com `-race` (aula 11a). Node serializaria tudo no event loop. O modelo muda, a disciplina é igual: dono dos dados, fechamento único, cancelamento cooperativo, timeout real.
