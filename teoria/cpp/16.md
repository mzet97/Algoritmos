## 2. `std::filesystem`

`std::filesystem` fornece tipos e operacoes para lidar com caminhos e arquivos.

Exemplos de recursos:

- `std::filesystem::path`
- `exists`
- `is_regular_file`
- `create_directories`
- `file_size`
- iteracao de diretorios

### 2.1 Por que isso importa?

Porque, antes, muito codigo acabava:

- dependente de API de SO cedo demais;
- fazendo manipulacao textual ruim de caminhos;
- misturando separador de diretorio com logica de negocio.

### 2.2 `path`

`std::filesystem::path` nao e apenas `std::string`.

Ele representa:

- caminho como entidade semantica;
- com operacoes de composicao e consulta.

Exemplo:

```cpp
std::filesystem::path base = "logs";
auto arquivo = base / "app.txt";
```

---

## 3. Streams

Streams sao a base classica de I/O textual em C++:

- `std::ifstream`
- `std::ofstream`
- `std::stringstream`
- `std::cin`
- `std::cout`
- `std::cerr`

### 3.1 Ideia central

Stream e um fluxo de dados com operacoes de leitura ou escrita.

### 3.2 Por que isso importa?

Porque CLIs reais costumam combinar:

- entrada por arquivo;
- entrada por `stdin`;
- saida para `stdout`;
- erro para `stderr`.

---

## 4. Parsing simples

Parsing e transformar texto cru em estrutura mais util.

Exemplos:

- separar linhas;
- quebrar `chave=valor`;
- converter inteiro;
- validar formato.

### 4.1 Regra pratica

Nao misture parsing, I/O e regra de negocio em um bloco unico gigante.

Separe:

- ler;
- validar;
- converter;
- agir.

---

## 5. CLIs: contrato minimo

Uma CLI seria deve deixar claro:

- quais argumentos aceita;
- o que imprime em `stdout`;
- o que imprime em `stderr`;
- qual `exit code` usa;
- o que conta como erro de uso;
- o que conta como erro operacional.

### 5.1 Erro de uso

Exemplos:

- argumento faltando;
- flag invalida;
- formato errado de comando.

### 5.2 Erro operacional

Exemplos:

- arquivo nao existe;
- permissao negada;
- parse do conteudo falhou.

## 6. Exemplo completo da aula

Programa: contar quantas linhas `chave=valor` validas existem em um arquivo.

```cpp
#include <filesystem>
#include <fstream>
#include <iostream>
#include <optional>
#include <string>

namespace fs = std::filesystem;

std::optional<std::pair<std::string, std::string>>
parse_linha(const std::string& linha) {
    auto pos = linha.find('=');
    if (pos == std::string::npos || pos == 0 || pos + 1 >= linha.size()) {
        return std::nullopt;
    }

    std::string chave = linha.substr(0, pos);
    std::string valor = linha.substr(pos + 1);
    return std::make_pair(chave, valor);
}

int main(int argc, char* argv[]) {
    if (argc != 2) {
        std::cerr << "uso: app <arquivo>\n";
        return 1;
    }

    fs::path caminho = argv[1];

    if (!fs::exists(caminho)) {
        std::cerr << "erro: arquivo nao existe\n";
        return 2;
    }

    if (!fs::is_regular_file(caminho)) {
        std::cerr << "erro: caminho nao e arquivo regular\n";
        return 3;
    }

    std::ifstream in(caminho);
    if (!in) {
        std::cerr << "erro: falha ao abrir arquivo\n";
        return 4;
    }

    std::string linha;
    std::size_t total = 0;
    std::size_t validas = 0;

    while (std::getline(in, linha)) {
        total++;
        if (parse_linha(linha)) {
            validas++;
        }
    }

    std::cout << "arquivo: " << caminho.string() << "\n";
    std::cout << "linhas totais: " << total << "\n";
    std::cout << "linhas validas: " << validas << "\n";

    return 0;
}
```

## 7. O que esse exemplo mostra?

### 7.1 `argc` e `argv`

Forma classica de entrada de argumentos em `main`.

- `argc`: quantidade de argumentos
- `argv`: vetor de strings C

### 7.2 `fs::path`

Representa caminho de forma mais adequada que string crua.

### 7.3 Validacao antes de abrir

O programa checa:

- existencia;
- tipo do caminho;
- abertura do arquivo.

### 7.4 `std::getline`

Leitura linha a linha.

### 7.5 `std::optional`

Usado para modelar:

- linha valida;
- ou linha malformada.

## 8. `stdout`, `stderr` e exit code

### 8.1 `stdout`

Use para:

- resultado nominal;
- dados esperados;
- saida consumivel por usuario ou pipe.

### 8.2 `stderr`

Use para:

- erros;
- avisos;
- diagnostico operacional.

### 8.3 Exit code

Use `0` para sucesso e valores nao zero para falha.

Isso importa para:

- scripts;
- automacao;
- CI;
- composicao com outras ferramentas.

## 9. Parsing melhor que `split` ingenuo

Muita gente tenta resolver tudo com:

- `find`
- `substr`
- pequenos helpers

Isso basta no inicio, mas sempre com contrato claro.

### 9.1 Pontos a verificar

- linha vazia;
- delimitador ausente;
- delimitador no inicio;
- delimitador no fim;
- espacos;
- normalizacao;
- mensagens de erro.

### 9.2 Regra pratica

Se o formato crescer, promova o parser para modulo proprio.

## 10. `std::stringstream`

Quando voce precisa parsear texto estruturado leve, `std::stringstream` pode ajudar.

Exemplo:

```cpp
#include <sstream>

std::stringstream ss("10 20");
int a = 0;
int b = 0;
ss >> a >> b;
```

### 10.1 Quando usar?

- parsing simples e legivel;
- prototipos;
- formatos pequenos.

### 10.2 Cuidado

Nem sempre sera a opcao mais rapida.

Para hot path, parsing pode exigir abordagem mais enxuta.

## 11. O que acontece em memoria?

`std::string`, `std::ifstream` e `fs::path` sao objetos com RAII.

Ou seja:

- o arquivo e fechado ao destruir o stream;
- strings gerenciam memoria dinamica quando necessario;
- o programa fica mais robusto do que fluxo manual de `open/close/free`.

### 11.1 Ligacao com aulas anteriores

Aqui se juntam:

- RAII;
- tratamento de erro;
- containers e strings;
- contrato de API.

## 12. Comparacao com C, Rust, Go e Python

- Em C, caminhos e arquivos frequentemente exigem mais manipulacao manual e buffers.
- Em Rust, `std::fs`, `Path` e `Result` tornam esse fluxo muito explicito e seguro.
- Em Go, `os`, `io` e slices de bytes oferecem caminho direto e muito pragmatica.
- Em Python, `pathlib`, `open()` e parsing textual sao muito ergonomicos, mas com menos exposicao do custo e lifetime interno.

C++ moderno fica num ponto interessante:

- boa biblioteca padrao;
- RAII;
- desempenho razoavel;
- controle forte quando necessario.

## 14. Erros comuns e anti-padroes

1. **Misturar parsing, I/O e regra de negocio num bloco unico**.
2. **Escrever tudo em `stdout`, inclusive erro**.
3. **Ignorar exit code em ferramenta que sera automatizada**.
4. **Tratar caminho como string crua em toda parte sem usar `fs::path`**.
5. **Abrir stream e nao verificar se realmente abriu**.
6. **Assumir formato perfeito do arquivo sem validar**.
