# Aula 03a - Lógica, invariantes e o limite da abstração de máquina

---

## Nesta aula

Escrever a pré-condição e a pós-condição de uma função, declarar o invariante de um laço, argumentar terminação por uma grandeza que diminui e reconhecer onde a prova matemática termina e o comportamento da máquina começa. Pré-requisitos: aulas 01 a 03 — tipos básicos, `const`, referências, controle de fluxo, funções e sobrecarga. Ainda não precisa saber classes, templates nem STL.

Você vai aprender a enunciar invariantes e o limite da abstracao de maquina; provar correcao de um algoritmo simples; e distinguir prova de medicao.

---

## 1. Ponte com as aulas anteriores

Na Aula 03, vimos:

- funções e sobrecarga;
- namespaces e escopo;
- decomposição de lógica em unidades reutilizáveis.

Agora falta a pergunta que separa código que funciona de código que se pode defender: *por que este laço sempre entrega o resultado prometido, para todas as entradas do contrato?* A resposta tem três peças — contrato, invariante e prova de término — e uma advertência: a prova vale no modelo matemático; o programa roda numa máquina com inteiros finitos, pilha limitada e otimizações.

---

## 2. Um contrato antes do código

Tome o máximo divisor comum (MDC) de dois inteiros não negativos.

- **Pré-condição:** as entradas pertencem ao domínio prometido, aqui `unsigned int`.
- **Pós-condição:** o resultado divide as duas entradas e nenhum divisor comum positivo é maior que ele.
- **Caso especial:** matematicamente, `mdc(0, 0)` não tem valor positivo único. Nossa API retorna `0` para esse caso. A escolha é convenção documentada, não teorema.

Um teste mostra que a função funcionou nas entradas testadas. Um argumento de correção explica por que funciona em *todas* as entradas do contrato. Ambos são necessários: a prova pode partir de uma hipótese errada sobre o código real, e os testes não enumeram todas as entradas.

Em C++, registre o contrato com `assert` da biblioteca padrão ([`<cassert>`](https://en.cppreference.com/w/cpp/error/assert)). `assert` verifica durante o desenvolvimento e desaparece em builds com `NDEBUG`; nunca o use como validação de entrada externa.

## 3. A propriedade que sobrevive ao laço

O algoritmo de Euclides usa a identidade:

```text
mdc(a, b) = mdc(b, a mod b), quando b > 0
```

Se um número divide `a` e `b`, ele também divide o resto de `a` por `b`; no sentido inverso, se divide `b` e o resto, divide a combinação que reconstrói `a`. Os divisores comuns dos dois pares são os mesmos.

Essa igualdade é o **invariante do laço**: antes e depois de cada iteração, o MDC do par atual continua igual ao MDC das entradas originais. Cada descarte preserva a promessa, e quando `b == 0`, `mdc(a, 0) == a` entrega a pós-condição — exceto o caso `0,0`, já convencionado.

**Terminação:** a grandeza `b` é um inteiro não negativo que diminui estritamente a cada iteração sem acerto. Não existe sequência infinita assim; o laço termina. Observe que a condição também impede a divisão por zero em `a % b`.

## 4. Exemplo completo e executável

O [arquivo-fonte desta aula](exemplos/03a_invariante.cpp) contém exatamente o programa abaixo:

```cpp
#include <cassert>
#include <chrono>
#include <iostream>
#include <numeric>
#include <random>
#include <vector>

// Contrato: a e b em unsigned int; devolve mdc(a, b), com mdc(0,0) == 0.
// Invariante: mdc(a, b) do par atual == mdc das entradas originais.
unsigned int mdc(unsigned int a, unsigned int b) {
    while (b != 0u) {
        const unsigned int resto = a % b;
        a = b;
        b = resto;
    }
    return a;
}

// Versao por subtracao, apenas para entradas positivas: contrato menor.
unsigned int mdc_sub(unsigned int a, unsigned int b) {
    assert(a > 0u && b > 0u);
    while (a != b) {
        if (a > b) {
            a -= b;
        } else {
            b -= a;
        }
    }
    return a;
}

long long medir_us(auto funcao, unsigned int a, unsigned int b, int repeticoes) {
    const auto inicio = std::chrono::steady_clock::now();
    for (int i = 0; i < repeticoes; ++i) {
        volatile unsigned int r = funcao(a, b);
        (void)r;
    }
    const auto fim = std::chrono::steady_clock::now();
    return std::chrono::duration_cast<std::chrono::microseconds>(fim - inicio).count();
}

int main() {
    assert(mdc(54u, 24u) == 6u);
    assert(mdc(0u, 24u) == 24u);
    assert(mdc(24u, 0u) == 24u);
    assert(mdc(0u, 0u) == 0u);
    assert(mdc_sub(54u, 24u) == 6u);

    // Teste de propriedade: oraculo independente (std::gcd) com semente fixa.
    std::mt19937 rng(42);  // semente fixa: a falha e reproduzivel
    std::uniform_int_distribution<unsigned int> dist(0u, 100000u);
    for (int i = 0; i < 2000; ++i) {
        const unsigned int a = dist(rng);
        const unsigned int b = dist(rng);
        assert(mdc(a, b) == std::gcd(a, b));
        if (a > 0u && b > 0u) {
            assert(mdc_sub(a, b) == std::gcd(a, b));
        }
    }

    std::cout << "mdc(54, 24) = " << mdc(54u, 24u) << "\n";
    const int rep = 20000;
    std::cout << "modulo (987,986): " << medir_us(mdc, 987u, 986u, rep) << " us\n";
    std::cout << "subtracao (987,986): " << medir_us(mdc_sub, 987u, 986u, rep) << " us\n";
    std::cout << "modulo (987,610): " << medir_us(mdc, 987u, 610u, rep) << " us\n";
    return 0;
}
```

Compile e execute (C++20 é o padrão do núcleo obrigatório):

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -Werror teoria/cpp/exemplos/03a_invariante.cpp -o invariante
./invariante
```

Saída esperada (tempos variam por máquina; a diferença de ordem de grandeza importa):

```text
mdc(54, 24) = 6
modulo (987,986): ~us
subtracao (987,986): ~us, muito maior
modulo (987,610): ~us
```

A versão por subtração sofre no par `(987, 986)`: após a primeira subtração resta subtrair `1` quase mil vezes. A versão por módulo resolve em poucas iterações. A previsão `O(log min(a,b))` contra `O(a/b)` iterações aparece na medição sem precisar de cronômetro de precisão científica.

### O que a memória faz aqui?

`a`, `b` e `resto` são valores locais; o programa usa espaço adicional `O(1)` e não aloca nada dinâmico. O compilador pode manter tudo em registradores. Não assuma que cada variável corresponde a uma posição de stack, nem que a ordem das operações no binário segue a ordem do fonte quando a semântica permite reordenar.

## 5. Indução e o limite da pilha

A soma `1 + ... + n` recursiva prova-se por indução (base em `n == 0`, passo somando `n` à hipótese), mas cada chamada pendente ocupa um quadro de pilha. Sem garantia de eliminação de chamada de cauda em C++, recursão profunda estoura a stack: a prova matemática não remove o limite da máquina. Prefira laço quando a profundidade depende da entrada; reserve recursão para profundidade logarítmica ou limitada por contrato.

## 6. Onde a abstração vaza

1. **Overflow com sinal é comportamento indefinido.** `INT_MAX + 1` com `int` não "dá a volta" por garantia: o compilador pode assumir que isso nunca acontece e otimizar em cima dessa suposição. Use tipos sem sinal com semântica modular documentada, ou verifique antes de operar.
2. **Módulo por zero e `assert` removido.** A guarda `b != 0` protege `a % b`; se o contrato for violado em build com `NDEBUG`, a proteção some junto com a checagem. Valide entrada externa com `if`, não com `assert`.
3. **Comparações com sinal misturado.** Comparar `int` com `size_t` converte o `int` para sem sinal; valores negativos viram números enormes. Ative os warnings e leia cada um.
4. **`operator[]` não verifica limites.** `v[i]` fora da faixa é indefinido; `.at(i)` lança `std::out_of_range`. O invariante "índice dentro dos limites" precisa ser provado antes de cada acesso, não depois do crash.

## 7. Ponte com Python e JavaScript

Python tem inteiros de precisão arbitrária, então a prova da soma recursiva vale sem ressalva de overflow — mas a ressalva volta em `float` e nas fronteiras com C. JavaScript usa `Number` de 64 bits para a aritmética comum: `2**53 + 1 === 2**53 + 2`. A identidade de Euclides é a mesma nas três linguagens; o que muda é em que representação a prova vale e o que acontece fora dela.
