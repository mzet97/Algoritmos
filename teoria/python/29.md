## 3. Ferramentas basicas

- `timeit`: benchmarking pequeno
- `cProfile`: tempo por funcao
- `pstats`: leitura do perfil
- `tracemalloc`: alocacao de memoria

Cada ferramenta responde pergunta diferente.

---

## 4. Exemplo completo da aula

```python
import cProfile
import pstats
import tracemalloc


def slow_sum(values: list[int]) -> int:
    total = 0
    for value in values:
        total += value * value
    return total


def build_strings(n: int) -> list[str]:
    result = []
    for i in range(n):
        result.append(f"item-{i}")
    return result


def run_workload() -> None:
    values = list(range(200_000))
    slow_sum(values)
    build_strings(50_000)


def main() -> None:
    tracemalloc.start()

    profiler = cProfile.Profile()
    profiler.enable()
    run_workload()
    profiler.disable()

    stats = pstats.Stats(profiler).sort_stats("cumtime")
    stats.print_stats(10)

    current, peak = tracemalloc.get_traced_memory()
    print(f"current_bytes={current}")
    print(f"peak_bytes={peak}")


if __name__ == "__main__":
    main()
```

---

## 6. Quando usar NumPy?

Bom candidato:

- dado numerico regular;
- operacao vetorizavel;
- muito loop numerico.

Mau candidato:

- logica cheia de ramificacao de negocio;
- objetos Python heterogeneos;
- pipeline dominado por I/O.

---

## 7. Quando usar Numba?

- **Numba**: JIT para certos tipos de codigo numerico em Python.

Ajuda quando ha:

- loops numericos;
- arrays bem estruturados;
- kernel computacional repetitivo.

Nem todo codigo Python e bom candidato.

---

## 8. Quando usar Cython ou FFI?

Quando voce precisa:

- controle mais fino;
- integrar biblioteca nativa;
- acelerar hot path especifico;
- sair do interpretador em trecho critico.

Mas isso traz custo de:

- build;
- distribuicao;
- depuracao;
- fronteira entre linguagens.

---

## 9. Heuristica pratica

1. faca a medicao
2. entenda o gargalo
3. simplifique algoritmo e estrutura
4. use biblioteca nativa pronta se houver
5. vetorize ou use JIT
6. so depois considere extensao customizada

---

## 10. Comparacao com C, C++ e Rust

- Em C e C++, o caminho nativo ja e a base, entao a conversa muda para profiling fino e layout.
- Em Rust, tambem se parte de codigo compilado e mais explicito.
- Em Python, a grande habilidade de engenharia e decidir o que fica no Python e o que deve descer para camada mais rapida.

## 12. Erros Comuns e Anti-Padroes

1. **Tentar Cython ou FFI antes de medir**.
2. **Confundir gargalo de I/O com gargalo de CPU**.
3. **Achar que JIT ou NumPy ajudam qualquer codigo**.
4. **Ignorar memoria e olhar apenas tempo total**.
5. **Levar complexidade nativa para o projeto sem necessidade real**.
