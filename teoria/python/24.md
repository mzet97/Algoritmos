# Aula 24 - CLIs profissionais, configuracao e codigos de saida

---

## Objetivo da Aula

Entender como desenhar CLIs mais profissionais em Python, com subcomandos, validacao de entrada, configuracao previsivel, separacao entre `stdout` e `stderr`, e codigos de saida coerentes. Ao final, você deverá: construir CLIs profissionais (argparse/click, config, códigos de saída), e distinguir sucesso de saída de sucesso de operação.
Mediremos com níveis de proficiência:
- **Nível 1 — Recordar:** `definir código de saída, config e CLI idiomática`;
- **Nível 2 — Aplicar:** `diagnosticar CLI sem código de erro e corrigir`;
- **Nível 3 — Projetar:** `projetar CLI justificando interface e saídas`.

## 2. CLI de verdade nao e so `sys.argv`

Ler `sys.argv` manualmente funciona para exemplo pequeno.

Mas CLI real precisa pensar em:

- ajuda;
- subcomando;
- validacao;
- erro de uso;
- codigo de saida;
- configuracao.

---

## 3. `stdout` vs `stderr`

Regra pratica:

- `stdout`: saida nominal, que pode ser redirecionada para outro programa;
- `stderr`: erro, aviso, diagnostico operacional.

Misturar tudo quebra:

- pipelines;
- automacao;
- previsibilidade.

---

## 4. Codigo de saida

- `0`: sucesso
- diferente de `0`: falha ou condicao especial

Isso importa porque automacao e shell usam:

- codigo de saida como contrato.

## 5. Exemplo completo da aula

```python
import argparse
import json
import os
import sys
from dataclasses import dataclass


@dataclass
class AppConfig:
    default_format: str


def load_config() -> AppConfig:
    return AppConfig(default_format=os.getenv("APP_FORMAT", "text"))


def cmd_echo(args: argparse.Namespace, config: AppConfig) -> int:
    output_format = args.format or config.default_format

    if output_format == "json":
        print(json.dumps({"message": args.message}))
        return 0

    print(args.message)
    return 0


def cmd_validate(args: argparse.Namespace, config: AppConfig) -> int:
    if not os.path.exists(args.path):
        print(f"file not found: {args.path}", file=sys.stderr)
        return 2

    print(f"ok: {args.path}")
    return 0


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="infra-tool")
    subparsers = parser.add_subparsers(dest="command", required=True)

    echo_parser = subparsers.add_parser("echo", help="print a message")
    echo_parser.add_argument("message")
    echo_parser.add_argument("--format", choices=["text", "json"])
    echo_parser.set_defaults(handler=cmd_echo)

    validate_parser = subparsers.add_parser("validate", help="validate a file path")
    validate_parser.add_argument("path")
    validate_parser.set_defaults(handler=cmd_validate)

    return parser


def main(argv: list[str] | None = None) -> int:
    parser = build_parser()
    args = parser.parse_args(argv)
    config = load_config()
    return args.handler(args, config)


if __name__ == "__main__":
    raise SystemExit(main())
```

---

## 6. O que esse exemplo ensina?

### 6.1 `build_parser`

Centraliza:

- contrato da CLI.

### 6.2 `set_defaults(handler=...)`

Ajuda a mapear:

- subcomando para funcao.

### 6.3 `main() -> int`

Explicita:

- codigo de saida.

### 6.4 `load_config`

Separa:

- configuracao do fluxo principal.

---

## 7. Configuracao

Ferramenta madura tende a aceitar configuracao por:

- flags;
- variaveis de ambiente;
- arquivo;
- combinacao com prioridade definida.

Sem isso, CLI cresce de forma caotica.

---

## 8. Ergonomia vs acoplamento

Boa CLI:

- e facil de usar;
- clara em erro;
- previsivel em automacao.

CLI ruim:

- imprime texto ambigo;
- muda comportamento silenciosamente;
- nao separa erro de sucesso;
- nao tem contrato estavel.

---

## 9. Comparacao com C, C++ e Rust

- Em C e C++, CLIs robustas costumam exigir mais trabalho manual com parsing, strings e tratamento de erro.
- Em Rust, crates de CLI ajudam bastante a modelar argumentos com tipagem forte.
- Em Python, a ergonomia e alta, o que torna ainda mais importante ter disciplina de contrato e saida.

---

## 10. Comandos exatos para executar

Rodar ajuda:

```bash
python main.py --help
```

Rodar subcomandos:

```bash
python main.py echo ola
python main.py echo ola --format json
python main.py validate arquivo.txt
```

Definir configuracao por ambiente:

```bash
set APP_FORMAT=json
python main.py echo teste
```

## 11. Erros Comuns e Anti-Padroes

1. **Misturar `stdout` e `stderr` sem criterio**.
2. **Nao retornar codigo de saida claro**.
3. **Esconder regra de configuracao em varios lugares**.
4. **Ter parsing de argumentos espalhado em varias funcoes**.
5. **Tratar CLI como script descartavel mesmo quando ela vira ferramenta critica**.
