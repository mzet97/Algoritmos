## 1. O modelo de objetos de Python

Se voce errar este modelo mental, vai errar listas, dicionarios, funcoes, classes e ate bugs de concorrencia mais tarde.

Em Python:

- o **nome** e apenas um identificador;
- o **objeto** e o valor real em runtime;
- a **referencia** e a ligacao entre nome e objeto.

Todo objeto possui:

1. **identidade**;
2. **tipo**;
3. **valor/estado**.

### 1.1 Identidade

Identidade responde: "este objeto e exatamente este mesmo objeto, ou apenas outro objeto com o mesmo conteudo?"

```python
x = [1, 2, 3]
y = x

print(id(x))
print(id(y))
```

`id()` retorna um identificador de identidade do objeto no runtime.

Se `y = x`, ambos os nomes apontam para o mesmo objeto.

### 1.2 Tipo

Tipo responde: "que tipo de objeto e esse e quais operacoes ele suporta?"

```python
print(type(10))
print(type("abc"))
print(type([1, 2, 3]))
```

### 1.3 Valor ou estado

Para objetos imutaveis, voce pode pensar no valor como conteudo fixo.

Para objetos mutaveis, o estado pode mudar ao longo do tempo.

## 2. Identidade vs igualdade

Este e um dos pontos mais importantes da linguagem.

### 2.1 Igualdade: `==`

`==` pergunta:

> Esses dois objetos representam o mesmo valor logico?

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)  # True
```

### 2.2 Identidade: `is`

`is` pergunta:

> Esses dois nomes apontam para o mesmo objeto?

```python
a = [1, 2, 3]
b = [1, 2, 3]

print(a is b)  # False
```

Agora:

```python
a = [1, 2, 3]
b = a

print(a == b)  # True
print(a is b)  # True
```

**Regra pratica:**

- use `==` para comparar valores;
- use `is` para identidade;
- use `is None` e `is not None` para checar `None`.

### 2.3 Por que `is None`?

Porque `None` e um singleton semantico da linguagem.

```python
valor = None

if valor is None:
    print("sem valor")
```

## 3. Objetos mutaveis e imutaveis

### 3.1 O que e mutabilidade?

- **Mutavel**: o mesmo objeto pode ter seu estado alterado.
- **Imutavel**: o objeto nao muda; se parece que mudou, na verdade outro objeto foi criado e o nome foi religado.

### 3.2 Tipos comuns imutaveis

- `int`
- `float`
- `bool`
- `str`
- `tuple`

### 3.3 Tipos comuns mutaveis

- `list`
- `dict`
- `set`

### 3.4 Exemplo com imutavel

```python
x = 10
print(id(x))

x = x + 1
print(x)
print(id(x))
```

O `id` tende a mudar porque `x = x + 1` nao altera o inteiro antigo; cria um novo inteiro e faz `x` apontar para ele.

### 3.5 Exemplo com mutavel

```python
numeros = [1, 2, 3]
print(id(numeros))

numeros.append(4)
print(numeros)
print(id(numeros))
```

Aqui o `id` tende a permanecer o mesmo, porque a lista foi alterada em lugar.

- **Alteracao em lugar (in-place)**: modificar o proprio objeto existente, sem criar outro equivalente.

## 4. Atribuicao nao copia objeto

Este e o bug classico de iniciante:

```python
a = [1, 2, 3]
b = a

b.append(4)

print(a)
print(b)
```

Saida:

```text
[1, 2, 3, 4]
[1, 2, 3, 4]
```

Por que isso acontece?

Porque `b = a` nao cria uma nova lista. Apenas cria outro nome apontando para o mesmo objeto.

Modelo:

```text
a ----\
       ---> lista [1, 2, 3]
b ----/
```

Depois do `append(4)`, a lista compartilhada vira `[1, 2, 3, 4]`.

## 5. Copia rasa e copia profunda

### 5.1 Copia rasa

Para criar outra lista com os mesmos elementos imediatos:

```python
a = [1, 2, 3]
b = a.copy()

b.append(4)

print(a)
print(b)
```

Saida:

```text
[1, 2, 3]
[1, 2, 3, 4]
```

Mas isso ainda pode falhar com estruturas aninhadas:

```python
a = [[1, 2], [3, 4]]
b = a.copy()

b[0].append(999)

print(a)
print(b)
```

Saida:

```text
[[1, 2, 999], [3, 4]]
[[1, 2, 999], [3, 4]]
```

Isso acontece porque a lista externa foi copiada, mas as listas internas continuam compartilhadas.

- **Copia rasa (shallow copy)**: copia o container externo, mas reutiliza referencias dos objetos internos.

### 5.2 Copia profunda

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.deepcopy(a)

b[0].append(999)

print(a)
print(b)
```

Agora `a` e `b` ficam independentes em toda a estrutura.

- **Copia profunda (deep copy)**: recria recursivamente a estrutura, produzindo novos objetos internos tambem.

## 6. Passagem de argumentos em funcoes

Esta e uma das areas mais mal explicadas em cursos rasos.

Python nao faz:

- "passagem por valor" no sentido de C para tudo;
- "passagem por referencia" no sentido simplificado de ponteiro mutavel exposto.

O modelo mais correto e:

> a funcao recebe novos nomes locais apontando para os mesmos objetos passados.

### 6.1 Exemplo com objeto imutavel

```python
def incrementar(x):
    x = x + 1
    print("dentro:", x)


valor = 10
incrementar(valor)
print("fora:", valor)
```

Saida:

```text
dentro: 11
fora: 10
```

O `x = x + 1` cria outro inteiro e faz o nome local `x` apontar para ele. O nome `valor` do chamador continua apontando para o inteiro antigo.

### 6.2 Exemplo com objeto mutavel

```python
def adicionar_item(lista):
    lista.append(99)
    print("dentro:", lista)


dados = [1, 2, 3]
adicionar_item(dados)
print("fora:", dados)
```

Saida:

```text
dentro: [1, 2, 3, 99]
fora: [1, 2, 3, 99]
```

Aqui a funcao altera o proprio objeto lista, que e compartilhado entre chamador e chamada.

### 6.3 Rebinding local vs mutacao do objeto

```python
def trocar(lista):
    lista = [999, 1000]
    print("dentro:", lista)


dados = [1, 2, 3]
trocar(dados)
print("fora:", dados)
```

Saida:

```text
dentro: [999, 1000]
fora: [1, 2, 3]
```

Agora nao houve mutacao da lista original. Houve rebinding do nome local `lista` para outro objeto.

**Resumo pratico:**

- mutar o objeto compartilhado afeta o chamador;
- religar o nome local nao afeta o chamador.

## 7. Escopo: local, global e `nonlocal`

### 7.1 Local e global

```python
total = 100


def mostrar():
    total = 50
    print("local:", total)


mostrar()
print("global:", total)
```

Saida:

```text
local: 50
global: 100
```

### 7.2 `global`

```python
contador = 0


def incrementar():
    global contador
    contador += 1


incrementar()
print(contador)
```

`global` diz que o nome usado dentro da funcao deve referenciar o binding global do modulo.

Use isso com moderacao. Estado global mutavel costuma dificultar manutencao, teste e concorrencia.

### 7.3 `nonlocal`

```python
def externa():
    contador = 0

    def interna():
        nonlocal contador
        contador += 1
        print(contador)

    interna()
    interna()


externa()
```

- **`nonlocal`**: permite alterar um nome de um escopo externo nao global, normalmente o da funcao imediatamente envolvente.

Isso sera essencial quando chegarmos em closures.

## 8. Garbage collection e reference counting

Python gerencia memoria automaticamente, mas isso nao significa "magica sem custo".

O CPython usa, em linhas gerais:

1. **reference counting**;
2. um **garbage collector** complementar para ciclos.

### 8.1 Reference counting

Cada objeto mantem uma contagem de quantas referencias apontam para ele.

Quando essa contagem vai a zero, o objeto pode ser liberado.

### 8.2 Ciclos de referencia

So reference counting nao basta para resolver ciclos:

```python
a = {}
b = {}

a["outro"] = b
b["outro"] = a
```

Aqui pode surgir um ciclo em que um objeto mantem o outro vivo. O GC complementar existe para detectar e limpar esse tipo de estrutura.

**Comparacao:**

- C: o programador libera memoria manualmente.
- Rust: ownership e borrowing provam tempo de vida em compilacao.
- Python: runtime rastreia vida dos objetos.

## 9. Exemplo completo da aula

```python
import copy


def modificar_lista(lista):
    lista.append("novo")


def rebinding_lista(lista):
    lista = ["outra", "lista"]
    print("rebind local:", lista)


original = [[1, 2], [3, 4]]
copia_rasa = original.copy()
copia_profunda = copy.deepcopy(original)

copia_rasa[0].append(999)
copia_profunda[1].append(777)

print("original:", original)
print("copia_rasa:", copia_rasa)
print("copia_profunda:", copia_profunda)

dados = [10, 20]
modificar_lista(dados)
print("apos mutacao:", dados)

rebinding_lista(dados)
print("apos rebinding local:", dados)
```

### Explicacao linha por linha

- `import copy`: traz a biblioteca usada para copia profunda.
- `original.copy()`: cria copia rasa.
- `copy.deepcopy(original)`: cria copia profunda.
- `copia_rasa[0].append(999)`: altera lista interna compartilhada com `original`.
- `copia_profunda[1].append(777)`: altera apenas a estrutura profunda independente.
- `modificar_lista(dados)`: muta o mesmo objeto recebido.
- `rebinding_lista(dados)`: troca apenas o nome local da funcao.

## 11. Erros Comuns e Anti-Padroes

1. **Usar `is` para comparar strings ou numeros**: para valor, use `==`.
2. **Achar que `b = a` faz copia**: normalmente nao faz; so compartilha referencia.
3. **Confundir rebinding local com mutacao do objeto**: sao coisas diferentes.
4. **Ignorar copia rasa em estruturas aninhadas**: isso cria bugs sutis e muito comuns.
5. **Usar `global` em excesso**: isso espalha estado mutavel e piora a arquitetura.
6. **Tratar Python como se fosse C com sintaxe curta**: o modelo mental de objetos e referencias e diferente.
