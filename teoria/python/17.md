# Aula 17 - Performance tuning, profiling e uso eficiente de memoria

---

## Nesta aula

Entender como medir desempenho em Python antes de otimizar. Aprender a usar profiling e benchmarking com criterio, construir intuicao sobre custo de objetos e alocacoes, e identificar quais tecnicas realmente ajudam em performance e memoria em codigo Python real.

Você vai aprender a perfilar com `cProfile`/`tracemalloc`, reduzir alocações no caminho quente, e distinguir otimização medida de prematura.

---

## 1. Regra zero da performance

Antes de otimizar, meca.

Sem medicao, voce corre alto risco de:

- otimizar a parte errada;
- trocar clareza por ganho irrelevante;
- piorar performance real;
- criar mito local em vez de engenharia.

**Regra zero:**

> primeiro descubra onde esta o custo.

---

## 2. Tipos de custo

Em Python, gargalo pode vir de varios lugares:

- CPU;
- I/O;
- alocacao de objetos;
- conversoes desnecessarias;
- chamadas Python em excesso;
- estruturas de dados inadequadas;
- serializacao;
- copia de memoria.

Nem todo problema de lentidao e "Python e lento".

Muitas vezes o problema e desenho do algoritmo ou do fluxo de dados.

---

## 3. Benchmarking basico

### 3.1 `time.perf_counter`

Para medicao simples:

```python
import time


inicio = time.perf_counter()

total = 0
for i in range(1_000_000):
    total += i

fim = time.perf_counter()
print(f"tempo: {fim - inicio:.6f}s")
```

- **Benchmark**: medicao de desempenho sob condicoes definidas.

### 3.2 Cuidado com benchmark ingenuo

Se voce medir uma vez so, em ambiente ruidoso, pode tirar conclusao errada.

Melhor pratica:

- repetir;
- comparar implementacoes equivalentes;
- aquecer quando fizer sentido;
- isolar ruido externo.

---

## 4. `timeit`

Para microbenchmarks, `timeit` e muito util.

```python
import timeit


tempo = timeit.timeit("sum(range(1000))", number=10000)
print(tempo)
```

`timeit` ajuda a reduzir alguns erros comuns de medicao manual.

Mas ainda vale o aviso:

> microbenchmark nao substitui medicao do sistema real.

---

## 5. Profiling

Se benchmark responde "quanto tempo", profiling ajuda a responder:

> onde o tempo esta sendo gasto?

Ferramenta classica:

```python
import cProfile


def trabalho():
    total = 0
    for i in range(100000):
        total += i * i
    return total


cProfile.run("trabalho()")
```

- **Profiler**: ferramenta que coleta estatisticas de execucao para localizar hotspots.
- **Hotspot**: regiao do codigo responsavel por parte relevante do custo total.

---

## 6. CPU time nao e tudo

Seu programa pode parecer lento por:

- espera de rede;
- acesso a disco;
- lock;
- serializacao;
- GC em momentos especificos;
- overhead de interpretacao.

Por isso, a pergunta certa nao e apenas "qual linha gasta CPU?", mas:

> qual recurso esta limitando o throughput ou a latencia?

- **Throughput**: quantidade de trabalho concluido por unidade de tempo.
- **Latencia**: tempo para concluir uma operacao individual.

---

## 7. Complexidade algoritmica ainda manda muito

Antes de mexer em micro-otimizacoes, olhe o algoritmo.

Exemplo conceitual:

- trocar O(n^2) por O(n log n) pode superar qualquer "truque" local.

Escolha de estrutura de dados tambem pesa:

- `set` para busca por pertinencia;
- `dict` para acesso por chave;
- `list` para sequencia simples;
- evitar busca linear repetitiva quando mapa resolveria.

**Comparacao com C/C++/Rust:**

- em todas essas linguagens, algoritmo ruim continua ruim;
- Python apenas torna mais visivel o custo de escolhas erradas quando o overhead de interpretacao soma junto.

---

## 8. Evite trabalho desnecessario

Alguns padroes comuns de desperdicio:

- recomputar a mesma coisa varias vezes;
- converter lista para set dentro de loop repetido;
- materializar lista inteira sem precisar;
- copiar estruturas grandes sem necessidade;
- montar strings por concatenacao repetitiva inadequada.

Exemplo:

```python
partes = []
for i in range(1000):
    partes.append(str(i))

texto = "".join(partes)
```

Isso costuma ser melhor do que concatenar string em loop de forma ingenua.

---

## 9. Memoria em Python

Python trabalha com objetos, referencias e metadados adicionais de runtime.

Comparado com C, o custo por objeto pode ser bem maior.

Isso significa:

- muitos objetos pequenos podem custar bastante;
- listas de objetos Python nao sao arrays crus de dados numericos;
- overhead estrutural importa.

Modelo mental:

- cada elemento da lista normalmente e referencia para objeto;
- o objeto tem cabecalho e metadados;
- o GC e o alocador participam do custo.

---

## 10. Geracao sob demanda

Generators e iteracao lazy ajudam memoria.

Em vez de:

```python
dados = [x * 2 for x in range(10_000_000)]
```

talvez seja melhor:

```python
dados = (x * 2 for x in range(10_000_000))
```

quando voce nao precisa materializar tudo.

Mas lembre:

- lazy pode reduzir memoria;
- nem sempre reduz tempo total;
- as vezes lista materializada e melhor se os dados serao usados varias vezes.

---

## 11. `__slots__`

Classes Python comuns costumam ter `__dict__` por instancia.

Em alguns casos, isso pode ter custo.

Exemplo:

```python
class Ponto:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y
```

`__slots__` pode:

- reduzir memoria por instancia;
- restringir atributos dinamicos;
- melhorar certos acessos.

Mas nao use automaticamente em toda classe.

So vale quando:

- ha muitas instancias;
- voce entende o trade-off;
- a classe tem forma estavel.

---

## 12. Copia custa

Copias profundas ou listas intermediarias grandes podem ser caras.

Exemplo ruim:

```python
resultado = [processar(x) for x in dados if condicao(x)]
outro = list(resultado)
```

Se `outro` so repete `resultado`, houve copia desnecessaria.

Em pipelines de dados, copiar demais e uma fonte comum de custo invisivel.

---

## 13. Baterias certas para trabalho pesado

Quando a carga e numerica ou vetorizavel, Python puro pode nao ser a melhor camada de execucao interna.

Ai entram:

- NumPy;
- bibliotecas compiladas;
- C extensions;
- Cython;
- Rust/C++ via FFI;
- multiprocessing em alguns casos.

Otimizacao madura em Python muitas vezes significa:

> mover o trecho quente para uma camada melhor, mantendo Python como orquestracao.

Isso conversa diretamente com seu objetivo futuro de HPC e integracao.

---

## 14. Garbage collection e tempo de vida

Python faz gerenciamento automatico de memoria, mas isso nao significa custo zero.

Objetos de vida curta em grande quantidade podem:

- aumentar pressao de alocacao;
- acionar trabalho do GC;
- degradar cache e locality.

- **Locality**: proximidade de dados e padroes de acesso que afetam eficiencia de memoria e cache.

Mesmo sem manipular ponteiros manualmente, desenho de dados ainda importa.

## 15. Exemplo completo da aula

```python
import cProfile
import time
import timeit


def soma_loop(n: int) -> int:
    total = 0
    for i in range(n):
        total += i
    return total


def soma_builtin(n: int) -> int:
    return sum(range(n))


def benchmark() -> None:
    inicio = time.perf_counter()
    soma_loop(1_000_000)
    fim = time.perf_counter()
    print(f"perf_counter loop: {fim - inicio:.6f}s")

    tempo_loop = timeit.timeit("soma_loop(10000)", globals=globals(), number=1000)
    tempo_builtin = timeit.timeit("soma_builtin(10000)", globals=globals(), number=1000)
    print(f"timeit soma_loop: {tempo_loop:.6f}s")
    print(f"timeit soma_builtin: {tempo_builtin:.6f}s")


def perfil() -> None:
    cProfile.run("soma_loop(500000)")


if __name__ == "__main__":
    benchmark()
    perfil()
```

### Explicacao linha por linha

- `perf_counter()`: medicao simples de tempo de alta resolucao.
- `timeit.timeit(...)`: microbenchmark repetido e mais controlado.
- `cProfile.run(...)`: profiling para localizar custo agregado.
- `sum(range(n))`: exemplo de uso de builtin geralmente mais eficiente que loop Python manual.

## 17. Erros Comuns e Anti-Padroes

1. **Otimizar antes de medir**.
2. **Concluir demais com um benchmark unico e ruidoso**.
3. **Focar em micro-otimizacao ignorando algoritmo e estrutura de dados**.
4. **Criar listas enormes quando processamento lazy bastaria**.
5. **Copiar dados sem necessidade**.
6. **Esperar que Python puro venza codigo compilado em hotspot numerico pesado**.
7. **Tentar usar `asyncio` ou threads para resolver gargalo que na verdade e CPU ou memoria**.
