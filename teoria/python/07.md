## 1. O modelo orientado a objetos de Python

Python e uma linguagem orientada a objetos, mas nao do mesmo jeito "fechado" de algumas linguagens classicas.

Aqui, quase tudo e objeto:

- numeros;
- strings;
- listas;
- funcoes;
- classes;
- instancias.

Isso significa que orientacao a objetos em Python nao e um "modo especial" da linguagem. Ela faz parte do proprio modelo de objetos.

---

## 2. O que e uma classe?

Uma **classe** e um molde para criar objetos.

Mais tecnicamente:

- define estrutura;
- define comportamento;
- participa do processo de criacao de instancias.

Exemplo minimo:

```python
class Pessoa:
    pass


p = Pessoa()
print(type(p))
```

- **Instancia**: objeto concreto criado a partir de uma classe.

`Pessoa` e a classe. `p` e a instancia.

**Comparacao:**

- C: voce normalmente modelaria isso com `struct`.
- C++/Rust: ficaria mais proximo de `class` ou `struct` com `impl`.
- Python: classes tambem sao objetos de primeira classe.

## 3. `__init__` e inicializacao

O metodo mais conhecido de uma classe e `__init__`.

```python
class Pessoa:
    def __init__(self, nome, idade):
        self.nome = nome
        self.idade = idade


p = Pessoa("Ana", 30)
print(p.nome)
print(p.idade)
```

### 3.1 O que e `self`?

`self` e a referencia para a propria instancia que esta recebendo a chamada do metodo.

Quando voce escreve:

```python
p.nome
```

isso acessa o atributo `nome` armazenado naquele objeto.

Quando voce chama:

```python
p.falar()
```

Python, conceitualmente, transforma isso em algo como:

```python
Pessoa.falar(p)
```

Ou seja, a instancia vira o primeiro argumento.

**Importante:** `self` nao e palavra reservada da linguagem, mas e a convencao universal. Quase nunca ha boa razao para trocar esse nome.

## 4. Atributos de instancia

### 4.1 O que sao?

Atributos de instancia sao dados armazenados em cada objeto individual.

```python
class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco


a = Produto("Teclado", 100)
b = Produto("Mouse", 50)

print(a.nome, a.preco)
print(b.nome, b.preco)
```

Cada instancia tem seu proprio estado.

### 4.2 Mutacao de atributos

```python
a.preco = 120
print(a.preco)
```

Se o atributo for publico, Python permite mudanca direta.

## 5. Metodos

Metodos sao funcoes definidas dentro da classe.

```python
class Conta:
    def __init__(self, saldo):
        self.saldo = saldo

    def depositar(self, valor):
        self.saldo += valor

    def sacar(self, valor):
        if valor > self.saldo:
            return False
        self.saldo -= valor
        return True


conta = Conta(100)
conta.depositar(50)
print(conta.saldo)
print(conta.sacar(30))
print(conta.saldo)
```

Metodos existem para acoplar comportamento aos dados que eles manipulam.

## 6. Atributos de classe vs atributos de instancia

### 6.1 Atributo de classe

```python
class Usuario:
    especie = "humano"

    def __init__(self, nome):
        self.nome = nome


u1 = Usuario("Ana")
u2 = Usuario("Bruno")

print(u1.especie)
print(u2.especie)
print(Usuario.especie)
```

`especie` pertence a classe. `nome` pertence a cada instancia.

### 6.2 Armadilha com mutaveis em atributo de classe

```python
class TimeRuim:
    membros = []


a = TimeRuim()
b = TimeRuim()

a.membros.append("Ana")
print(b.membros)
```

Saida:

```text
['Ana']
```

Isso acontece porque a lista esta compartilhada no nivel da classe.

Forma correta se cada instancia deve ter sua propria lista:

```python
class Time:
    def __init__(self):
        self.membros = []
```

## 7. Encapsulamento em Python

Python nao trabalha com encapsulamento rigido como Java ou C++ com `private` de forma forte no nivel da linguagem.

Em vez disso, Python usa convencoes.

### 7.1 Um underscore

```python
class Exemplo:
    def __init__(self):
        self._interno = 123
```

`_interno` sinaliza:

> isto e detalhe interno; nao deveria ser API publica.

### 7.2 Dois underscores

```python
class Exemplo:
    def __init__(self):
        self.__segredo = 42
```

Aqui ocorre **name mangling**.

- **Name mangling**: transformacao de nome feita pela linguagem para reduzir colisao acidental em subclasses.

Nao e seguranca real. E apenas um mecanismo de protecao semantica fraca.

### 7.3 `property`

Quando voce quer controlar acesso sem expor getter/setter verboso como em Java, Python oferece `property`.

```python
class Temperatura:
    def __init__(self, celsius):
        self._celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, valor):
        if valor < -273.15:
            raise ValueError("temperatura invalida")
        self._celsius = valor
```

Uso:

```python
t = Temperatura(25)
print(t.celsius)
t.celsius = 30
```

O codigo do usuario parece acesso simples a atributo, mas por baixo ha logica.

## 8. Heranca

Heranca permite criar uma classe derivada a partir de outra.

```python
class Animal:
    def falar(self):
        return "som generico"


class Cachorro(Animal):
    def falar(self):
        return "au au"


class Gato(Animal):
    def falar(self):
        return "miau"
```

### 8.1 Polimorfismo

```python
animais = [Cachorro(), Gato()]

for animal in animais:
    print(animal.falar())
```

- **Polimorfismo**: mesma interface logica (`falar`) com implementacoes diferentes dependendo do objeto concreto.

Python favorece muito esse estilo.

### 8.2 `super()`

```python
class Funcionario:
    def __init__(self, nome):
        self.nome = nome


class Gerente(Funcionario):
    def __init__(self, nome, equipe):
        super().__init__(nome)
        self.equipe = equipe
```

`super()` permite chamar comportamento da classe base de forma cooperativa.

## 9. Duck typing

Python tem forte cultura de **duck typing**:

> se anda como pato e grasna como pato, trate como pato.

Em vez de perguntar "qual e exatamente a classe?", muitas vezes o mais importante e:

> o objeto suporta a operacao de que eu preciso?

Exemplo:

```python
class Pato:
    def falar(self):
        return "quack"


class Pessoa:
    def falar(self):
        return "ola"


def emitir_fala(obj):
    print(obj.falar())


emitir_fala(Pato())
emitir_fala(Pessoa())
```

Nao precisamos de heranca obrigatoria comum para isso funcionar.

Isso e profundamente Pythonico.

## 10. Metodos especiais

Classes Python podem participar de varios protocolos especiais com metodos "dunder" (`__nome__`).

Exemplos:

- `__init__`: inicializacao;
- `__repr__`: representacao oficial;
- `__str__`: representacao amigavel;
- `__len__`: tamanho;
- `__iter__`: iteracao.

Exemplo:

```python
class Livro:
    def __init__(self, titulo, autor):
        self.titulo = titulo
        self.autor = autor

    def __repr__(self):
        return f"Livro(titulo={self.titulo!r}, autor={self.autor!r})"

    def __str__(self):
        return f"{self.titulo} - {self.autor}"


livro = Livro("Python Profundo", "Ana")
print(livro)
print(repr(livro))
```

## 11. Composicao vs heranca

Heranca nao deve ser a primeira resposta para tudo.

Muitas vezes, **composicao** e melhor:

- **Composicao**: um objeto contem outro objeto para reutilizar comportamento.

Exemplo:

```python
class Motor:
    def ligar(self):
        print("Motor ligado")


class Carro:
    def __init__(self):
        self.motor = Motor()

    def ligar(self):
        self.motor.ligar()
```

Aqui `Carro` tem um `Motor`; ele nao precisa ser um `Motor`.

**Regra pratica:** heranca para relacao "e um". Composicao para "tem um".

## 12. Exemplo completo da aula

```python
class Conta:
    taxa_transferencia = 2.5

    def __init__(self, titular, saldo=0):
        self.titular = titular
        self._saldo = saldo

    @property
    def saldo(self):
        return self._saldo

    def depositar(self, valor):
        if valor <= 0:
            raise ValueError("deposito invalido")
        self._saldo += valor

    def sacar(self, valor):
        if valor <= 0:
            raise ValueError("saque invalido")
        if valor > self._saldo:
            return False
        self._saldo -= valor
        return True

    def __repr__(self):
        return f"Conta(titular={self.titular!r}, saldo={self._saldo!r})"


class ContaPremium(Conta):
    def transferir(self, outra, valor):
        total = valor + self.taxa_transferencia
        if self.sacar(total):
            outra.depositar(valor)
            return True
        return False


a = ContaPremium("Ana", 200)
b = Conta("Bruno", 50)

print(a)
print(b)

ok = a.transferir(b, 40)
print("transferencia:", ok)
print(a)
print(b)
```

### Explicacao linha por linha

- `taxa_transferencia = 2.5`: atributo de classe.
- `self._saldo`: atributo de instancia com convencao de uso interno.
- `@property`: expande acesso de leitura de forma idiomatica.
- `ContaPremium(Conta)`: heranca simples.
- `self.sacar(total)`: reuso de metodo herdado.
- `outra.depositar(valor)`: colaboracao entre objetos.

## 14. Erros Comuns e Anti-Padroes

1. **Esquecer `self` no metodo de instancia**: isso quebra a assinatura.
2. **Usar atributo de classe mutavel quando queria estado por instancia**.
3. **Tratar `__dunder__` como decoracao sem entender protocolo**.
4. **Exagerar em heranca quando composicao resolveria melhor**.
5. **Achar que `__privado` e seguranca real**: nao e.
6. **Fazer getters/setters estilo Java para tudo sem necessidade**: em Python, `property` costuma ser mais idiomatico.
7. **Usar OOP onde funcoes simples e dados claros bastariam**: orientacao a objetos nao e obrigacao universal.
