# Aula 11 - Tipagem com `type hints` em Python

---

## Objetivo da Aula

Entender o que sao `type hints` e por que Python adicionou anotacoes de tipo sem deixar de ser dinamico. Aprender como usar tipagem para melhorar legibilidade, manutencao e ferramentas, alem dos conceitos fundamentais de `typing` para escrever codigo Python moderno e claro.

---

## 1. Python e dinamicamente tipado

Antes de falar de `type hints`, precisamos reforcar um ponto:

Python continua sendo uma linguagem **dinamicamente tipada**.

Isso significa que:

- nomes apontam para objetos;
- os objetos tem tipo em runtime;
- o nome em si nao carrega um tipo fixo imposto pela linguagem como em C, C++ ou Rust.

Exemplo:

```python
x = 10
print(type(x))

x = "agora sou string"
print(type(x))
```

Nada em Python impede esse rebinding.

`type hints` nao mudam esse modelo fundamental.

---

## 2. O que sao `type hints`?

`Type hints` sao **anotacoes de tipo** adicionadas ao codigo-fonte para comunicar intencao a humanos e ferramentas.

Exemplo:

```python
def soma(a: int, b: int) -> int:
    return a + b
```

Aqui:

- `a: int` sugere que `a` deve ser um inteiro;
- `b: int` sugere que `b` deve ser um inteiro;
- `-> int` sugere que a funcao retorna inteiro.

**Importante:** Python normalmente nao impede em runtime que voce chame:

```python
print(soma("a", "b"))
```

A linguagem vai executar de acordo com a semantica real dos objetos.

Ou seja:

> `type hints` servem principalmente para documentacao, leitura, analise estatica e suporte de ferramentas.

---

## 3. Por que isso existe?

Conforme projetos Python cresceram, surgiram dores classicas:

- interfaces ambiguas;
- erros simples descobertos tarde demais;
- dificuldade de navegar APIs grandes;
- refatoracoes arriscadas;
- autocomplete fraco sem contexto semantico.

`Type hints` ajudam a reduzir esse custo.

Eles nao transformam Python em Rust nem em C++.

Eles criam uma camada de contrato leve sobre uma linguagem dinamica.

**Comparacao:**

- C/C++: tipos fazem parte obrigatoria do compilador e da geracao de codigo.
- Rust: tipos participam fortemente de seguranca e inferencia.
- Python: tipos anotados ajudam principalmente ferramentas como analisadores estaticos, IDEs e leitores humanos.

---

## 4. Anotando variaveis

```python
idade: int = 30
nome: str = "Ana"
ativo: bool = True
```

Isso nao cria variavel "mais forte" em runtime.

Mas deixa o codigo mais explicito.

Tambem e possivel anotar sem inicializar imediatamente:

```python
resultado: float
resultado = 3.14
```

---

## 5. Anotando funcoes

### 5.1 Parametros e retorno

```python
def area_retangulo(largura: float, altura: float) -> float:
    return largura * altura
```

### 5.2 Sem retorno util

```python
def exibir(msg: str) -> None:
    print(msg)
```

`None` aqui significa:

> a funcao nao devolve valor util para o chamador.

### 5.3 Parametros opcionais

```python
def saudacao(nome: str, titulo: str | None = None) -> str:
    if titulo is None:
        return f"Ola, {nome}"
    return f"Ola, {titulo} {nome}"
```

`str | None` significa uniao de tipos.

- **Uniao de tipos**: valor pode pertencer a mais de um tipo possivel.

Em Python mais antigo, isso aparecia como `Optional[str]` ou `Union[str, None]`.

---

## 6. Colecoes tipadas

### 6.1 Lista

```python
nomes: list[str] = ["Ana", "Bruno", "Carla"]
```

### 6.2 Tupla

```python
ponto: tuple[int, int] = (10, 20)
```

### 6.3 Dicionario

```python
idades: dict[str, int] = {
    "Ana": 30,
    "Bruno": 25,
}
```

### 6.4 Conjunto

```python
tags: set[str] = {"python", "backend", "dados"}
```

Essas anotacoes deixam explicito o contrato esperado da colecao.

---

## 7. `Any`

```python
from typing import Any


def processar(valor: Any) -> Any:
    return valor
```

`Any` significa:

> aqui eu estou abrindo mao de informacao de tipo precisa.

Isso pode ser necessario em pontos de fronteira, integracao ou codigo muito dinamico.

Mas `Any` em excesso enfraquece o valor da tipagem.

**Regra pratica:** use `Any` como escape hatch, nao como padrao.

- **Escape hatch**: mecanismo usado para sair de uma restricao ou disciplina mais forte quando necessario.

---

## 8. `Iterable`, `Sequence`, `Mapping`

Nem sempre o melhor tipo e concreto como `list[str]`.

As vezes o que voce quer expressar e a **capacidade** exigida.

```python
from collections.abc import Iterable


def imprimir_todos(valores: Iterable[str]) -> None:
    for valor in valores:
        print(valor)
```

Aqui nao exigimos lista especificamente.

Serve:

- lista;
- tupla;
- generator;
- set;
- qualquer iteravel de strings.

Isso melhora flexibilidade.

**Regra de design:** anote a interface mais geral que satisfaz o contrato, nao um tipo concreto sem necessidade.

---

## 9. `TypeAlias`

Se um tipo fica repetitivo ou representa conceito de dominio, vale nomea-lo.

```python
from typing import TypeAlias

Coordenada: TypeAlias = tuple[float, float]


def distancia(a: Coordenada, b: Coordenada) -> float:
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return (dx * dx + dy * dy) ** 0.5
```

Isso melhora legibilidade sem criar custo de runtime significativo.

---

## 10. `TypedDict`

Dicionarios soltos sao comuns em Python, mas podem ficar ambiguos.

```python
from typing import TypedDict


class Usuario(TypedDict):
    nome: str
    idade: int
    ativo: bool


def saudacao(usuario: Usuario) -> str:
    return f"Ola, {usuario['nome']}"
```

`TypedDict` ajuda a expressar estrutura esperada de dicionario.

Isso e util quando:

- voce trabalha com JSON;
- dados estruturados ainda nao viraram classe;
- quer tipar contratos de mapa com chaves fixas.

---

## 11. `Protocol`

Python tambem permite tipar por comportamento, nao apenas por classe concreta.

```python
from typing import Protocol


class TemFalar(Protocol):
    def falar(self) -> str:
        ...


def anunciar(obj: TemFalar) -> None:
    print(obj.falar())
```

Isso conversa com duck typing:

> se o objeto fornece o metodo esperado, ele satisfaz o protocolo.

- **Protocol**: contrato estrutural baseado em operacoes suportadas pelo objeto.

Isso e conceitualmente muito Pythonico.

---

## 12. Generics

Quando uma funcao ou classe deve funcionar com varios tipos preservando relacao entre entrada e saida, entramos em **generics**.

```python
from typing import TypeVar

T = TypeVar("T")


def primeiro(valores: list[T]) -> T:
    return valores[0]
```

Aqui `T` representa "algum tipo qualquer, mas o mesmo tipo se propaga na relacao".

Sem isso, seria facil cair em `Any` e perder precisao.

---

## 13. Tipagem estatica vs runtime

Um ponto central:

```python
def soma(a: int, b: int) -> int:
    return a + b


print(soma("x", "y"))
```

Esse codigo pode rodar e produzir:

```text
xy
```

porque `+` entre strings e concatenacao.

As anotacoes nao bloquearam nada em runtime.

Quem ajuda a detectar a incoerencia e a analise estatica.

Ferramentas comuns:

- `mypy`
- `pyright`
- suporte da propria IDE

---

## 14. Quando tipar e quanto tipar

Nem todo script curto precisa de tipagem pesada.

Mas tipagem tende a ser muito valiosa em:

- bibliotecas;
- backend;
- automacao de medio porte;
- sistemas com equipe;
- codigo que sofre refatoracao frequente;
- interfaces publicas.

**Regra pratica equilibrada:**

- tipar funcoes publicas;
- tipar estruturas de dados importantes;
- evitar `Any` sem necessidade;
- nao transformar tipagem em burocracia vazia.

## 15. Exemplo completo da aula

```python
from collections.abc import Iterable
from typing import Protocol, TypeAlias, TypedDict


Coordenada: TypeAlias = tuple[float, float]


class Usuario(TypedDict):
    nome: str
    cidade: str


class TemResumo(Protocol):
    def resumo(self) -> str:
        ...


class Produto:
    def __init__(self, nome: str, preco: float) -> None:
        self.nome = nome
        self.preco = preco

    def resumo(self) -> str:
        return f"{self.nome}: R$ {self.preco:.2f}"


def media(valores: Iterable[float]) -> float:
    total = 0.0
    quantidade = 0
    for valor in valores:
        total += valor
        quantidade += 1
    if quantidade == 0:
        raise ValueError("iteravel vazio")
    return total / quantidade


def distancia(a: Coordenada, b: Coordenada) -> float:
    dx = a[0] - b[0]
    dy = a[1] - b[1]
    return (dx * dx + dy * dy) ** 0.5


def imprimir_resumo(obj: TemResumo) -> None:
    print(obj.resumo())


usuario: Usuario = {"nome": "Ana", "cidade": "Recife"}
produto = Produto("Mouse", 79.9)

print(usuario["nome"])
print(media([10.0, 20.0, 30.0]))
print(distancia((0.0, 0.0), (3.0, 4.0)))
imprimir_resumo(produto)
```

### Explicacao linha por linha

- `TypeAlias`: da nome semantico a um tipo composto.
- `TypedDict`: descreve estrutura esperada de dicionario.
- `Protocol`: descreve comportamento exigido.
- `Iterable[float]`: aceita qualquer fonte iteravel de `float`.
- `-> None`: documenta funcao sem retorno util.
- as anotacoes melhoram o contrato sem remover a natureza dinamica da linguagem.

## 17. Erros Comuns e Anti-Padroes

1. **Achar que `type hints` impoem validacao automatica em runtime**.
2. **Usar `Any` em tudo** e perder o valor da tipagem.
3. **Tipar com tipo concreto demais** quando uma interface geral seria melhor.
4. **Misturar contrato real e anotacao errada**, criando falsa seguranca.
5. **Transformar codigo simples em labirinto de tipos sem ganho pratico**.
6. **Esquecer que Python continua dinamico mesmo com anotacoes**.
