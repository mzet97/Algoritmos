# Aula 21 - Banco de dados, ORMs, pooling e transacoes

Banco de dados cobra em pool, transação e isolamento o que o ORM tenta esconder. Em Python, entender a física por baixo da sessão é a diferença entre sistema correto e sistema que só funciona com um usuário.

---

## Nesta aula

Entender como backend Python conversa com banco de dados, quais problemas ORMs resolvem e criam, como pensar em pooling de conexoes, e por que transacao e parte do contrato da aplicacao. Você vai aprender a usar ORM com pooling, executar transações, tratar concorrência e retries, e prever N+1 e vazamento.

## 2. Banco nao e "uma lista mais lenta"

Banco de dados existe para:

- persistir estado;
- permitir consulta;
- controlar concorrencia;
- garantir consistencia;
- sobreviver ao fim do processo.

Quando seu backend cresce, essa camada passa a dominar varias decisoes de arquitetura.

---

## 3. ORM: o que resolve?

- **ORM**: ferramenta que mapeia tabelas e linhas para objetos Python.

Ajuda em:

- produtividade;
- composicao de consultas simples;
- organizacao do codigo;
- integracao com modelos.

Mas tambem pode esconder:

- custo de query;
- numero de round-trips;
- joins ruins;
- transacoes mal pensadas.

---

## 4. Pooling de conexoes

Abrir conexao para cada operacao custa.

Por isso, aplicacoes reais costumam usar:

- pool de conexoes.

### 4.1 O que pool faz?

- reaproveita conexoes abertas;
- limita concorrencia ate o banco;
- reduz overhead de abertura e handshake.

---

## 5. Transacao

- **Transacao**: unidade logica de trabalho que deve acontecer por inteiro ou falhar por inteiro.

Exemplo:

- debitar saldo;
- creditar destino;
- registrar historico.

Sem transacao:

- estado parcial vira bug serio.

---

## 6. Exemplo completo da aula

```python
from sqlalchemy import Integer, String, create_engine, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, sessionmaker


class Base(DeclarativeBase):
    pass


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    name: Mapped[str] = mapped_column(String(80))
    email: Mapped[str] = mapped_column(String(120), unique=True)


engine = create_engine(
    "sqlite:///app.db",
    echo=False,
    pool_pre_ping=True,
)

SessionLocal = sessionmaker(bind=engine)


def init_db() -> None:
    Base.metadata.create_all(engine)


def create_user(name: str, email: str) -> User:
    with SessionLocal() as session:
        user = User(name=name, email=email)
        session.add(user)
        session.commit()
        session.refresh(user)
        return user


def find_user_by_email(email: str) -> User | None:
    with SessionLocal() as session:
        stmt = select(User).where(User.email == email)
        return session.scalar(stmt)


def rename_user(email: str, new_name: str) -> bool:
    with SessionLocal() as session:
        stmt = select(User).where(User.email == email)
        user = session.scalar(stmt)
        if user is None:
            return False

        user.name = new_name
        session.commit()
        return True


def main() -> None:
    init_db()

    user = create_user("Ana", "ana@example.com")
    print(user.id, user.name, user.email)

    ok = rename_user("ana@example.com", "Ana Silva")
    print("rename:", ok)

    found = find_user_by_email("ana@example.com")
    if found is not None:
        print(found.id, found.name, found.email)


if __name__ == "__main__":
    main()
```

---

## 7. O que esse exemplo ensina?

### 7.1 `Session`

Representa:

- unidade de trabalho com banco.

### 7.2 `commit`

Confirma:

- mudanca persistente.

### 7.3 `select`

Explicita:

- consulta.

### 7.4 `with SessionLocal()`

Ajuda a garantir:

- fechamento previsivel da sessao.

---

## 8. ORM nao elimina SQL mental

Mesmo usando ORM, voce precisa pensar em:

- cardinalidade;
- indices;
- joins;
- N+1 queries;
- latencia;
- volume de dados.

Quem ignora isso costuma culpar "Python lento" por um problema de acesso a banco ruim.

---

## 9. Transacoes maiores

Imagine operacao com varios passos:

- criar pedido;
- reservar estoque;
- registrar auditoria.

Se um passo falha no meio, a pergunta e:

- o que deve ficar gravado?

Essa resposta define sua transacao.

---

## 10. Comparacao com C, C++ e Rust

- Em C e C++, ORMs costumam ser menos dominantes e o acesso SQL explicito aparece mais cedo.
- Em Rust, o modelo tende a explicitar mais tipos e lifetimes de conexao, mas custo de banco continua o mesmo.
- Em Python, ORMs aceleram muito desenvolvimento, mas podem incentivar cegueira de custo se usados sem disciplina.

## 12. Erros Comuns e Anti-Padroes

1. **Usar ORM sem pensar em query real**.
2. **Abrir e fechar conexao de forma ingenua para cada pequeno passo**.
3. **Misturar regra de negocio e detalhes de persistencia sem fronteira minima**.
4. **Fazer varias mudancas relacionadas sem transacao**.
5. **Achar que problema de banco e problema do framework web**.
