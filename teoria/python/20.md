# Aula 20 - APIs Web com FastAPI/ASGI e organizacao em camadas

---

## Objetivo da Aula

Entender como estruturar uma API web moderna em Python com foco em ASGI, rotas, validacao, separacao entre camada HTTP e regra de negocio, e organizacao de projeto mais profissional. Ao final, voce deve conseguir olhar para um backend Python e distinguir framework, contrato HTTP, casos de uso e infraestrutura de forma menos improvisada.

## 2. O que e ASGI?

- **ASGI**: interface padrao para aplicacoes Python assincronas, pensada para HTTP, WebSocket e integracao com event loop.

### 2.1 Por que isso existe?

Porque o modelo antigo WSGI funciona bem para muito backend classico, mas:

- nao foi desenhado para async moderno;
- nao cobre bem WebSocket;
- nao conversa tao naturalmente com concorrencia cooperativa.

### 2.2 FastAPI e a unica opcao?

Nao.

Mas ela e boa para ensino porque combina:

- tipagem;
- validacao;
- ergonomia;
- ecossistema ASGI.

---

## 3. Framework nao substitui arquitetura

Erro comum de backend Python:

- colocar regra de negocio inteira dentro da funcao de rota.

Queremos separar:

- camada HTTP;
- casos de uso;
- acesso a dados;
- configuracao.

---

## 4. Estrutura minima saudavel

Exemplo conceitual:

```text
src/
`-- app/
    |-- main.py
    |-- api.py
    |-- schemas.py
    |-- services.py
    `-- config.py
```

### 4.1 Ideia de cada parte

- `main.py`: monta a aplicacao
- `api.py`: define rotas
- `schemas.py`: modelos de entrada e saida
- `services.py`: regra de negocio
- `config.py`: leitura de configuracao

---

## 5. Validacao e contrato

Em backend, contrato importa muito.

Precisamos responder:

- o que entra?
- o que sai?
- o que e erro de cliente?
- o que e erro interno?

Em FastAPI, schemas ajudam nisso.

## 6. Exemplo completo da aula

```python
from dataclasses import dataclass
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field


@dataclass
class ItemRecord:
    item_id: int
    name: str
    quantity: int


class ItemCreate(BaseModel):
    name: str = Field(min_length=1, max_length=80)
    quantity: int = Field(ge=0, le=1_000_000)


class ItemOut(BaseModel):
    item_id: int
    name: str
    quantity: int


class InventoryService:
    def __init__(self) -> None:
        self._items: dict[int, ItemRecord] = {}
        self._next_id = 1

    def create_item(self, payload: ItemCreate) -> ItemRecord:
        record = ItemRecord(
            item_id=self._next_id,
            name=payload.name,
            quantity=payload.quantity,
        )
        self._items[record.item_id] = record
        self._next_id += 1
        return record

    def get_item(self, item_id: int) -> ItemRecord | None:
        return self._items.get(item_id)


app = FastAPI(title="inventory-service")
service = InventoryService()


@app.post("/items", response_model=ItemOut, status_code=201)
def create_item(payload: ItemCreate) -> ItemOut:
    record = service.create_item(payload)
    return ItemOut.model_validate(record.__dict__)


@app.get("/items/{item_id}", response_model=ItemOut)
def get_item(item_id: int) -> ItemOut:
    record = service.get_item(item_id)
    if record is None:
        raise HTTPException(status_code=404, detail="item not found")

    return ItemOut.model_validate(record.__dict__)
```

---

## 7. O que esse exemplo ensina?

### 7.1 `ItemCreate`

Representa:

- entrada da API.

### 7.2 `ItemOut`

Representa:

- saida publica.

### 7.3 `InventoryService`

Concentra:

- regra de negocio simples.

### 7.4 Rota

Faz apenas:

- traduzir HTTP para chamada de servico;
- devolver resposta;
- mapear erro para codigo HTTP.

---

## 8. Dependencia e estado

Neste exemplo, `service` esta em memoria.

Em sistema real, isso pode virar:

- dependencia por request;
- integracao com banco;
- cache;
- fila;
- cliente HTTP externo.

Ponto central:

- framework entrega mecanismo;
- arquitetura define fronteiras.

---

## 9. Erro do cliente vs erro interno

Se o cliente manda payload invalido:

- isso e erro de entrada.

Se o sistema falha ao acessar dependencia:

- isso e erro operacional interno.

Misturar os dois leva a API ruim.

---

## 10. Camadas sem fanatismo

Separar em camadas ajuda.

Mas excesso de camadas tambem atrapalha.

Objetivo:

- reduzir acoplamento;
- aumentar clareza;
- facilitar teste;
- nao criar cerimonia vazia.

---

## 11. Comparacao com C, C++ e Rust

- Em C e C++, muito dessa infraestrutura web vem de bibliotecas externas com mais trabalho manual de serializacao e integracao.
- Em Rust, frameworks modernos tambem exploram tipagem e async com fronteiras mais explicitas em compile time.
- Em Python, a ergonomia e muito alta, o que acelera entrega, mas aumenta o risco de esconder arquitetura ruim atras do framework.

## 13. Erros Comuns e Anti-Padroes

1. **Colocar toda a regra de negocio dentro da rota**.
2. **Misturar modelo interno com schema publico sem pensar em contrato**.
3. **Achar que framework bom resolve arquitetura sozinho**.
4. **Transformar qualquer erro em `500` sem criterio**.
5. **Deixar configuracao, dependencia externa e HTTP totalmente acoplados**.
