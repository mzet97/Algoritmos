# Aula 12 - `dataclasses`, `enum` e padroes idiomaticos

---

## Objetivo da Aula

Entender quando usar `dataclasses` para modelar dados e quando usar `Enum` para representar conjuntos fechados de valores. Aprender tambem como aplicar padroes idiomaticos de Python para deixar o codigo mais claro, menos verboso e mais facil de manter.

Ao final, você deverá: usar `dataclasses` e `enum`, aplicar padrões idiomáticos (EAFP, unpacking), e distinguir classe de dados de classe com comportamento.
Mediremos com níveis de proficiência:
- **Nível 1 — Recordar:** `definir `dataclass`, `Enum` e EAFP`;
- **Nível 2 — Aplicar:** `diagnosticar dataclass mutável como chave e corrigir com `frozen``;
- **Nível 3 — Projetar:** `projetar tipos de domínio justificando dataclass vs. classe`.

## 1. O problema do boilerplate

Quando modelamos objetos simples em Python, muitas vezes queremos so isso:

- guardar dados;
- comparar instancias;
- representar o objeto de forma legivel;
- evitar escrever codigo repetitivo.

Considere:

```python
class Ponto:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Ponto(x={self.x!r}, y={self.y!r})"
```

Isso ainda e simples, mas em classes maiores com 5, 10 ou 20 campos, comecam a surgir repeticoes.

Foi para esse tipo de caso que `dataclasses` surgiram.

---

## 2. O que e `dataclass`?

`dataclass` e um decorador da biblioteca padrao que gera automaticamente metodos comuns para classes orientadas principalmente a dados.

Exemplo:

```python
from dataclasses import dataclass


@dataclass
class Ponto:
    x: int
    y: int
```

Isso ja fornece, entre outras coisas:

- `__init__`;
- `__repr__`;
- `__eq__`.

Ou seja, voce descreve os campos e o Python gera parte do trabalho repetitivo.

---

## 3. Por que isso existe?

Porque ha uma categoria muito comum de classe cujo objetivo principal e **transportar e organizar estado**, nao encapsular comportamento complexo.

Em vez de escrever muito codigo mecanico, voce declara a estrutura.

**Comparacao:**

- em C, isso lembra usar `struct` para agrupar dados;
- em C++ moderno, pode lembrar `struct` simples com construtores gerados;
- em Rust, lembra `struct` com `derive(Debug, PartialEq)` e afins;
- em Python, `@dataclass` cobre esse espaco idiomaticamente.

---

## 4. Campos, tipos e valores padrao

```python
from dataclasses import dataclass


@dataclass
class Usuario:
    nome: str
    idade: int
    ativo: bool = True
```

Uso:

```python
u = Usuario("Ana", 30)
print(u)
```

### 4.1 Ordem importa

Campos sem valor padrao devem vir antes dos que tem valor padrao.

Isto e invalido:

```python
@dataclass
class Exemplo:
    ativo: bool = True
    nome: str
```

---

## 5. `field()` e `default_factory`

Quando um campo mutavel precisa ter valor padrao, nao faca isso:

```python
from dataclasses import dataclass


@dataclass
class TimeRuim:
    membros: list[str] = []
```

Esse problema lembra o mesmo risco de atributo mutavel compartilhado que vimos em classes comuns.

Forma correta:

```python
from dataclasses import dataclass, field


@dataclass
class Time:
    membros: list[str] = field(default_factory=list)
```

- **`default_factory`**: funcao chamada para criar um valor novo para cada instancia.

Isso evita compartilhamento acidental entre objetos.

---

## 6. `frozen=True`

Voce pode pedir uma dataclass imutavel do ponto de vista de atribuicao de campos:

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Coordenada:
    x: float
    y: float
```

Agora:

```python
c = Coordenada(1.0, 2.0)
# c.x = 10.0
```

tentara modificar algo que deve permanecer congelado.

Isso nao torna tudo magicamente "imutavel profundo", mas ja ajuda a modelar objetos de valor.

- **Objeto de valor**: entidade cujo significado principal esta nos dados que carrega, e nao em identidade mutavel unica.

---

## 7. `order=True`

Se fizer sentido comparar objetos por ordenacao:

```python
from dataclasses import dataclass


@dataclass(order=True)
class Tarefa:
    prioridade: int
    nome: str
```

Agora instancias podem ser comparadas conforme os campos declarados.

Mas use isso somente quando a ordem fizer sentido semantico.

---

## 8. `__post_init__`

As vezes precisamos validar ou derivar algo depois da geracao automatica do `__init__`.

```python
from dataclasses import dataclass


@dataclass
class Produto:
    nome: str
    preco: float

    def __post_init__(self):
        if self.preco < 0:
            raise ValueError("preco nao pode ser negativo")
```

- **`__post_init__`**: hook chamado apos a inicializacao gerada pela dataclass.

Isso permite validacao, normalizacao ou calculo complementar.

---

## 9. Quando `dataclass` nao e a melhor escolha

Nem toda classe deve virar dataclass.

Evite quando:

- a classe e principalmente comportamental;
- o estado interno e delicado e precisa de forte encapsulamento;
- ha invariantes complexas que exigem controle manual detalhado;
- a API publica nao deve expor diretamente os campos.

`dataclass` e excelente para dados bem comportados, nao para qualquer objeto indiscriminadamente.

---

## 10. O que e `Enum`?

`Enum` representa um conjunto fechado de constantes nomeadas.

Exemplo:

```python
from enum import Enum


class Status(Enum):
    PENDENTE = "pendente"
    PROCESSANDO = "processando"
    CONCLUIDO = "concluido"
```

Uso:

```python
status = Status.PENDENTE
print(status)
print(status.value)
```

---

## 11. Por que usar `Enum` em vez de strings soltas?

Sem `Enum`:

```python
status = "concluido"
```

Problemas:

- typo passa facil;
- semantica dispersa;
- dificil descobrir conjunto valido de valores;
- refatoracao pior.

Com `Enum`, o dominio fica mais explicito.

```python
status = Status.CONCLUIDO
```

Isso melhora:

- leitura;
- autocomplete;
- robustez semantica;
- manutencao.

---

## 12. `Enum`, `IntEnum` e comparacoes

### 12.1 `Enum`

Mais semantico quando voce quer identidade nomeada.

### 12.2 `IntEnum`

```python
from enum import IntEnum


class Prioridade(IntEnum):
    BAIXA = 1
    MEDIA = 2
    ALTA = 3
```

`IntEnum` integra melhor com contextos numericos, mas use apenas quando isso tiver valor real.

---

## 13. Combinando `dataclass` e `Enum`

Exemplo:

```python
from dataclasses import dataclass
from enum import Enum


class StatusPedido(Enum):
    ABERTO = "aberto"
    PAGO = "pago"
    ENVIADO = "enviado"


@dataclass
class Pedido:
    id_: int
    cliente: str
    status: StatusPedido
```

Aqui temos:

- estrutura de dados clara com dataclass;
- dominio fechado e bem nomeado com enum.

## 14. Padroes idiomaticos importantes

### 14.1 Prefira clareza a "engenharia demais"

Em Python, o melhor codigo costuma ser:

- direto;
- legivel;
- coerente com a biblioteca padrao;
- sem camadas desnecessarias.

### 14.2 Evite getters/setters sem necessidade

Se o dado pode ser publico e simples, nao complique.

### 14.3 Modele dados simples como dados simples

Se o objeto e basicamente um pacote de campos, `dataclass` pode ser melhor que escrever classe manual excessiva.

### 14.4 Use `Enum` para estados e categorias fechadas

Em vez de espalhar strings magicas.

- **String magica**: literal textual importante repetido no codigo sem centralizacao adequada.

### 14.5 Prefira nomes de dominio, nao nomes tecnicos genericos

`StatusPedido` e melhor que `StateThing`.

## 15. `asdict` e `astuple`

Dataclasses tambem podem ser convertidas:

```python
from dataclasses import asdict, astuple, dataclass


@dataclass
class Ponto:
    x: int
    y: int


p = Ponto(10, 20)
print(asdict(p))
print(astuple(p))
```

Isso ajuda em serializacao, debug e integracao.

## 16. Exemplo completo da aula

```python
from dataclasses import asdict, dataclass, field
from enum import Enum


class StatusTarefa(Enum):
    ABERTA = "aberta"
    EM_ANDAMENTO = "em_andamento"
    CONCLUIDA = "concluida"


@dataclass(order=True)
class Tarefa:
    prioridade: int
    titulo: str
    status: StatusTarefa = StatusTarefa.ABERTA
    etiquetas: list[str] = field(default_factory=list)

    def __post_init__(self):
        if self.prioridade < 1:
            raise ValueError("prioridade deve ser >= 1")


t1 = Tarefa(2, "Estudar Python", etiquetas=["curso", "tipagem"])
t2 = Tarefa(1, "Revisar codigo", status=StatusTarefa.EM_ANDAMENTO)

print(t1)
print(asdict(t1))
print(t2)
print(t2.status.value)
print(t2 < t1)
```

### Explicacao linha por linha

- `Enum`: modela conjunto fechado de estados.
- `@dataclass(order=True)`: gera metodos utilitarios e comparacao ordenada.
- `field(default_factory=list)`: cria lista nova por instancia.
- `__post_init__`: valida o estado apos a inicializacao.
- `asdict(...)`: converte dataclass em dicionario util para inspeccao ou serializacao.

## 18. Erros Comuns e Anti-Padroes

1. **Usar lista ou dict mutavel como valor padrao direto em dataclass**.
2. **Transformar qualquer classe em dataclass sem avaliar o papel dela**.
3. **Usar string solta quando o dominio pede `Enum`**.
4. **Usar `Enum` para algo que nao e conjunto fechado real**.
5. **Ignorar validacao necessaria achando que dataclass resolve semantica sozinha**.
6. **Criar modelos excessivamente abstratos para dados simples**.
