# Aula 30 - Projeto pratico: construindo um servico backend em Python

Um serviço backend completo — API, banco, fila, observabilidade — é onde os capítulos viram sistema. Projeto prático com padrão de produção, não de tutorial.

---

## Nesta aula

Integrar API, estado em memoria, configuracao, logging e testes em um pequeno backend Python. Você vai aprender a construir serviço backend completo (API, dados, observabilidade), revisar contra checklist de produção, e medir sob carga.
---

## 1. O que vamos construir?

Um servico pequeno de tarefas com:

- API HTTP;
- validacao;
- armazenamento em memoria;
- configuracao;
- logging basico;
- health check;
- testes de fluxo principal.

---

## 3. Exemplo completo da aula

```python
from dataclasses import dataclass
import logging
import os
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field


logging.basicConfig(level=logging.INFO)
logger = logging.getLogger("todo-service")


@dataclass
class Settings:
    app_name: str


def load_settings() -> Settings:
    return Settings(app_name=os.getenv("APP_NAME", "todo-service"))


class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=120)


class TaskOut(BaseModel):
    task_id: int
    title: str
    done: bool


class TaskService:
    def __init__(self) -> None:
        self._tasks: dict[int, dict] = {}
        self._next_id = 1

    def create_task(self, title: str) -> dict:
        task = {"task_id": self._next_id, "title": title, "done": False}
        self._tasks[self._next_id] = task
        self._next_id += 1
        logger.info("task_created id=%s", task["task_id"])
        return task

    def get_task(self, task_id: int) -> dict | None:
        return self._tasks.get(task_id)


settings = load_settings()
service = TaskService()
app = FastAPI(title=settings.app_name)


@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok", "app": settings.app_name}


@app.post("/tasks", response_model=TaskOut, status_code=201)
def create_task(payload: TaskCreate) -> TaskOut:
    task = service.create_task(payload.title)
    return TaskOut.model_validate(task)


@app.get("/tasks/{task_id}", response_model=TaskOut)
def get_task(task_id: int) -> TaskOut:
    task = service.get_task(task_id)
    if task is None:
        raise HTTPException(status_code=404, detail="task not found")
    return TaskOut.model_validate(task)
```

## 4. O que esse projeto consolida?

- contrato HTTP;
- schema de entrada;
- regra de negocio;
- configuracao;
- health;
- logging.

Mesmo sem banco real, a espinha dorsal ja aparece.

## 5. Teste minimo

```python
from fastapi.testclient import TestClient
from main import app


client = TestClient(app)


def test_create_and_get_task() -> None:
    response = client.post("/tasks", json={"title": "estudar"})
    assert response.status_code == 201
    task_id = response.json()["task_id"]

    response = client.get(f"/tasks/{task_id}")
    assert response.status_code == 200
    assert response.json()["title"] == "estudar"
```

## 6. Limites assumidos

Este projeto ainda nao cobre:

- persistencia: as tarefas desaparecem ao reiniciar o processo;
- banco real;
- autenticacao;
- migracao;
- sincronizacao de escrita entre threads/processos (o contador e o dicionario globais nao sao armazenamento concorrente seguro);
- fila;
- tracing distribuido.

Mas cobre o suficiente para consolidar arquitetura inicial.

## 7. Comandos exatos para executar

Criar ambiente:

```bash
python -m venv .venv
.venv\Scripts\python -m pip install fastapi uvicorn pytest httpx
```

No Linux/macOS, use `.venv/bin/python` no lugar de `.venv\Scripts\python`.

Salve os dois blocos Python acima como `main.py` e `test_api.py` no mesmo diretorio antes de executar.

Rodar servidor:

```bash
.venv\Scripts\python -m uvicorn main:app --reload --host 127.0.0.1
```

Rodar testes:

```bash
.venv\Scripts\python -m pytest test_api.py
```

## 8. Erros Comuns e Anti-Padroes

1. **Misturar configuracao, rota e negocio no mesmo bloco sem fronteira**.
2. **Nao ter health check e logs minimos**.
3. **Criar API sem teste minimo de fluxo principal**.
4. **Achar que projeto pequeno nao precisa de estrutura**.
5. **Acoplar tudo ao framework antes de consolidar servico interno**.
