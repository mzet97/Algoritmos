# Aula 16 - `async`/`await` e fundamentos de `asyncio`

---

## Objetivo da Aula

Entender o que sao coroutines, `async`/`await` e `asyncio`. Construir o modelo mental de concorrencia cooperativa em Python, compreender o papel do event loop e diferenciar `threading` de I/O assincrono. Aprender tambem quando `asyncio` realmente faz sentido.

---

## 1. Ponte com a aula anterior

Na aula anterior vimos `threading` e `multiprocessing`.

Agora vamos olhar para outra forma de concorrencia:

- nao baseada em varios processos;
- nao necessariamente baseada em varias threads de trabalho;
- fortemente orientada a tarefas I/O-bound;
- baseada em cooperacao explicita.

Essa e a base de `asyncio`.

---

## 2. O problema que `asyncio` tenta resolver

Imagine um programa que precisa:

- atender milhares de conexoes;
- fazer muitas requisicoes de rede;
- ler e escrever sockets;
- coordenar varias esperas ao mesmo tempo.

Se cada espera bloquear uma thread inteira, o custo pode crescer.

`asyncio` existe para permitir alta concorrencia de I/O com um modelo diferente:

> em vez de bloquear a thread esperando, a tarefa cede controle e volta depois.

---

## 3. O que e uma coroutine?

Uma **coroutine** e uma unidade de execucao que pode ser suspensa e retomada.

Em Python moderno, ela normalmente nasce de uma funcao definida com `async def`.

Exemplo:

```python
async def saudacao():
    print("ola")
```

Mas cuidado:

```python
resultado = saudacao()
print(resultado)
```

Isso nao executa o corpo como uma funcao normal. Em vez disso, cria um objeto de coroutine.

- **Coroutine object**: objeto que representa uma computacao assincrona ainda nao executada completamente.

---

## 4. `async def`

Quando voce escreve:

```python
async def tarefa():
    return 42
```

essa funcao:

- nao se comporta como funcao sincrona comum;
- retorna objeto awaitable quando chamada;
- precisa ser aguardada dentro de contexto assincrono ou executada por um runtime apropriado.

- **Awaitable**: objeto que pode ser aguardado com `await`.

---

## 5. `await`

`await` significa:

> suspenda esta coroutine aqui ate o resultado assincrono estar disponivel e permita que o event loop rode outras tarefas nesse meio tempo.

Exemplo:

```python
import asyncio


async def tarefa():
    print("inicio")
    await asyncio.sleep(1)
    print("fim")
```

`asyncio.sleep(1)` nao e apenas um `time.sleep(1)` com outro nome.

Diferenca crucial:

- `time.sleep(1)` bloqueia a thread;
- `await asyncio.sleep(1)` suspende a coroutine sem bloquear da mesma forma o loop de tarefas.

---

## 6. O que e o event loop?

O **event loop** e o componente que coordena execucao de tarefas assincronas.

Ele:

- agenda coroutines;
- observa quando alguma pode progredir;
- retoma a execucao no momento adequado;
- multiplexa varias esperas em poucas threads.

- **Multiplexar**: compartilhar um mesmo executor entre varias atividades intercaladas.

Modelo mental:

> o event loop e como um maestro que decide qual coroutine avanca em cada momento em que alguma fica pronta para continuar.

---

## 7. Primeiro exemplo executavel

```python
import asyncio


async def ola():
    print("antes da espera")
    await asyncio.sleep(1)
    print("depois da espera")


asyncio.run(ola())
```

`asyncio.run(...)` cria e gerencia o ciclo de vida principal do event loop para a coroutine raiz.

---

## 8. Concorrencia cooperativa

Em `asyncio`, a concorrencia e **cooperativa**.

Isso significa:

- a tarefa em execucao continua ate encontrar um ponto de suspensao;
- normalmente esse ponto aparece em `await`;
- o runtime nao interrompe arbitrariamente sua funcao Python no meio como preempcao de thread do SO.

- **Cooperativa**: cada tarefa precisa ceder controle explicitamente nos pontos adequados.

Consequencia:

Se voce escreve uma coroutine que faz trabalho pesado de CPU sem `await`, ela pode travar o progresso das outras.

---

## 9. `create_task` e concorrencia real entre coroutines

Se voce fizer:

```python
import asyncio


async def a():
    await asyncio.sleep(1)
    print("A")


async def b():
    await asyncio.sleep(1)
    print("B")
```

e rodar uma apos a outra, nao ha concorrencia util.

Forma idiomatica:

```python
import asyncio


async def a():
    await asyncio.sleep(1)
    print("A")


async def b():
    await asyncio.sleep(1)
    print("B")


async def main():
    t1 = asyncio.create_task(a())
    t2 = asyncio.create_task(b())

    await t1
    await t2


asyncio.run(main())
```

- **Task**: encapsulamento de coroutine agendada no event loop.

---

## 10. `gather`

Outro recurso comum:

```python
import asyncio


async def trabalho(nome, atraso):
    await asyncio.sleep(atraso)
    return f"{nome} terminou"


async def main():
    resultados = await asyncio.gather(
        trabalho("A", 1),
        trabalho("B", 2),
        trabalho("C", 1),
    )
    print(resultados)


asyncio.run(main())
```

`gather` espera varias operacoes awaitable e reune os resultados.

---

## 11. `asyncio` nao acelera CPU-bound

Isso precisa ficar explicitissimo.

`asyncio` e excelente para:

- sockets;
- rede;
- servicos com muitas esperas;
- coordenacao de I/O concorrente.

`asyncio` nao e solucao magica para:

- loops numericos pesados;
- compressao intensiva;
- parsing CPU-bound;
- algoritmos de alto custo em Python puro.

Para CPU-bound, geralmente voce volta a pensar em:

- `multiprocessing`;
- extensoes em C/C++;
- NumPy;
- offload especializado.

---

## 12. Bloqueio acidental

Anti-padrao comum:

```python
import asyncio
import time


async def ruim():
    time.sleep(2)
    print("terminei")
```

Apesar de ser `async def`, `time.sleep(2)` continua bloqueando.

Esse e um erro conceitual comum:

> marcar funcao como `async` nao torna tudo dentro dela automaticamente nao bloqueante.

Voce precisa usar operacoes de fato compativeis com o modelo assincrono.

---

## 13. Cancelamento e timeout

Em sistemas reais, tarefa assincrona pode precisar ser cancelada ou limitada por tempo.

Exemplo conceitual:

```python
import asyncio


async def lenta():
    await asyncio.sleep(10)


async def main():
    try:
        await asyncio.wait_for(lenta(), timeout=1)
    except asyncio.TimeoutError:
        print("tempo esgotado")


asyncio.run(main())
```

Isso e importante em backend e integracoes externas.

---

## 14. Sincronizacao em `asyncio`

Mesmo sem threads, ainda pode existir disputa logica por recursos.

`asyncio` oferece mecanismos como:

- `Lock`
- `Event`
- `Semaphore`

Exemplo conceitual:

```python
import asyncio

lock = asyncio.Lock()


async def usar_recurso():
    async with lock:
        await asyncio.sleep(1)
```

Aqui a necessidade nao e "tranca de thread", mas coordenacao entre tarefas cooperativas.

---

## 15. Comparacao com `threading`

`threading`:

- bom para I/O tambem;
- usa threads do sistema;
- pode ser mais simples em certos cenarios;
- enfrenta problemas classicos de estado compartilhado e GIL.

`asyncio`:

- excelente para alto numero de operacoes I/O concorrentes;
- exige ecossistema compativel com async;
- muda o estilo de arquitetura da aplicacao;
- favorece concorrencia cooperativa em um loop.

Nao existe vencedor universal.

## 16. Exemplo completo da aula

```python
import asyncio


async def baixar(nome: str, atraso: float) -> str:
    print(f"iniciando {nome}")
    await asyncio.sleep(atraso)
    print(f"concluindo {nome}")
    return f"{nome} pronto"


async def main() -> None:
    tarefas = [
        asyncio.create_task(baixar("arquivo_a", 1.0)),
        asyncio.create_task(baixar("arquivo_b", 2.0)),
        asyncio.create_task(baixar("arquivo_c", 1.5)),
    ]

    resultados = await asyncio.gather(*tarefas)
    print(resultados)


if __name__ == "__main__":
    asyncio.run(main())
```

### Explicacao linha por linha

- `async def baixar(...)`: define coroutine.
- `await asyncio.sleep(...)`: simula espera nao bloqueante.
- `create_task(...)`: agenda coroutines para progresso concorrente.
- `gather(...)`: aguarda todas e junta os retornos.
- `asyncio.run(...)`: executa a coroutine principal no event loop.

## 18. Erros Comuns e Anti-Padroes

1. **Achar que `async` significa automaticamente paralelo**.
2. **Usar `time.sleep()` dentro de coroutine**.
3. **Esquecer de `await` e acabar com coroutine nao executada**.
4. **Aplicar `asyncio` em carga CPU-bound esperando milagre**.
5. **Misturar ecossistema sincrono e assincrono sem ponte adequada**.
6. **Criar muitas tasks sem estrategia de cancelamento, timeout ou controle**.
7. **Nao entender que o event loop depende de pontos cooperativos de suspensao**.
