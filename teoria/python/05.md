# Aula 5 - Funcoes avancadas, argumentos, closures e decorators

Argumento padrão mutável, closure que captura a variável e não o valor, decorator que é só uma função vestida: funções avançadas em Python são onde a linguagem mostra que tudo é objeto — inclusive o comportamento.

---

## Nesta aula

Ir alem do `def` basico e dominar a parte mais expressiva das funcoes em Python: argumentos posicionais e nomeados, valores padrao, `*args`, `**kwargs`, funcoes como objetos de primeira classe, closures e decorators.

Você vai aprender a usar *args/**kwargs, escrever closures, aplicar decorators com `functools.wraps`, e prever o efeito de captura tardia (late binding).

---

## 1. Funcoes sao objetos

Em Python, funcoes nao sao apenas "subrotinas". Elas tambem sao objetos.

Isso significa que uma funcao pode:

- ser atribuida a uma variavel;
- ser passada como argumento;
- ser retornada por outra funcao;
- ser armazenada em estruturas de dados.

Esse conceito existe para permitir composicao de comportamento de forma flexivel.

### 1.1 Exemplo

```python
def saudacao(nome):
    return f"Ola, {nome}"


f = saudacao

print(f("Ana"))
```

Aqui, `f` e outro nome apontando para o mesmo objeto funcao.

**Comparacao:**

- C: isso lembra ponteiros de funcao.
- Rust: lembra passar uma `fn` ou closure.
- Python: e mais leve sintaticamente porque funcoes ja sao objetos normais.

## 2. Parametros posicionais e nomeados

### 2.1 Posicionais

```python
def apresentar(nome, idade):
    print(f"{nome} tem {idade} anos")


apresentar("Marina", 28)
```

### 2.2 Nomeados

```python
apresentar(idade=28, nome="Marina")
```

Argumentos nomeados aumentam legibilidade, especialmente quando ha muitos parametros ou varios do mesmo tipo.

## 3. Valores padrao

```python
def conectar(host, porta=5432):
    print(f"Conectando em {host}:{porta}")


conectar("localhost")
conectar("localhost", 3306)
```

Valores padrao existem para reduzir repeticao quando um parametro costuma assumir o mesmo valor na maioria das chamadas.

### 3.1 Cuidado com mutaveis como padrao

Este e um classico:

```python
def adicionar_item(item, itens=[]):
    itens.append(item)
    return itens
```

Isso e perigoso porque a lista padrao e criada **uma vez**, no momento da definicao da funcao, e depois reutilizada.

Exemplo:

```python
print(adicionar_item(1))
print(adicionar_item(2))
print(adicionar_item(3))
```

Saida:

```text
[1]
[1, 2]
[1, 2, 3]
```

Muita gente esperaria listas independentes, mas nao e o que acontece.

Forma correta:

```python
def adicionar_item(item, itens=None):
    if itens is None:
        itens = []
    itens.append(item)
    return itens
```

## 4. `*args` e `**kwargs`

### 4.1 `*args`

`*args` coleta argumentos posicionais extras em uma tupla.

```python
def somar_todos(*args):
    total = 0
    for valor in args:
        total += valor
    return total


print(somar_todos(1, 2, 3))
print(somar_todos(10, 20, 30, 40))
```

### 4.2 `**kwargs`

`**kwargs` coleta argumentos nomeados extras em um dicionario.

```python
def mostrar_config(**kwargs):
    for chave, valor in kwargs.items():
        print(f"{chave} = {valor}")


mostrar_config(host="localhost", porta=5432, ssl=True)
```

### 4.3 Desempacotamento na chamada

```python
valores = [1, 2, 3]
print(somar_todos(*valores))

config = {"host": "db.local", "porta": 3306}
mostrar_config(**config)
```

- **Desempacotamento**: expandir uma sequencia ou mapeamento em argumentos separados.

## 5. Ordem dos parametros

Exemplo mais completo:

```python
def exemplo(a, b, *args, opcao=False, **kwargs):
    print(a, b, args, opcao, kwargs)
```

Aqui temos:

- parametros posicionais obrigatorios;
- extras posicionais;
- parametro nomeado com default;
- extras nomeados.

Essa flexibilidade e poderosa, mas deve ser usada com criterio. API confusa tambem e bug de design.

## 6. Escopo lexico e closures

### 6.1 O que e closure?

Closure e uma funcao que "lembra" variaveis do escopo onde foi criada, mesmo depois que esse escopo externo aparentemente ja terminou.

Isso so faz sentido se voce entender:

- funcoes sao objetos;
- escopos podem sobreviver logicamente por causa dessas referencias.

Exemplo:

```python
def criar_multiplicador(fator):
    def multiplicar(x):
        return x * fator

    return multiplicar


dobro = criar_multiplicador(2)
triplo = criar_multiplicador(3)

print(dobro(10))
print(triplo(10))
```

`multiplicar` usa `fator`, que pertence ao escopo externo da funcao `criar_multiplicador`.

- **Escopo lexico**: nomes sao resolvidos com base na estrutura textual de onde a funcao foi definida.
- **Closure**: funcao + ambiente capturado de que ela depende.

### 6.2 `nonlocal` em closure

```python
def criar_contador():
    contador = 0

    def incrementar():
        nonlocal contador
        contador += 1
        return contador

    return incrementar


contador_a = criar_contador()
print(contador_a())
print(contador_a())
print(contador_a())
```

Sem `nonlocal`, `contador += 1` tentaria criar um binding local novo, causando erro semantico nesse contexto.

## 7. Decorators

### 7.1 O que e um decorator?

Decorator e uma funcao que recebe outra funcao e devolve uma nova funcao com comportamento adicional.

Isso existe para separar preocupacoes transversais, como:

- logging;
- medicao de tempo;
- autorizacao;
- cache;
- validacao.

### 7.2 Forma manual

```python
def logar(func):
    def wrapper():
        print("Antes")
        func()
        print("Depois")

    return wrapper


def ola():
    print("Ola!")


ola = logar(ola)
ola()
```

### 7.3 Sintaxe com `@`

```python
def logar(func):
    def wrapper():
        print("Antes")
        func()
        print("Depois")

    return wrapper


@logar
def ola():
    print("Ola!")


ola()
```

`@logar` e apenas acucar sintatico para:

```python
ola = logar(ola)
```

### 7.4 Decorator com argumentos arbitrarios

Se a funcao decorada recebe parametros, o wrapper tambem precisa aceitar:

```python
def logar(func):
    def wrapper(*args, **kwargs):
        print(f"Chamando {func.__name__}")
        resultado = func(*args, **kwargs)
        print(f"{func.__name__} terminou")
        return resultado

    return wrapper


@logar
def soma(a, b):
    return a + b


print(soma(3, 4))
```

### 7.5 Preservando metadados com `functools.wraps`

```python
from functools import wraps


def logar(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Chamando {func.__name__}")
        return func(*args, **kwargs)

    return wrapper
```

Sem `@wraps`, voce pode perder metadados como nome e docstring da funcao original.

## 8. Exemplo completo da aula

```python
from functools import wraps


def repetir(vezes):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            resultado = None
            for _ in range(vezes):
                resultado = func(*args, **kwargs)
            return resultado

        return wrapper

    return decorator


def criar_somador(base):
    def somar(valor):
        return base + valor

    return somar


@repetir(3)
def saudacao(nome):
    print(f"Ola, {nome}!")
    return nome


somar10 = criar_somador(10)
print(somar10(5))
print(somar10(20))

saudacao("Marina")
```

### Explicacao linha por linha

- `from functools import wraps`: importa utilitario para preservar metadados.
- `repetir(vezes)`: factory de decorator.
- `decorator(func)`: recebe a funcao original.
- `wrapper(*args, **kwargs)`: envolve qualquer assinatura pratica.
- `criar_somador(base)`: closure que captura `base`.
- `@repetir(3)`: substitui `saudacao` por versao decorada.

## 10. Erros Comuns e Anti-Padroes

1. **Usar lista ou dict como valor padrao de parametro**: isso causa compartilhamento inesperado entre chamadas.
2. **Usar `*args` e `**kwargs` sem necessidade**: flexibilidade excessiva pode piorar a clareza.
3. **Esquecer `return` dentro do wrapper de decorator**: isso quebra o valor original da funcao.
4. **Nao usar `functools.wraps` em decorators reais**: isso atrapalha introspeccao e ferramentas.
5. **Confundir closure com variavel global**: closure captura escopo lexico, nao "qualquer nome magico".
6. **Fazer APIs com assinatura opaca demais**: a linguagem permite, mas manutencao sofre.
