# Aula 31 - Projeto pratico: ferramenta de automacao de infraestrutura em Python

Uma ferramenta de automação de infraestrutura que outra pessoa roda em produção: idempotente, auditável e honesta quando falha. O outro rosto de Python, com padrão profissional.

---

## Nesta aula

Construir o modelo mental e a espinha dorsal de uma ferramenta de automacao de infraestrutura em Python, integrando CLI, argumentos de configuracao, subprocessos, timeout, codigos de saida e checkpoint simples. Você vai aprender a construir ferramenta de automação de infraestrutura (CLI, config, idempotência, logs), e revisar contra produção.
---

## 1. O que vamos construir?

Uma CLI que:

- recebe uma lista de arquivos;
- valida existencia;
- chama um subprocesso Python para calcular SHA-256 de cada arquivo;
- registra resultado;
- salva checkpoint simples;
- retorna codigo de saida coerente.

---

## 3. Exemplo completo da aula

```python
import argparse
import json
import subprocess
import sys
from pathlib import Path


CHECKPOINT_PATH = Path("infra_checkpoint.json")


def load_checkpoint() -> set[str]:
    if not CHECKPOINT_PATH.exists():
        return set()
    data = json.loads(CHECKPOINT_PATH.read_text(encoding="utf-8"))
    return set(data.get("processed", []))


def save_checkpoint(processed: set[str]) -> None:
    CHECKPOINT_PATH.write_text(
        json.dumps({"processed": sorted(processed)}),
        encoding="utf-8",
    )


def run_probe(path: Path, timeout_s: float) -> int:
    # O processo filho calcula o SHA-256 do arquivo recebido, em streaming.
    code = (
        "import hashlib, sys\n"
        "with open(sys.argv[1], 'rb') as source:\n"
        "    print(hashlib.file_digest(source, 'sha256').hexdigest())\n"
    )
    try:
        completed = subprocess.run(
            [sys.executable, "-c", code, str(path)],
            capture_output=True,
            text=True,
            timeout=timeout_s,
            check=False,
        )
    except subprocess.TimeoutExpired:
        print(f"[error] timeout: {path}", file=sys.stderr)
        return 1
    except OSError as exc:
        print(f"[error] nao foi possivel iniciar subprocesso: {exc}", file=sys.stderr)
        return 1
    if completed.returncode != 0:
        print(completed.stderr.strip(), file=sys.stderr)
    else:
        print(f"sha256={completed.stdout.strip()} file={path}")
    return completed.returncode


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(prog="infra-tool")
    parser.add_argument("paths", nargs="+")
    parser.add_argument("--timeout", type=float, default=2.0)
    return parser


def main(argv: list[str] | None = None) -> int:
    parser = build_parser()
    args = parser.parse_args(argv)
    if args.timeout <= 0:
        parser.error("--timeout deve ser positivo")
    processed = load_checkpoint()
    failures = 0

    for raw_path in args.paths:
        path = Path(raw_path)

        if raw_path in processed:
            print(f"[skip] already processed {raw_path}")
            continue

        if not path.is_file():
            print(f"[error] arquivo ausente ou nao regular: {raw_path}", file=sys.stderr)
            failures += 1
            continue

        code = run_probe(path, timeout_s=args.timeout)
        if code != 0:
            print(f"[error] probe failed for {raw_path}", file=sys.stderr)
            failures += 1
            continue

        processed.add(raw_path)
        save_checkpoint(processed)
        print(f"[ok] processed {raw_path}")

    return 0 if failures == 0 else 2


if __name__ == "__main__":
    raise SystemExit(main())
```

## 4. O que esse projeto consolida?

- parsing de argumentos;
- `stdout` vs `stderr`;
- subprocesso com timeout;
- checkpoint;
- codigo de saida;
- reexecucao controlada.

Esta aula é a avaliação de SO em espaço de usuário do volume (PY10): o que se avalia aqui não é sintaxe de CLI, e sim a observação do sistema operacional sem sair do espaço de usuário — processos filhos lançados e colhidos (`runner.py`), tempo e prazo (`timeout`), estado e erro (códigos de saída e `stderr`), e persistência de progresso (checkpoint). Quem conclui esta aula demonstra: lançar e supervisionar processo filho, impor prazo, ler estado de saída e retomar trabalho interrompido — o vocabulário operacional mínimo para as peças distribuídas da aula 33.

---

## 5. Por que checkpoint e util aqui?

Porque ferramenta de infraestrutura costuma:

- falhar no meio;
- ser reexecutada;
- processar muitos itens;
- precisar de rastreabilidade minima.

## 7. Comandos exatos para executar

Criar arquivos de teste:

```bash
Set-Content a.txt a
Set-Content b.txt b
```

Rodar:

```bash
python main.py a.txt b.txt
```

Reexecutar:

```bash
python main.py a.txt b.txt
```

Inspecionar checkpoint:

```bash
type infra_checkpoint.json
```

Os comandos de criacao e `type` acima usam PowerShell. No Linux/macOS, use `printf 'a\n' > a.txt`, `printf 'b\n' > b.txt` e `cat infra_checkpoint.json`. Salve o bloco Python como `main.py` antes de executar. O checkpoint usa caminhos exatamente como digitados e nao e atomico; execute uma instancia por vez neste laboratorio. Para entradas externas, valide diretorio permitido e limite de tamanho antes de processar arquivos.

O exemplo requer Python 3.11+ para `hashlib.file_digest`.

## 8. Erros Comuns e Anti-Padroes

1. **Automacao sem timeout em subprocesso**.
2. **Ferramenta sem codigo de saida coerente**.
3. **Nao separar falha de uso de falha operacional**.
4. **Nao ter checkpoint quando reexecucao e esperada**.
5. **Tratar script de infraestrutura como algo sem contrato**.
