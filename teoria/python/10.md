## 1. O que e um protocolo em Python?

Em Python, muitos comportamentos da linguagem nao dependem de heranca obrigatoria de uma classe-base especifica. Eles dependem de o objeto suportar certas operacoes esperadas.

Isso se expressa por **protocolos**.

Exemplos:

- se um objeto implementa `__len__`, ele pode responder a `len(obj)`;
- se implementa `__iter__`, pode participar de `for`;
- se implementa `__enter__` e `__exit__`, pode ser usado com `with`.

**Protocolo**, aqui, significa:

> conjunto esperado de metodos/comportamentos que permite integrar um objeto a uma parte da linguagem.

Isso conversa diretamente com duck typing.

## 2. Metodos especiais

Metodos especiais sao nomes do tipo `__algo__`, tambem chamados informalmente de **dunder methods**.

Eles nao existem para "enfeitar" a classe. Eles conectam sua classe ao runtime e a operadores da linguagem.

### 2.1 `__repr__`

Representacao mais tecnica e objetiva do objeto.

```python
class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco

    def __repr__(self):
        return f"Produto(nome={self.nome!r}, preco={self.preco!r})"


p = Produto("Teclado", 100)
print(repr(p))
```

### 2.2 `__str__`

Representacao mais amigavel para usuario.

```python
class Produto:
    def __init__(self, nome, preco):
        self.nome = nome
        self.preco = preco

    def __repr__(self):
        return f"Produto(nome={self.nome!r}, preco={self.preco!r})"

    def __str__(self):
        return f"{self.nome} - R$ {self.preco:.2f}"
```

Se `__str__` nao existir, Python pode cair para `__repr__`.

### 2.3 `__len__`

```python
class Sacola:
    def __init__(self, itens):
        self.itens = itens

    def __len__(self):
        return len(self.itens)


s = Sacola(["a", "b", "c"])
print(len(s))
```

### 2.4 `__bool__`

```python
class Conexao:
    def __init__(self, ativa):
        self.ativa = ativa

    def __bool__(self):
        return self.ativa


c1 = Conexao(True)
c2 = Conexao(False)

print(bool(c1))
print(bool(c2))
```

Isso controla como o objeto se comporta em contexto booleano.

### 2.5 `__iter__`

Se sua classe implementa `__iter__`, ela pode participar do `for`.

```python
class Caixa:
    def __init__(self, itens):
        self.itens = itens

    def __iter__(self):
        return iter(self.itens)
```

## 3. Por que isso existe?

Sem protocolos, a linguagem precisaria de mecanismos especiais para cada tipo builtin e integracao seria mais fechada.

Com protocolos:

- a linguagem fica extensivel;
- seus objetos podem se comportar como objetos nativos;
- operacoes como `len`, `for`, `with` e `print` continuam genericas.

Esse e um dos grandes poderes de Python.

## 4. Context managers

### 4.1 O problema

Considere:

```python
arquivo = open("dados.txt", "r", encoding="utf-8")
conteudo = arquivo.read()
arquivo.close()
```

Parece simples, mas e fragil.

E se:

- `read()` falhar?
- houver excecao no meio?
- o programador esquecer `close()`?

Entao surge o problema de gerenciamento de recurso.

### 4.2 O que e context manager?

Context manager e um objeto que define um contexto de uso com entrada e saida controladas.

Ele existe para garantir setup e cleanup corretos.

Uso idiomatico:

```python
with open("dados.txt", "r", encoding="utf-8") as arquivo:
    conteudo = arquivo.read()
```

Ao sair do bloco `with`, o recurso e fechado automaticamente.

---

## 5. O que o `with` faz?

Conceitualmente, algo parecido com:

```python
gerenciador = open("dados.txt", "r", encoding="utf-8")
arquivo = gerenciador.__enter__()
try:
    conteudo = arquivo.read()
finally:
    gerenciador.__exit__(...)
```

Ou seja, `with` e acucar sintatico sobre o protocolo de context manager.

Metodos centrais:

- `__enter__()`: prepara o contexto e retorna o objeto associado ao `as`.
- `__exit__(exc_type, exc, tb)`: executa limpeza ao sair do contexto.

## 6. Criando um context manager manual

```python
class Recurso:
    def __enter__(self):
        print("abrindo recurso")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("fechando recurso")


with Recurso() as r:
    print("usando recurso")
```

Saida:

```text
abrindo recurso
usando recurso
fechando recurso
```

### 6.1 `__exit__` recebe informacao de excecao

```python
class Recurso:
    def __enter__(self):
        print("abrindo")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("fechando")
        print("tipo:", exc_type)
        print("erro:", exc)
```

Se ocorrer erro dentro do `with`, `__exit__` recebe contexto sobre a excecao.

---

## 7. Suprimir ou nao a excecao

Se `__exit__` retornar `True`, a excecao pode ser considerada tratada e nao propagada.

```python
class Suprimidor:
    def __enter__(self):
        return self

    def __exit__(self, exc_type, exc, tb):
        return True


with Suprimidor():
    1 / 0

print("programa continua")
```

Isso e poderoso, mas perigoso se usado sem clareza.

**Regra pratica:** so suprima excecoes quando isso fizer parte explicita do contrato do context manager.

## 8. `contextlib`

Python tambem oferece utilitarios para criar context managers de forma mais simples.

### 8.1 `@contextmanager`

```python
from contextlib import contextmanager


@contextmanager
def recurso():
    print("abrindo")
    try:
        yield "objeto"
    finally:
        print("fechando")


with recurso() as r:
    print("usando", r)
```

Aqui, `yield` separa a parte de entrada da parte de saida.

Essa abordagem costuma ser excelente para context managers simples.

## 9. Mais protocolos uteis

### 9.1 `__contains__`

Controla operador `in`.

```python
class Colecao:
    def __init__(self, itens):
        self.itens = itens

    def __contains__(self, valor):
        return valor in self.itens


c = Colecao([1, 2, 3])
print(2 in c)
```

### 9.2 `__getitem__`

Controla indexacao com `obj[chave]`.

```python
class Sequencia:
    def __init__(self, dados):
        self.dados = dados

    def __getitem__(self, indice):
        return self.dados[indice]
```

### 9.3 `__call__`

Permite que o objeto seja chamado como funcao.

```python
class Multiplicador:
    def __init__(self, fator):
        self.fator = fator

    def __call__(self, valor):
        return valor * self.fator


dobro = Multiplicador(2)
print(dobro(10))
```

Isso torna o objeto **callable**.

- **Callable**: qualquer objeto que pode ser invocado com sintaxe de chamada `obj(...)`.

## 10. Protocolos e design de classe

Quando sua classe implementa protocolos corretos, ela fica mais natural de usar.

Compare:

```python
class CarrinhoRuim:
    def tamanho(self):
        ...
```

com:

```python
class Carrinho:
    def __len__(self):
        ...
```

No segundo caso, o objeto integra com `len(carrinho)` como qualquer container da linguagem.

Isso melhora:

- legibilidade;
- previsibilidade;
- reuso com funcoes genericas.

## 11. Exemplo completo da aula

```python
from contextlib import contextmanager


class ListaNomes:
    def __init__(self, nomes):
        self.nomes = nomes

    def __repr__(self):
        return f"ListaNomes({self.nomes!r})"

    def __str__(self):
        return ", ".join(self.nomes)

    def __len__(self):
        return len(self.nomes)

    def __iter__(self):
        return iter(self.nomes)

    def __contains__(self, nome):
        return nome in self.nomes


@contextmanager
def log_operacao(nome):
    print(f"[inicio] {nome}")
    try:
        yield
    finally:
        print(f"[fim] {nome}")


lista = ListaNomes(["Ana", "Bruno", "Carla"])
print(lista)
print(repr(lista))
print(len(lista))
print("Ana" in lista)

for nome in lista:
    print(nome)

with log_operacao("processamento"):
    print("trabalhando...")
```

### Explicacao linha por linha

- `__repr__`: representa o objeto de forma mais tecnica.
- `__str__`: representa o objeto de forma amigavel.
- `__len__`: integra com `len(...)`.
- `__iter__`: integra com `for`.
- `__contains__`: integra com `in`.
- `@contextmanager`: cria context manager via gerador.
- `yield`: separa entrada e saida do contexto.

## 13. Erros Comuns e Anti-Padroes

1. **Implementar `__repr__` sem informacao util**.
2. **Usar `with` sem entender que ele existe para cleanup garantido**.
3. **Criar context manager que engole excecoes sem documentar isso**.
4. **Inventar metodos customizados como `tamanho()` quando a linguagem ja espera `__len__`**.
5. **Implementar protocolos de forma inconsistente com a semantica esperada**.
6. **Usar context manager manual complexo quando `contextlib` resolveria melhor**.
7. **Nao perceber que protocolos fazem parte da ergonomia publica da sua classe**.
