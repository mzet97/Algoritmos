## 2. Declaracao de variaveis

Exemplos:

```c
int x = 10;
double y = 3.14;
char c = 'Z';
```

### 2.1 O que e declarar?

- **Declarar uma variavel**: informar ao compilador seu tipo e seu nome, e opcionalmente inicializa-la.

Em C, o tipo vem antes do nome.

Isso parece simples, mas define:

- quanto espaco sera reservado;
- como interpretar os bits;

## 3. Tipos inteiros e sinal

Tipos inteiros comuns:

- `char`
- `short`
- `int`
- `long`
- `long long`

Versoes sem sinal:

- `unsigned char`
- `unsigned short`
- `unsigned int`
- `unsigned long`
- `unsigned long long`

### 3.1 O que significa "sem sinal"?

Um inteiro sem sinal representa apenas valores nao negativos.

Isso muda o intervalo de representacao: com 32 bits, `int` cobre de −2 147 483 648 a 2 147 483 647, enquanto `unsigned int` cobre de 0 a 4 294 967 295 — mesma quantidade de valores, fronteira deslocada.

### 3.2 Regra importante

Nao assuma tamanhos exatos para todos esses tipos.

Assuma apenas o que o padrao e a ABI permitem.

Se precisarmos de largura exata, mais tarde usaremos tipos de `stdint.h`.

## 4. Tipos de ponto flutuante

Principais (tamanhos e limites na tabela da secao 3.3: `float` 4 bytes, `double` 8 bytes, `long double` 16 bytes aqui):

- `float`
- `double`
- `long double`

### 4.1 Ponto importante

Numeros de ponto flutuante:

- nao representam todos os reais exatamente;
- acumulam erro de arredondamento;
- exigem cuidado em comparacoes.

Exemplo conceitual:

```c
double x = 0.1 + 0.2;
```

Voce nao deve assumir que isso e exatamente `0.3` em representacao binaria. Demonstre em vez de acreditar:

```c
#include <stdio.h>

int main(void) {
    double x = 0.1 + 0.2;
    printf("x=%.17g igual-a-0.3? %d\n", x, x == 0.3);
    return 0;
}
```

```text
x=0.30000000000000004 igual-a-0.3? 0
```

`%.17g` mostra os 17 digitos significativos que um `double` carrega: nem `0.1`, nem `0.2`, nem a soma cabem exatamente em binario, e o erro aparece na 17a casa. Comparar ponto flutuante com `==` apos aritmetica e o antipadrao que esta aula proibe; igualdade de flutuante se testa por faixa (`fabs(a - b) < tol`), nunca por bit.

## 5. `char` nao e "string"

`char` representa um byte.

Frequentemente ele armazena caractere textual, mas o tipo em si nao e "texto magico".

Exemplo:

```c
char letra = 'A';
char numero_bruto = 65;
```

Nos dois casos, estamos lidando com um byte interpretado de modos diferentes. Tres qualificacoes que a versao curta escondia:

- A equivalencia entre `'A'` e 65 depende do conjunto de caracteres da **execucao**: vale em ASCII e nos conjuntos compativeis (praticamente tudo hoje), mas a linguagem nao garante ASCII em toda plataforma.
- `char` sozinho pode ser com ou sem sinal, conforme a implementacao; `signed char` e `unsigned char` sao os sabores explicitos, e os tres sao tipos distintos. `CHAR_BIT` (de `<limits.h>`) diz quantos bits ha num byte aqui.
- `'A'` e um caractere (valor inteiro); `"A"` e uma string (dois bytes: `'A'` e o terminador `'\0'`). Confundir os dois e o erro que a aula de strings vai cobrar.

Demonstracao:

```c
#include <stdio.h>
#include <limits.h>

enum { TAMANHO_DEMO = 8 };

int main(void) {
    printf("Bits por byte: %d\n", CHAR_BIT);
    printf("sizeof(char): %zu\n", sizeof(char));
    printf("Codigo de A: %d\n", 'A');
    printf("'A'==65 aqui? %d\n", 'A' == 65);
    printf("char com sinal? min=%d\n", CHAR_MIN);
    return 0;
}
```

```text
Bits por byte: 8
sizeof(char): 1
Codigo de A: 65
'A'==65 aqui? 1
char com sinal? min=-128
```

(`CHAR_MIN == -128` denuncia `char` com sinal nesta plataforma; onde `char` e sem sinal, seria 0. O programa nao afirma ASCII universal — ele mede e mostra o desta maquina.)

## 6. Constantes em C

Forma simples:

```c
const int limite = 100;
```

### 6.1 O que `const` faz?

Ele diz que aquele objeto nao deve ser modificado atraves daquele nome: `limite` e um lvalue nao modificavel. Tentar modifica-lo por conversao de ponteiro (`*(int *)&limite = 200;`) e undefined behavior — nao "um jeito de contornar", e proibicao da linguagem.

### 6.2 Quatro coisas diferentes com cara de "constante"

- **Objeto qualificado com `const`:** tem endereco, vive em memoria (ou registrador); nao serve onde a linguagem exige constante de tempo de compilacao.
- **Constante inteira de tempo de compilacao:** enumerador (`enum { TAMANHO = 100; }`) — serve em `case`, tamanho de array e onde constante integral e exigida.
- **Macro (`#define TAM 100`):** substituicao textual antes da compilacao; sem tipo, sem escopo, sem endereco.
- **Literal (`100`):** valor puro, sem nome.

A diferenca morde neste ponto exato: em C11, `const int limite` **nao** e expressao constante inteira para todos os contextos — este programa nao compila:

```c
const int limite = 100;
switch (v) {
case limite: /* erro: case label does not reduce to an integer constant */
```

O erro real do GCC e `case label does not reduce to an integer constant`. A versao correta usa o enumerador:

```c
#include <stdio.h>

enum { TAMANHO = 100 };

int main(void) {
    int v = 100;
    switch (v) {
    case TAMANHO:
        printf("cem (TAMANHO=%d)\n", TAMANHO);
        break;
    default:
        printf("outro\n");
        break;
    }
    return 0;
}
```

```text
cem (TAMANHO=100)
```

Regra pratica: `const` documenta intencao e protege leitura (APIs, buffers somente leitura); `enum` nomeia constantes inteiras de verdade; macro e ultimo recurso, para o que nem `enum` nem `const` expressam.

## 7. Operadores aritmeticos

Principais:

- `+`
- `-`
- `*`
- `/`
- `%`

Exemplo:

```c
int a = 7;
int b = 3;

printf("%d\n", a + b);
printf("%d\n", a - b);
printf("%d\n", a * b);
printf("%d\n", a / b);
printf("%d\n", a % b);
```

### 7.1 Divisao inteira

Em:

```c
7 / 3
```

com operandos inteiros, o resultado e inteiro.

Ou seja:

- resultado: `2`

Esse detalhe gera muito bug em iniciantes. O erro classico mora na atribuicao: o tipo do destino nao converte a divisao — a divisao ja aconteceu em inteiros antes de chegar ao `double`:

```c
#include <stdio.h>

int main(void) {
    int a = 7, b = 3;
    double x = a / b;
    double y = (double)a / b;
    printf("x = %.2f (divisao inteira antes da conversao)\n", x);
    printf("y = %.2f (conversao antes da divisao)\n", y);
    return 0;
}
```

```text
x = 2.00 (divisao inteira antes da conversao)
y = 2.33 (conversao antes da divisao)
```

Regra: o tipo da **operacao** e decidido pelos operandos, nao pelo destino. `(double)a` converte antes de dividir; `double x = ...` converte depois — tarde demais.

### 7.2 Operadores bit a bit (primeiro contato)

`|`, `&`, `^`, `~`, `<<`, `>>` operam bit a bit e sao o vocabulario de flags e registradores de hardware — por isso moram nesta aula, mesmo com modulo proprio mais adiante:

```c
#include <stdio.h>

int main(void) {
    unsigned int flags = 0xA5A5U;
    printf("flags=0x%X nbits=%zu\n", flags, sizeof flags * 8U);
    printf("bit0=%u bit1=%u\n", (flags >> 0) & 1U, (flags >> 1) & 1U);
    flags |= (1U << 3);
    flags &= ~(1U << 7);
    printf("apos set3/clr7: 0x%X\n", flags);
    return 0;
}
```

```text
flags=0xA5A5 nbits=32
bit0=1 bit1=0
apos set3/clr7: 0xA52D
```

Tres ideias numa saida: deslocar e mascarar le um bit (`>> n` traz o bit para a posicao 0, `& 1U` apaga o resto); `|=` liga sem tocar nos vizinhos; `&= ~` desliga sem tocar nos vizinhos. Trabalhe sempre sem sinal aqui: deslocar inteiro com sinal para a esquerda ate o bit de sinal e undefined behavior, e o primeiro contato nao precisa desse risco.

### 7.3 Conversoes implicitas: a armadilha classica

C converte operandos para um tipo comum antes de operar (promocoes e conversoes aritmeticas usuais). Na comparacao entre com sinal e sem sinal, o com sinal vira sem sinal — e negativo vira gigante:

```c
#include <stdio.h>

int main(void) {
    int a = -1;
    unsigned int b = 1U;
/* Experimento didatico: este aviso e o conteudo da aula, por isso ele e
   silenciado aqui com pragma. Em codigo real, ouca o aviso em vez de
   silencia-lo: a conversao de `a` e o bug. */
#pragma GCC diagnostic push
#pragma GCC diagnostic ignored "-Wsign-compare"
    int r = a < b;
#pragma GCC diagnostic pop
    printf("a < b vale: %d (-1 virou 4294967295)\n", r);
    return 0;
}
```

```text
a < b vale: 0 (-1 virou 4294967295)
```

Sem o pragma, o GCC avisa: `comparison of integer expressions of different signedness: 'int' and 'unsigned int' [-Wsign-compare]`. Esse aviso e o diagnostico pedindo para voce escolher: ou os dois lados sao sem sinal por decisao (e o programador prova que negativo nunca chega), ou a comparacao precisa de conversao explicita antes. Tipos sem sinal exigem cuidado redobrado exatamente porque o erro compila, roda e responde 0 com cara de resposta.

### 7.4 Overflow: indefinido contra modular

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    int maximo = INT_MAX;
    printf("Maximo: %d\n", maximo);
    /* Nao executar supondo resultado fixo: maximo + 1 e indefinido
       para int com sinal. A linha abaixo fica comentada de proposito:
       int resultado = maximo + 1; */
    printf("sem sinal: %u + 1 = %u (modular, definido)\n", UINT_MAX, UINT_MAX + 1U);
    return 0;
}
```

```text
Maximo: 2147483647
sem sinal: 4294967295 + 1 = 0 (modular, definido)
```

A diferenca e normativa, nao quantitativa: estourar `int` com sinal e undefined behavior (o compilador pode fazer qualquer coisa, inclusive o que parece "funcionar"); estourar `unsigned int` e aritmetica modular definida (volta a zero). Modelo mental honesto: inteiros de maquina nao sao inteiros da matematica — com sinal, o transbordo e proibicao; sem sinal, e volta no relogio. O comentado acima nao e preguica: executar UB "para ver o que da" ensina o comportamento de um build, nao da linguagem.

## 8. Operadores relacionais e logicos

Relacionais:

- `==`
- `!=`
- `<`
- `<=`
- `>`
- `>=`

Logicos:

- `&&`
- `||`
- `!`

### 8.1 Verdade em C

C nao tem `bool` na origem historica da linguagem como Python ou Go.

No modelo tradicional:

- `0` significa falso;
- qualquer valor diferente de `0` significa verdadeiro.

Hoje existe `_Bool` e `stdbool.h`, mas o modelo numerico ainda importa.

### 8.2 Curto-circuito: o segundo operando pode nem existir

`&&` e `||` avaliam da esquerda para a direita e param cedo: se o primeiro operando de `&&` e falso, o segundo nao e avaliado; se o primeiro de `||` e verdadeiro, idem. Isso nao e otimizacao — e semantica, e programacao defensiva depende dela:

```c
#include <stdio.h>

int main(void) {
    int divisor = 0, numerador = 10;
    if (divisor != 0 && numerador / divisor > 2) {
        printf("condicao verdadeira\n");
    } else {
        printf("divisao protegida: segundo operando nem avaliado\n");
    }
    return 0;
}
```

```text
divisao protegida: segundo operando nem avaliado
```

Se o segundo operando fosse avaliado, haveria divisao por zero. A guarda `divisor != 0 &&` antes de qualquer divisao e o idioma que esta aula instala: condicao que protege nao e estilo, e correcao.

### 8.3 Precedencia e associatividade (a tabela que evita parenteses adivinhados)

Da ligacao mais forte para a mais fraca, no que esta aula usa:

| Nivel | Operadores | Associa |
|---|---|---|
| Pos/pre | `++ --` (como expressao), chamada, `[]` | esquerda |
| Unario | `+ - ! ~` | direita |
| Multiplicativo | `* / %` | esquerda |
| Aditivo | `+ -` | esquerda |
| Deslocamento | `<< >>` | esquerda |
| Relacional | `< <= > >=` | esquerda |
| Igualdade | `== !=` | esquerda |
| E bit a bit | `&` | esquerda |
| XOR bit a bit | `^` | esquerda |
| Ou bit a bit | `\|` | esquerda |
| E logico | `&&` | esquerda |
| Ou logico | `\|\|` | esquerda |
| Atribuicao | `= += ...` | direita |

Duas linhas que mordem calouro: `==` liga mais forte que `&` (ou seja, `flags & 1 == 1` e `flags & (1 == 1)` — quase nunca o que se queria; use parenteses sempre aqui); `=` e quase o mais fraco (por isso `if (x = 5)` atribui em vez de comparar — e o compilador avisa, como a secao 10.2 mostra). Na duvida, parentese explicito: precedencia decorada e fragil, parentese e legivel.

## 9. Incremento e decremento

Exemplos:

```c
int x = 5;
x++;   /* pos-incremento */
++x;   /* pre-incremento */
x--;   /* pos-decremento */
--x;   /* pre-decremento */
```

(Nota de errata da primeira edicao: aqui aparecia `+x;`, que e apenas o operador unario positivo com resultado descartado — nao incrementa nada. Corrigido para `++x`.)

### 9.1 Pre-incremento vs pos-incremento

- `x++`: usa o valor atual e depois incrementa.
- `++x`: incrementa primeiro e depois usa o valor.

A diferenca so aparece quando o valor da expressao e usado:

```c
#include <stdio.h>

int main(void) {
    int x = 5;
    int a = x++;
    int b = ++x;
    printf("a=%d (pos: usa 5, depois x=6)\n", a);
    printf("b=%d x=%d (pre: x=7, usa 7)\n", b, x);
    return 0;
}
```

```text
a=5 (pos: usa 5, depois x=6)
b=7 x=7 (pre: x=7, usa 7)
```

Regra pratica forte:

- evite expressoes confusas com muitos incrementos no mesmo lugar;
- expressoes como `i++ + ++i` nao tem comportamento definido em C: dois efeitos colaterais no mesmo objeto sem sequenciamento. Nao e "ordem de avaliacao curiosa" — e proibicao, e o compilador pode fazer qualquer coisa.

Em C, legibilidade e seguranca mental importam muito.

### 9.2 Declarar nao e zerar

```c
int x;
```

declara sem inicializar: `x` tem valor **indeterminado** — nao necessariamente zero. Ler esse valor antes de atribuir e erro grave (em alguns casos, undefined behavior de verdade), e o compilador avisa quando consegue ver:

```text
aviso: 'x' is used uninitialized [-Wuninitialized]
```

Regra: toda variavel nasce com atribuicao na declaracao (`int x = 0;`) ate voce saber exatamente por que adiaria. "Declarar e usar depois" sem valor inicial e a fonte mais comum de lixo deterministico em programa de iniciante — lixo que muda com otimizacao, plataforma e fase da lua.

## 10. `if`, `else` e `else if`

Exemplo:

```c
if (idade < 18) {
    printf("menor\n");
} else if (idade < 60) {
    printf("adulto\n");
} else {
    printf("idoso\n");
}
```

### 10.1 Parenteses importam

Em C, a condicao de `if` vai entre parenteses.

As chaves sao fortemente recomendadas mesmo para bloco curto.

### 10.2 Atribuicao nao e comparacao

```c
int x = 10;
if (x = 5) {
    printf("Verdadeiro\n");
}
```

Isto compila: `x = 5` e uma expressao valida cujo valor e 5 (diferente de zero, logo verdadeiro) — e `x` passa a valer 5 como efeito colateral. Nao e erro de sintaxe; e logica trocada. O compilador desconfia e avisa:

```text
aviso: suggest parentheses around assignment used as truth value [-Wparentheses]
```

Regra: condicao com `=` so de proposito e com parenteses duplos `if ((x = f()))`; comparacao e sempre `==`. Aviso lido e aviso obedecido.

## 11. `switch`

Exemplo:

```c
switch (opcao) {
    case 1:
        printf("abrir\n");
        break;
    case 2:
        printf("salvar\n");
        break;
    default:
        printf("opcao invalida\n");
        break;
}
```

### 11.1 Por que `break` importa?

Sem `break`, o fluxo pode continuar no proximo `case`.

Isso se chama:

- **fallthrough**

E pode ser:

- util em casos raros;
- perigoso em casos comuns.

## 12. Loops

### 12.1 `while`

```c
int i = 0;
while (i < 3) {
    printf("%d\n", i);
    i++;
}
```

### 12.2 `for`

```c
for (int i = 0; i < 3; i++) {
    printf("%d\n", i);
}
```

### 12.3 `do ... while`

```c
int i = 0;
do {
    printf("%d\n", i);
    i++;
} while (i < 3);
```

O `do ... while` roda pelo menos uma vez.

### 12.4 `break`, `continue` e lacos aninhados

`break` sai do laco; `continue` pula para a proxima iteracao. Comparar `for` e `while` no mesmo problema mostra que a escolha e de leitura — e que condicao de parada e invariante vao escritas, nao presumidas:

```c
#include <stdio.h>

int main(void) {
    int npares = 0;
    for (int i = 0; i < 10; i++) {
        if (i % 2 != 0)
            continue;
        npares++;
    }
    printf("for: pares em [0,10): %d\n", npares);
    npares = 0;
    int i = 0;
    while (i < 10) {
        if (i % 2 == 0)
            npares++;
        i++;
    }
    printf("while: pares em [0,10): %d\n", npares);
    return 0;
}
```

```text
for: pares em [0,10): 5
while: pares em [0,10): 5
```

Invariante deste laco: ao inicio de cada iteracao, `npares` conta os pares ja vistos em `[0,i)` e `i` anda de 1 em 1 sem pular o incremento (no `while`, o `i++` e a ultima coisa do corpo — `continue` antes dele seria laco infinito). Laco aninhado segue a mesma disciplina: cada nivel com sua condicao de parada escrita e testavel separadamente.

## 13. O que acontece em memoria aqui?

Considere:

```c
int a = 10;
int b = 3;
int c = a + b;
```

Conceitualmente:

- `a`, `b` e `c` sao variaveis locais;
- tipicamente vivem na stack frame da funcao atual;
- o compilador pode usar registradores em vez de sempre gravar tudo na memoria;
- o tipo `int` define como os bits serao interpretados nas operacoes.

Isso importa porque C e linguagem onde:

- representacao e operacao andam muito proximas.

## 14. Exemplo completo da aula

Este bloco corresponde ao arquivo executavel [`exemplos/aula02.c`](exemplos/aula02.c).

```c
#include <stdio.h>

int main(void) {
    int idade = 32;
    const int limite = 18;
    double nota = 8.5;

    printf("idade = %d\n", idade);
    printf("nota = %.1f\n", nota);

    if (idade >= limite && nota >= 7.0) {
        printf("aprovado\n");
    } else {
        printf("reprovado\n");
    }

    for (int i = 0; i < 3; i++) {
        printf("i = %d\n", i);
    }

    return 0;
}
```

### 14.1 Explicacao linha por linha

- `const int limite = 18;`: constante de leitura local.
- `double nota = 8.5;`: ponto flutuante.
- `idade >= limite && nota >= 7.0`: combinacao de operadores relacionais e logicos.
- `for (int i = 0; i < 3; i++)`: loop classico com inicializacao, condicao e passo.

## 16. Comparacao com C++, Rust, Go e Python

- Em C++, o nucleo desses operadores ainda e muito parecido, mas a linguagem adiciona sobrecarga e tipos mais ricos.
- Em Rust, comparacoes e booleanos sao mais estritos, e varias ambiguidades perigosas de C desaparecem.
- Em Go, a sintaxe e mais enxuta em alguns pontos e certas armadilhas de conversao sao menos permissivas.
- Em Python, inteiros e objetos de alto nivel; em C, estamos muito mais proximos da representacao bruta.

## 17. Erros Comuns e Anti-Padroes

1. **Confundir `=` com `==`** (a secao 10.2 mostra que compila e avisa — aviso lido e aviso obedecido).
2. **Esquecer que divisao entre inteiros trunca** (e que o destino nao converte a operacao: `(double)a / b` sim, `double x = a / b` tarde demais).
3. **Assumir que `char` e sempre "texto"** (e sempre ASCII, e sempre com sinal — as tres presumidas, as tres falsas em geral).
4. **Escrever `if` sem chaves e criar bugs de manutencao**.
5. **Montar expressoes com muitos `++` e `--` desnecessariamente** (`i++ + ++i` e undefined behavior, nao "ordem curiosa").
6. **Usar `%f` ou `%d` no `printf` para o tipo errado**.
7. **Comparar com sinal contra sem sinal sem conversao explicita** (o `-Wsign-compare` e o diagnostico; a secao 7.3 mostra o 0 com cara de resposta).
8. **Ler variavel nao inicializada** ("declarar e usar depois" sem valor: lixo que muda com otimizacao).
9. **Misturar `&` com `==` sem parenteses** (`flags & 1 == 1` e `flags & (1 == 1)` — precedencia decorada e fragil).
