# Aula 13 - Estruturas de dados classicas em C

---

## Objetivo da Aula

Ao final, voce deve conseguir conectar custo assintotico, layout de memoria, localidade de cache e ownership ao desenho dessas estruturas em C.

## 2. O que queremos de uma estrutura de dados?

Em geral, queremos algum equilibrio entre:

- custo de insercao;
- custo de busca;
- custo de remocao;
- uso de memoria;
- simplicidade;
- localidade de cache.

Em C, isso sempre conversa com:

- stack ou heap;
- contiguidade de memoria;
- ponteiros;
- custo de alocacao.

---

## 3. Pilha com array

- **Pilha (stack data structure)**: estrutura LIFO, isto e, ultimo a entrar, primeiro a sair.

Implementacao simples:

```c
typedef struct {
    int *dados;
    int topo;
    int capacidade;
} Pilha;
```

Operacoes classicas:

- `push`
- `pop`
- `peek`

### 3.1 Por que array funciona bem aqui?

Porque:

- acesso ao topo e direto;
- memoria contigua;
- boa localidade;
- implementacao simples.

---

## 4. Fila circular com array

- **Fila**: estrutura FIFO, primeiro a entrar, primeiro a sair.

Implementacao comum com:

- buffer circular;
- `inicio`;
- `fim`;
- `quantidade`.

### 4.1 Por que circular?

Para reutilizar o array sem deslocar elementos o tempo todo.

---

## 5. Lista ligada

- **Lista ligada**: sequencia de nos em que cada no aponta para o proximo.

Exemplo:

```c
typedef struct No {
    int valor;
    struct No *prox;
} No;
```

### 5.1 Vantagens

- crescimento dinamico;
- insercao local simples em varios cenarios.

### 5.2 Desvantagens

- mais alocacoes;
- pior localidade de cache;
- mais ponteiros;
- mais overhead e risco de bug.

---

## 6. Array dinamico vs lista ligada

Essa comparacao e importantissima.

Array dinamico:

- melhor localidade;
- melhor para iteracao e acesso por indice;
- `realloc` pode ser muito eficiente;
- crescimento exige estrategia de capacidade.

Lista ligada:

- nao exige bloco contiguo unico grande;
- insercoes locais podem ser boas;
- custa mais em ponteiros e cache.

### 6.1 Regra pratica moderna

Muita gente superestima lista ligada e subestima array dinamico.

Em maquinas reais, cache pesa muito.

## 7. Tabela simples

Nesta aula, nao vou entrar em hash table completa de producao.

Mas e importante introduzir a ideia:

- associar chave a valor;
- reduzir custo medio de busca;
- aceitar trade-off entre memoria e velocidade.

### 7.1 Estrategia didatica

Hoje vamos manter o foco em:

- pilha;
- fila;
- lista ligada.

Porque elas expoem melhor ownership e modelo de memoria.

## 8. Exemplo 1: pilha dinamica

```c
typedef struct {
    int *dados;
    int topo;
    int capacidade;
} Pilha;
```

Operacao conceitual:

```c
int pilha_push(Pilha *p, int valor);
int pilha_pop(Pilha *p, int *valor);
```

### 8.1 Modelo mental

- `topo` aponta para a proxima posicao livre;
- `push` grava e incrementa;
- `pop` decrementa e le.

---

## 9. Exemplo 2: lista ligada simples

```c
typedef struct No {
    int valor;
    struct No *prox;
} No;
```

Insercao no inicio:

```c
No *novo = malloc(sizeof(*novo));
novo->valor = valor;
novo->prox = head;
head = novo;
```

### 9.1 O que isso mostra?

- cada no vive no heap;
- a lista e costurada por ponteiros;
- liberar a lista exige percorrer e desalocar no por no.

## 10. Exemplo completo da aula

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *dados;
    int topo;
    int capacidade;
} Pilha;

typedef struct No {
    int valor;
    struct No *prox;
} No;

int pilha_init(Pilha *p, int capacidade) {
    p->dados = malloc((size_t)capacidade * sizeof(int));
    if (p->dados == NULL) {
        return 0;
    }
    p->topo = 0;
    p->capacidade = capacidade;
    return 1;
}

void pilha_destroy(Pilha *p) {
    free(p->dados);
    p->dados = NULL;
    p->topo = 0;
    p->capacidade = 0;
}

int pilha_push(Pilha *p, int valor) {
    if (p->topo >= p->capacidade) {
        return 0;
    }
    p->dados[p->topo++] = valor;
    return 1;
}

int pilha_pop(Pilha *p, int *valor) {
    if (p->topo <= 0) {
        return 0;
    }
    p->topo--;
    *valor = p->dados[p->topo];
    return 1;
}

No *lista_push_front(No *head, int valor) {
    No *novo = malloc(sizeof(*novo));
    if (novo == NULL) {
        return head;
    }
    novo->valor = valor;
    novo->prox = head;
    return novo;
}

void lista_print(const No *head) {
    while (head != NULL) {
        printf("%d\n", head->valor);
        head = head->prox;
    }
}

void lista_destroy(No *head) {
    while (head != NULL) {
        No *prox = head->prox;
        free(head);
        head = prox;
    }
}

int main(void) {
    Pilha p;
    if (!pilha_init(&p, 4)) {
        return 1;
    }

    pilha_push(&p, 10);
    pilha_push(&p, 20);

    int valor;
    if (pilha_pop(&p, &valor)) {
        printf("pop pilha = %d\n", valor);
    }

    pilha_destroy(&p);

    No *head = NULL;
    head = lista_push_front(head, 3);
    head = lista_push_front(head, 2);
    head = lista_push_front(head, 1);
    lista_print(head);
    lista_destroy(head);

    return 0;
}
```

### 10.1 Explicacao linha por linha

- `Pilha`: usa array dinamico contiguo.
- `No`: modela lista ligada simples.
- `pilha_init`: aloca bloco unico.
- `pilha_push`: custo O(1) amortizado para esta versao fixa.
- `lista_push_front`: cria um novo no no heap.
- `lista_destroy`: percorre e libera todos os nos.

---

## 11. O que acontece em memoria?

Na pilha:

- a struct `Pilha` pode viver na stack;
- o campo `dados` aponta para bloco contiguo no heap;
- iteracao tende a ser amigavel ao cache.

Na lista ligada:

- cada no e alocado separadamente;
- os nos podem ficar espalhados no heap;
- seguir `prox` custa indirecao e pior localidade.

Esse contraste importa muito mais do que varios iniciantes imaginam.

---

## 12. Custo assintotico e custo real

Pilha por array:

- `push`: O(1)
- `pop`: O(1)

Lista ligada simples no inicio:

- inserir no inicio: O(1)
- buscar valor: O(n)

### 12.1 Mas isso nao basta

Duas estruturas com mesma complexidade assintotica podem ter comportamento real muito diferente por:

- cache;
- alocacao;
- branch prediction;
- numero de indirecoes.

## 14. Comparacao com C++, Rust, Go e Python

- Em C++, containers da STL encapsulam boa parte desses detalhes, embora custo e layout ainda importem.
- Em Rust, `Vec` e listas explicitam ownership com muito mais seguranca.
- Em Go, slices e listas do pacote padrao escondem parte da mecanica, mas nao eliminam custo real.
- Em Python, listas e dicionarios sao estruturas de alto nivel com semantica muito mais distante do layout bruto.

Em C, voce implementa a estrutura e o contrato de memoria ao mesmo tempo.

---

## 15. Erros Comuns e Anti-Padroes

1. **Escolher lista ligada por reflexo sem pensar em cache**.
2. **Nao definir ownership da estrutura claramente**.
3. **Esquecer de liberar todos os nos**.
4. **Misturar logica de estrutura com I/O e baguncar a API**.
5. **Assumir que O(1) no papel resolve performance sozinho**.
6. **Fazer `realloc` de forma insegura ao crescer array dinamico**.
