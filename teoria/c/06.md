# Aula 6 - Headers, multiplos arquivos, preprocessor, macros e organizacao de projetos

---

## Objetivo da Aula

Entender como C organiza projetos reais em multiplos arquivos, por que headers existem, o que o preprocessor faz, onde macros ajudam e onde atrapalham, e como declaracao, definicao e linkagem se conectam. Ao final, voce deve conseguir quebrar um programa em `.c` e `.h` sem confundir interface com implementacao.

## 2. O que e uma unidade de traducao?

- **Translation unit**: resultado de um arquivo `.c` depois que o preprocessor expande `#include`, macros e diretivas relacionadas.

Regra pratica:

- cada `.c` vira uma unidade de traducao;
- cada unidade e compilada separadamente;
- o linker junta tudo depois.

### 2.1 Por que isso importa?

Porque varios erros de C aparecem exatamente na fronteira entre:

- o que foi declarado;
- o que foi definido;
- o que o linker realmente encontrou.

---

## 3. Header e source file

Organizacao classica:

- `.h`: interface, tipos, macros, prototipos
- `.c`: implementacao

Exemplo:

`calculadora.h`

```c
#ifndef CALCULADORA_H
#define CALCULADORA_H

int soma(int a, int b);
int multiplica(int a, int b);

#endif
```

`calculadora.c`

```c
#include "calculadora.h"

int soma(int a, int b) {
    return a + b;
}

int multiplica(int a, int b) {
    return a * b;
}
```

`main.c`

```c
#include <stdio.h>
#include "calculadora.h"

int main(void) {
    printf("%d\n", soma(2, 3));
    printf("%d\n", multiplica(4, 5));
    return 0;
}
```

---

## 4. Por que header existe?

Porque em C o compilador precisa conhecer a assinatura correta de simbolos antes de usalos de forma segura.

Header resolve isso ao centralizar:

- prototipos;
- `structs` publicas;
- `typedefs`;
- `enums`;
- macros;
- constantes compartilhadas.

### 4.1 Modelo mental

Pense assim:

- `.h` diz "o que este modulo oferece"
- `.c` diz "como isso e implementado"

---

## 5. `#include` nao "importa modulo" como em Go ou Python

Em C, `#include` age mais como:

- copia textual do conteudo do header naquele ponto

Isso e trabalho do preprocessor, antes da compilacao real.

### 5.1 Consequencia

Se voce incluir o mesmo header varias vezes sem protecao, pode receber:

- redefinicao de tipos;
- redefinicao de macros;
- conflitos de declaracao.

---

## 6. Include guard

Exemplo:

```c
#ifndef CALCULADORA_H
#define CALCULADORA_H

int soma(int a, int b);

#endif
```

### 6.1 O que isso faz?

Evita que o conteudo do header seja processado varias vezes na mesma unidade de traducao.

### 6.2 Por que isso importa?

Porque headers podem incluir outros headers, e isso gera grafo de inclusao.

Sem guardas, o caos aparece rapido.

---

## 7. O que e o preprocessor?

- **Preprocessor**: etapa textual anterior a compilacao que processa diretivas como `#include`, `#define`, `#if`, `#ifdef`.

Ele nao entende o programa como compilador completo.

Ele faz transformacoes textuais.

### 7.1 Diretivas comuns

- `#include`
- `#define`
- `#undef`
- `#if`
- `#ifdef`
- `#ifndef`
- `#endif`

---

## 8. Macros

Exemplo:

```c
#define PI 3.141592653589793
```

ou

```c
#define QUADRADO(x) ((x) * (x))
```

### 8.1 Por que macro existe?

Historicamente para:

- constantes;
- geracao textual;
- configuracao por compilacao;
- adaptacao de plataforma;
- pequenos atalhos.

### 8.2 Por que macro e perigosa?

Porque ela nao e funcao.

Ela e substituicao textual.

Exemplo classico:

```c
#define QUADRADO(x) x * x
```

Uso:

```c
QUADRADO(1 + 2)
```

expande para:

```c
1 + 2 * 1 + 2
```

Resultado inesperado.

### 8.3 Regra pratica

Se usar macro funcional:

- parentetize tudo agressivamente.

Melhor ainda:

- prefira funcao `static inline` quando fizer sentido.

---

## 9. `static` em arquivo `.c`

Exemplo:

```c
static int helper(int x) {
    return x * 2;
}
```

### 9.1 O que isso faz?

`static` em funcao global de arquivo limita a visibilidade daquele simbolo a unidade de traducao atual.

Isso ajuda encapsulamento.

### 9.2 Regra pratica

- simbolo interno ao modulo: `static`
- simbolo parte da interface publica: declaracao no header e definicao nao `static`

---

## 10. Variaveis globais e `extern`

Exemplo:

`config.h`

```c
#ifndef CONFIG_H
#define CONFIG_H

extern int modo_debug;

#endif
```

`config.c`

```c
#include "config.h"

int modo_debug = 0;
```

### 10.1 O que `extern` comunica?

Que a definicao daquela variavel existe em outro lugar.

### 10.2 Cuidado

Globais aumentam acoplamento.

Use com criterio.

## 11. Exemplo completo da aula

Estrutura:

```text
projeto/
  main.c
  calculadora.c
  calculadora.h
```

`calculadora.h`

```c
#ifndef CALCULADORA_H
#define CALCULADORA_H

int soma(int a, int b);
int subtrai(int a, int b);

#define CALCULADORA_VERSAO 1

#endif
```

`calculadora.c`

```c
#include "calculadora.h"

static int normaliza(int x) {
    return x;
}

int soma(int a, int b) {
    return normaliza(a) + normaliza(b);
}

int subtrai(int a, int b) {
    return normaliza(a) - normaliza(b);
}
```

`main.c`

```c
#include <stdio.h>
#include "calculadora.h"

int main(void) {
    printf("versao = %d\n", CALCULADORA_VERSAO);
    printf("soma = %d\n", soma(10, 20));
    printf("subtrai = %d\n", subtrai(10, 3));
    return 0;
}
```

### 11.1 O que acontece no build?

1. `main.c` vira uma unidade de traducao.
2. `calculadora.c` vira outra unidade de traducao.
3. ambas sao compiladas em objetos.
4. o linker resolve chamadas de `soma` e `subtrai`.

---

## 12. Comandos exatos

Compilar em uma linha:

```bash
gcc -Wall -Wextra -Wpedantic -O0 -g main.c calculadora.c -o app
```

Rodar:

```bash
.\app
```

Compilar separado:

```bash
gcc -Wall -Wextra -Wpedantic -O0 -g -c main.c -o main.o
gcc -Wall -Wextra -Wpedantic -O0 -g -c calculadora.c -o calculadora.o
gcc main.o calculadora.o -o app
```

### 12.1 Por que compilar separado?

Porque isso mostra o modelo real:

- compilacao por arquivo;
- linkagem no final.

---

## 13. Exemplo de `Makefile` minimo

```make
app: main.o calculadora.o
	gcc main.o calculadora.o -o app

main.o: main.c calculadora.h
	gcc -Wall -Wextra -Wpedantic -O0 -g -c main.c -o main.o

calculadora.o: calculadora.c calculadora.h
	gcc -Wall -Wextra -Wpedantic -O0 -g -c calculadora.c -o calculadora.o
```

### 13.1 O que esse `Makefile` ensina?

- dependencias importam;
- recompilacao incremental existe;
- organizacao manual faz parte da cultura de C.

---

## 14. Comparacao com C++, Rust, Go e Python

- Em C++, headers e linkagem ainda dominam grande parte do modelo tradicional.
- Em Rust, `cargo` e o sistema de modulos escondem muito da dor textual de `#include`.
- Em Go, packages e a toolchain integram importacao, build e organizacao de modo muito mais uniforme.
- Em Python, `import` opera em nivel de modulo e runtime, nao em substituicao textual previa.

O ponto central e:

- em C, preprocessor e linkagem fazem parte do modelo mental obrigatorio.

## 15. Erros Comuns e Anti-Padroes

1. **Colocar definicoes de funcao comum dentro de header**: gera simbolos duplicados.
2. **Esquecer include guard**: gera redefinicoes.
3. **Declarar uma coisa no header e definir com assinatura diferente no `.c`**.
4. **Abusar de macro onde funcao resolveria melhor**.
5. **Expor detalhes internos no header sem necessidade**.
6. **Espalhar globais por todo o projeto**.
