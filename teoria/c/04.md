# Aula 4 - Arrays, strings em C, ponteiros e aritmetica de ponteiros

**Competencias SDD:** FND, MEM, SEC. **Pre-requisitos:** aulas 01 a 03 e a [ponte de raciocinio algoritmico](03a_raciocinio_algoritmico.md), `for`, tipos, funcoes e `sizeof`. Em Python/JavaScript, listas ou arrays informam seu comprimento e um acesso fora da faixa nao le memoria arbitraria; em C, o array cru nao verifica os limites por voce.

**Evidencia ao terminar:** executar [`exemplos/aula04.c`](exemplos/aula04.c), explicar `sizeof` antes e depois de passar um array a funcao e entregar uma rotina que percorra um buffer apenas ate seu comprimento recebido.

Blocos com uma unica declaracao ou expressao sao **trechos conceituais**, nao programas completos. O programa integral esta na secao 14.

---

## Objetivo da Aula

Ao final, voce devera: desenhar um array de 5 `int` com enderecos relativos; prever o que `sizeof` devolve antes e depois de passar o array a uma funcao; explicar por que `strlen` para no primeiro `\0`; e escrever uma rotina que percorre um buffer apenas ate o comprimento recebido, sem ler alem dele.

### Como ler esta aula (tres niveis)

- **Fundamental:** array contiguo, `&`/`*`, `valores[i] == *(valores+i)`, string com `\0`.
- **Intermediario:** `sizeof` nos dois escopos, comprimento explicito, literal imutavel.
- **Aprofundamento (opcional):** aritmetica alem do fim como UB mesmo sem dereferencia distante, e `restrict` como promessa ao otimizador (aula 10 retoma).

### Pre-teste e pos-teste da porta C2

**Pre-teste:** (1) o que `sizeof` de um array mede? (2) para onde aponta um ponteiro? (3) o que termina uma string C? **Pos-teste:** (1) por que `sizeof` muda ao passar o array a funcao? (2) desenhe `char s[]="Oi"` byte a byte com enderecos relativos; (3) onde mora o `\0` e quem garante que ele existe? Gabarito curto: pre -- (1) bytes totais do array, (2) um endereco de objeto, (3) o byte `\0`; pos -- (1) o array decai para ponteiro (mede o ponteiro), (2) `'O','i','\0'` em 3 bytes seguidos, (3) dentro do array, colocado pelo compilador na inicializacao.

Se voce entender mal esta aula, quase tudo em C fica perigoso.

Porque ela junta:

- memoria contigua;
- enderecos;
- arrays;
- strings;
- ponteiros;

Muita da fama de C vem daqui.

---

## 2. O que e um array?

- **Array**: sequencia contigua de elementos do mesmo tipo armazenados em memoria.

Exemplo:

```c
int valores[4] = {10, 20, 30, 40};
```

### 2.1 O que isso significa em memoria?

Conceitualmente:

- `valores[0]`
- `valores[1]`
- `valores[2]`
- `valores[3]`

ficam lado a lado em memoria.

Se `int` ocupar 4 bytes naquela plataforma, o array ocupa 16 bytes contiguos.

---

## 3. Indexacao

Exemplo:

```c
printf("%d\n", valores[0]);
printf("%d\n", valores[3]);
```

O indice em C comeca em `0`.

### 3.1 O que acontece por baixo?

`valores[i]` usa deslocamento a partir do primeiro elemento. O programa deve garantir `0 <= i < 4`; C nao interrompe automaticamente um acesso fora desse intervalo.

Mais adiante vamos ligar isso diretamente a ponteiros.

---

## 4. O nome do array nao e um ponteiro, mas...

Esse e um dos pontos mais famosos de C.

O nome do array:

- nao e "um ponteiro" no sentido estrito;
- mas, em muitas expressoes, decai para ponteiro para o primeiro elemento.

Exemplo:

```c
int valores[4] = {10, 20, 30, 40};
int *p = valores;
```

Aqui a expressao `valores` e convertida para `&valores[0]`. Isso nao ocorre, por exemplo, ao aplicar `sizeof valores` ou `&valores`.

### 4.1 Regra pratica

Para iniciante:

- trate arrays e ponteiros como relacionados, mas nao identicos.

Essa diferenca fica importante em:

- `sizeof`;
- declaracoes;
- funcao recebendo array;
- mutabilidade do objeto inteiro.

---

## 5. O que e um ponteiro?

- **Ponteiro**: valor usado para referenciar um objeto ou funcao; no modelo usual, representa um endereco. Um endereco numerico arbitrario nao se torna valido so por ser colocado num ponteiro.

Exemplo:

```c
int x = 42;
int *p = &x;
```

### 5.1 O que esta acontecendo?

- `x` e um inteiro;
- `&x` significa "endereco de `x`";
- `p` guarda esse endereco;
- `*p` acessa o conteudo armazenado naquele endereco.

### 5.2 Operadores fundamentais

- `&`: endereco de
- `*`: indirecao, isto e, acesso ao valor apontado

---

## 6. Leitura e escrita via ponteiro

Exemplo:

```c
int x = 42;
int *p = &x;

printf("%d\n", *p);
*p = 99;
printf("%d\n", x);
```

Aqui:

- `*p` primeiro le `x`;
- depois escreve em `x`.

---

## 7. Aritmetica de ponteiros

Exemplo:

```c
int valores[4] = {10, 20, 30, 40};
int *p = valores;
```

Agora:

```c
p + 1
```

nao significa "somar 1 byte".

Significa:

- avancar um elemento do tipo apontado.

Se `p` aponta para `int`, `p + 1` anda um elemento `int`. A aritmetica deve permanecer no mesmo array ou uma posicao apos o fim; esse ponteiro de fim pode ser comparado, mas nao desreferenciado.

### 7.1 Por que isso existe?

Porque ponteiro em C e fortemente ligado a tipo.

O tipo informa o passo da aritmetica.

---

## 8. Equivalencias importantes

Em contexto classico:

```c
valores[i]
```

equivale a:

```c
*(valores + i)
```

Isso vale quando `i` designa um elemento valido do mesmo array. O resultado fora do objeto nao ganha seguranca por usar a notacao de indice.

### 8.1 Consequencia

Indexacao de array em C e, no fundo, sintaxe sobre ponteiros.

Por isso:

- poder alto;
- risco alto.

---

## 9. `sizeof` com array e com ponteiro

Exemplo:

```c
int valores[4] = {10, 20, 30, 40};
int *p = valores;
```

Agora:

```c
sizeof(valores)
```

retorna o tamanho total do array em bytes.

Mas:

```c
sizeof(p)
```

retorna o tamanho do ponteiro, nao do array.

### 9.1 Esse erro destroi muito codigo

Em funcoes, especialmente.

Porque "receber array" geralmente vira receber ponteiro.

---

## 10. Strings em C

Em C, string nao e um objeto alto nivel.

String C classica e:

- um array de `char` terminado por byte zero

Exemplo:

```c
char nome[] = "Ana";
```

Em memoria isso vira:

- `'A'`
- `'n'`
- `'a'`
- `'\0'`

### 10.1 O que e `\0`?

- **NUL terminator**: byte zero que marca o fim da string C.

Sem ele, funcoes como `strlen` procuram alem do limite do array, produzindo comportamento indefinido. Um buffer de bytes recebido da rede nao vira string apenas por ser do tipo `char *`; antes de usar `%s` ou `strlen`, verifique se existe terminador dentro do limite conhecido.

---

## 11. String literal vs array mutavel

Exemplo 1:

```c
char nome[] = "Ana";
```

Aqui:

- `nome` e um array local inicializado com copia dos bytes da literal.

Exemplo 2:

```c
const char *p = "Ana";
```

Aqui:

- `p` aponta para string literal;
- modificar a literal tem comportamento indefinido. `const` ajuda a impedir essa tentativa na compilacao.

### 11.1 Regra pratica fortissima

Se voce quer alterar conteudo:

- use array proprio mutavel.

Nao tente modificar literal.

---

## 12. Arrays de `char` e funcoes de string

Headers comuns:

```c
#include <string.h>
```

Funcoes classicas:

- `strlen`
- `strcpy` (somente quando a capacidade do destino ja foi provada suficiente)
- `strcmp`

### 12.1 Cuidado enorme

Essas funcoes presumem string bem formada com `\0`.

Se o terminador nao existir, o programa pode ler memoria alem do buffer.

Isso e um caminho classico para bug serio.

---

## 13. Array em parametro de funcao

Trecho conceitual: o chamador precisa fornecer um ponteiro valido para pelo menos `n` inteiros; `n` nao pode ser negativo.

Exemplo:

```c
void imprime(const int valores[], size_t n) {
    for (size_t i = 0; i < n; i++) {
        printf("%d\n", valores[i]);
    }
}
```

Ou:

```c
void imprime(const int *valores, size_t n)
```

Na pratica, aqui isso vira a mesma ideia:

- ponteiro para o primeiro elemento

### 13.1 Consequencia pratica

A funcao nao sabe sozinha o tamanho do array.

Por isso quase sempre passamos:

- ponteiro/base;
- tamanho.

O chamador deve passar o comprimento real, nao a capacidade presumida. `sizeof valores` dentro dessa funcao mede um ponteiro, nao o array original.

## 14. Exemplo completo da aula

Versao compilavel em [`exemplos/aula04.c`](exemplos/aula04.c); ela usa `size_t` para comprimentos e deriva o numero de elementos com `sizeof` ainda no escopo do array.

```c
#include <stdio.h>
#include <string.h>

void imprime_array(const int *valores, size_t n);

int main(void) {
    int valores[4] = {10, 20, 30, 40};
    size_t quantidade = sizeof valores / sizeof valores[0];
    int *p = valores;

    printf("valores[0] = %d\n", valores[0]);
    printf("*(p + 2) = %d\n", *(p + 2));

    p[1] = 99;
    imprime_array(valores, quantidade);

    char nome[] = "Ana";
    printf("nome = %s\n", nome);
    printf("strlen(nome) = %zu\n", strlen(nome));

    return 0;
}

void imprime_array(const int *valores, size_t n) {
    for (size_t i = 0; i < n; i++) {
        printf("valores[%zu] = %d\n", i, valores[i]);
    }
}
```

### 14.1 Explicacao linha por linha

- `int *p = valores;`: array decai para ponteiro para o primeiro elemento.
- `*(p + 2)`: acesso por aritmetica de ponteiro.
- `p[1] = 99;`: notacao de indice sobre ponteiro.
- `char nome[] = "Ana";`: array mutavel inicializado com copia da literal.
- `strlen(nome)`: conta ate encontrar `\0`.
- `const int *valores`: a funcao promete nao modificar os inteiros apontados.

## 15. O que acontece em memoria nesse exemplo?

Para:

```c
int valores[4] = {10, 20, 30, 40};
```

conceitualmente temos um bloco contiguo:

```text
[10][20][30][40]
```

`p` guarda uma referencia ao primeiro `int`. O desenho nao representa enderecos reais, alinhamento nem registradores.

Entao:

- `p + 0` aponta para `10`
- `p + 1` aponta para `20`
- `p + 2` aponta para `30`
- `p + 3` aponta para `40`

Para:

```c
char nome[] = "Ana";
```

temos algo como:

```text
['A']['n']['a']['\0']
```

Esse `\0` e parte da representacao.

## 17. Comparacao com C++, Rust, Go e Python

- Em C++, `std::string` e containers padrao escondem muito da dor de strings C cruas.
- Em Rust, `String` e `&str` tornam invalidacoes e terminacao muito mais seguras e explicitas.
- Em Go, string e slice tem semantica de alto nivel, embora slices ainda conversem com arrays por baixo.
- Em Python, string e objeto imutavel de alto nivel; voce nao lida com terminador `\0` diretamente.

Em C, voce esta muito mais perto do buffer real.

## 18. Erros Comuns e Anti-Padroes

1. **Confundir array com ponteiro em todos os contextos**.
2. **Usar `sizeof` em ponteiro achando que mede o array inteiro**.
3. **Esquecer o `\0` em strings manuais**.
4. **Tentar modificar string literal**.
5. **Ler ou escrever fora dos limites do array**.
6. **Passar array para funcao sem passar tamanho junto**.

## 21. Criterio de aprovacao e referencias

Entregue o codigo, a saida e um desenho dos cinco elementos e seus enderecos relativos. Aprovacao exige: acesso restrito a indices `0..4`, terminador dentro do array de caracteres, comprimento passado explicitamente a funcao, nenhuma tentativa de editar literal, compilacao sem avisos e explicacao correta de `sizeof` em ambos os escopos. Teste tambem o caso `n == 0`: a funcao nao deve acessar elemento algum.

### Pesos da avaliacao

| Criterio | Peso |
|---|---|
| Buffers percorridos so ate o comprimento (nenhuma leitura alem) | 35% |
| `sizeof` nos dois escopos + `\0` explicados com desenho | 25% |
| Diagnostico (prever decaimento/literal antes de rodar) | 25% |
| Documentacao (codigo, saida, desenho com enderecos relativos) | 15% |
