# Aula 8 - Entrada e saida com `stdio.h`, arquivos, buffers e erros

---

## Objetivo da Aula

Ao final, voce devera: abrir, ler e fechar um arquivo tratando cada retorno de erro; explicar por que `fgets`+`fputs` e `fread`+`fwrite` servem a propositos diferentes; e separar `stdout` de `stderr` justificando para onde vai cada mensagem.

### Como ler esta aula (tres niveis)

- **Fundamental:** `fopen`/`fclose`, `fgets`/`fputs`, checar retorno, `stderr` para erro.
- **Intermediario:** `fread`/`fwrite`, buffering, modos de abertura.
- **Aprofundamento (opcional):** erro parcial de I/O (curto conta como falha tratada) e `setvbuf` sob medida (aula 20 retoma).

## 2. O que e `FILE *`?

- **`FILE *`**: handle opaco da biblioteca `stdio` que representa um stream.

Stream aqui significa:

- fluxo sequencial de bytes com operacoes de leitura ou escrita.

Exemplos classicos:

- `stdin`
- `stdout`
- `stderr`
- arquivo em disco

### 2.1 Por que nao operar direto em syscall desde o inicio?

Porque `stdio` oferece:

- API portavel;
- buffering;
- formatacao;
- conveniencia.

Mais tarde veremos fronteiras mais proximas do kernel.

---

## 3. Abrindo arquivo com `fopen`

Exemplo:

```c
FILE *fp = fopen("dados.txt", "r");
```

### 3.1 O que significam modos comuns?

- `"r"`: leitura
- `"w"`: escrita, truncando
- `"a"`: append
- `"rb"`: leitura binaria
- `"wb"`: escrita binaria

### 3.2 Regra pratica

Sempre cheque:

```c
if (fp == NULL) {
    /* tratar erro */
}
```

---

## 4. Fechando com `fclose`

Exemplo:

```c
fclose(fp);
```

### 4.1 Por que fechar importa?

- libera recursos;
- forca flush quando necessario;
- evita vazamento de descritores;
- conclui corretamente a operacao.

---

## 5. Leitura de linha com `fgets`

Exemplo:

```c
char linha[128];
if (fgets(linha, sizeof(linha), fp) != NULL) {
    printf("%s", linha);
}
```

### 5.1 Por que `fgets` e tao importante?

Porque:

- limita quantidade de bytes lidos;
- ajuda a evitar overflow de buffer;
- funciona bem para linha textual.

### 5.2 Cuidado

`fgets` preserva o `\n` se ele couber no buffer.

---

## 6. Escrita com `fprintf` e `fputs`

Exemplo:

```c
fprintf(fp, "idade=%d\n", 32);
fputs("linha simples\n", fp);
```

### 6.1 Quando usar cada um?

- `fprintf`: quando precisa formatar
- `fputs`: quando ja tem string pronta

---

## 7. Leitura binaria e escrita binaria

Exemplo:

```c
size_t n = fread(buffer, 1, sizeof(buffer), fp);
size_t m = fwrite(buffer, 1, n, out);
```

### 7.1 O que esses parametros significam?

- ponteiro para buffer;
- tamanho de cada item;
- quantidade de itens;
- stream.

Forma comum para bytes crus:

- item de tamanho `1`;
- quantidade igual ao total de bytes.

---

## 8. Buffering

- **Buffering**: uso de memoria intermediaria para amortizar custo de I/O.

### 8.1 Por que isso existe?

Porque chamar o sistema operacional byte a byte seria caro demais.

Buffering reduz:

- numero de chamadas caras;
- overhead por operacao.

### 8.2 Consequencia pratica

Voce nem sempre ve a escrita imediatamente.

Por isso existem:

- `fflush`;
- `fclose`.

---

## 9. `stderr` vs `stdout`

Regra pratica:

- saida normal: `stdout`
- erros e diagnosticos: `stderr`

Exemplo:

```c
fprintf(stderr, "falha ao abrir arquivo\n");
```

### 9.1 Por que separar?

Porque shell e automacao podem redirecionar:

- saida normal de um jeito;
- erros de outro.

---

## 10. Erros de I/O

Ferramentas importantes:

- `perror`
- `ferror`
- `feof`

Exemplo:

```c
if (fp == NULL) {
    perror("fopen");
    return 1;
}
```

### 10.1 `feof` nao significa "leia assim"

Anti-padrao famoso:

```c
while (!feof(fp)) {
    ...
}
```

Melhor:

- tente ler;
- teste o retorno da leitura.

---

## 11. Exemplo completo da aula

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("entrada.txt", "r");
    if (fp == NULL) {
        perror("fopen entrada.txt");
        return 1;
    }

    FILE *out = fopen("saida.txt", "w");
    if (out == NULL) {
        perror("fopen saida.txt");
        fclose(fp);
        return 1;
    }

    char linha[256];
    while (fgets(linha, sizeof(linha), fp) != NULL) {
        fprintf(out, "lido: %s", linha);
    }

    if (ferror(fp)) {
        fprintf(stderr, "erro durante leitura\n");
        fclose(fp);
        fclose(out);
        return 1;
    }

    fclose(fp);
    fclose(out);
    return 0;
}
```

### 11.1 Explicacao linha por linha

- `fopen("entrada.txt", "r")`: abre arquivo para leitura.
- `fopen("saida.txt", "w")`: cria ou trunca arquivo para escrita.
- `char linha[256]`: buffer local para leitura textual.
- `while (fgets(...) != NULL)`: loop robusto controlado pela operacao real de leitura.
- `fprintf(out, "lido: %s", linha)`: escreve no arquivo de saida.
- `ferror(fp)`: checa erro de stream.
- `fclose(...)`: fecha recursos.

---

## 12. O que acontece em memoria?

Conceitualmente:

- `FILE *fp` e `FILE *out` sao ponteiros locais na stack;
- os objetos internos de stream e buffers ficam sob controle da biblioteca padrao;
- `linha[256]` e buffer local na stack;
- cada chamada a `fgets` preenche esse buffer com bytes lidos do stream.

O ponto central:

- I/O quase nunca e "byte magico";
- e sempre fluxo de bytes entre buffers e recursos externos.

## 14. Comparacao com C++, Rust, Go e Python

- Em C++, streams e RAII reduzem parte da carga manual, embora tragam outro estilo.
- Em Rust, tipos de I/O e `Result` forcam tratamento mais explicito.
- Em Go, `io.Reader` e `io.Writer` oferecem modelo muito elegante e composicional.
- Em Python, arquivos e excecoes tornam o fluxo mais ergonomico.

Em C, o controle e mais cru:

- ponteiros;
- buffers;
- retorno de funcao;
- disciplina manual.

## 15. Erros Comuns e Anti-Padroes

1. **Nao checar retorno de `fopen`**.
2. **Usar `while (!feof(fp))`**.
3. **Esquecer `fclose`**.
4. **Usar buffer pequeno demais sem pensar em truncamento de linha**.
5. **Misturar saida normal e erro no mesmo stream sem criterio**.
6. **Assumir que escrita foi efetivamente persistida sem fechar ou flushar**.
