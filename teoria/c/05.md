# Aula 5 - Structs, unions, enums e layout de memoria

---

## Objetivo da Aula

Entender como C agrupa dados com `struct`, reaproveita a mesma area de memoria com `union`, define conjuntos nomeados de constantes com `enum`, e como tudo isso se conecta a alinhamento, padding e layout de memoria. Ao final, voce deve conseguir modelar dados compostos em C sem perder de vista a representacao fisica em memoria.

---

## 1. Ponte com a aula anterior

Na aula 4, vimos:

- arrays;
- strings C;
- ponteiros;
- aritmetica de ponteiros;
- memoria contigua.

Agora precisamos responder outra pergunta importante:

- como representar varios campos diferentes que pertencem ao mesmo objeto logico?

E aqui entram `struct`, `union` e `enum`.

---

## 2. O que e `struct`?

- **Struct**: tipo composto que agrupa varios campos possivelmente de tipos diferentes sob um unico nome.

Exemplo:

```c
struct Pessoa {
    char nome[32];
    int idade;
    double altura;
};
```

### 2.1 O que isso resolve?

Sem `struct`, voce teria que manter campos soltos:

- um array para nomes;
- outro para idades;
- outro para alturas.

Isso degrada clareza e aumenta chance de erro.

---

## 3. Criando e acessando uma `struct`

Exemplo:

```c
struct Pessoa p = {"Ana", 30, 1.68};

printf("%s\n", p.nome);
printf("%d\n", p.idade);
printf("%.2f\n", p.altura);
```

### 3.1 Operador `.`

Usamos `.` para acessar campo em objeto direto.

---

## 4. `struct` via ponteiro e operador `->`

Exemplo:

```c
struct Pessoa p = {"Ana", 30, 1.68};
struct Pessoa *pp = &p;

printf("%d\n", pp->idade);
```

`pp->idade` equivale a:

```c
(*pp).idade
```

### 4.1 Regra pratica

- objeto direto: `.`
- ponteiro para objeto: `->`

---

## 5. O que e layout de memoria?

- **Layout de memoria**: forma concreta como os campos de um tipo sao organizados em bytes na memoria.

Isso importa porque:

- afeta tamanho do objeto;
- afeta alinhamento;
- afeta performance;
- afeta interoperabilidade com disco, rede e outras linguagens.

---

## 6. Padding e alignment

Considere:

```c
struct Exemplo {
    char a;
    int b;
};
```

Muita gente acha que o tamanho sera:

- 1 byte de `char`
- 4 bytes de `int`
- total 5 bytes

Mas frequentemente nao e isso.

### 6.1 Por que?

Porque o compilador pode inserir:

- **padding**: bytes extras entre campos ou no final

para respeitar:

- **alignment**: alinhamento adequado para cada tipo

### 6.2 Por que alinhamento existe?

Porque varias arquiteturas acessam certos tipos com mais eficiencia, e as vezes com obrigacao, quando eles estao em enderecos adequadamente alinhados.

---

## 7. Ordem dos campos importa

Exemplo 1:

```c
struct A {
    char c;
    int x;
    char d;
};
```

Exemplo 2:

```c
struct B {
    int x;
    char c;
    char d;
};
```

Essas `structs` podem ter tamanhos diferentes.

### 7.1 Consequencia pratica

A ordem dos campos:

- nao e so estetica;
- pode influenciar memoria e cache;
- pode influenciar ABI e serializacao binaria.

---

## 8. O que e `union`?

- **Union**: tipo em que todos os campos compartilham a mesma area de memoria.

Exemplo:

```c
union Valor {
    int i;
    float f;
    char bytes[4];
};
```

### 8.1 Diferenca para `struct`

Em `struct`:

- cada campo tem seu proprio espaco.

Em `union`:

- os campos se sobrepoem.

### 8.2 Quando `union` faz sentido?

- interpretacao alternativa do mesmo bloco de bytes;
- economia de memoria em representacoes mutuamente exclusivas;
- interoperabilidade com protocolos ou hardware;
- implementacao de tagged union manual em C.

---

## 9. O que e `enum`?

- **Enum**: tipo enumerado que associa nomes simbolicos a valores inteiros.

Exemplo:

```c
enum Estado {
    ESTADO_OK,
    ESTADO_AVISO,
    ESTADO_ERRO
};
```

Agora voce pode escrever:

```c
enum Estado atual = ESTADO_OK;
```

### 9.1 Por que isso e melhor do que inteiros crus?

Porque nomes simbolicos:

- documentam intencao;
- reduzem magia numerica;
- melhoram leitura.

---

## 10. Exemplo completo da aula

```c
#include <stdio.h>

struct Pessoa {
    char nome[32];
    int idade;
    double altura;
};

union Valor {
    int i;
    float f;
    unsigned char bytes[4];
};

enum Estado {
    ESTADO_OK,
    ESTADO_AVISO,
    ESTADO_ERRO
};

int main(void) {
    struct Pessoa p = {"Ana", 30, 1.68};
    struct Pessoa *pp = &p;

    printf("nome = %s\n", p.nome);
    printf("idade = %d\n", pp->idade);
    printf("altura = %.2f\n", pp->altura);
    printf("sizeof(struct Pessoa) = %zu\n", sizeof(struct Pessoa));

    union Valor v;
    v.i = 0x12345678;
    printf("union como int = 0x%x\n", v.i);
    printf("primeiro byte = 0x%x\n", v.bytes[0]);

    enum Estado atual = ESTADO_AVISO;
    printf("estado = %d\n", atual);

    return 0;
}
```

### 10.1 Explicacao linha por linha

- `struct Pessoa { ... };`: define tipo composto com varios campos.
- `union Valor { ... };`: define campos sobrepostos.
- `enum Estado { ... };`: define conjunto simbolico de estados.
- `pp->idade`: acessa campo atraves de ponteiro.
- `sizeof(struct Pessoa)`: mede o tamanho real do objeto, incluindo padding se houver.
- `v.i = 0x12345678;`: escreve na area compartilhada da `union`.
- `v.bytes[0]`: le os mesmos bytes por outra interpretacao.

---

## 11. O que acontece em memoria?

### 11.1 `struct Pessoa`

Conceitualmente:

```text
[nome.........................][idade][padding?][altura]
```

O compilador pode inserir padding para alinhar `double`.

### 11.2 `union Valor`

Conceitualmente:

```text
mesmos bytes:

[ byte0 byte1 byte2 byte3 ]
```

Esses mesmos bytes podem ser lidos como:

- `int`
- `float`
- array de bytes

### 11.3 `enum`

Normalmente e representado como inteiro, embora detalhes finos possam depender de compilador e ABI.

---

## 12. `typedef` com `struct`

Forma comum em C:

```c
typedef struct {
    int x;
    int y;
} Ponto;
```

Agora voce pode escrever:

```c
Ponto p = {10, 20};
```

em vez de:

```c
struct Ponto p;
```

### 12.1 Devemos usar agora?

Por enquanto, vou te expor primeiro a forma explicita com `struct Nome`.

Ela deixa o modelo mental mais claro para iniciante.

---

## 13. Cuidados com serializacao e binario

Nunca assuma automaticamente que uma `struct` em memoria:

- pode ser enviada pela rede sem criterio;
- pode ser gravada em disco e lida igual em outra maquina;
- tem layout identico entre compiladores e plataformas.

Por que?

- padding;
- alinhamento;
- endianess;
- tamanhos de tipos;
- ABI.

Esse ponto e central em engenharia de sistemas.

## 15. Comparacao com C++, Rust, Go e Python

- Em C++, `struct` e `class` expandem muito o modelo com metodos, construtores e RAII.
- Em Rust, `struct` e `enum` sao muito mais poderosos e seguros, especialmente com pattern matching e ownership.
- Em Go, `struct` e valor composto importante, mas sem heranca classica; layout ainda importa, mas a linguagem esconde outras dores.
- Em Python, objetos e dicionarios estao muito acima desse nivel de layout manual.

Em C, `struct`, `union` e `enum` continuam extremamente proximos da representacao real.

## 16. Erros Comuns e Anti-Padroes

1. **Achar que soma dos tamanhos dos campos sempre bate com `sizeof(struct)`**.
2. **Usar `union` sem entender que os campos se sobrepoem**.
3. **Assumir layout binario fixo para rede ou disco sem criterio**.
4. **Confundir `.` com `->`**.
5. **Usar inteiros crus onde `enum` deixaria a intencao clara**.
6. **Ordenar campos sem pensar em padding e alinhamento**.
