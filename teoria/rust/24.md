# Aula 24 — HPC: Instruções SIMD Nativas (`std::simd`) e Otimização Extrema

## Nesta aula
Bem-vindo ao **Módulo 2: Computação de Alto Desempenho (HPC) e SIMD**.
Nesta aula, deixaremos o I/O assíncrono (redes, discos) de lado para focar puramente em **CPU Bound**. Vamos descer ao nível do silício e aprender a usar instruções SIMD (Single Instruction, Multiple Data) em Rust para processar múltiplos dados em um único ciclo de clock, superando em muito a performance de *loops* tradicionais.

Esta aula marca uma mudança de domínio: saímos de rede e I/O e entramos em otimização numérica e uso direto da capacidade vetorial da CPU.

Mapa mental:

- nem todo gargalo é rede; muitos sistemas morrem em cálculo puro;
- CPU moderna consegue operar sobre vetores inteiros de dados por instrução;
- o desafio não é só escrever código correto, mas organizá-lo de forma que o hardware consiga explorá-lo.

Você vai aprender a escrever kernels com `std::simd`, explicar alinhamento e layout para vetorização, prever quando o autovetorizador falha (cadeia de dependência, aliasing), e medir speedup contra a linha de base escalar.

## 1. O Modelo Mental: O que é SIMD?

### O Loop Escalar Tradicional
Imagine que você quer somar dois arrays gigantes (`A` e `B`), guardando o resultado em `C`.
O código clássico (Escalar) faz o seguinte:
```rust
for i in 0..1000 {
    c[i] = a[i] + b[i]; // A CPU soma 1 número por ciclo
}
```
A CPU busca `a[0]` e `b[0]`, passa pela ALU (Unidade Lógica Aritmética) e guarda em `c[0]`. Depois repete para `1`. Isso leva 1000 ciclos (simplificando muito).

- **Escalar**: modelo em que cada instrução trabalha com um elemento por vez.
- **ALU**: unidade da CPU responsável por operações aritméticas e lógicas básicas.

### O Poder do SIMD (Vetorização)
Processadores modernos (x86, ARM) possuem registradores especiais muito largos (128 bits, 256 bits, até 512 bits). 
Em vez de somar número por número, você pode empacotar quatro inteiros de 32 bits (4 * 32 = 128) dentro de um único registrador e comandar a CPU a somar os quatro simultaneamente usando uma única instrução de hardware (como `paddd` no SSE2 da Intel).
O mesmo loop de 1000 repetições passa a ser executado em 250 ciclos. **Um aumento de 4x na performance (teórica) da noite para o dia!**

- **SIMD** significa *Single Instruction, Multiple Data*: uma instrução, vários elementos de dados ao mesmo tempo.
- **Vetorização** é o processo de reestruturar a computação para explorar esse paralelismo de dados.

## 2. SIMD em C/C++ vs Rust

Em C/C++, para usar SIMD, você costuma recorrer a *intrinsics* (funções mapeadas diretamente para instruções em assembly), como as do header `<immintrin.h>`.

- **Intrinsic**: função especial fornecida pelo compilador que representa quase diretamente uma instrução de CPU.
- Isso oferece controle fino, mas costuma sacrificar portabilidade e ergonomia.
Exemplo em C++ (Intel AVX):
```cpp
__m256 a = _mm256_loadu_ps(arr1);
__m256 b = _mm256_loadu_ps(arr2);
__m256 c = _mm256_add_ps(a, b);
_mm256_storeu_ps(res, c);
```
**O Problema em C/C++:**
1. O código não é portável! Se você compilar isso para um Mac M1 (arquitetura ARM com Neon), o código nem compila.
2. É extremamente feio e suscetível a erros de alinhamento de memória (Segmentation Faults).

**A Solução em Rust: `std::simd` (Portable SIMD)**
Rust introduziu um módulo SIMD *portátil*. Você escreve a lógica de vetorização de alto nível, e o compilador (LLVM) traduz para a melhor instrução disponível na máquina alvo (AVX512 no PC moderno, Neon no ARM/Apple Silicon), sem que você mude uma linha de código.

- **Portable SIMD**: API vetorial que descreve a intenção em nível mais alto, deixando o backend escolher as instruções adequadas da arquitetura alvo.
- Isso é importante porque separa "quero processar 8 floats juntos" de "qual instrução exata meu processador usa para isso".

## 3. O Código Prático: Somando Milhões de Elementos

*Nota: Atualmente (2024), `std::simd` requer a versão *Nightly* do Rust. Para acompanhar, configure o diretório para nightly rodando `rustup override set nightly`.*

- **Nightly**: canal experimental do Rust com recursos ainda não estabilizados.
- Usar nightly significa ganhar acesso a funcionalidades novas, mas com menor garantia de estabilidade de interface.

### Setup Inicial

```bash
cargo new simd_rust
cd simd_rust
rustup override set nightly
```

### O Código (`src/main.rs`)

```rust
// Habilita a feature experimental SIMD portátil na biblioteca padrão
#![feature(portable_simd)]

use std::simd::f32x8; // Um vetor que comporta 8 floats (32-bit * 8 = 256 bits)
use std::time::Instant;

// 1. A Abordagem Escalar (Normal)
fn soma_escalar(a: &[f32], b: &[f32], c: &mut [f32]) {
    for i in 0..a.len() {
        c[i] = a[i] + b[i];
    }
}

// 2. A Abordagem SIMD Explícita
fn soma_simd(a: &[f32], b: &[f32], c: &mut [f32]) {
    // Definimos o "chunk_size" como 8 (porque usamos f32x8).
    // O array pode ter 1003 elementos. Vamos processar de 8 em 8 (1000 elementos).
    // Os 3 restantes terão que ser processados no método escalar (remainder).
    
    let (chunks_a, remainder_a) = a.as_chunks::<8>();
    let (chunks_b, remainder_b) = b.as_chunks::<8>();
    let (chunks_c, remainder_c) = c.as_chunks_mut::<8>();

    // Processamento Massivo Simultâneo (A Mágica)
    // O LLVM vai emitir instruções AVX ou Neon aqui!
    for i in 0..chunks_a.len() {
        // Carrega 8 floats de uma vez para os registradores
        let vec_a = f32x8::from_array(chunks_a[i]);
        let vec_b = f32x8::from_array(chunks_b[i]);
        
        // Executa 8 somas simultâneas no hardware!
        let vec_c = vec_a + vec_b;
        
        // Salva os 8 floats de volta na memória
        chunks_c[i] = vec_c.to_array();
    }

    // Processa a "sobra" (os últimos elementos que não fecharam o pacote de 8)
    for i in 0..remainder_a.len() {
        remainder_c[i] = remainder_a[i] + remainder_b[i];
    }
}

fn main() {
    // Vamos somar 10 milhões de floats
    let size = 10_000_000;
    
    // Alocando no heap (Stack overflow se tentar colocar 10M de floats na stack)
    let a = vec![1.0; size];
    let b = vec![2.0; size];
    let mut c_escalar = vec![0.0; size];
    let mut c_simd = vec![0.0; size];

    // Benchmark Escalar
    let start = Instant::now();
    soma_escalar(&a, &b, &mut c_escalar);
    let duracao_escalar = start.elapsed();

    // Benchmark SIMD
    let start = Instant::now();
    soma_simd(&a, &b, &mut c_simd);
    let duracao_simd = start.elapsed();

    // Verifica se os resultados batem
    assert_eq!(c_escalar[0], c_simd[0]);

    println!("Tempo Escalar: {:?}", duracao_escalar);
    println!("Tempo SIMD:    {:?}", duracao_simd);
    
    // O ganho pode variar. Em release mode (onde a CPU ativa cache de forma agressiva),
    // o SIMD tende a ser de 2x a 4x mais rápido, mas fica limitado pela velocidade 
    // de buscar os dados da memória RAM (Memory Bound).
}
```

- **Chunk**: bloco fixo de elementos processado em grupo.
- **Remainder**: sobra de elementos que não fecha exatamente o tamanho do vetor SIMD.
- Essas duas partes existem porque o tamanho total do array raramente é múltiplo exato da largura vetorial.

## 4. Auto-Vectorization (A Ajuda Invisível do Compilador)

Você deve estar se perguntando: *"Mas professor, em `soma_escalar`, o LLVM não é inteligente o suficiente para aplicar SIMD sozinho?"*

Sim, ele é! Isso se chama **Auto-Vectorization**. 
Se você compilar o código usando `cargo run --release`, o compilador Rust/LLVM tentará transformar seu loop for simples em instruções SIMD automaticamente.

- **Auto-vectorization**: otimização em que o compilador detecta loops apropriados e gera código vetorial sozinho.
- Isso funciona muito bem em casos simples, mas não é garantido em toda situação.

**Por que escrever SIMD explícito então?**
1. O LLVM só auto-vetoriza loops simples. Se houver um `if` dentro do loop, conversão de tipos, ou se houver dúvida se `c` pode estar apontando para o mesmo lugar na memória que `a` (aliasing), o compilador desiste e volta para o escalar.
2. Ao escrever usando `std::simd`, você **força** e **garante** a vetorização. O compilador obedece sua ordem sem hesitar.

- **Aliasing**: possibilidade de dois ponteiros ou referências apontarem para a mesma região de memória.
- Quando o compilador suspeita de aliasing perigoso, ele pode recuar e escolher código mais conservador.

## 5. Passando Flags para o Hardware (Target CPU)

Para extrair poder máximo, você deve dizer ao compilador em qual CPU o código vai rodar. Se você compila um programa normalmente em Rust, ele não usa as instruções AVX512 (mesmo que sua máquina suporte), porque ele tenta gerar um binário que rode em qualquer computador antigo de 15 anos atrás.

Para compilar usando **todas as instruções do SEU hardware atual**:
```bash
# A flag 'target-cpu=native' diz ao LLVM:
# "Eu não ligo se não rodar no PC do vizinho. Compile usando as instruções
# extremas que existem no meu processador agora."
RUSTFLAGS="-C target-cpu=native" cargo run --release
```

- **`target-cpu=native`**: instrução para o compilador gerar código otimizado especificamente para a CPU da máquina atual.
- Isso melhora performance local, mas reduz portabilidade binária para máquinas mais antigas ou diferentes.

## Erros Comuns e Anti-Padrões

1.  **Ignorar o Gargalo de Memória (Memory Wall):** Não adianta sua CPU somar números 8x mais rápido se os dados não chegam rápido o suficiente da memória RAM para os registradores. SIMD brilha intensamente quando você tem muito processamento matemático sobre os mesmos dados (ex: multiplicação de matrizes ou criptografia).
2.  **Esquecer de processar o *Remainder* (a sobra):** Dividir arrays em *chunks* de 8 exige que você trate manualmente os últimos elementos caso o tamanho não seja divisível por 8. O uso da API `as_chunks` ajuda, mas é fácil errar a lógica do resto em linguagens como C. O Rust te entrega a "sobra" de forma segura.
3.  **Fazer Benchmark em modo Debug:** Código SIMD em modo `debug` (`cargo run` sem `--release`) pode rodar *mais devagar* que o código escalar, porque o LLVM não aplica as otimizações de *inlining* e as instruções viram chamadas de função pesadas.

- **Memory Wall**: limite prático em que a velocidade da memória passa a dominar mais do que a velocidade bruta de cálculo da CPU.
- Ou seja, nem todo problema acelera só porque você vetorizou; às vezes o verdadeiro gargalo é alimentar os registradores com dados.

## Exercícios Obrigatórios

1.  **Multiplicação de Array:** Modifique o código da aula para calcular `c[i] = a[i] * b[i]`. Use `f32x8` ou tente usar `f64x4` (floats de 64 bits em pacotes de 4).
2.  **Achar o Máximo em um Array:** Um desafio clássico. Escreva uma função que encontre o maior número de um array muito grande. No loop escalar você usaria um `if arr[i] > max`. Em SIMD, use o método `.simd_max()` presente no vetor para extrair o máximo de 8 números por vez, acumulando em um único `f32x8`, e no final, extraia o maior valor do próprio pacote de 8.
3.  **Assembly Check:** Use o site `godbolt.org` (Compiler Explorer), coloque a função `soma_simd` lá, escolha a linguagem Rust, adicione a flag `-C target-cpu=native -O` e olhe o assembly gerado. Tente identificar a instrução `vaddps` (Vector Add Packed Single).
