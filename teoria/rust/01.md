- **Nível 3 — Projetar:** `organizar um binário pequeno em funções e módulos, justificando quando usar `mut``.

## 1. O que é Rust?

Rust é uma linguagem de sistemas criada pela Mozilla (primeira versão estável em 2015) com três pilares:

1. **Segurança de memória** — sem garbage collector, com referências seguras não nulas e proteção contra uso após liberação e data races em código seguro. Ponteiros brutos e FFI exigem cuidado adicional; Rust não promete ausência de vazamentos de memória.

Para a diferença entre segurança de memória e vazamento, consulte [The Rust Programming Language: Reference Cycles Can Leak Memory](https://doc.rust-lang.org/book/ch15-06-reference-cycles.html).
2. **Concorrência sem medo** (*fearless concurrency*) — o mesmo sistema que garante segurança de memória também impede data races em tempo de compilação.
3. **Zero-cost abstractions** — abstrações de alto nível (iterators, traits, closures) que não adicionam custo em runtime. Se você não usa, não paga.

Como esta é a primeira vez que esses termos aparecem, vamos defini-los com precisão:

- **Linguagem de sistemas**: é uma linguagem usada para escrever software próximo do hardware ou da infraestrutura central do sistema, como servidores de alta performance, bancos de dados, runtimes, drivers, sistemas operacionais e bibliotecas de baixo nível.
- **Segurança de memória**: significa impedir bugs como acessar memória já liberada, ler um ponteiro inválido, escrever fora dos limites corretos ou ter acessos concorrentes inseguros ao mesmo dado.
- **Garbage collector (GC)**: é um mecanismo de runtime que rastreia objetos que não estão mais em uso e libera sua memória automaticamente. Isso simplifica a vida do programador, mas consome CPU, memória e pode introduzir pausas.
- **Null pointer**: ponteiro que não aponta para nenhum dado válido. Em C/C++, desreferenciar `NULL` ou `nullptr` costuma causar crash, normalmente um segmentation fault.
- **Use-after-free**: usar um dado depois que sua memória já foi liberada.
- **Data race**: duas execuções acessam o mesmo dado ao mesmo tempo, sendo que pelo menos uma escreve, sem sincronização correta.
- **Borrow checker**: parte do compilador de Rust que analisa ownership, borrowing e lifetimes para provar, em tempo de compilação, que esses bugs não ocorrerão em código safe.
- **Zero-cost abstractions**: recursos de alto nível que melhoram a expressividade do código sem impor custo extra obrigatório em runtime. A ideia é: a abstração melhora o código-fonte, mas o binário final continua tão eficiente quanto uma versão manual equivalente.

Por que isso existe? Porque Rust quer ocupar o espaço de C/C++ em software crítico sem herdar as classes clássicas de bugs de memória dessas linguagens.

**Comparação com C/C++:**

| Conceito | C/C++ | Rust |
|----------|-------|------|
| Gerenciamento de memória | Manual (malloc/free, new/delete) | Ownership + Borrowing (compilador enforce) |
| Null pointers | `NULL` / `nullptr` podem ser desreferenciados indevidamente | Referências seguras não são nulas; ponteiros brutos podem ser nulos; ausência de valor usa `Option<T>` |
| Use-after-free | Pode causar UB | Código seguro impede; FFI e `unsafe` exigem invariantes explícitas |
| Data races | Comum, UB | Impossível em código safe |
| Exceções | `try/catch` (C++) | `Result<T, E>` e `Option<T>` |
| Garbage collector | Não (C), não (C++) | Não |
| Headers | `.h` / `.hpp` | Módulos nativos |

Rust ocupa o mesmo nicho de C e C++: sistemas operacionais, drivers, motores de jogos, runtimes, compiladores, rede de alta performance, criptografia, WebAssembly. Mas com garantias de segurança que C/C++ não oferecem.

Quando dizemos que Rust ocupa o mesmo nicho de C/C++, queremos dizer que ele foi desenhado para o tipo de software em que:

- desempenho importa de verdade;
- previsibilidade de memória importa;
- latência importa;
- e o programador precisa controlar a representação dos dados com precisão.

## 2. Instalação

### 2.1 Instalar Rust via rustup

`rustup` é o gerenciador de toolchain Rust (equivalente ao que `nvm` é para Node.js).

Aqui aparecem dois termos importantes:

- **Toolchain**: é o conjunto de ferramentas usado para desenvolver em uma linguagem. No caso de Rust, inclui compilador, gerenciador de pacotes, formatador, linter e componentes auxiliares.
- **Gerenciador de toolchain**: programa que instala, atualiza e alterna versões dessas ferramentas. Isso é importante porque versões diferentes do compilador podem habilitar recursos ou corrigir comportamentos.

**Windows:**
Baixe e execute `rustup-init.exe` em https://rustup.rs

**Linux/macOS:**
```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

Verificar instalação:
```bash
rustc --version
cargo --version
```

Saída esperada (versões podem variar):
```
rustc 1.85.0 (4d91de4e4 2025-02-17)
cargo 1.85.0 (d73d2caf9 2024-12-31)
```

### 2.2 O que foi instalado

| Ferramenta | Função | Análogo C/C++ |
|------------|--------|---------------|
| `rustc` | Compilador Rust | `gcc` / `g++` / `clang` |
| `cargo` | Gerenciador de projetos, dependências, build, test, run | `make` + `cmake` + `vcpkg` |
| `rustup` | Gerenciador de versões do toolchain | — |
| `rustfmt` | Formatador de código | `clang-format` |
| `clippy` | Linter avançado | `clang-tidy` |

## 3. Usando rustc diretamente (como gcc/g++)

Para arquivos únicos, `rustc` funciona como `gcc`:

```rust
// hello.rs
fn main() {
    println!("Olá, mundo!");
}
```

Compilar e executar:
```bash
rustc hello.rs
./hello          # Linux/macOS
hello.exe        # Windows
```

Isso produz um binário nativo diretamente — assim como `gcc hello.c -o hello`.

- **Binário nativo**: executável já compilado para a arquitetura do seu processador e sistema operacional. Ou seja, não é script interpretado nem bytecode para uma VM; é código de máquina pronto para ser executado.

**Quando usar `rustc` diretamente:**
- Arquivos únicos de teste
- Scripts rápidos
- Entender o que o compilador faz
- Aulas como esta, onde queremos simplicidade

**Quando usar `cargo` (a maioria das vezes):**
- Projetos reais
- Múltiplos arquivos
- Dependências (crates)
- Testes
- Tudo que não é um arquivo único

## 4. Usando Cargo — o sistema de build do Rust

Cargo é ao mesmo tempo:
- **Build system** (como Make/CMake)
- **Gerenciador de pacotes** (como pip, npm, vcpkg)
- **Runner de testes**
- **Runner de documentação**

Vale definir alguns desses termos:

- **Build system**: ferramenta que coordena as etapas de compilação de um projeto.
- **Gerenciador de pacotes**: ferramenta que baixa e integra dependências externas.
- **Dependência**: biblioteca externa que seu projeto usa em vez de reimplementar tudo do zero.
- **Crate**: unidade básica de código distribuível em Rust. Na prática, uma crate pode ser uma biblioteca ou um executável. Quando você adiciona uma dependência no `Cargo.toml`, normalmente está adicionando uma crate.

### 4.1 Criando um projeto com Cargo

```bash
cargo new ola_mundo
cd ola_mundo
```

Estrutura gerada:
```
ola_mundo/
├── Cargo.toml      # Equivalente ao CMakeLists.txt / package.json
├── src/
│   └── main.rs     # Ponto de entrada
└── .git/           # Já inicializa como repo git
```

### 4.2 Cargo.toml — o arquivo de configuração

```toml
[package]
name = "ola_mundo"
version = "0.1.0"
edition = "2021"    # Edition do Rust (2015, 2018, 2021, 2024)
```

**Edition** é uma característica única do Rust: a linguagem evolui em "edições" a cada 3 anos. Código de edições diferentes pode coexistir. Isso permite evolução sem quebrar compatibilidade — algo que C++ faz com muito mais dor.

**Por que isso existe?** Porque Rust evolui a linguagem sem exigir que o ecossistema inteiro quebre de uma vez. É uma forma de modernizar sintaxe e regras mantendo compatibilidade gradual.

### 4.3 src/main.rs — o código

```rust
fn main() {
    println!("Olá, mundo!");
}
```

### 4.4 Comandos essenciais do Cargo

```bash
cargo build          # Compila o projeto (gera binário em target/debug/)
cargo run            # Compila e executa
cargo build --release  # Compila com otimizações (target/release/)
cargo check          # Verifica erros sem gerar binário (mais rápido)
cargo test           # Roda os testes
cargo doc --open     # Gera e abre documentação
cargo fmt            # Formata o código (rustfmt)
cargo clippy         # Roda o linter
```

**Comparação:**

| Ação | C/C++ | Rust (Cargo) |
|------|-------|--------------|
| Compilar | `gcc -o prog main.c` | `cargo build` |
| Compilar + rodar | `gcc -o prog main.c && ./prog` | `cargo run` |
| Build otimizado | `gcc -O2 -o prog main.c` | `cargo build --release` |
| Formatador | `clang-format` | `cargo fmt` |
| Linter | `clang-tidy` | `cargo clippy` |
| Dependência | Copiar .h/.a ou usar vcpkg | Adicionar em Cargo.toml |

## 5. Estrutura de um programa Rust

```rust
fn main() {
    println!("Olá, mundo!");
}
```

Linha por linha:

### `fn main()`
- `fn` — palavra-chave para declarar uma função (equivalente a definir uma função em C/C++)
- `main` — nome da função. `main` é o ponto de entrada do programa, assim como em C/C++
- `()` — lista de parâmetros (vazio = sem parâmetros)
- Não há tipo de retorno explícito — quando uma função não declara retorno, retorna `()` (unit type, equivalente a `void` em C/C++)

Definições importantes:

- **Função**: bloco nomeado de código que recebe zero ou mais entradas, executa alguma lógica e pode devolver um resultado.
- **Ponto de entrada** (*entry point*): primeira função chamada quando o programa começa.
- **Tipo unit `()`**: tipo que representa "nenhum valor útil". Em Rust ele é um tipo real; em C/C++ a ideia mais próxima é `void`.

**Em C:**
```c
int main(void) {
    printf("Olá, mundo!\n");
    return 0;
}
```

**Em C++:**
```cpp
int main() {
    std::cout << "Olá, mundo!" << std::endl;
    return 0;
}
```

**Diferenças importantes:**
- Rust não exige `return 0` no main. Retorno 0 (sucesso) é automático.
- Rust usa `fn` em vez de declarar o tipo de retorno antes do nome.
- Não existe "protótipo" de função em Rust — a ordem de declaração não importa dentro de um módulo.

### `println!("Olá, mundo!");`
- `println!` — **macro** (não função). O `!` indica que é uma macro.
- Por que macro? Porque `println!` faz verificação de formato em **tempo de compilação**. Se você passar tipos errados, o compilador te avisa. Em C, `printf` não tem essa garantia — erros de formato causam UB.
- `"Olá, mundo!"` — string literal, do tipo `&'static str` (referência para um slice de string com lifetime estático). Veremos isso em detalhes na aula 3 e 4.

Termos novos desta linha:

- **Macro**: mecanismo que gera código durante a compilação. Em Rust, macros são usadas quando a linguagem precisa de flexibilidade sintática ou verificação especial feita pelo compilador.
- **Tempo de compilação**: fase em que o compilador analisa o código e gera o binário.
- **Runtime**: fase em que o programa já está executando na máquina.
- **String literal**: texto escrito diretamente no código-fonte entre aspas.
- **`&'static str`**: por enquanto, pense como "uma referência para um texto fixo embutido no binário". O texto não fica no heap e existe durante toda a execução do programa. Na Aula 4 isso será formalizado.

**Em C:**
```c
printf("Olá, mundo!\n");  // sem verificação de tipos em runtime
```

**Em Rust, se você errar o formato:**
```rust
println!("{} {}", 1);  // ERRO DE COMPILAÇÃO: esperava 2 argumentos, recebeu 1
```

**Em C, o mesmo erro:**
```c
printf("%d %d\n", 1);   // COMPILA normalmente → UB em runtime
```

Essa é uma vitória concreta do Rust: erros que em C só aparecem em runtime são pegos pelo compilador.

## 6. Variáveis em Rust

### 6.1 Variáveis são imutáveis por padrão

Este é um dos conceitos mais fundamentais de Rust. Por padrão, toda variável é **imutável** — você não pode alterar seu valor depois de atribuído.

```rust
fn main() {
    let x = 5;
    println!("x = {}", x);

    // x = 6;  // ERRO DE COMPILAÇÃO: cannot assign twice to immutable variable `x`
}
```

**Por que?**
- A imutabilidade por padrão força você a ser explícito sobre o que pode mudar.
- Isso facilita o raciocínio sobre o código — você sabe que uma variável não muda a menos que veja `mut`.
- O compilador pode otimizar mais agressivamente variáveis imutáveis.
- Em concorrência, dados imutáveis são naturalmente thread-safe.

Definições úteis aqui:

- **Variável**: nome associado a um valor.
- **Imutável**: não pode ser alterado depois de criado.
- **Mutável**: pode ser alterado depois da criação.
- **Thread-safe**: seguro para uso em cenários com múltiplas threads sem introduzir corrupção de dados por si só.

**Comparação com C/C++:**
```c
const int x = 5;  // Em C, imutabilidade é opt-in com const
int y = 5;        // Mutável por padrão
```

```rust
let x = 5;        // Em Rust, imutabilidade é o padrão
let mut y = 5;    // Mutabilidade é opt-in com mut
```

Rust inverteu o padrão. Em C/C++, tudo é mutável e você usa `const` para proteger. Em Rust, tudo é imutável e você usa `mut` quando precisa modificar.

### 6.2 Variáveis mutáveis com `mut`

```rust
fn main() {
    let mut x = 5;
    println!("x = {}", x);

    x = 6;  // OK! x é mutável
    println!("x = {}", x);
}
```

`mut` é uma **promessa ao compilador**: "esta variável vai mudar, me deixe alterá-la".

Saída:
```
x = 5
x = 6
```

### 6.3 Shadowing (sombreamento)

Rust permite re-declarar uma variável com o mesmo nome. Isso **não é reatribuição** — é uma nova variável que "sombreia" a anterior.

Por que isso existe?

- para permitir transformações passo a passo sem precisar inventar nomes artificiais;
- para possibilitar mudança de tipo entre uma etapa e outra;
- para deixar explícito que o valor anterior não é mais o foco lógico daquele ponto do código.

```rust
fn main() {
    let x = 5;
    let x = x + 1;     // nova variável x, valor 6
    let x = x * 2;     // outra nova variável x, valor 12

    println!("x = {}", x);
}
```

Saída:
```
x = 12
```

**O que acontece em memória:**

```
Stack:
  ┌─────────┐
  │ x = 5   │  ← primeira declaração (sombreada, inacessível, mas ainda em stack até sair do escopo)
  │ x = 6   │  ← segunda declaração (sombreada)
  │ x = 12  │  ← terceira declaração (esta é a visível)
  └─────────┘
```

**Importante:** Shadowing permite mudar o **tipo** da variável, porque é uma variável nova:

```rust
fn main() {
    let x = 5;            // x: i32
    let x = "cinco";      // x: &str (tipo diferente!)
    println!("x = {}", x);
}
```

Isso seria impossível com `mut`:
```rust
let mut x = 5;
x = "cinco";  // ERRO: expected integer, found `&str`
```

**Comparação com C:**
Em C, não existe shadowing no mesmo escopo. O mais próximo seria blocos aninhados:
```c
{
    int x = 5;
    {
        const char* x = "cinco";  // OK em C, mas escopo diferente
        printf("%s\n", x);
    }
}
```

**Quando usar shadowing vs mut:**
- `mut`: o valor muda, mas o tipo permanece o mesmo.
- Shadowing: você quer transformar o valor (possivelmente mudando o tipo) e não precisa mais do valor antigo.

## 7. Tipos Básicos (Tipos Escalares)

Rust é **estaticamente tipada** com **inferência de tipos**. O compilador deduz o tipo quando possível, mas todo valor tem um tipo definido em tempo de compilação.

Aqui surgem três conceitos fundamentais:

- **Tipo**: descrição formal do formato do dado e das operações válidas sobre ele.
- **Linguagem estaticamente tipada**: linguagem em que o tipo dos valores é conhecido e verificado durante a compilação.
- **Inferência de tipos**: capacidade do compilador de descobrir automaticamente o tipo em alguns contextos, sem que você o escreva explicitamente.

### 7.1 Tipos inteiros

| Tipo | Tamanho | Com sinal | Range |
|------|---------|-----------|-------|
| `i8` | 8 bits | Sim | -128 a 127 |
| `u8` | 8 bits | Não | 0 a 255 |
| `i16` | 16 bits | Sim | -32768 a 32767 |
| `u16` | 16 bits | Não | 0 a 65535 |
| `i32` | 32 bits | Sim | -2³¹ a 2³¹-1 |
| `u32` | 32 bits | Não | 0 a 2³²-1 |
| `i64` | 64 bits | Sim | -2⁶³ a 2⁶³-1 |
| `u64` | 64 bits | Não | 0 a 2⁶⁴-1 |
| `i128` | 128 bits | Sim | -2¹²⁷ a 2¹²⁷-1 |
| `u128` | 128 bits | Não | 0 a 2¹²⁸-1 |
| `isize` | ptr-sized | Sim | depende da arquitetura |
| `usize` | ptr-sized | Não | depende da arquitetura |

**Convenções:**
- `i` = signed (com sinal), `u` = unsigned (sem sinal)
- O padrão (quando não especificado) é `i32`
- `isize`/`usize` tem o tamanho de um ponteiro na arquitetura (64 bits em x86_64). Usado para indexação e aritmética de ponteiros.

- **Arquitetura**: conjunto de regras do processador e do sistema alvo. Exemplo: `x86_64` significa ambiente de 64 bits da família x86.
- **Ponteiro-sized**: significa "tem o mesmo tamanho de um ponteiro naquela máquina".

**Comparação com C:**
| Rust | C equivalente |
|------|---------------|
| `i8` | `int8_t` / `signed char` |
| `u8` | `uint8_t` / `unsigned char` |
| `i32` | `int32_t` / `int` (na maioria das plataformas) |
| `i64` | `int64_t` / `long long` |
| `usize` | `size_t` |

**Diferença crítica:** Em C, `int` pode ter tamanhos diferentes dependendo da plataforma. Em Rust, `i32` é **sempre** 32 bits. Sem surpresas.

### 7.2 Tipo padrão e anotação explícita

```rust
fn main() {
    let x = 42;          // tipo inferido: i32 (padrão para literais inteiros)
    let y: i64 = 42;     // anotação explícita: i64
    let z = 42u8;        // sufixo: u8
    let w = 42_i64;      // sufixo com underscore para legibilidade

    println!("x: i32 = {}", x);
    println!("y: i64 = {}", y);
    println!("z: u8 = {}", z);
    println!("w: i64 = {}", w);
}
```

### 7.3 Ponto flutuante

| Tipo | Tamanho | Precisão |
|------|---------|----------|
| `f32` | 32 bits | IEEE 754 single (equivalente a `float` em C) |
| `f64` | 64 bits | IEEE 754 double (equivalente a `double` em C) |

O padrão para literais de ponto flutuante é `f64`.

```rust
fn main() {
    let x = 2.0;         // f64 (padrão)
    let y: f32 = 3.0;    // f32 explícito
    let z = 4.0f32;      // f32 por sufixo

    println!("x = {}, y = {}, z = {}", x, y, z);
}
```

### 7.4 Booleano

```rust
fn main() {
    let verdadeiro = true;
    let falso: bool = false;

    println!("verdadeiro = {}, falso = {}", verdadeiro, falso);
    println!("tamanho de bool = {} bytes", std::mem::size_of::<bool>());  // 1 byte
}
```

`bool` em Rust é sempre 1 byte, assim como em C. Mas ao contrário de C, Rust **não** converte implicitamente inteiros para bool.

- **Conversão implícita**: conversão feita automaticamente pelo compilador sem você pedir.
- Rust evita isso aqui para impedir ambiguidades e bugs silenciosos em expressões condicionais.

**Em C:**
```c
if (1) { }    // OK em C — qualquer valor != 0 é verdadeiro
```

**Em Rust:**
```rust
if 1 { }      // ERRO: expected `bool`, found integer
if true { }   // OK
```

### 7.5 Character

```rust
fn main() {
    let c = 'z';
    let z: char = 'ℤ';
    let emoji = '🦀';

    println!("c = {}, z = {}, emoji = {}", c, z, emoji);
    println!("tamanho de char = {} bytes", std::mem::size_of::<char>());  // 4 bytes
}
```

**Diferença crítica em relação a C:**
- Em C, `char` é 1 byte e representa ASCII (ou um byte de UTF-8).
- Em Rust, `char` é **4 bytes** e representa um **Unicode Scalar Value** (ponto de código Unicode).

- **Unicode**: padrão universal de codificação de caracteres para representar alfabetos, símbolos e emojis.
- **Unicode Scalar Value**: valor válido do conjunto Unicode que representa um caractere abstrato. Em Rust, `char` representa esse conceito, não um byte cru.

Isso significa que Rust suporta emojis, acentos, kanji, etc. nativamente no tipo `char`. Mas cuidado: `char` não é o mesmo que uma string — uma string em Rust é UTF-8, e um `char` pode ser multibyte quando codificado em UTF-8.

### 7.6 Tipo unit `()`

```rust
fn main() {
    let unit = ();
    println!("unit = {:?}", unit);
}
```

`()` é o tipo unit — representa "nenhum valor". Equivalente a `void` em C/C++, mas é um tipo de verdade em Rust. Toda função sem retorno explícito retorna `()`.

## 8. Modelo Mental: Variáveis em Memória

Vamos visualizar o que acontece na stack quando declaramos variáveis:

```rust
fn main() {
    let x: i32 = 42;
    let y: f64 = 3.14;
    let z: bool = true;
    let c: char = 'A';
}
```

```
Stack (cresce para baixo):
┌──────────────────────┐
│ main() frame         │
│ ┌──────────────────┐ │
│ │ x: i32 = 42      │ │  4 bytes
│ ├──────────────────┤ │
│ │ y: f64 = 3.14    │ │  8 bytes
│ ├──────────────────┤ │
│ │ z: bool = true   │ │  1 byte + padding
│ ├──────────────────┤ │
│ │ c: char = 'A'    │ │  4 bytes
│ └──────────────────┘ │
└──────────────────────┘
```

**Pontos importantes:**
- Todos esses tipos escalares vivem na **stack**.
- Não há alocação dinâmica (heap) aqui.
- O tamanho é conhecido em tempo de compilação.
- Quando a função retorna, a stack frame é desalocada automaticamente — sem free, sem delete.

Definições que amarram esta seção:

- **Stack**: região de memória organizada para variáveis locais e controle de chamadas de função.
- **Heap**: região de memória usada para alocações dinâmicas, quando o tamanho ou a duração dos dados não é conveniente para a stack.
- **Alocação dinâmica**: memória pedida em runtime, normalmente mais flexível e mais cara que a stack.
- **Stack frame**: bloco da stack pertencente a uma chamada específica de função.
- **Padding**: bytes inseridos pelo compilador para alinhar dados em memória de forma eficiente para a CPU.

**Comparação com C:**
Em C, o layout na stack seria idêntico. A diferença é que Rust garante que:
- A variável não pode ser acessada após sair do escopo.
- A variável não pode ser modificada sem `mut`.
- Não há dangling pointer para stack variables.

## 9. Constantes

```rust
const MAXIMO: i32 = 1000;

fn main() {
    println!("MAXIMO = {}", MAXIMO);
}
```

**Regras:**
- `const` exige anotação de tipo.
- `const` não pode usar `mut`.
- `const` é avaliada em tempo de compilação.
- `const` pode ser usada em qualquer escopo, inclusive global.
- Por convenção, nomes de constantes são `SCREAMING_SNAKE_CASE`.

**Diferença de `let`:**

| Característica | `let` | `const` |
|----------------|-------|---------|
| Tipo | Inferido ou anotado | Obrigatório anotar |
| Valor | Avaliado em runtime | Avaliado em compilação |
| Mutabilidade | Pode usar `mut` | Sempre imutável |
| Shadowing | Permite | Não permite |
| Escopo | Bloco onde foi declarada | Pode ser global |

**Comparação com C:**
```c
#define MAXIMO 1000       // C — preprocessador, sem tipo, sem segurança
const int MAXIMO = 1000;  // C — tem tipo, mas em C não é true const (pode ser castado)
```

```rust
const MAXIMO: i32 = 1000;  // Rust — verdadeiramente constante, inlining garantido
```

## 10. Conversão entre tipos (casting)

Em Rust, conversões numéricas são **sempre explícitas** com `as`:

```rust
fn main() {
    let x: i32 = 42;
    let y: f64 = x as f64;      // i32 → f64 (seguro, sem perda)
    let z: i8 = 300 as i8;      // truncamento! 300 → 44 (overflow silencioso)
    let w: u8 = -1 as u8;       // wrap! -1 → 255

    println!("x = {}, y = {}, z = {}, w = {}", x, y, z, w);
}
```

Saída:
```
x = 42, y = 42, z = 44, w = 255
```

**Comparação com C:**
Em C, conversões implícitas acontecem o tempo todo:
```c
int x = 42;
double y = x;    // conversão implícita — C permite
```

Em Rust, isso seria erro de compilação:
```rust
let x: i32 = 42;
let y: f64 = x;  // ERRO: expected f64, found i32
```

Rust força você a ser explícito sobre conversões. Isso elimina uma enorme classe de bugs silenciosos.

**Para conversões seguras**, Rust oferece métodos na trait `TryFrom`/`TryInto` (veremos na aula 9):
```rust
use std::convert::TryInto;

fn main() {
    let x: i32 = 300;
    let y: Result<u8, _> = x.try_into();  // Retorna Err porque 300 > 255
    println!("{:?}", y);  // Err(TryFromIntError(()))
}
```

## 11. Operadores aritméticos e lógicos

```rust
fn main() {
    // Aritméticos — mesmos de C
    let soma = 5 + 3;
    let sub = 5 - 3;
    let mult = 5 * 3;
    let div = 5 / 3;       // divisão inteira: 1 (trunca como em C)
    let resto = 5 % 3;     // 2

    // Lógicos
    let and = true && false;    // false
    let or = true || false;     // true
    let not = !true;            // false

    // Comparação — mesmos de C, mas sem surpresas com tipos
    let igual = 5 == 5;
    let diferente = 5 != 3;
    let maior = 5 > 3;
    let menor = 5 < 3;

    // Bit a bit — mesmos de C
    let bitwise_and = 0b1100 & 0b1010;  // 0b1000 = 8
    let bitwise_or = 0b1100 | 0b1010;   // 0b1110 = 14
    let bitwise_xor = 0b1100 ^ 0b1010;  // 0b0110 = 6
    let bitwise_not = !0b1100u8;        // 0b00110011 = 243
    let shift_left = 1u8 << 3;          // 8
    let shift_right = 16u8 >> 2;        // 4

    println!("soma = {}, div = {}, resto = {}", soma, div, resto);
    println!("bitwise_and = {}, shift_left = {}", bitwise_and, shift_left);
}
```

**Overflow:** Em compilação de desenvolvimento, operações inteiras que estouram normalmente causam **panic**. Em uma compilação release padrão, sem verificações de overflow habilitadas, elas fazem *wrapping*; `-C overflow-checks` pode mudar essa configuração. Não dependa dessa diferença para a correção do programa. Em C, inteiros sem sinal fazem wrapping, mas overflow de inteiros com sinal é comportamento indefinido. Uma expressão constante como `255u8 + 1` também pode ser rejeitada já na compilação. Para lidar explicitamente:

Referência para o comportamento em Rust: [Rust Reference: Integer Overflow](https://doc.rust-lang.org/reference/expressions/operator-expr.html#overflow).

```rust
fn main() {
    // `255u8 + 1` é uma expressão constante inválida e pode ser rejeitada
    // na compilação; o exemplo abaixo usa APIs com semântica explícita.

    // Forma segura de lidar com overflow:
    let x: u8 = 255;
    let saturado = x.saturating_add(1);     // 255 (satura no máximo)
    let wrapping = x.wrapping_add(1);       // 0 (wrap)
    let checked = x.checked_add(1);         // None (Option)

    println!("saturado = {}, wrapping = {}, checked = {:?}", saturado, wrapping, checked);
}
```

`checked_add`, `saturating_add` e `wrapping_add` deixam o comportamento escolhido visível em qualquer perfil de compilação.

## 12. Exemplo completo

```rust
// aula1_tipos.rs
// Compilar: rustc aula1_tipos.rs
// Executar: ./aula1_tipos (Linux/macOS) ou aula1_tipos.exe (Windows)

fn main() {
    // Inteiros
    let inteiro_padrao = 42;          // i32
    let inteiro_grande: i64 = 1_000_000_000_000;  // underscores para legibilidade
    let byte: u8 = 255;
    let ptr_sized: usize = 0xdeadbeef;

    println!("inteiro_padrao = {} (i32)", inteiro_padrao);
    println!("inteiro_grande = {} (i64)", inteiro_grande);
    println!("byte = {} (u8)", byte);
    println!("ptr_sized = {} (usize)", ptr_sized);

    // Ponto flutuante
    let pi: f64 = 3.14159265358979;
    let float32: f32 = 2.71828;

    println!("pi = {} (f64)", pi);
    println!("e = {} (f32)", float32);

    // Booleano
    let ativo = true;
    let inativo: bool = false;

    println!("ativo = {}, inativo = {}", ativo, inativo);

    // Char
    let letra = 'R';
    let coracao = '❤';
    let rust_crab = '🦀';

    println!("letra = {}, coração = {}, rust = {}", letra, coracao, rust_crab);

    // Mutabilidade
    let mut contador = 0;
    println!("contador = {}", contador);
    contador = contador + 1;
    println!("contador = {}", contador);

    // Shadowing
    let x = 5;
    let x = x + 1;
    let x = x * 2;
    println!("x (shadowed) = {}", x);  // 12

    // Shadowing mudando tipo
    let espaco = "   ";
    let espaco = espaco.len();
    println!("espaco = {} (mudou de &str para usize)", espaco);

    // Constante
    const VELOCIDADE_DA_LUZ: u64 = 299_792_458;
    println!("velocidade da luz = {} m/s", VELOCIDADE_DA_LUZ);

    // Tamanhos em memória
    println!("\n--- Tamanhos em memória ---");
    println!("i32:    {} bytes", std::mem::size_of::<i32>());
    println!("i64:    {} bytes", std::mem::size_of::<i64>());
    println!("u8:     {} bytes", std::mem::size_of::<u8>());
    println!("usize:  {} bytes", std::mem::size_of::<usize>());
    println!("f32:    {} bytes", std::mem::size_of::<f32>());
    println!("f64:    {} bytes", std::mem::size_of::<f64>());
    println!("bool:   {} bytes", std::mem::size_of::<bool>());
    println!("char:   {} bytes", std::mem::size_of::<char>());
    println!("():     {} bytes", std::mem::size_of::<()>());
}
```

Compilar e executar:
```bash

```

ativo = true, inativo = false

contador = 0

espaco = 3 (mudou de &str para usize)

## 13. Erros Comuns

### Erro 1: Tentar modificar variável imutável

```rust
fn main() {
    let x = 5;
    x = 6;  // erroE0384: cannot assign twice to immutable variable `x`
}
```

**Solução:** Use `let mut x = 5;`

### Erro 2: Type mismatch

```rust
fn main() {
    let x: i32 = 5.0;  // erroE0308: mismatched types — expected `i32`, found floating-point number
}
```

**Solução:** Use `let x: f64 = 5.0;` ou converta explicitamente.

### Erro 3: Overflow em debug

```rust
fn main() {
    let x: u8 = 255;
    let y: u8 = x + 1;  // panic em debug mode (thread 'main' panicked at 'attempt to add with overflow')
}
```

**Solução:** Use `wrapping_add`, `saturating_add`, ou `checked_add`.

### Erro 4: Esquecer o `!` em `println!`

```rust
fn main() {
    println("Olá");  // erro: expected function, found macro `println`
}
```

**Solução:** Macros sempre usam `!` → `println!("Olá");`

### Erro 5: Usar variável não utilizada

```rust
fn main() {
    let x = 5;  // warning: unused variable: `x`
}
```

**Solução:** Use `_x = 5` para suprimir, ou simplesmente use a variável. Rust avisa sobre código morto.
