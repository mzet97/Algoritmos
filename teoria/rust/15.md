# Aula 15 — Unsafe Rust

---

## Nesta aula

Dominar **`unsafe` Rust** — quando usar, o que ele permite, e como manter o código seguro. Entenderemos os **5 superpoderes do unsafe** (ponteiros brutos, `extern`/FFI, acessar campos de union, mutar `static`, chamar `unsafe fn`), os **invariantes de segurança** que o compilador não pode verificar, **Undefined Behavior** em Rust, o modelo mental **safe wrapper / unsafe implementation**, e como escrever abstrações seguras sobre código perigoso. Você vai aprender a delimitar o que `unsafe` permite (desreferenciar ponteiros brutos, chamar `unsafe fn`, acessar `static mut`, implementar `unsafe trait`), enunciar o contrato que o programador assume, justificar cada bloco `unsafe` com uma frase, e apontar o que nem `unsafe` pode violar.

## 1. O Que É `unsafe` e Por Que Existe

### 1.1 A promessa de Rust

Rust garante **memory safety** e **thread safety** em tempo de compilação — sem garbage collector. Mas o compilador é **conservador**: rejeita alguns programas seguros porque não consegue provar que são seguros.

```rust
// O compilador recusa isso — não consegue provar que os slices não se sobrepõem
fn dividir_slice(slice: &mut [i32], meio: usize) -> (&mut [i32], &mut [i32]) {
    // (&mut slice[..meio], &mut slice[meio..])  // ERRO: cannot borrow `slice` as mutable more than once
    // Mas nós SABEMOS que [..meio] e [meio..] nunca se sobrepõem!
}
```

`unsafe` é a **escape hatch** controlada que permite ao programador assumir responsabilidades que o compilador não pode verificar.

- **Escape hatch**: mecanismo de saída controlada das regras normais da linguagem.
- Ele existe porque algumas abstrações fundamentais, FFI e estruturas de baixo nível simplesmente não podem ser expressas só com safe Rust.

### 1.2 O que `unsafe` NÃO é

| Mito | Realidade |
|------|-----------|
| `unsafe` desliga o borrow checker | `unsafe` não desliga nada — apenas adiciona 5 superpoderes |
| `unsafe` = indefensável | `unsafe` é necessário para abstrações de baixo nível |
| Quem usa `unsafe` está fazendo errado | A std library usa `unsafe` extensivamente — wrapped em APIs seguras |
| `unsafe` = C | `unsafe` Rust ainda tem mais garantias que C |

O ponto mais importante é este:

- `unsafe` não desliga o compilador;
- não desliga ownership;
- não desliga lifetimes;
- ele apenas permite operações adicionais que exigem responsabilidade manual.

### 1.3 Os 5 superpoderes do `unsafe`

```rust
unsafe {
    // 1. Desreferenciar ponteiros brutos (*const T, *mut T)
    // 2. Chamar funções unsafe
    // 3. Acessar ou modificar static mut
    // 4. Acessar campos de union
    // 5. Implementar traits unsafe (Send, Sync, GlobalAlloc, etc.)
}

// Além disso:
// 6. Declarar funções unsafe: unsafe fn foo() { ... }
// 7. Declarar blocos extern: unsafe extern "C" { ... }
```

### 1.4 O contrato de segurança

Ao usar `unsafe`, você assume a responsabilidade de garantir **4 invariantes** que o compilador não pode verificar:

- **Invariante**: propriedade que precisa continuar verdadeira para que o programa permaneça correto e seguro.
- Em código unsafe, invariantes são a base do raciocínio de segurança.

| Invariante | Significado | Violação causa |
|------------|-------------|---------------|
| **Dereferencing validity** | Ponteiro aponta para memória válida, inicializada e alinhada | UB — segfault, lixo |
| **Alias rules** | `&mut T` é a única referência mutável, `&T` permite leitura compartilhada | UB — data race, corrumpa |
| **Lifetimes** | Referências não vivem mais que os dados | UB — dangling pointer |
| **Thread safety** | Acesso concorrente respeita `Send`/`Sync` | UB — data race |

**Crucial:** `unsafe` dentro de uma função **não torna a função inteira unsafe**. A função pode ter uma API safe que internamente usa `unsafe`. O chamador nunca precisa saber.

Essa distinção é a essência do design idiomático de baixo nível em Rust:

- API externa segura;
- implementação interna pontualmente insegura, mas cuidadosamente encapsulada.

## 2. Ponteiros Brutos — `*const T` e `*mut T`

### 2.1 O que são

Ponteiros brutos são como ponteiros de C — sem garantias de segurança:

- **Ponteiro bruto**: endereço sem as garantias semânticas de uma referência Rust (`&T` / `&mut T`).
- Eles existem para interoperabilidade, aritmética de ponteiros, alocação manual e construção de abstrações fundamentais.

| Tipo | Descrição | Equivalente C |
|------|-----------|---------------|
| `*const T` | Ponteiro imutável bruto | `const T*` |
| `*mut T` | Ponteiro mutável bruto | `T*` |

Diferenças de referências (`&T`, `&mut T`):

| Aspecto | `&T` / `&mut T` | `*const T` / `*mut T` |
|---------|-----------------|----------------------|
| Borrow checker | Verifica | Ignora |
| Pode ser null | Não | Sim |
| Pode ser dangling | Não (compilador impede) | Sim (sua responsabilidade) |
| Pode ser desalinhado | Não | Sim |
| `Send` / `Sync` | Derivado do T | **Nunca** (manual) |
| Desreferenciar | Seguro | **Requer `unsafe`** |
| Aritmética | Não | Sim (`.add()`, `.offset()`) |
| Criação | Segura | Segura (a partir de referências) |

### 2.2 Criando ponteiros brutos

```rust
fn main() {
    let x = 42;

    // Criar ponteiro bruto a partir de referência — SEGURO
    let ptr_const: *const i32 = &x;
    let ptr_mut: *mut i32 = &x as *const i32 as *mut i32;  // cast duplo

    // A partir de Box
    let mut v = Box::new(100);
    let ptr_box: *mut i32 = &mut *v;

    // A partir de vetor
    let v = vec![1, 2, 3, 4, 5];
    let ptr_vec: *const i32 = v.as_ptr();
    let ptr_mut_vec: *mut i32 = v.as_ptr() as *mut i32;

    // Null
    let null_ptr: *const i32 = std::ptr::null();
    let null_mut: *mut i32 = std::ptr::null_mut();

    // CRIOU ponteiros — TUDO ISSO É SEGURO (nenhuma desreferência)
    println!("ptr_const: {:?}", ptr_const);
    println!("null: {:?}", null_ptr);
    println!("null? {}", null_ptr.is_null());
}
```

**Criar ponteiros é seguro.** O perigo está na **desreferência** — que requer `unsafe`.

- **Desreferenciar** significa seguir o ponteiro e acessar o valor apontado.
- É nesse momento que memória inválida, null, desalinhamento ou dados destruídos podem causar UB.

### 2.3 Desreferenciando ponteiros brutos

```rust
fn main() {
    let x = 42;
    let ptr: *const i32 = &x;

    // Desreferência REQUER unsafe
    unsafe {
        let valor = *ptr;
        println!("Valor via ponteiro: {}", valor);  // 42
    }

    // Através de ponteiro mutável
    let mut y = 10;
    let ptr_mut: *mut i32 = &mut y;
    unsafe {
        *ptr_mut = 99;
        println!("y modificado via ponteiro: {}", y);  // 99
    }
}
```

### 2.4 Aritmética de ponteiros

```rust
fn main() {
    let v = vec![10, 20, 30, 40, 50];
    let ptr = v.as_ptr();

    unsafe {
        // offset — desloca N posições (em unidades de T, não bytes)
        let segundo = *ptr.add(1);      // ptr + 1 * sizeof(i32)
        let terceiro = *ptr.add(2);     // ptr + 2 * sizeof(i32)
        let ultimo = *ptr.add(4);       // ptr + 4 * sizeof(i32)
        // ptr.add(5) → UM ATRÁS do fim — UB se desreferenciado!
        // ptr.add(6) → totalmente fora — UB!

        println!("segundo: {}", segundo);    // 20
        println!("terceiro: {}", terceiro);  // 30
        println!("ultimo: {}", ultimo);      // 50

        // offset com sinal
        let ptr_meio = ptr.add(2);          // aponta para 30
        let anterior = *ptr_meio.sub(1);     // volta 1 → 20
        println!("anterior: {}", anterior);  // 20

        // byte_offset — desloca em bytes (cuidado com alinhamento!)
        // let ptr_bytes = (ptr as *const u8).add(4);  // avança 4 bytes = 1 i32
    }
}
```

**Regras de aritmética de ponteiros:**

| Operação | Resultado | Segurança |
|----------|-----------|-----------|
| `ptr.add(n)` | `ptr + n * size_of::<T>()` | Deve estar dentro ou 1 após o allocation |
| `ptr.sub(n)` | `ptr - n * size_of::<T>()` | Deve estar dentro do allocation |
| `ptr.offset(n)` | Igual ao add, mas aceita `isize` | Mesmas regras |
| `ptr.byte_offset(n)` | Offset em bytes brutos | Cuidado com alinhamento |

**Warning:** Em Rust, diferente de C, sair 1 posição após o fim do allocation é permitido APENAS para calcular o endereço (sem desreferenciar). Ir além é UB.

- **Allocation**: bloco de memória reservado dinamicamente para um objeto, array, `Vec`, `Box`, etc.
- Essa distinção é importante porque "calcular um endereço" e "usar esse endereço" não são a mesma coisa.

### 2.5 Conversão ponteiro ↔ inteiro

```rust
fn main() {
    let x = 42;
    let ptr: *const i32 = &x;

    // Ponteiro → inteiro
    let addr = ptr as usize;
    println!("Endereço: {:#x}", addr);

    // Inteiro → ponteiro (unsafe porque não sabemos se é válido)
    let ptr_reconstruido = addr as *const i32;
    unsafe {
        println!("Via ponteiro reconstruído: {}", *ptr_reconstruido);
    }
}
```

## 3. Unsafe Functions — `unsafe fn`

### 3.1 Declarando funções unsafe

```rust
// unsafe fn: o CHAMADOR deve garantir as pré-condições
unsafe fn ler_em_endereco(ptr: *const i32) -> i32 {
    // Pré-condição (chamador deve garantir):
    // - ptr não é null
    // - ptr aponta para memória válida e inicializada
    // - ptr está alinhado para i32
    *ptr
}

// O corpo de unsafe fn é implicitamente unsafe
// Não precisa de bloco unsafe para desreferenciar ponteiros

- **Pré-condição**: requisito que precisa ser verdadeiro antes da função ser chamada corretamente.
- Em `unsafe fn`, quem chama é responsável por garantir essas pré-condições.

fn main() {
    let x = 42;
    let ptr: *const i32 = &x;

    // Chamada REQUER bloco unsafe
    let valor = unsafe { ler_em_endereco(ptr) };
    println!("Valor: {}", valor);

    // let valor2 = ler_em_endereco(ptr);  // ERRO: call to unsafe function
}
```

### 3.2 Safe API com unsafe interno

O padrão mais importante: **safe wrapper, unsafe implementation**.

Esse é provavelmente o padrão mais importante de toda a aula.

Por que ele existe?

- porque o restante do programa não deveria carregar o peso mental do código perigoso;
- porque uma abstração segura pode concentrar a complexidade unsafe em um ponto pequeno e auditável;
- porque esse é o mesmo modelo usado pela própria biblioteca padrão.

```rust
// API PÚBLICA — 100% segura
pub fn dividir_em_dois(slice: &mut [i32], meio: usize) -> (&mut [i32], &mut [i32]) {
    assert!(meio <= slice.len(), "meio não pode ser maior que o tamanho");

    let ptr = slice.as_mut_ptr();

    // unsafe interno — chamador nunca vê
    unsafe {
        (
            std::slice::from_raw_parts_mut(ptr, meio),
            std::slice::from_raw_parts_mut(ptr.add(meio), slice.len() - meio),
        )
    }
}

fn main() {
    let mut v = vec![1, 2, 3, 4, 5, 6];

    let (esquerda, direita) = dividir_em_dois(&mut v, 3);

    println!("Esquerda: {:?}", esquerda);  // [1, 2, 3]
    println!("Direita: {:?}", direita);    // [4, 5, 6]

    esquerda[0] = 10;
    direita[0] = 40;
    println!("Modificado: {:?}", v);  // [10, 2, 3, 40, 5, 6]
}
```

**Por que é seguro:** O `assert!` garante que `meio <= slice.len()`. Sabemos que `ptr` e `ptr + meio` não se sobrepõem. O borrow checker não consegue provar isso, mas matematicamente é verdade.

**Este padrão aparece em toda a std library:**
- `Vec::push` — usa `unsafe` para escrever na memória alocada.
- `String::from_utf8_unchecked` — assume que bytes são UTF-8 válido.
- `slice::get_unchecked` — pula bounds check.
- `HashMap::insert` — usa `unsafe` para gerenciar a tabela hash interna.

### 3.3 Commentando o contrato de segurança

Toda função `unsafe` deve documentar **exatamente** o que o chamador precisa garantir:

```rust
/// # Safety
///
/// O chamador deve garantir que:
/// - `ptr` aponta para memória válida, inicializada e alinhada para `T`
/// - `len` elementos consecutivos a partir de `ptr` estão dentro do allocation
/// - A memória não é mutada concorrentemente por outra thread
unsafe fn ler_slice<T>(ptr: *const T, len: usize) -> &[T] {
    std::slice::from_raw_parts(ptr, len)
}
```

O comentário `# Safety` é **obrigatório** em código de produção. Documenta as pré-condições que o `unsafe` exige.

Sem documentação explícita, `unsafe` vira adivinhação. E adivinhação em código de baixo nível é receita para UB.

## 4. `extern` — Chamando Código C (FFI Básico)

### 4.1 Declarando funções externas

```rust
// Declaração de funções C — sempre unsafe para chamar
unsafe extern "C" {
    fn abs(input: i32) -> i32;
    fn strlen(s: *const i8) -> usize;
    fn malloc(size: usize) -> *mut std::ffi::c_void;
    fn free(ptr: *mut std::ffi::c_void);
}

fn main() {
    // Chamar função C — requer unsafe
    let x = -42;
    let resultado = unsafe { abs(x) };
    println!("abs({}) = {}", x, resultado);  // 42

    // strlen — precisa de CString
    use std::ffi::CString;
    let s = CString::new("olá mundo").unwrap();
    let tamanho = unsafe { strlen(s.as_ptr()) };
    println!("strlen(\"olá mundo\") = {}", tamanho);  // 9
}
```

- **FFI (Foreign Function Interface)**: mecanismo para uma linguagem conversar com código compilado em outra linguagem, como C ou C++.
- **Convenção de chamada** (`extern "C"`): acordo binário sobre como argumentos e retornos são passados entre funções.

### 4.2 Exportando funções Rust para C

```rust
// #[unsafe(no_mangle)] impede o compilador de renomear a função
// extern "C" usa a convenção de chamada C
#[unsafe(no_mangle)]
pub extern "C" fn rust_soma(a: i32, b: i32) -> i32 {
    a + b
}

// Isso gera um símbolo C compatível:
// int32_t rust_soma(int32_t a, int32_t b);
```

### 4.3 Representação C em structs

```rust
// #[repr(C)] garante layout de memória compatível com C
#[repr(C)]
struct PontoC {
    x: f64,
    y: f64,
}

// Sem #[repr(C)], Rust pode reordenar campos!
// #[repr(C)] garante ordem: x primeiro, y depois, sem padding inesperado

- **Layout de memória**: organização exata dos campos em bytes.
- `#[repr(C)]` existe para que Rust respeite a convenção de layout esperada por código C.

#[repr(C)]
struct CabecalhoArquivo {
    magic: [u8; 4],     // offset 0
    versao: u32,         // offset 4
    tamanho: u64,        // offset 8 (pode ter padding dependendo do alinhamento)
    flags: u32,          // offset 16
}

fn main() {
    println!("sizeof PontoC: {}", std::mem::size_of::<PontoC>());  // 16

    // Reinterpretar bytes como struct
    let bytes: [u8; 16] = [0u8; 16];
    let ponto: &PontoC = unsafe {
        &*(bytes.as_ptr() as *const PontoC)
    };
    println!("Ponto: ({}, {})", ponto.x, ponto.y);
}
```

### 4.4 Tipos FFI comuns

| Rust | C | Descrição |
|------|---|-----------|
| `i32` | `int32_t` | Inteiro 32 bits |
| `i64` | `int64_t` | Inteiro 64 bits |
| `f64` | `double` | Ponto flutuante 64 bits |
| `*const T` | `const T*` | Ponteiro imutável |
| `*mut T` | `T*` | Ponteiro mutável |
| `bool` | `_Bool` | Booleano |
| `()` | `void` | Tipo vazio (apenas em retorno) |
| `std::ffi::c_void` | `void` | Ponteiro opaco (`*mut c_void`) |
| `CString` | `char*` | String C (null-terminated) |
| `CStr` | `const char*` | String C borrowed |

**Veremos FFI em profundidade na Aula 16.**

## 5. `union` — Acessando Campos

### 5.1 Union em Rust

Rust tem `union` (como C) — todos os campos compartilham a mesma memória:

- **union**: estrutura em que vários campos ocupam a mesma região física de memória.
- Ela existe principalmente para interoperabilidade com C e reinterpretacão controlada de bits.

```rust
#[repr(C)]
union Valor {
    inteiro: i32,
    decimal: f32,
    bytes: [u8; 4],
}

fn main() {
    let mut v = Valor { inteiro: 42 };

    // Ler um campo de union SEMPRE requer unsafe
    unsafe {
        println!("inteiro: {}", v.inteiro);  // 42

        // Reinterpretar os mesmos bytes como f32
        println!("decimal (reinterpretado): {}", v.decimal);

        // Reinterpretar como bytes
        println!("bytes: {:?}", v.bytes);
    }

    // Escrever é seguro (affecta todos os campos)
    v = Valor { decimal: 3.14 };
    unsafe {
        println!("decimal: {}", v.decimal);           // 3.14
        println!("inteiro (lixo): {}", v.inteiro);    // lixo — reinterpretação
    }
}
```

**Comparação com C:**

```c
// C — undefined behavior ler o campo "errado"
union Valor {
    int inteiro;
    float decimal;
};

union Valor v;
v.inteiro = 42;
printf("%f\n", v.decimal);  // UB em C! (type punning)
```

Em Rust, ler o campo "errado" também é tecnicamente UB (exceto para tipos `Copy`), mas Rust é mais honesto sobre isso — exige `unsafe` explícito.

### 5.2 Quando usar union

- Interoperabilidade com C (structs com union).
- Parsing de formatos binários (interpretar bytes como tipos diferentes).
- Tipagem taguda manual (junto com discriminador).

**Na prática**, prefira `enum` ( seguro) em vez de `union` ( unsafe). Use `union` apenas para FFI.

`enum` modela alternativas de forma semanticamente segura. `union` modela sobreposição bruta de memória.

## 6. `static mut` — Variáveis Estáticas Mutáveis

### 6.1 O problema

```rust
static mut CONTADOR: i32 = 0;

fn incrementar() {
    // Acessar static mut é unsafe porque qualquer thread pode acessar
    // Data race é possível se duas threads chamam incrementar simultaneamente
    unsafe {
        CONTADOR += 1;
    }
}

fn main() {
    incrementar();
    incrementar();
    incrementar();
    unsafe {
        println!("Contador: {}", CONTADOR);  // 3
    }
}
```

**Por que é unsafe:** `static mut` é acessível de qualquer thread, sem sincronização. Data races são possíveis.

- **Variável estática**: valor com duração de programa inteiro.
- O problema não é a duração; o problema é a mutação global sem sincronização explícita.

### 6.2 Alternativas seguras

```rust
use std::sync::atomic::{AtomicI32, Ordering};
use std::sync::OnceLock;

// 1. Atomic — para contadores e flags
static CONTADOR_SEGURO: AtomicI32 = AtomicI32::new(0);

// 2. OnceLock — para inicialização one-time
static CONFIGURACAO: OnceLock<String> = OnceLock::new();

// 3. thread_local — para estado por thread
thread_local! {
    static ESTADO_LOCAL: std::cell::RefCell<Vec<i32>> = std::cell::RefCell::new(Vec::new());
}

fn main() {
    // Atomic — seguro
    CONTADOR_SEGURO.fetch_add(1, Ordering::SeqCst);
    println!("Contador: {}", CONTADOR_SEGURO.load(Ordering::SeqCst));

    // OnceLock — seguro
    CONFIGURACAO.set("config valor".to_string()).ok();
    println!("Config: {}", CONFIGURACAO.get().unwrap());

    // thread_local — seguro
    ESTADO_LOCAL.with(|estado| {
        estado.borrow_mut().push(42);
        println!("Estado local: {:?}", *estado.borrow());
    });
}
```

**Regra:** Nunca use `static mut` em código novo. Use `AtomicXxx`, `OnceLock`, `LazyLock`, ou `thread_local!`.

Essas alternativas existem justamente para dar semânticas seguras e específicas para casos comuns de estado global.

## 7. Implementando Traits Unsafe

### 7.1 `unsafe trait` e `unsafe impl`

```rust
// unsafe trait: o IMPLEMENTADOR deve garantir que a implementação é segura
unsafe trait MeuTraitSeguro {
    fn metodo(&self) -> i32;
}

// unsafe impl: afirma-se que a implementação respeita o contrato

- **unsafe trait**: trait cujo contrato não pode ser verificado automaticamente pelo compilador.
- **unsafe impl**: afirmação manual de que aquele tipo cumpre o contrato exigido.
struct MeuTipo;

unsafe impl MeuTraitSeguro for MeuTipo {
    fn metodo(&self) -> i32 {
        42
    }
}

fn main() {
    let x = MeuTipo;
    // Chamar método do trait é seguro — unsafe está na implementação
    println!("Valor: {}", x.metodo());
}
```

### 7.2 Implementando `Send` e `Sync` manualmente

```rust
use std::sync::Arc;
use std::sync::Mutex;

struct RecursoCompartilhado {
    dados: *mut i32,  // ponteiro bruto — não é Send nem Sync por padrão
}

// SAFETY: O acesso a dados é protegido por Mutex externo (documentado)
// Na verdade, este exemplo é problemático — use apenas se realmente seguro
unsafe impl Send for RecursoCompartilhado {}
unsafe impl Sync for RecursoCompartilhado {}
```

**Cuidado:** Implementar `Send`/`Sync` manualmente é uma afirmação de que seu tipo é thread-safe. Se estiver errado, data races ocorrerão. Sempre prefira usar tipos que já são `Send`/`Sync`.

## 8. Undefined Behavior em Rust

### 8.1 O que é UB

Undefined Behavior é quando o programa viola as regras da linguagem de forma que o compilador pode fazer **qualquer coisa** — incluindo apagar seus arquivos (teoricamente):

- **Undefined Behavior (UB)**: situação em que a linguagem deixa de prometer qualquer resultado confiável.
- A partir daí, "parecer funcionar" não significa "estar correto".

```rust
fn main() {
    let r;
    {
        let x = 42;
        r = &x as *const i32;  // ponteiro para variável local
    }   // x morre aqui

    unsafe {
        // *r é UB — dangling pointer!
        // Pode imprimir 42, lixo, crashar, ou parecer funcionar às vezes
        // println!("{}", *r);  // NÃO DESCOMENTE — UB!
    }
}
```

### 8.2 Catálogo de UB em Rust

| Operação | Descrição |
|----------|-----------|
| Dangling pointer | Desreferenciar ponteiro para memória desalocada |
| Null pointer dereference | Desreferenciar ponteiro null |
| Unaligned access | Desreferenciar ponteiro não alinhado ao tipo |
| Data race | Duas threads acessam mesma memória, pelo menos uma escrita, sem sincronização |
| Invalid value | Criar valor inválido (ex: `bool` que não é 0 ou 1, `Option<&T>` com bit pattern None mas com ponteiro não-null) |
| Out of bounds | Acessar índice fora do allocation |
| Use after move | Usar valor após move (borrow checker previne em safe code) |
| Breaking alias rules | Ter `&mut T` e `&T` (ou outro `&mut T`) ao mesmo tempo para o mesmo dado |
| Invalid UTF-8 | Criar `&str` a partir de bytes não-UTF-8 |

### 8.3 UB vs Erros de Compilação vs Panics

| Tipo | Detecção | Exemplo |
|------|----------|---------|
| Erro de compilação | Compilação | `let r: &i32; { let x = 42; r = &x; }` — lifetime |
| Panic | Runtime | `v[100]` em vec com 3 elementos |
| UB | **Nunca** — silencioso | `*ptr` onde ptr é dangling |

**Comparação com C:**

| Em Rust | Em C |
|---------|------|
| UB é exceção — 95%+ do código é safe | UB é regra — qualquer acesso a ponteiro pode ser UB |
| `unsafe` marca onde UB pode ocorrer | Nada marca onde UB pode ocorrer |
| Ferramentas como Miri detectam UB em testes | UBSan, ASan, Valgrind detectam alguns UB |

### 8.4 Miri — Detector de UB

Miri é um interpretador de Rust que detecta UB em tempo de execução:

```bash

```

## 9. `unsafe` na Biblioteca Padrão

A std library usa `unsafe` extensivamente — mas sempre encapsulado:

```rust
// std::vec::Vec internamente:
pub struct Vec<T> {
    buf: RawVec<T>,      // ponteiro bruto + capacidade
    len: usize,          // número de elementos
}

impl<T> Vec<T> {
    pub fn push(&mut self, val: T) {
        if self.len == self.buf.cap() {
            self.buf.grow();
        }
        unsafe {
            let end = self.buf.ptr().add(self.len);
            std::ptr::write(end, val);  // unsafe: escreve na memória
        }
        self.len += 1;
    }

    pub fn get(&self, index: usize) -> Option<&T> {
        if index < self.len {
            // unsafe interno — chamador nunca vê
            unsafe { Some(&*self.buf.ptr().add(index)) }
        } else {
            None
        }
    }
}
```

**Princípio:** `Vec` é uma **abstração segura** sobre memória não segura. O chamador nunca precisa de `unsafe` — a `Vec` garante invariantes internamente.

**Isso é o modelo Rust:** unsafe nas fundações, safe na superfície.

Essa frase resume a filosofia inteira:

- componentes fundamentais usam `unsafe` porque precisam;
- usuários da abstração interagem com uma API segura e validada.

## 10. Padrões e Anti-Padrões

### 10.1 Padrão correto — safe wrapper

```rust
/// Um buffer circular seguro construído sobre ponteiros brutos.
pub struct RingBuffer<T> {
    data: *mut T,
    capacity: usize,
    head: usize,
    tail: usize,
    len: usize,
}

impl<T> RingBuffer<T> {
    pub fn novo(capacity: usize) -> Self {
        let layout = std::alloc::Layout::array::<T>(capacity).unwrap();
        let data = unsafe { std::alloc::alloc(layout) as *mut T };
        if data.is_null() {
            std::alloc::handle_alloc_error(layout);
        }
        RingBuffer { data, capacity, head: 0, tail: 0, len: 0 }
    }

    pub fn push(&mut self, valor: T) -> Result<(), T> {
        if self.len == self.capacity {
            return Err(valor);  // buffer cheio — safe!
        }
        unsafe {
            std::ptr::write(self.data.add(self.tail), valor);
        }
        self.tail = (self.tail + 1) % self.capacity;
        self.len += 1;
        Ok(())
    }

    pub fn pop(&mut self) -> Option<T> {
        if self.len == 0 {
            return None;  // vazio — safe!
        }
        let valor = unsafe {
            std::ptr::read(self.data.add(self.head))
        };
        self.head = (self.head + 1) % self.capacity;
        self.len -= 1;
        Some(valor)
    }

    pub fn len(&self) -> usize {
        self.len
    }

    pub fn is_empty(&self) -> bool {
        self.len == 0
    }
}

impl<T> Drop for RingBuffer<T> {
    fn drop(&mut self) {
        // Dropar elementos restantes
        while self.pop().is_some() {}
        // Liberar memória
        let layout = std::alloc::Layout::array::<T>(self.capacity).unwrap();
        unsafe {
            std::alloc::dealloc(self.data as *mut u8, layout);
        }
    }
}

fn main() {
    let mut buf = RingBuffer::novo(3);

    buf.push(10).unwrap();
    buf.push(20).unwrap();
    buf.push(30).unwrap();

    // buf.push(40).unwrap();  // buffer cheio — retorna Err(40)

    println!("pop: {:?}", buf.pop());  // Some(10)
    buf.push(40).unwrap();  // agora cabe

    println!("len: {}", buf.len());  // 3
    while let Some(v) = buf.pop() {
        println!("  valor: {}", v);
    }
}
```

**Chamador nunca usa `unsafe`.** Toda a complexidade está encapsulada dentro de `RingBuffer`.

### 10.2 Anti-padrão — funções que deveriam ser safe

```rust
// ANTI-PADRÃO — função safe que pode causar UB
fn obter_elemento(vec: &Vec<i32>, idx: usize) -> i32 {
    unsafe {
        *vec.as_ptr().add(idx)  // pula bounds check!
    }
    // Se idx >= vec.len() → UB silencioso
    // A função é safe, mas o comportamento é indefinido!
}

// CORRETO — Either:
fn obter_elemento_seguro(vec: &Vec<i32>, idx: usize) -> Option<i32> {
    vec.get(idx).copied()  // verifica bounds, retorna Option
}

// Ou se performance é crítica e o chamador garante o idx:
unsafe fn obter_elemento_unchecked(vec: &Vec<i32>, idx: usize) -> i32 {
    debug_assert!(idx < vec.len());  // check em debug, removido em release
    *vec.as_ptr().add(idx)
}
```

### 10.3 Minimizar a superfície unsafe

```rust
// RUIM — bloco unsafe grande
unsafe {
    let a = *ptr1;
    let b = *ptr2;
    algum_calculo(a, b);  // isso não precisa ser unsafe!
    *ptr3 = resultado;
}

// BOM — mínimo de código unsafe
let (a, b) = unsafe { (*ptr1, *ptr2) };
let resultado = algum_calculo(a, b);  // código safe entre unsafe blocks
unsafe { *ptr3 = resultado; }
```

## 11. Exemplo Completo — Vetor Customizado com Alocação Manual

Este exercício implementa apenas tipos de tamanho não zero (`size_of::<T>() > 0`). Um `Vec<T>` de produção também precisa tratar tipos de tamanho zero sem pedir alocação de zero bytes ao alocador; aqui rejeitamos esses tipos explicitamente para manter o contrato de `alloc`/`realloc` válido.

Veja o contrato de tamanho das alocações em [`Layout`](https://doc.rust-lang.org/std/alloc/struct.Layout.html) e a implementação de tipos de tamanho zero em [`Vec`](https://doc.rust-lang.org/std/vec/struct.Vec.html).

```rust
// aula15_unsafe.rs
// Compilar: rustc aula15_unsafe.rs
// Executar: ./aula15_unsafe
// Testar com Miri: cargo +nightly miri run (requer Cargo setup)

use std::alloc::{self, Layout};
use std::ptr;
use std::fmt;

// === MeuVec — Vec implementado do zero ===

pub struct MeuVec<T> {
    ptr: *mut T,
    cap: usize,
    len: usize,
}

impl<T> MeuVec<T> {
    pub fn novo() -> Self {
        assert!(std::mem::size_of::<T>() > 0, "MeuVec não suporta tipos de tamanho zero");
        MeuVec { ptr: ptr::null_mut(), cap: 0, len: 0 }
    }

    pub fn com_capacidade(cap: usize) -> Self {
        assert!(std::mem::size_of::<T>() > 0, "MeuVec não suporta tipos de tamanho zero");
        if cap == 0 {
            return Self::novo();
        }
        let layout = Layout::array::<T>(cap).unwrap();
        let ptr = unsafe { alloc::alloc(layout) as *mut T };
        if ptr.is_null() {
            alloc::handle_alloc_error(layout);
        }
        MeuVec { ptr, cap, len: 0 }
    }

    pub fn push(&mut self, valor: T) {
        if self.len == self.cap {
            self.crescer();
        }
        unsafe {
            ptr::write(self.ptr.add(self.len), valor);
        }
        self.len += 1;
    }

    pub fn pop(&mut self) -> Option<T> {
        if self.len == 0 {
            None
        } else {
            self.len -= 1;
            unsafe { Some(ptr::read(self.ptr.add(self.len))) }
        }
    }

    pub fn get(&self, idx: usize) -> Option<&T> {
        if idx < self.len {
            unsafe { Some(&*self.ptr.add(idx)) }
        } else {
            None
        }
    }

    pub fn get_mut(&mut self, idx: usize) -> Option<&mut T> {
        if idx < self.len {
            unsafe { Some(&mut *self.ptr.add(idx)) }
        } else {
            None
        }
    }

    pub fn len(&self) -> usize { self.len }
    pub fn is_empty(&self) -> bool { self.len == 0 }
    pub fn capacity(&self) -> usize { self.cap }

    fn crescer(&mut self) {
        let nova_cap = if self.cap == 0 { 4 } else { self.cap.checked_mul(2).expect("capacidade excedida") };
        let novo_layout = Layout::array::<T>(nova_cap).unwrap();
        let novo_ptr = unsafe {
            if self.cap == 0 {
                alloc::alloc(novo_layout) as *mut T
            } else {
                let old_layout = Layout::array::<T>(self.cap).unwrap();
                let old_ptr = self.ptr as *mut u8;
                alloc::realloc(old_ptr, old_layout, novo_layout.size()) as *mut T
            }
        };
        if novo_ptr.is_null() {
            alloc::handle_alloc_error(novo_layout);
        }
        self.ptr = novo_ptr;
        self.cap = nova_cap;
    }
}

impl<T> Drop for MeuVec<T> {
    fn drop(&mut self) {
        // Dropar cada elemento
        while self.pop().is_some() {}
        // Liberar memória
        if self.cap > 0 {
            let layout = Layout::array::<T>(self.cap).unwrap();
            unsafe {
                alloc::dealloc(self.ptr as *mut u8, layout);
            }
        }
    }
}

impl<T: fmt::Debug> fmt::Debug for MeuVec<T> {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        let slice = if self.len > 0 {
            unsafe { std::slice::from_raw_parts(self.ptr, self.len) }
        } else {
            &[]
        };
        write!(f, "MeuVec({:?}, cap={})", slice, self.cap)
    }
}

// === Dividir slice — safe wrapper ===

fn dividir<T>(slice: &mut [T], meio: usize) -> (&mut [T], &mut [T]) {
    assert!(meio <= slice.len());
    let ptr = slice.as_mut_ptr();
    unsafe {
        (
            std::slice::from_raw_parts_mut(ptr, meio),
            std::slice::from_raw_parts_mut(ptr.add(meio), slice.len() - meio),
        )
    }
}

// === Demonstração ===

fn main() {
    println!("=== Unsafe Rust em Ação ===\n");

    // 1. MeuVec
    println!("--- MeuVec<T> (Vec do zero) ---\n");

    let mut v: MeuVec<i32> = MeuVec::novo();
    println!("Criado: {:?}", v);

    for i in 0..10 {
        v.push(i * 10);
    }
    println!("Após 10 pushes: {:?}", v);
    println!("len={}, cap={}", v.len(), v.capacity());

    // Acesso por índice
    if let Some(val) = v.get(3) {
        println!("v[3] = {}", val);  // 30
    }

    // Modificar
    if let Some(val) = v.get_mut(5) {
        *val = 999;
    }
    println!("Após v[5] = 999: {:?}", v);

    // Pop
    while let Some(val) = v.pop() {
        println!("  pop: {}", val);
    }
    println!("Após esvaziar: {:?}", v);

    // 2. Dividir slice
    println!("\n--- Dividir Slice (safe wrapper) ---\n");

    let mut dados = vec![1, 2, 3, 4, 5, 6, 7, 8];
    let (esq, dir) = dividir(&mut dados, 4);
    println!("Esquerda: {:?}", esq);
    println!("Direita: {:?}", dir);
    esq[0] = 100;
    dir[0] = 200;
    println!("Original modificado: {:?}", dados);

    // 3. Ponteiros brutos
    println!("\n--- Ponteiros Brutos ---\n");

    let x: i32 = 42;
    let ptr: *const i32 = &x;
    let addr = ptr as usize;
    println!("Endereço de x: {:#x}", addr);
    println!("Tamanho do ponteiro: {} bytes", std::mem::size_of::<*const i32>());
    println!("Alinhamento de i32: {} bytes", std::mem::align_of::<i32>());

    unsafe {
        println!("Valor via ponteiro: {}", *ptr);
    }

    // 4. Union
    println!("\n--- Union ---\n");

    #[repr(C)]
    union Conversor {
        inteiro: u32,
        bytes: [u8; 4],
    }

    let c = Conversor { inteiro: 0x41424344 };
    unsafe {
        println!("Inteiro: {:#x}", c.inteiro);
        println!("Bytes: {:?}", c.bytes);  // little-endian: [0x44, 0x43, 0x42, 0x41]
    }

    // 5. static com Atomic (alternativa segura a static mut)
    println!("\n--- Variáveis Estáticas ---\n");

    use std::sync::atomic::{AtomicUsize, Ordering};
    static CHAMADAS: AtomicUsize = AtomicUsize::new(0);
    CHAMADAS.fetch_add(1, Ordering::Relaxed);
    CHAMADAS.fetch_add(1, Ordering::Relaxed);
    println!("Chamadas: {}", CHAMADAS.load(Ordering::Relaxed));

    // 6. transmute — reinterpretação de bytes (ULTRA PERIGOSO)
    println!("\n--- transmute (cuidado!) ---\n");

    let bytes: [u8; 4] = [0x44, 0x43, 0x42, 0x41];
    #[allow(unnecessary_transmutes)] // demonstracao do transmute em si
    let valor: u32 = unsafe {
        std::mem::transmute::<[u8; 4], u32>(bytes)
    };
    println!("Bytes {:?} → u32 {:#x}", bytes, valor);

    // Alternativa segura (preferir sempre):
    let valor_seguro = u32::from_ne_bytes(bytes);
    println!("Seguro: {:#x}", valor_seguro);
}
```

## 12. Erros Comuns

### Erro 1: Usar `unsafe` para "simplificar" o borrow checker

```rust
// ANTI-PADRÃO
fn duas_refs_mut(slice: &mut [i32]) -> (&mut i32, &mut i32) {
    let ptr = slice.as_mut_ptr();
    unsafe {
        (&mut *ptr, &mut *ptr.add(1))  // Se slice tem 1 elemento → UB!
    }
}

// CORRETO — use split_at_mut (safe)
fn duas_refs_mut_seguro(slice: &mut [i32]) -> (&mut i32, &mut i32) {
    let (a, b) = slice.split_at_mut(1);
    (&mut a[0], &mut b[0])
}
```

### Erro 2: Esquecer de dropar valores ao desalocar

```rust
// ERRO — memory leak de Drop
unsafe {
    let layout = Layout::new::<String>();
    let ptr = alloc::alloc(layout) as *mut String;
    ptr::write(ptr, String::from("olá"));
    // dealloc sem chamar Drop — String vaza o buffer interno!
    alloc::dealloc(ptr as *mut u8, layout);
}

// CORRETO
unsafe {
    ptr::drop_in_place(ptr);  // chama Drop da String
    alloc::dealloc(ptr as *mut u8, layout);
}
```

### Erro 3: `transmute` para tipos com lifetime

```rust
// ERRO — transmute não respeita lifetimes
let r: &'static str = unsafe {
    std::mem::transmute("temporário")  // &'static str de dado temporário → UB!
};
```

### Erro 4: Criar referência para memória não inicializada

```rust
// ERRO — referência para lixo
unsafe {
    let layout = Layout::new::<i32>();
    let ptr = alloc::alloc(layout) as *mut i32;
    // let r: &i32 = &*ptr;  // UB! *ptr não está inicializado
    // Referências SEMPRE apontam para valores válidos

    ptr::write(ptr, 42);  // agora é válido
    let r: &i32 = &*ptr;  // OK
    println!("{}", r);
}
```

### Erro 5: Usar `unsafe` onde safe funciona

```rust
// DESNECESSÁRIO
unsafe {
    let v = vec![1, 2, 3];
    let x = *v.as_ptr().add(1);  // por que não v[1]?
}

// CORRETO
let v = vec![1, 2, 3];
let x = v[1];  // seguro, com bounds check
let y = v.get(1);  // seguro, sem panic
```

## 13. Comparação — C vs Rust (Unsafe)

| Aspecto | C | Rust unsafe |
|---------|---|-------------|
| Toda função é unsafe? | Sim (implicitamente) | Não — apenas blocos/funções marcadas |
| Bounds check | Manual (nunca) | Safe code: automático. Unsafe: manual |
| Ponteiros null | Comum (UB se deref) | Possível, mas raro |
| Memory leak | Comum | Possível, mas Drop previne na maioria |
| Data race detection | Nenhuma | `Send`/`Sync` traits previnem fora de unsafe |
| Ferramentas | Valgrind, ASan, UBSan | Miri (detecta UB em Rust) |
| Documentação de invariantes | Nenhum padrão | `# Safety` comments obrigatórios |
| Escopo do "perigo" | Programa inteiro | Apenas onde `unsafe` aparece |
| % do código unsafe | 100% | Tipicamente <5% (std: ~10%) |

**Na std library do Rust (1.75):**
- ~10% do código é `unsafe`
- ~90% é safe
- Todo `unsafe` é encapsulado em APIs seguras

## 14. Checklist — Quando Usar `unsafe`

| Situação | Precisa de unsafe? | Alternativa safe |
|----------|-------------------|-----------------|
| Acessar `Vec[i]` | Não | `v[i]` ou `v.get(i)` |
| Ponteiro aritmético | Sim | Iterators, slices |
| Chamar função C | Sim | bindgen (gera bindings), cxx crate |
| Escrever allocator | Sim | `std::alloc` com cuidado |

| Cast de tipos (transmute) | Sim | `from_bits`, `try_from`, `bytemuck` crate |
| Acessar hardware (embedded) | Sim | `svd2rust`, PAC/HAL crates |
