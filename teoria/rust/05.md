# Aula 5 — Structs, Enums e Pattern Matching

---

## Nesta aula

Dominar os mecanismos de modelagem de dados em Rust: **structs** (dados nomeados), **enums** (dados variantes — muito mais poderosos que C), e **pattern matching** com `match` e `if let`. Você vai aprender a definir structs com campos nomeados, construir enums com dados associados, escrever `match` exaustivo, usar `if let` para um caso de interesse, e prever o que o compilador reclama quando um padrão é esquecido.

## 1. Structs — Dados Nomeados

### 1.1 Struct clássica (campos nomeados)

**Struct** é a forma básica de dizer: "esses campos pertencem à mesma entidade".

Por que isso existe?

- para modelar dados compostos;
- para dar nome semântico ao agrupamento;
- para substituir pares soltos de variáveis por um tipo coerente.

Em outras palavras, `struct Ponto { x, y }` é mais expressivo e seguro do que carregar `x` e `y` separadamente pelo programa inteiro.

```rust
struct Ponto {
    x: f64,
    y: f64,
}

fn main() {
    let p = Ponto { x: 3.0, y: 4.0 };
    println!("ponto: ({}, {})", p.x, p.y);
    println!("distância da origem: {}", (p.x * p.x + p.y * p.y).sqrt());
}
```

**Comparação com C:**
```c
struct Ponto {
    double x;
    double y;
};

struct Ponto p = {3.0, 4.0};
```

Diferenças:
- Rust não precisa de `typedef` — `Ponto` já é o tipo diretamente.
- Rust exige **inicialização completa** — não existe struct parcialmente inicializada.
- Campos são privados por padrão fora do módulo (veremos na Aula 6).

- **Inicialização completa**: todos os campos devem receber valor válido antes do uso.
- Isso existe para impedir objetos parcialmente construídos, um problema clássico em código de baixo nível quando memória é reservada mas nem todos os campos são corretamente definidos.

### 1.2 Struct mutável

Em Rust, você não marca campos individuais como `mut`. Marca a **variável inteira**:

```rust
struct Ponto {
    x: f64,
    y: f64,
}

fn main() {
    let mut p = Ponto { x: 3.0, y: 4.0 };
    p.x = 5.0;    // OK — p é mut
    p.y = 12.0;

    // let q = Ponto { x: 1.0, y: 2.0 };
    // q.x = 3.0;  // ERRO: cannot assign to `q.x`, as `q` is not declared as mutable
}
```

Isso é deliberado: mutabilidade é da variável, não do campo. Facilita o raciocínio — se `p` é `mut`, tudo em `p` pode mudar. Se não é, nada muda.

### 1.3 Métodos com `impl`

- **Método**: função associada a um tipo.
- **`impl`**: bloco onde declaramos comportamentos do tipo.

Por que o `impl` existe?

- para organizar operações ao redor do próprio tipo;
- para expressar claramente "esta função pertence logicamente a este tipo";
- para aproximar dados e comportamento sem precisar do modelo de classes de C++.

```rust
#[derive(Debug)]
struct Ponto {
    x: f64,
    y: f64,
}

impl Ponto {
    // Método associativo (como "construtor estático")
    // Não recebe &self — é chamado via Ponto::origem()
    fn origem() -> Ponto {
        Ponto { x: 0.0, y: 0.0 }
    }

    // Método de instância — recebe &self (borrow imutável)
    fn distancia(&self, outro: &Ponto) -> f64 {
        let dx = self.x - outro.x;
        let dy = self.y - outro.y;
        (dx * dx + dy * dy).sqrt()
    }

    // Método que modifica — recebe &mut self
    fn transladar(&mut self, dx: f64, dy: f64) {
        self.x += dx;
        self.y += dy;
    }

    // Método que consome self — recebe self ( ownership)
    fn para_array(self) -> [f64; 2] {
        [self.x, self.y]
    }
}

fn main() {
    let mut p1 = Ponto { x: 3.0, y: 4.0 };
    let p2 = Ponto::origem();

    println!("distância: {:.2}", p1.distancia(&p2));  // 5.00
    p1.transladar(1.0, 1.0);
    println!("depois de transladar: {:?}", p1);        // Ponto { x: 4.0, y: 5.0 }

    let coords = p1.para_array();   // p1 é consumido
    // println!("{:?}", p1);        // ERRO: p1 foi movido
    println!("coords: {:?}", coords);
}
```

**Os 4 modos de `self` em métodos:**

| Assinatura | Recebe | Ownership | Uso |
|------------|--------|-----------|-----|
| `&self` | Referência imutável | Borrow | Ler dados |
| `&mut self` | Referência mutável | Borrow mutável | Modificar dados |
| `self` | Valor (move) | Consome | Destruir/transformar |
| Sem self | Nada | — | Construtor/fábrica |

Aqui, `self` significa "a instância atual do tipo".

- `&self`: empresta a instância para leitura;
- `&mut self`: empresta a instância para modificação;
- `self`: consome a instância, transferindo ownership.

Essa tabela conecta diretamente os métodos ao sistema de ownership da Aula 3.

**Comparação com C++:**
```cpp
class Ponto {
    double x, y;
public:
    Ponto(double x, double y) : x(x), y(y) {}
    double distancia(const Ponto& outro) const;
    void transladar(double dx, double dy);
};

Ponto p(3.0, 4.0);
p.transladar(1.0, 1.0);
```

Rust não tem `this` implícito — usa `self` explicitamente. Não tem construtores nomeados — usa funções associativas (`Ponto::origem()`). Não tem destrutores manuais — `Drop` trait (veremos depois).

### 1.4 Tuple struct — struct sem nomes de campo

```rust
struct Cor(u8, u8, u8);       // RGB
struct Km(f64);                // wrapper type (newtype pattern)

fn main() {
    let vermelho = Cor(255, 0, 0);
    println!("R={}, G={}, B={}", vermelho.0, vermelho.1, vermelho.2);

    let distancia = Km(42.5);
    println!("distância: {} km", distancia.0);
}
```

Tuple structs são úteis quando você quer um tipo nomeado mas os campos são óbvios por posição. O **newtype pattern** (`struct Km(f64)`) cria um tipo distinto — `Km` não é `f64`, não pode ser confundido com `f64` em parâmetros de função.

- **Newtype pattern**: técnica de criar um novo tipo embrulhando outro tipo existente.
- Para que serve? Para dar significado semântico e impedir misturas acidentais de valores compatíveis em nível de bits, mas diferentes em nível de domínio.

Exemplo mental: `Km(f64)` e `Segundos(f64)` poderiam ambos ser `f64`, mas não deveriam ser intercambiáveis.

### 1.5 Unit struct — sem campos

```rust
struct Marcador;

fn main() {
    let _m = Marcador;
}
```

Usado para tipos que representam estados ou markers sem dados. Veremos utilidade com traits.

### 1.6 Derive — traits automáticos

- **Trait**: conjunto de capacidades ou comportamentos que um tipo pode implementar.
- **`derive`**: mecanismo que pede ao compilador para gerar automaticamente implementações padrão de traits comuns.

Por que isso existe?

- para reduzir código repetitivo;
- para padronizar comportamentos comuns como comparação, cópia, impressão e clonagem.

```rust
#[derive(Debug, Clone, Copy, PartialEq)]
struct Ponto {
    x: f64,
    y: f64,
}

fn main() {
    let p1 = Ponto { x: 3.0, y: 4.0 };
    let p2 = p1;  // Copy — não move

    println!("{:?}", p1);           // Debug
    println!("{:?}", p2);           // ambos válidos
    println!("igual? {}", p1 == p2);  // PartialEq → true
}
```

`#[derive(...)]` implementa traits automaticamente:
- `Debug` — permite `{:?}` em `println!`
- `Clone` — permite `.clone()`
- `Copy` — permite cópia em vez de move
- `PartialEq` — permite `==` e `!=`
- `Eq` — igualdade total
- `PartialOrd` / `Ord` — permite `<`, `>`, ordenação
- `Hash` — permite uso como chave em HashMap

## 2. Enums — O Poder dos Tipos de Dados Algébricos

### 2.1 O que é enum em Rust vs C

**Em C, enum é apenas inteiros nomeados:**
```c
enum Cor { VERMELHO, VERDE, AZUL };          // 0, 1, 2
enum Status { OK = 0, ERRO = 1, PENDENTE = 2 };
```

**Em Rust, enum pode carregar dados:**
```rust
enum Forma {
    Circulo { raio: f64 },             // variante com campos nomeados
    Retangulo { largura: f64, altura: f64 },
    Triangulo(f64, f64, f64),          // variante com tupla
    Ponto,                             // variante sem dados
}
```

Isso é um **tipo de dados algébrico (ADT)** — cada variante pode ter dados completamente diferentes. Isso substitui:

Vamos traduzir os termos:

- **Enum**: tipo cujos valores possíveis são variantes nomeadas.
- **Variante**: cada forma possível daquele enum.
- **ADT (Algebraic Data Type)**: tipo que pode assumir formas estruturalmente diferentes, cada uma com seus próprios dados.

Por que isso é importante?

- porque muitos problemas reais têm exatamente esse formato: um valor pode estar em um entre vários estados, e cada estado carrega dados diferentes;
- Rust eleva isso a um recurso nativo e seguro, em vez de forçar `enum + union + tag manual` como em C.

| C/C++ | Rust |
|-------|------|
| `enum` + `union` | `enum` com dados |
| `struct` com `type` tag | `enum` variant |
| Herança com `virtual` | `enum` + `match` |
| `std::variant` (C++17) | `enum` (nativo, muito mais ergonômico) |

### 2.2 Enum básico

```rust
enum Direcao {
    Norte,
    Sul,
    Leste,
    Oeste,
}

fn main() {
    let dir = Direcao::Norte;

    match dir {
        Direcao::Norte => println!("Apontando para o norte"),
        Direcao::Sul   => println!("Apontando para o sul"),
        Direcao::Leste => println!("Apontando para o leste"),
        Direcao::Oeste => println!("Apontando para o oeste"),
    }
}
```

### 2.3 Enum com dados — o exemplo clássico

```rust
// Representação de um endereço IP — v4 ou v6
// Cada variante carrega dados diferentes
enum IpAddr {
    V4(u8, u8, u8, u8),
    V6(String),
}

fn main() {
    let home = IpAddr::V4(127, 0, 0, 1);
    let server = IpAddr::V6(String::from("::1"));

    descrever_ip(&home);
    descrever_ip(&server);
}

fn descrever_ip(ip: &IpAddr) {
    match ip {
        IpAddr::V4(a, b, c, d) => {
            println!("IPv4: {}.{}.{}.{}", a, b, c, d);
        }
        IpAddr::V6(addr) => {
            println!("IPv6: {}", addr);
        }
    }
}
```

Saída:
```
IPv4: 127.0.0.1
IPv6: ::1
```

**O equivalente em C seria:**
```c
typedef enum { IP_V4, IP_V6 } IpKind;

typedef struct {
    IpKind kind;
    union {
        struct { uint8_t a, b, c, d; } v4;
        char v6[46];
    };
} IpAddr;

void descrever_ip(const IpAddr* ip) {
    switch (ip->kind) {
        case IP_V4:
            printf("IPv4: %d.%d.%d.%d\n", ip->v4.a, ip->v4.b, ip->v4.c, ip->v4.d);
            break;
        case IP_V6:
            printf("IPv6: %s\n", ip->v6);
            break;
        // ESQUECER O BREAK? UB. ESQUECER UM CASE? BUG SILENCIOSO.
    }
}
```

Em Rust:
- Não há `union` inseguro — os dados estão dentro do enum.
- O `match` é **exaustivo** — esquecer um variant é **erro de compilação**.
- Não há fall-through — impossível esquecer `break`.
- Os dados de cada variante só são acessíveis dentro do braço correspondente.

- **Exaustivo**: todos os casos possíveis devem ser cobertos.
- **Fall-through**: comportamento do `switch` em C em que a execução pode continuar para o próximo `case` se você esquecer `break`.

Essa combinação existe para trocar bugs silenciosos por erros de compilação explícitos.

### 2.4 Enum com dados complexos

```rust
enum Mensagem {
    Sair,                                  // sem dados
    Mover { x: i32, y: i32 },             // struct-like
    Escrever(String),                      // String (heap)
    MudarCor(u8, u8, u8),                 // tupla
    Redimensionar(Vec<(u32, u32)>),        // Vec de tuplas
}

fn processar(msg: Mensagem) {
    match msg {
        Mensagem::Sair => {
            println!("Saindo...");
        }
        Mensagem::Mover { x, y } => {
            println!("Mover para ({}, {})", x, y);
        }
        Mensagem::Escrever(texto) => {
            println!("Texto: '{}'", texto);
        }
        Mensagem::MudarCor(r, g, b) => {
            println!("Cor: rgb({}, {}, {})", r, g, b);
        }
        Mensagem::Redimensionar(dimensoes) => {
            println!("Redimensionar para {} tamanhos", dimensoes.len());
        }
    }
}

fn main() {
    processar(Mensagem::Sair);
    processar(Mensagem::Mover { x: 10, y: 20 });
    processar(Mensagem::Escrever(String::from("olá")));
    processar(Mensagem::MudarCor(255, 128, 0));
    processar(Mensagem::Redimensionar(vec![(800, 600), (1024, 768)]));
}
```

### 2.5 Option<T> — o enum mais importante de Rust

`Option<T>` é definido na biblioteca padrão assim:

```rust
enum Option<T> {
    Some(T),   // tem valor
    None,      // não tem valor
}
```

**Option substitui null.** Em Rust, **não existe null**. Em vez disso, valores que podem estar ausentes usam `Option<T>`.

Essa é uma das decisões mais importantes da linguagem.

Por que `Option<T>` existe?

- para representar ausência de valor de forma explícita;
- para impedir que o programador trate "talvez exista" como "com certeza existe";
- para eliminar a classe clássica de bugs com null pointers.

Pense assim:

- `Some(T)` = tenho um valor válido;
- `None` = não tenho valor.

```rust
fn encontrar_usuario(id: u32) -> Option<String> {
    if id == 1 {
        Some(String::from("Alice"))
    } else if id == 2 {
        Some(String::from("Bob"))
    } else {
        None
    }
}

fn main() {
    match encontrar_usuario(1) {
        Some(nome) => println!("Encontrado: {}", nome),
        None       => println!("Usuário não encontrado"),
    }

    match encontrar_usuario(99) {
        Some(nome) => println!("Encontrado: {}", nome),
        None       => println!("Usuário não encontrado"),
    }
}
```

Saída:
```
Encontrado: Alice
Usuário não encontrado
```

**Comparação com C — o problema do null:**
```c
// C — null é um valor válido de qualquer ponteiro
char* encontrar_usuario(int id) {
    if (id == 1) return "Alice";
    return NULL;           // chamador deve lembrar de verificar
}

char* nome = encontrar_usuario(99);
printf("%s\n", nome);       // SEGFAULT se esquecer de verificar NULL!
printf("tamanho: %zu\n", strlen(nome));  // UB!
```

Tony Hoare, inventor do null, chama isso de "seu erro de um bilhão de dólares". Rust elimina isso:

```rust
let nome: Option<String> = encontrar_usuario(99);
// println!("{}", nome);           // ERRO: Option<String> não é String
// println!("{}", nome.len());     // ERRO: não existe .len() em Option
// O COMPILADOR TE OBRIGA a lidar com o caso None!
```

### 2.6 Métodos em Option

```rust
fn main() {
    let x: Option<i32> = Some(42);
    let y: Option<i32> = None;

    // is_some / is_none
    println!("x tem valor? {}", x.is_some());  // true
    println!("y tem valor? {}", y.is_some());  // false

    // unwrap — extrai o valor, panic se None
    // println!("{}", y.unwrap());  // PANIC: called `Option::unwrap()` on a `None` value

    // unwrap_or — valor padrão
    println!("y ou 0: {}", y.unwrap_or(0));    // 0

    // map — transforma o valor interno
    let dobrado = x.map(|v| v * 2);
    println!("dobrado: {:?}", dobrado);         // Some(84)

    // and_then — encadeia operações que retornam Option
    let resultado = x.and_then(|v| {
        if v > 10 {
            Some(v * 100)
        } else {
            None
        }
    });
    println!("resultado: {:?}", resultado);      // Some(4200)

    // if let — extrai sem match completo
    if let Some(valor) = x {
        println!("x contém: {}", valor);         // 42
    }
}
```

### 2.7 Result<T, E> — outro enum essencial

```rust
enum Result<T, E> {
    Ok(T),     // sucesso
    Err(E),    // erro
}
```

`Result` é como `Option`, mas o caso de ausência carrega informação sobre o erro. Veremos em detalhes na Aula 8, mas vamos usar o básico:

- `Ok(T)`: operação bem-sucedida;
- `Err(E)`: operação falhou, e `E` descreve o erro.

`Result` existe porque falhas fazem parte do fluxo normal de sistemas reais: arquivo pode não existir, conexão pode cair, parsing pode falhar. Rust força isso a aparecer no tipo.

```rust
use std::fs;

fn main() {
    match fs::read_to_string("arquivo.txt") {
        Ok(conteudo) => println!("Conteúdo: {}", conteudo),
        Err(erro)    => println!("Erro: {}", erro),
    }
}
```

## 3. Pattern Matching — `match`

**Pattern matching** é o mecanismo de comparar a forma de um valor contra padrões e, se houver encaixe, extrair seus dados.

Por que isso existe?

- para lidar com enums, structs, tuplas e valores compostos de forma declarativa;
- para substituir cadeias frágeis de `if`, `switch`, casts e acesso manual;
- para deixar o compilador verificar cobertura de casos.

### 3.1 match básico

```rust
fn main() {
    let numero = 3;

    match numero {
        1 => println!("um"),
        2 => println!("dois"),
        3 => println!("três"),
        4 | 5 => println!("quatro ou cinco"),       // OR pattern
        6..=10 => println!("entre 6 e 10"),          // range pattern
        _ => println!("outro número"),               // wildcard (catch-all)
    }
}
```

**Comparação com switch em C:**
```c
switch (numero) {
    case 1: printf("um\n"); break;
    case 2: printf("dois\n"); break;
    case 3: printf("três\n"); break;
    // ESQUECER O BREAK? Fall-through silencioso!
    // ESQUECER UM CASE? Nenhum aviso!
    default: printf("outro\n"); break;
}
```

Rust:
- Não tem fall-through — cada braço é independente.
- É **exaustivo** — se você esquecer um caso, erro de compilação.
- Pode usar OR (`|`), ranges (`..=`), guards (`if`), bindings (`@`).
- É uma **expressão** — retorna um valor.

- **Pattern**: molde que descreve a forma esperada de um valor.
- **Guard**: condição adicional aplicada ao braço do `match`.
- **Binding**: criação de um nome para o valor capturado pelo padrão.

### 3.2 match é uma expressão

```rust
fn main() {
    let x = 3;

    let descricao = match x {
        1 => "um",
        2 | 3 => "dois ou três",
        _ => "outro",
    };

    println!("x é {}", descricao);  // "x é dois ou três"
}
```

Os braços devem retornar o **mesmo tipo**. E deve ser exaustivo.

### 3.3 Desestruturação de struct

```rust
struct Ponto {
    x: f64,
    y: f64,
}

fn main() {
    let p = Ponto { x: 3.0, y: -4.0 };

    match p {
        Ponto { x: 0.0, y: 0.0 } => println!("origem"),
        Ponto { x: _, y: 0.0 }   => println!("no eixo x"),
        Ponto { x: 0.0, y: _ }   => println!("no eixo y"),
        Ponto { x, y }           => println!("({}, {})", x, y),
    }
}
```

### 3.4 Desestruturação de enum

```rust
enum Forma {
    Circulo(f64),              // raio
    Retangulo(f64, f64),       // largura, altura
    Triangulo(f64, f64, f64),  // lados a, b, c
}

fn area(f: &Forma) -> f64 {
    match f {
        Forma::Circulo(raio) => std::f64::consts::PI * raio * raio,
        Forma::Retangulo(larg, alt) => larg * alt,
        Forma::Triangulo(a, b, c) => {
            // Fórmula de Heron
            let s = (a + b + c) / 2.0;
            (s * (s - a) * (s - b) * (s - c)).sqrt()
        }
    }
}

fn main() {
    let formas = [
        Forma::Circulo(5.0),
        Forma::Retangulo(3.0, 4.0),
        Forma::Triangulo(3.0, 4.0, 5.0),
    ];

    for f in &formas {
        println!("área: {:.2}", area(f));
    }
}
```

Saída:
```
área: 78.54
área: 12.00
área: 6.00
```

### 3.5 Match guards — filtrando com `if`

```rust
fn main() {
    let par = (2, -3);

    match par {
        (0, 0) => println!("origem"),
        (x, 0) => println!("no eixo x, x={}", x),
        (0, y) => println!("no eixo y, y={}", y),
        (x, y) if x == y => println!("na diagonal, valor={}", x),
        (x, y) if x == -y => println!("na antidiagonal: ({}, {})", x, y),
        (x, y) => println!("ponto: ({}, {})", x, y),
    }
}
```

Saída:
```
na antidiagonal: (2, -3)
```

### 3.6 Binding com `@`

```rust
fn main() {
    let idade: i32 = 25;

    match idade {
        0 => println!("recém-nascido"),
        n @ 1..=12 => println!("criança, idade={}", n),
        n @ 13..=17 => println!("adolescente, idade={}", n),
        n @ 18..=64 => println!("adulto, idade={}", n),
        n @ 65..=120 => println!("idoso, idade={}", n),
        _ => println!("idade inválida"),
    }
}
```

Saída:
```
adulto, idade=25
```

O `@` cria um binding (variável) ao mesmo tempo que testa o range. `n @ 18..=64` significa: "se o valor está entre 18 e 64, chame-o de `n`".

### 3.7 Match em Option — o uso mais comum

```rust
fn dividir(a: f64, b: f64) -> Option<f64> {
    if b == 0.0 {
        None
    } else {
        Some(a / b)
    }
}

fn main() {
    let resultados = [dividir(10.0, 3.0), dividir(5.0, 0.0)];

    for r in resultados {
        match r {
            Some(valor) => println!("resultado: {:.4}", valor),
            None        => println!("divisão por zero!"),
        }
    }
}
```

Saída:
```
resultado: 3.3333
divisão por zero!
```

## 4. `if let` — Match Simplificado

Quando você só se importa com **um padrão** e quer ignorar o resto:

`if let` existe para reduzir verbosidade.

Use-o quando:

- você só quer tratar um único caso;
- o restante pode ser ignorado ou tratado por um `else` simples.

Se vários casos importam, `match` continua sendo a ferramenta mais clara.

```rust
fn main() {
    let valor: Option<i32> = Some(42);

    // Com match (verboso quando só queremos um caso)
    match valor {
        Some(v) => println!("valor: {}", v),
        _ => (),   // ignora o resto
    }

    // Com if let (mais limpo)
    if let Some(v) = valor {
        println!("valor: {}", v);
    }

    // Com else
    if let Some(v) = valor {
        println!("tem valor: {}", v);
    } else {
        println!("nenhum valor");
    }
}
```

### `while let` — loop condicional com pattern

```rust
fn main() {
    let mut pilha: Vec<i32> = vec![1, 2, 3, 4, 5];

    while let Some(topo) = pilha.pop() {
        println!("desempilhou: {}", topo);
    }
    println!("pilha vazia: {:?}", pilha);
}
```

Saída:
```
desempilhou: 5
desempilhou: 4
desempilhou: 3
desempilhou: 2
desempilhou: 1
pilha vazia: []
```

## 5. Modelo Mental — Layout de Enums em Memória

### 5.1 Enum simples (sem dados)

```rust
enum Direcao { Norte, Sul, Leste, Oeste }
let d = Direcao::Norte;
```

```
Stack:
┌────────────┐
│ d: u8 = 0  │  // discriminant: Norte=0, Sul=1, Leste=2, Oeste=3
└────────────┘
Tamanho: 1 byte
```

- **Discriminant**: valor interno usado para indicar qual variante do enum está ativa.
- Em enums sem dados, ele praticamente basta para representar tudo.

### 5.2 Enum com dados

```rust
enum Forma {
    Circulo(f64),          // 8 bytes de dados
    Retangulo(f64, f64),   // 16 bytes de dados
}
```

```
Stack (Forma::Circulo(5.0)):
┌─────────────────────────────────────┐
│ discriminant: 0 (Circulo)  │ 1 byte + padding
│ dados:                     │
│   f64 = 5.0                │ 8 bytes
└─────────────────────────────────────┘
Tamanho: 16 bytes (1 + 7 padding + 8, ou discriminant otimizado)

Stack (Forma::Retangulo(3.0, 4.0)):
┌─────────────────────────────────────┐
│ discriminant: 1 (Retangulo) │
│ dados:                     │
│   f64 = 3.0                │
│   f64 = 4.0                │
└─────────────────────────────────────┘
Tamanho: 24 bytes (1 + 7 padding + 16)
```

O tamanho do enum é: **maior variante + discriminant + padding**. Rust usa o espaço do maior variante porque qualquer variante pode estar ativo.

Isso é importante para entender custo de memória:

- enum não significa alocar uma estrutura separada para cada variante;
- significa reservar espaço suficiente para a maior delas e um marcador de qual está ativa.

**Comparação com C:**
```c
// Em C, você precisaria manualmente:
typedef enum { CIRCULO, RETANGULO } FormaKind;

typedef struct {
    FormaKind kind;
    union {
        struct { double raio; } circulo;
        struct { double larg, alt; } retangulo;
    } dados;
} Forma;
```

Em C, você gerencia o union manualmente. Errar o kind e acessar o campo errado = UB. Em Rust, o `match` garante acesso seguro.

### 5.3 Option<T> e a otimização null-pointer

```rust
let x: Option<&i32> = Some(&42);
let y: Option<&i32> = None;
```

Rust otimiza `Option<&T>` para ter o **mesmo tamanho** que `&T`:
- `Some(ptr)` → o ponteiro normal (nunca null)
- `None` → representado como ponteiro null

```
sizeof(&i32) = 8 bytes
sizeof(Option<&i32>) = 8 bytes  // SEM OVERHEAD!
```

Isso é a **null pointer optimization**. Em C, você usaria NULL. Em Rust, usa `None`, mas com o mesmo custo. Zero overhead abstração.

## 6. Exemplo Completo — Calculadora com Expressões

```rust
// aula5_enums.rs
// Compilar: rustc aula5_enums.rs
// Executar: ./aula5_enums

use std::fmt;

// Enum que representa expressões matemáticas (AST simplificada)
#[derive(Debug, Clone, PartialEq)]
enum Expr {
    Numero(f64),
    Soma(Box<Expr>, Box<Expr>),
    Sub(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
    Div(Box<Expr>, Box<Expr>),
    Neg(Box<Expr>),
}

// Box<T> — ponteiro inteligente que aloca no heap
// Necessário aqui porque Expr contém Expr recursivamente
// Veremos Box em detalhes na Aula 12

impl Expr {
    fn numero(v: f64) -> Box<Expr> {
        Box::new(Expr::Numero(v))
    }

    fn soma(a: Box<Expr>, b: Box<Expr>) -> Box<Expr> {
        Box::new(Expr::Soma(a, b))
    }

    fn sub(a: Box<Expr>, b: Box<Expr>) -> Box<Expr> {
        Box::new(Expr::Sub(a, b))
    }

    fn mul(a: Box<Expr>, b: Box<Expr>) -> Box<Expr> {
        Box::new(Expr::Mul(a, b))
    }

    fn div(a: Box<Expr>, b: Box<Expr>) -> Box<Expr> {
        Box::new(Expr::Div(a, b))
    }

    fn neg(a: Box<Expr>) -> Box<Expr> {
        Box::new(Expr::Neg(a))
    }
}

// Avaliar a expressão
fn avaliar(expr: &Expr) -> Result<f64, String> {
    match expr {
        Expr::Numero(v) => Ok(*v),
        Expr::Soma(a, b) => {
            let va = avaliar(a)?;
            let vb = avaliar(b)?;
            Ok(va + vb)
        }
        Expr::Sub(a, b) => {
            let va = avaliar(a)?;
            let vb = avaliar(b)?;
            Ok(va - vb)
        }
        Expr::Mul(a, b) => {
            let va = avaliar(a)?;
            let vb = avaliar(b)?;
            Ok(va * vb)
        }
        Expr::Div(a, b) => {
            let va = avaliar(a)?;
            let vb = avaliar(b)?;
            if vb == 0.0 {
                Err(String::from("divisão por zero"))
            } else {
                Ok(va / vb)
            }
        }
        Expr::Neg(a) => {
            let va = avaliar(a)?;
            Ok(-va)
        }
    }
}

// Imprimir a expressão (pretty print)
impl fmt::Display for Expr {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            Expr::Numero(v) => write!(f, "{}", v),
            Expr::Soma(a, b) => write!(f, "({} + {})", a, b),
            Expr::Sub(a, b) => write!(f, "({} - {})", a, b),
            Expr::Mul(a, b) => write!(f, "({} * {})", a, b),
            Expr::Div(a, b) => write!(f, "({} / {})", a, b),
            Expr::Neg(a)    => write!(f, "(-{})", a),
        }
    }
}

// Struct para representar um cálculo
struct Calculo {
    expressao: Box<Expr>,
    descricao: String,
}

impl Calculo {
    fn novo(descricao: &str, expressao: Box<Expr>) -> Self {
        Calculo {
            expressao,
            descricao: descricao.to_string(),
        }
    }

    fn executar(&self) {
        println!("Cálculo: {}", self.descricao);
        println!("  Expressão: {}", self.expressao);

        match avaliar(&self.expressao) {
            Ok(resultado) => println!("  Resultado: {:.4}\n", resultado),
            Err(erro) => println!("  ERRO: {}\n", erro),
        }
    }
}

fn main() {
    println!("=== Calculadora com Enums e Pattern Matching ===\n");

    // (3 + 4) * 2 = 14
    let c1 = Calculo::novo(
        "Multiplicação após soma",
        Expr::mul(
            Expr::soma(Expr::numero(3.0), Expr::numero(4.0)),
            Expr::numero(2.0),
        ),
    );

    // (10 - 3) / (1 + 1) = 3.5
    let c2 = Calculo::novo(
        "Divisão de subtração",
        Expr::div(
            Expr::sub(Expr::numero(10.0), Expr::numero(3.0)),
            Expr::soma(Expr::numero(1.0), Expr::numero(1.0)),
        ),
    );

    // 10 / 0 → erro
    let c3 = Calculo::novo(
        "Divisão por zero",
        Expr::div(Expr::numero(10.0), Expr::numero(0.0)),
    );

    // -(5 * 3) = -15
    let c4 = Calculo::novo(
        "Negação",
        Expr::neg(Expr::mul(Expr::numero(5.0), Expr::numero(3.0))),
    );

    for calculo in [&c1, &c2, &c3, &c4] {
        calculo.executar();
    }

    // Demonstração de Option com map e and_then
    println!("=== Option encadeado ===\n");

    let numeros = [Some(10), Some(20), None, Some(30)];

    for (i, opt) in numeros.iter().enumerate() {
        let resultado = opt
            .map(|n| n * 2)
            .and_then(|n| if n > 30 { Some(n) } else { None });

        println!("[{}] {:?} → {:?}", i, opt, resultado);
    }

    // Pattern matching avançado
    println!("\n=== Pattern Matching Avançado ===\n");

    enum Comando {
        Sair,
        Listar,
        Criar { nome: String, valor: i32 },
        Deletar(u32),
    }

    let comandos = [
        Comando::Sair,
        Comando::Listar,
        Comando::Criar { nome: String::from("item"), valor: 42 },
        Comando::Deletar(7),
    ];

    for cmd in &comandos {
        match cmd {
            Comando::Sair => println!("→ Saindo do programa"),
            Comando::Listar => println!("→ Listando itens"),
            Comando::Criar { nome, valor } => {
                println!("→ Criando '{}' com valor {}", nome, valor);
            }
            Comando::Deletar(id) => {
                println!("→ Deletando item #{}", id);
            }
        }
    }
}
```

Compilar e executar:
```bash
rustc aula5_enums.rs
./aula5_enums
```

Saída esperada:
```
=== Calculadora com Enums e Pattern Matching ===

Cálculo: Multiplicação após soma
  Expressão: ((3 + 4) * 2)
  Resultado: 14.0000

Cálculo: Divisão de subtração
  Expressão: ((10 - 3) / (1 + 1))
  Resultado: 3.5000

Cálculo: Divisão por zero
  Expressão: (10 / 0)
  ERRO: divisão por zero

Cálculo: Negação
  Expressão: (-(5 * 3))
  Resultado: -15.0000

=== Option encadeado ===

[0] Some(10) → None
[1] Some(20) → None
[2] None → None
[3] Some(30) → Some(60)

=== Pattern Matching Avançado ===

→ Saindo do programa
→ Listando itens
→ Criando 'item' com valor 42
→ Deletando item #7
```

## 7. Erros Comuns

### Erro 1: Match não exaustivo

```rust
let x = 3;
match x {
    1 => println!("um"),
    2 => println!("dois"),
    // erroE0004: non-exhaustive patterns: `3u32..=u32::MAX` not covered
}
```

**Solução:** Adicione `_ =>` para o caso padrão, ou cubra todos os casos.

### Erro 2: Acessar dados do enum sem match

```rust
enum Forma { Circulo(f64), Quadrado(f64) }
let f = Forma::Circulo(5.0);
// println!("{}", f.0);  // ERRO: no field `0` on type `Forma`
```

**Solução:** Use `match` ou `if let` para extrair:
```rust
if let Forma::Circulo(raio) = f {
    println!("raio: {}", raio);
}
```

### Erro 3: Esquecer Box em tipos recursivos

```rust
// enum Expr {
//     Numero(f64),
//     Soma(Expr, Expr),  // ERRO: recursive type has infinite size
// }
```

**Solução:** Use `Box<Expr>` para quebrar a recursão — o tamanho de `Box` é fixo (um ponteiro):
```rust
enum Expr {
    Numero(f64),
    Soma(Box<Expr>, Box<Expr>),  // OK — Box tem tamanho fixo
}
```

### Erro 4: Derivar Copy em tipo com dados não-Copy

```rust
// #[derive(Copy)]
// struct Dado { nome: String }  // ERRO: the trait `Copy` cannot be implemented for this type
```

**Solução:** `String` não é `Copy`. Remova `Copy` ou use `&str` (que é Copy).

### Erro 5: Struct parcialmente inicializada

```rust
// let p = Ponto { x: 3.0 };  // ERRO: missing field `y`
```

**Solução:** Rust exige inicialização completa de todos os campos.

## 8. Comparação — C/C++ vs Rust (Tipos de Dados)

| Conceito | C/C++ | Rust |
|----------|-------|------|
| Struct com campos | `struct Ponto { double x, y; };` | `struct Ponto { x: f64, y: f64 }` |
| Métodos | Funções separadas ou C++ classes | `impl Struct { fn metodo(&self) {} }` |
| Enum | Inteiros nomeados | Tipos de dados algébricos com dados |
| Union | Inseguro (UB acessar membro errado) | Enum com variantes (seguro) |
| Tagged union | Manual (enum + union) | Automático (enum com dados) |
| Null | `NULL` / `nullptr` | `Option<T>` — sem null |
| Switch | Fall-through, não exaustivo | `match` — sem fall-through, exaustivo |
| Pattern matching | Não existe | Nativo, em structs/enums/tuplas/arrays |
| Tipo recursivo | Ponteiros manualmente | `Box<T>` para recursão |

### Exercício 7 — Sistema de permissões com pattern matching
