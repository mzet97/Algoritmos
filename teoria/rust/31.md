Para coroar tudo o que aprendemos, vamos construir a espinha dorsal de um banco de dados em memória, inspirado na arquitetura do Redis.
O desafio aqui é duplo:
1. Criar um servidor TCP puro que processe um protocolo de texto customizado (ex: `SET chave valor`).
2. Armazenar os dados de forma global, garantindo que 10.000 clientes simultâneos possam ler e escrever no mesmo "banco" sem corromper a memória (*Data Races*) e sem travar o servidor (*Lock Contention*).

Esta aula fecha a trilha juntando quase tudo o que vimos: sockets, parsing, estruturas de dados, sincronizacao, tasks assíncronas e custo real de lock. Um **protocolo de texto customizado** e apenas um conjunto de regras de bytes que cliente e servidor combinam para se entender. Ja **lock contention** significa disputa excessiva por travas: o programa continua correto, mas perde desempenho porque muitas tarefas ficam esperando umas pelas outras.

## 1. O Problema da Estrutura de Dados Global

Se precisamos de um banco de dados Chave-Valor, a estrutura natural no Rust é o `HashMap<String, String>`.
Como múltiplos clientes (Tasks do Tokio) precisam acessar o mesmo mapa, nosso instinto (da Aula 20) nos diz para envolvê-lo em um `Arc<RwLock<HashMap>>`. Um **banco chave-valor** e a forma mais simples de banco de dados: voce fornece uma chave unica e recebe de volta um valor associado. Um **RwLock** existe para permitir muitos leitores simultaneos ou um unico escritor exclusivo.

**O Gargalo do RwLock Global:**
Se você tem um `RwLock` protegendo o mapa inteiro, múltiplas conexões podem fazer o comando `GET` simultaneamente (Read Lock). Mas, se *uma única* conexão quiser fazer um comando `SET` (Write Lock), ela vai travar **todas** as outras conexões que tentarem ler ou escrever até que ela termine.
Se o servidor estiver processando 50.000 requisições por segundo, esse único `RwLock` será um estrangulamento fatal na performance.

### A Solução Arquitetural: Sharded HashMap
Para resolver isso, usamos uma técnica chamada *Sharding* (Fragmentação). Em vez de termos 1 grande HashMap protegido por 1 trava, teremos **16 ou 64 pequenos HashMaps**, cada um protegido por sua própria trava independente. **Sharding** significa particionar o conjunto total de chaves em varios subconjuntos menores. Ele existe para reduzir contencao, pois chaves diferentes deixam de competir pela mesma trava global.
Quando uma chave chega (ex: `usuario:123`), nós calculamos um *hash* rápido dela. Se o hash terminar em `3`, vamos para o Mapa 3 e travamos apenas o Mapa 3. As chaves que caem no Mapa 7 continuam sendo lidas e escritas livremente em paralelo!

O ecossistema Rust possui crates maravilhosas que implementam HashMaps concorrentes super-otimizados (como o `dashmap` ou `scc`), que usam exatamente essa técnica por baixo dos panos. A crate **DashMap** existe para oferecer uma API parecida com `HashMap`, mas com sincronizacao interna fragmentada, evitando que voce tenha de gerenciar `Mutex` ou `RwLock` manualmente no mapa inteiro.

## 3. O Código Completo (`src/main.rs`)

O código abaixo implementa um servidor TCP que entende três comandos simples:
*   `SET <chave> <valor>` (Grava no banco)
*   `GET <chave>` (Lê do banco)
*   `DEL <chave>` (Remove do banco)

Aqui, o **parser** e o trecho do programa que transforma bytes recebidos da rede em uma estrutura ou comando compreensivel pela aplicacao. Em sistemas reais, parser ruim vira gargalo de CPU e tambem superficie de bugs de protocolo.

```rust
use dashmap::DashMap;
use std::sync::Arc;
use tokio::io::{AsyncReadExt, AsyncWriteExt};
use tokio::net::TcpListener;

// O Estado Global: Nosso Banco de Dados
// DashMap é como um RwLock<HashMap>, mas fragmentado internamente (Sharded).
// Ele permite alta concorrência de leitura e escrita simultâneas em chaves diferentes.
type Db = Arc<DashMap<String, String>>;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // 1. Inicializa o banco de dados vazio
    let db: Db = Arc::new(DashMap::new());

    // Laboratório sem autenticação: aceite apenas conexões da própria máquina.
    let listener = TcpListener::bind("127.0.0.1:6379").await?;
    println!("🚀 Mini-Redis rodando na porta 6379");

    // 2. Event Loop de Aceite de Conexões
    // TcpListener aceita novas conexoes; cada conexao vira um socket independente.
    loop {
        let (mut socket, addr) = listener.accept().await?;
        println!("Cliente conectado: {}", addr);

        let db_clone = db.clone();

        // 3. Spawna uma task para cada cliente
        tokio::spawn(async move {
            let mut buffer = [0; 1024];

            // Loop de processamento de comandos DO cliente
            loop {
                // Lê os bytes da rede
                let bytes_lidos = match socket.read(&mut buffer).await {
                    Ok(n) if n == 0 => return, // Conexão fechada pelo cliente
                    Ok(n) => n,
                    Err(e) => {
                        eprintln!("Erro na leitura: {}", e);
                        return;
                    }
                };

                // Tenta converter os bytes para uma string UTF-8.
                // UTF-8 e a codificacao de texto padrao do Rust para strings.
                // Se os bytes nao forem texto valido, ignoramos aquele pacote.
                if let Ok(comando_str) = std::str::from_utf8(&buffer[..bytes_lidos]) {
                    // Remove quebras de linha (\r\n) que vêm do telnet/nc
                    let comando = comando_str.trim();

                    // Executa a lógica de banco de dados
                    let resposta = processar_comando(comando, &db_clone);

                    // Devolve a resposta pela rede
                    if let Err(e) = socket.write_all(resposta.as_bytes()).await {
                        eprintln!("Erro ao escrever no socket: {}", e);
                        return;
                    }
                }
            }
        });
    }
}

// 4. O Parser do Protocolo e Execução
fn processar_comando(comando: &str, db: &Db) -> String {
    // Divide o comando por espaços em até 3 partes: ["SET", "chave", "valor..."]
    let partes: Vec<&str> = comando.splitn(3, ' ').collect();

    if partes.is_empty() {
        return "-ERR Comando vazio\r\n".to_string();
    }

    match partes[0].to_uppercase().as_str() {
        "SET" => {
            if partes.len() < 3 {
                return "-ERR Sintaxe do SET: SET <chave> <valor>\r\n".to_string();
            }
            let chave = partes[1].to_string();
            let valor = partes[2].to_string();
            
            // O DashMap gerencia a sincronizacao do fragmento internamente
            db.insert(chave, valor);
            "+OK\r\n".to_string()
        }
        "GET" => {
            if partes.len() < 2 {
                return "-ERR Sintaxe do GET: GET <chave>\r\n".to_string();
            }
            let chave = partes[1];
            
            // Tenta pegar a referência da chave (Read Lock fino)
            match db.get(chave) {
                Some(valor) => format!("+{}\r\n", valor.value()),
                None => "$-1\r\n".to_string(), // Formato Redis para "Não encontrado" (Null)
            }
        }
        "DEL" => {
            if partes.len() < 2 {
                return "-ERR Sintaxe do DEL: DEL <chave>\r\n".to_string();
            }
            let chave = partes[1];
            
            // Remove a chave e retorna a quantidade de itens removidos
            if db.remove(chave).is_some() {
                ":1\r\n".to_string()
            } else {
                ":0\r\n".to_string()
            }
        }
        "PING" => "+PONG\r\n".to_string(),
        _ => format!("-ERR Comando desconhecido '{}'\r\n", partes[0]),
    }
}
```

## 5. Como Elevar a Performance a Nível de Produção (Zero-Copy Parser)

O código acima demonstra concorrência, mas não é um servidor pronto para produção. O parser ainda precisa delimitar comandos, limitar tamanho, lidar com leituras parciais e rejeitar entradas malformadas. Do ponto de vista de *CPU Bound*, ele também tem falhas de performance clássicas:
1. **Alocação Desnecessária:** Toda vez que damos `SET`, chamamos `.to_string()` na chave e no valor. Se o valor for um JSON de 5MB, alocaremos 5MB na RAM para copiar a string, além do buffer do socket.
2. **Buffer Fixo Estourado:** Criamos um buffer `[0; 1024]`. Se o cliente tentar salvar um valor maior que 1KB, o nosso parser falhará silenciosamente cortando os dados.

**A Solução Real (Arquitetura do Redis/Tokio Mini-Redis):**
Um banco de produção não usa `String` para armazenar valores, ele usa `Bytes` (da crate `bytes`).
A crate `bytes` fornece uma estrutura `BytesMut` e `Bytes` que atuam como um `Arc<[u8]>` otimizado. **Zero-copy** significa evitar copias desnecessarias dos mesmos bytes entre buffers e camadas da aplicacao. Quando você lê 5MB da rede para o `BytesMut`, e depois guarda a chave no HashMap como um `Bytes`, o Rust **não copia os 5MB**. Ele apenas aumenta um contador atômico de compartilhamento, o que resolve um problema clássico de C/C++: mover blobs grandes sem multiplicar custo de memoria e CPU.
