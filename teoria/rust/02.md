# Aula 2 — Controle de Fluxo, Funções, Expressões vs Statements

---

## Nesta aula

Dominar controle de fluxo em Rust (`if`, `else if`, `else`, `loop`, `while`, `for`), entender que **blocos em Rust são expressões** (não apenas statements), criar funções com parâmetros, retorno, e entender o modelo mental de como chamadas de função e escopos funcionam na stack. Você vai aprender a distinguir expressões de statements, usar `if` como expressão, escrever funções com retorno por valor final (sem `;`), escolher entre `loop`, `while` e `for`, e prever o valor produzido por um bloco com e sem ponto e vírgula.
---

## 1. Statements vs Expressions — O Conceito Central

Este é um dos conceitos mais importantes para entender Rust. Diferente de C/C++, onde quase tudo é um statement, Rust distingue claramente:

- **Statement**: uma instrução que **não produz um valor**. Executa e pronto.
- **Expression**: algo que **produz um valor**.

Esses dois termos existem para responder a uma pergunta simples:

- esta construção apenas executa uma ação?
- ou ela também devolve um valor que pode ser usado em outro lugar?

Isso importa muito em Rust porque a linguagem foi desenhada para deixar o fluxo de valores explícito. Em vez de ter blocos que apenas "fazem coisas", Rust incentiva blocos que também devolvem resultados de forma previsível.

**Em C/C++:**
```c
int x = 5;       // statement
int y = x + 1;   // statement (x + 1 é expression, mas a atribuição inteira é statement)
```

**Em Rust:**
```rust
let x = 5;                    // statement
let y = {
    let temp = x + 1;
    temp * 2                  // expressão (sem ponto-e-vírgula!) → valor do bloco
};
```

### Regra de ouro em Rust:

> **Tudo que termina com ponto-e-vírgula é um statement.**
> **Tudo que NÃO termina com ponto-e-vírgula é uma expressão (e produz um valor).**

Isso se aplica a blocos inteiros:

```rust
fn main() {
    let resultado = {
        let a = 10;
        let b = 20;
        a + b          // sem ; → esta é a expressão final → valor do bloco
    };

    println!("resultado = {}", resultado);  // 30
}
```

Se você colocar `;` na última linha, muda tudo:

```rust
fn main() {
    let resultado = {
        let a = 10;
        let b = 20;
        a + b;         // com ; → statement → bloco retorna ()
    };

    // erro: mismatched types — expected integer, found `()`
    println!("resultado = {}", resultado);
}
```

**Modelo mental:** Um bloco `{ ... }` em Rust é uma expressão. O valor do bloco é o valor da **última expressão** (sem `;`). Se a última linha tem `;`, o bloco retorna `()` (unit).

- **Bloco**: trecho de código delimitado por `{}`.
- **Tipo unit `()`**: representa "nenhum valor útil". Em Rust ele aparece naturalmente quando algo executa, mas não produz resultado consumível.

**Comparação com C/C++:**
Em C/C++, blocos não têm valor. Você não pode fazer:
```c
int x = { int a = 5; a + 1; };  // ERRO em C
```

Em Rust, isso é perfeitamente normal e idiomático.

## 2. Controle de Fluxo — if / else if / else

**Controle de fluxo** é o nome dado às estruturas que alteram o caminho de execução do programa.

Por que isso existe?

- porque programas reais não executam sempre a mesma sequência linear de instruções;
- eles precisam decidir, repetir, interromper, pular e escolher caminhos diferentes.

Em termos de CPU, controle de fluxo significa escolher qual bloco de instruções será executado a seguir.

### 2.1 if básico

```rust
fn main() {
    let numero = 7;

    if numero > 10 {
        println!("maior que 10");
    } else if numero > 5 {
        println!("maior que 5");
    } else {
        println!("5 ou menor");
    }
}
```

Saída:
```
maior que 5
```

**Diferença crítica em relação a C:** Em Rust, a condição do `if` **deve ser `bool`**. Não há conversão implícita de inteiro para booleano.

- **`bool`** é o tipo lógico que só pode ser `true` ou `false`.
- Rust exige isso para evitar condições ambíguas, deixando a intenção do programador explícita.

```c
// C — compila e funciona (mas é péssimo estilo)
if (1) { printf("sempre true\n"); }
if (42) { printf("também true\n"); }
```

```rust
// Rust — ERRO de compilação
// if 1 { }     // expected `bool`, found integer
// if 42 { }    // expected `bool`, found integer
if true { }     // OK
```

### 2.2 if é uma expressão!

Como tudo em Rust, `if` produz um valor. Isso substitui o operador ternário de C/C++:

**Em C:**
```c
int x = condicao ? valor_a : valor_b;
```

**Em Rust — não existe ternário. Em vez disso:**
```rust
fn main() {
    let condicao = true;
    let x = if condicao { 5 } else { 10 };

    println!("x = {}", x);  // 5
}
```

**Os tipos nos dois braços devem ser compatíveis:**

```rust
fn main() {
    let condicao = true;
    // let x = if condicao { 5 } else { "dez" };
    // ERRO: `if` and `else` have incompatible types — expected integer, found `&str`
}
```

### 2.3 if com blocos complexos

```rust
fn main() {
    let temperatura = 35;

    let classificacao = if temperatura > 30 {
        println!("Está quente!");          // side effect
        "quente"                           // valor retornado
    } else if temperatura > 20 {
        println!("Agradável.");
        "agradável"
    } else {
        println!("Está frio.");
        "frio"
    };

    println!("Classificação: {}", classificacao);
}
```

Saída:
```
Está quente!
Classificação: quente
```

**O que acontece na memória:**
```
Stack:
  ┌──────────────────────────┐
  │ temperatura: i32 = 35    │
  │ classificacao: &str      │
  │   └→ aponta para "quente"│  (string literal em memória estática)
  └──────────────────────────┘
```

O `if` é avaliado em tempo de execução. O braço `true` é executado, seus statements rodam (o `println!`), e a última expressão (`"quente"`) se torna o valor da expressão `if` inteira, que é atribuída a `classificacao`.

- **Tempo de execução (runtime)**: momento em que o programa já está rodando de verdade.
- **Braço do `if`**: cada caminho possível (`if`, `else if`, `else`) dentro da estrutura condicional.

## 3. Controle de Fluxo — loop

### 3.1 loop infinito

`loop` cria um loop infinito. Equivalente a `while(1)` ou `for(;;)` em C.

- **Loop**: estrutura que repete um bloco de código.
- `loop` é a forma mais bruta e explícita de repetição em Rust: ele continuará para sempre até encontrar `break` ou o programa terminar.

```rust
fn main() {
    let mut contador = 0;

    loop {
        println!("contador = {}", contador);
        contador += 1;

        if contador == 5 {
            break;  // sai do loop
        }
    }

    println!("fim");
}
```

Saída:
```
contador = 0
contador = 1
contador = 2
contador = 3
contador = 4
fim
```

**Nota:** `contador += 1` é equivalente a `contador = contador + 1`. Rust não tem `++` nem `--` (estes foram removidos intencionalmente — em C/C++ o comportamento de `i++ + ++i` é UB).

- **UB (Undefined Behavior)**: comportamento indefinido. A linguagem deixa de garantir qualquer resultado confiável a partir daquele ponto.

### 3.2 Retornando valor de loop

`break` pode retornar um valor! Isso faz de `loop` uma expressão:

```rust
fn main() {
    let mut contador = 0;

    let resultado = loop {
        contador += 1;

        if contador == 10 {
            break contador * 2;  // retorna 20
        }
    };

    println!("resultado = {}", resultado);  // 20
}
```

**Comparação com C:**
Em C, loops não retornam valores. Você precisaria de uma variável externa:
```c
int resultado;
int contador = 0;
while (1) {
    contador++;
    if (contador == 10) {
        resultado = contador * 2;
        break;
    }
}
```

Em Rust, o valor flui diretamente — mais limpo, mais expressivo.

### 3.3 Labels de loop (break/continue com rótulo)

Quando você tem loops aninhados, pode usar labels para controlar qual loop `break` ou `continue` afeta:

- **Loop aninhado**: um loop dentro de outro.
- **Label**: nome associado a um loop para permitir controlar explicitamente qual deles será interrompido ou retomado.

```rust
fn main() {
    'externo: loop {
        println!("Loop externo");

        let mut interno = 0;
        loop {
            println!("  Loop interno {}", interno);
            interno += 1;

            if interno == 3 {
                break;  // sai do loop interno
            }
        }

        break 'externo;  // sai do loop externo (label)
    }
}
```

Saída:
```
Loop externo
  Loop interno 0
  Loop interno 1
  Loop interno 2
```

**Comparação com C:**
Em C, não existe break com label. O equivalente seria `goto`:
```c
externo:
while (1) {
    printf("Loop externo\n");
    for (int i = 0; ; i++) {
        printf("  Loop interno %d\n", i);
        if (i == 2) break;     // sai do for
    }
    break;                     // sai do while
}
```

Rust resolve isso de forma mais estruturada com labels.

## 4. Controle de Fluxo — while

```rust
fn main() {
    let mut n = 3;

    while n != 0 {
        println!("{}!", n);
        n -= 1;
    }

    println!("Lançar!");
}
```

Saída:
```
3!
2!
1!
Lançar!
```

Assim como `if`, a condição do `while` deve ser `bool`. Não existe `while (n)` como em C — seria `while n != 0`.

**Atenção:** `while` **não é uma expressão** em Rust. Diferente de `loop` e `if`, `while` não pode retornar um valor com `break`. Isso porque o compilador não sabe se o loop executa 0 ou N vezes, então não há como garantir um tipo de retorno consistente.

```rust
// ERRO: `while` loop cannot be a `break` expression with a value
// let x = while false { break 5; };
```

## 5. Controle de Fluxo — for

`for` em Rust é **sempre sobre um iterável**. Não existe o `for(init; cond; incr)` do C.

- **Iterável**: qualquer valor que pode fornecer elementos em sequência.
- Em Rust, `for` não é uma mini-linguagem especial como em C; ele consome algo que sabe ser percorrido elemento por elemento.

### 5.1 for com range

```rust
fn main() {
    // Range exclusivo: 1..5 → [1, 2, 3, 4]
    for i in 1..5 {
        println!("i = {}", i);
    }

    println!("---");

    // Range inclusivo: 1..=5 → [1, 2, 3, 4, 5]
    for i in 1..=5 {
        println!("i = {}", i);
    }
}
```

Saída:
```
i = 1
i = 2
i = 3
i = 4
---
i = 1
i = 2
i = 3
i = 4
i = 5
```

**Comparação com C:**
```c
for (int i = 1; i < 5; i++) {    // exclusivo: 1..5
    printf("i = %d\n", i);
}

for (int i = 1; i <= 5; i++) {   // inclusivo: 1..=5
    printf("i = %d\n", i);
}
```

Rust elimina a possibilidade de erros off-by-one usando ranges explícitos.

- **Range**: intervalo de valores.
- **Off-by-one error**: erro clássico em loops e índices em que você inclui ou exclui um elemento indevidamente por engano.

### 5.2 for com rev (reverso)

```rust
fn main() {
    for i in (1..=5).rev() {
        println!("i = {}", i);
    }
}
```

Saída:
```
i = 5
i = 4
i = 3
i = 2
i = 1
```

### 5.3 for com step_by

```rust
fn main() {
    for i in (0..=20).step_by(5) {
        println!("i = {}", i);
    }
}
```

Saída:
```
i = 0
i = 5
i = 10
i = 15
i = 20
```

### 5.4 for sobre arrays (preview)

```rust
fn main() {
    let frutas = ["maçã", "banana", "cereja"];

    for fruta in frutas {
        println!("fruta: {}", fruta);
    }

    // Com índice (menos idiomático, mas útil)
    for (indice, fruta) in frutas.iter().enumerate() {
        println!("[{}] = {}", indice, fruta);
    }
}
```

Saída:
```
fruta: maçã
fruta: banana
fruta: cereja
[0] = maçã
[1] = banana
[2] = cereja
```

### 5.5 _ como descarte

Quando você não precisa da variável do loop:

```rust
fn main() {
    // Quero repetir 5 vezes, não preciso do índice
    for _ in 0..5 {
        println!("beep!");
    }
}
```

`_` é o descarte em Rust — diz ao compilador "eu não vou usar este valor, não me avise".

Isso serve para documentar intenção: o valor existe, mas é irrelevante para a lógica daquele trecho.

## 6. Controle de Fluxo — break e continue

```rust
fn main() {
    // continue: pula para a próxima iteração
    for i in 1..=10 {
        if i % 2 == 0 {
            continue;  // pula números pares
        }
        println!("ímpar: {}", i);
    }

    println!("---");

    // break: sai do loop
    let mut encontrado = 0;
    for i in 1..=100 {
        if i * i > 50 {
            encontrado = i;
            break;
        }
    }
    println!("primeiro i onde i² > 50: {}", encontrado);  // 8
}
```

Saída:
```
ímpar: 1
ímpar: 3
ímpar: 5
ímpar: 7
ímpar: 9
---
primeiro i onde i² > 50: 8
```

**break e continue com labels:**

```rust
fn main() {
    'externo: for i in 1..=3 {
        for j in 1..=3 {
            if i == 2 && j == 2 {
                continue 'externo;  // pula para próxima iteração do loop EXTERNO
            }
            println!("i={}, j={}", i, j);
        }
    }
}
```

Saída:
```
i=1, j=1
i=1, j=2
i=1, j=3
i=2, j=1
i=3, j=1
i=3, j=2
i=3, j=3
```

Note que `i=2, j=2` e `i=2, j=3` não aparecem — `continue 'externo` pula tudo.

## 7. Funções

**Função** é um bloco nomeado de código que pode receber entradas, executar uma lógica e produzir uma saída.

Por que funções existem?

- para evitar repetição;
- para dividir o programa em partes menores;
- para dar nomes a comportamentos;
- para permitir reutilização e testes mais organizados.

### 7.1 Função básica

```rust
fn saudacao() {
    println!("Olá!");
}

fn main() {
    saudacao();
}
```

**Comparação com C:**
```c
void saudacao(void) {
    printf("Olá!\n");
}

int main(void) {
    saudacao();
    return 0;
}
```

Diferenças:
- Rust usa `fn`, C usa tipo + nome.
- Rust não precisa de `void` para parâmetros vazios.
- Rust não precisa de protótipo (declaração antes do uso). A ordem das funções no arquivo **não importa**.

### 7.2 Função com parâmetros

```rust
fn soma(a: i32, b: i32) -> i32 {
    a + b  // sem ; → expressão → valor de retorno
}

fn main() {
    let resultado = soma(3, 4);
    println!("3 + 4 = {}", resultado);
}
```

**Sintaxe:** `fn nome(param: Tipo, ...) -> TipoRetorno { ... }`

**Atenção:** Os tipos dos parâmetros e do retorno **devem** ser explícitos em funções `fn`. Rust não infere tipos em assinaturas de função (diferente de variáveis locais com `let`).

- **Parâmetro**: dado de entrada que a função recebe.
- **Assinatura da função**: parte que descreve nome, parâmetros e tipo de retorno.
- **Tipo de retorno**: tipo do valor devolvido pela função.

**Comparação com C:**
```c
int soma(int a, int b) {
    return a + b;
}
```

Em C, `return` é obrigatório. Em Rust, você pode usar `return` para retorno antecipado, mas a última expressão (sem `;`) é o retorno implícito:

```rust
fn soma(a: i32, b: i32) -> i32 {
    a + b            // retorno implícito (idiomático)
}

fn soma_explicita(a: i32, b: i32) -> i32 {
    return a + b;    // retorno explícito com return (também funciona, menos idiomático)
}
```

**Quando usar `return`:** Para retornar cedo, antes do fim da função:

```rust
fn eh_par(n: i32) -> bool {
    if n % 2 == 0 {
        return true;   // retorno antecipado
    }
    false              // retorno implícito (última expressão)
}
```

### 7.3 Função sem retorno (retorna unit)

```rust
fn imprimir_separador() {
    println!("========================");
    // Retorna () implicitamente
}

// Equivalente explícito:
fn imprimir_separador_explicito() -> () {
    println!("========================");
}
```

### 7.4 Função com bloco como parâmetro (statement vs expression)

```rust
fn main() {
    let x = calcular_idade(2026, {
        let ano_nascimento = 1990;
        ano_nascimento
    });

    println!("Idade: {}", x);  // 36
}

fn calcular_idade(ano_atual: i32, ano_nascimento: i32) -> i32 {
    ano_atual - ano_nascimento
}
```

O bloco `{ let ano_nascimento = 1990; ano_nascimento }` é uma expressão que produz `1990`. Isso é perfeitamente válido em Rust.

### 7.5 Funções como valores (preview — closures na aula 11)

```rust
fn aplicar(f: fn(i32) -> i32, x: i32) -> i32 {
    f(x)
}

fn dobrar(x: i32) -> i32 {
    x * 2
}

fn main() {
    let resultado = aplicar(dobrar, 21);
    println!("resultado = {}", resultado);  // 42
}
```

**Comparação com C:**
```c
#include <stdio.h>

int dobrar(int x) { return x * 2; }

int aplicar(int (*f)(int), int x) { return f(x); }

int main(void) {
    printf("resultado = %d\n", aplicar(dobrar, 21));
    return 0;
}
```

Em C, ponteiros de função são verbosos. Em Rust, `fn(i32) -> i32` é o tipo de uma função (não confundir com closures — veremos na aula 11).

- **Função como valor**: usar a própria função como dado, por exemplo passando-a para outra função.
- **Closure**: bloco de código que também pode capturar variáveis do ambiente. Aqui ainda não estamos usando closures; só funções nomeadas.

## 8. Modelo Mental: Stack Frames e Chamadas de Função

```rust
fn soma(a: i32, b: i32) -> i32 {
    let resultado = a + b;
    resultado
}

fn main() {
    let x = 3;
    let y = 4;
    let z = soma(x, y);
    println!("z = {}", z);
}
```

**O que acontece na memória:**

```
1. main() começa:
Stack:
┌──────────────────────┐
│ main() frame         │
│   x: i32 = 3         │
│   y: i32 = 4         │
│   z: ???             │
└──────────────────────┘

2. soma(x, y) é chamada — os valores são COPIADOS para os parâmetros:
Stack:
┌──────────────────────┐
│ main() frame         │
│   x: i32 = 3         │
│   y: i32 = 4         │
│   z: ???             │
├──────────────────────┤
│ soma() frame         │
│   a: i32 = 3 (cópia) │
│   b: i32 = 4 (cópia) │
│   resultado: i32 = 7 │
└──────────────────────┘

3. soma() retorna 7, sua frame é desalocada:
Stack:
┌──────────────────────┐
│ main() frame         │
│   x: i32 = 3         │
│   y: i32 = 4         │
│   z: i32 = 7         │
└──────────────────────┘
```

**Pontos importantes:**
- Em Rust (como em C), argumentos são passados **por valor** (cópia) por padrão para tipos que implementam `Copy` (inteiros, floats, bool, char, tuplas de tipos Copy).
- A stack frame da função chamada é criada no topo da stack e destruída quando a função retorna.
- O valor de retorno é colocado em um registrador ou na stack da função chamadora.

Termos novos importantes:

- **Passagem por valor**: a função recebe sua própria cópia lógica do argumento.
- **Registrador**: pequena região de armazenamento dentro da própria CPU, muito mais rápida que RAM.
- **Função chamadora**: a função que fez a chamada.
- **Função chamada**: a função que está sendo executada por causa dessa chamada.

**Comparação com C:** O mecanismo é idêntico. A diferença é que Rust garante que ninguém segura uma referência para variáveis na stack de `soma()` após ela retornar — isso seria um dangling pointer, e o borrow checker (aula 3) impede isso.

## 9. Escopo e Drop

Variáveis vivem dentro do escopo onde foram declaradas. Quando o escopo termina, a variável é **dropped** (destruída):

- **Escopo**: região do código em que um nome continua visível e válido.
- **Drop**: destruição lógica do valor ao fim de sua vida útil. Para tipos simples, isso é só o fim do uso da memória local; para tipos com recursos, pode envolver limpeza real.

```rust
fn main() {
    let x = 5;              // x nasce aqui

    {
        let y = 10;         // y nasce aqui
        println!("x + y = {}", x + y);  // 15
    }                       // y morre aqui (dropped)

    // println!("{}", y);   // ERRO: y não existe mais

    println!("x = {}", x);  // x ainda vive
}                           // x morre aqui
```

**Em C:**
```c
int main(void) {
    int x = 5;
    {
        int y = 10;
        printf("x + y = %d\n", x + y);
    }
    // y não é mais acessível, mas em C, acessar fora do escopo é UB
    // (na prática, o valor ainda está na stack até ser sobrescrito)
    printf("x = %d\n", x);
    return 0;
}
```

**Diferença:** Em C, acessar `y` fora do escopo compila (com warnings). Em Rust, é erro de compilação. Mais importante: para tipos que alocam recursos (heap, arquivos, locks), Rust **automaticamente** chama o destructor (`Drop`) quando a variável sai do escopo. Em C, você esquece o `free` e vaza memória.

## 10. Exemplo Completo — Jogo de Adivinhação Simplificado

```rust
// aula2_exemplo.rs
// Compilar: rustc aula2_exemplo.rs
// Executar: ./aula2_exemplo

use std::io;

fn ler_numero() -> i32 {
    let mut entrada = String::new();
    io::stdin()
        .read_line(&mut entrada)
        .expect("Falha ao ler entrada");

    // trim() remove \n, parse() converte para i32
    entrada.trim().parse().expect("Por favor, digite um número")
}

fn avaliar_palpite(palpite: i32, segredo: i32) -> &'static str {
    if palpite < segredo {
        "maior"
    } else if palpite > segredo {
        "menor"
    } else {
        "correto"
    }
}

fn main() {
    let segredo = 42;  // normalmente viria de rand()
    let mut tentativas = 0;

    println!("=== Jogo de Adivinhação ===");
    println!("Adivinhe o número entre 1 e 100!");

    loop {
        println!("\nDigite seu palpite:");

        let palpite = ler_numero();
        tentativas += 1;

        let resultado = avaliar_palpite(palpite, segredo);

        match resultado {
            "correto" => {
                println!("Parabéns! Você acertou em {} tentativas!", tentativas);
                break;
            }
            "maior" => println!("O segredo é MAIOR que {}", palpite),
            "menor" => println!("O segredo é MENOR que {}", palpite),
            _ => unreachable!(),
        }
    }

    // Avaliação usando if como expressão
    let mensagem = if tentativas <= 3 {
        "Excelente!"
    } else if tentativas <= 7 {
        "Bom!"
    } else {
        "Tente melhorar!"
    };

    println!("{}", mensagem);
}
```

Compilar e executar:
```bash
rustc aula2_exemplo.rs
./aula2_exemplo
```

**O que este exemplo demonstra:**
- `if` / `else if` / `else` (controle de fluxo)
- `loop` com `break` (loop com saída condicional)
- `match` (preview — aprofundaremos na aula 5)
- Funções com parâmetros e retorno
- `if` como expressão (atribuindo a `mensagem`)
- `use std::io` (importação de módulo)
- `String::new()` e `&mut entrada` (preview de ownership/borrowing)
- Mutabilidade (`let mut`)
- Variáveis acumuladoras (`tentativas`)

## 11. Resumo de Sintaxe de Fluxo

| Constructo | Sintaxe Rust | Equivalente C | É expressão? |
|------------|-------------|---------------|--------------|
| Condicional | `if cond { } else { }` | `if (cond) { } else { }` | **Sim** |
| Loop infinito | `loop { }` | `while(1) { }` / `for(;;) { }` | Sim (com `break valor`) |
| While | `while cond { }` | `while (cond) { }` | Não |
| For (range) | `for i in 0..n { }` | `for (int i = 0; i < n; i++) { }` | Não |
| Match | `match x { ... }` | `switch (x) { ... }` | **Sim** |
| Block | `{ expr }` | — | **Sim** |

## 12. Erros Comuns

### Erro 1: Ponto-e-vírgula na última expressão de função

```rust
fn soma(a: i32, b: i32) -> i32 {
    a + b;   // com ; → statement → retorna () → tipo errado!
}
// erro: mismatched types — expected `i32`, found `()`
```

**Solução:** Remova o `;` da última expressão quando quiser que ela seja o retorno.

### Erro 2: Condição do if não é bool

```rust
let x = 5;
if x { }    // erro: expected `bool`, found integer
```

**Solução:** `if x != 0 { }`

### Erro 3: Tipos incompatíveis nos braços do if

```rust
let x = if true { 5 } else { "cinco" };
// erro: `if` and `else` have incompatible types
```

**Solução:** Ambos os braços devem retornar o mesmo tipo.

### Erro 4: For estilo C

```rust
// Rust NÃO tem for estilo C:
// for (int i = 0; i < 10; i++) { }   // SINTAXE INVÁLIDA EM RUST

// Use range:
for i in 0..10 { }
```

### Erro 5: Semicolon thinking it's a return

```rust
fn dobro(x: i32) -> i32 {
    return x * 2;  // funciona, mas não é o estilo idiomático
}

// Idiomático:
fn dobro(x: i32) -> i32 {
    x * 2  // sem ; e sem return
}
```

Ambos funcionam. O segundo é preferido para retornos no fim da função. `return` se reserva para retornos antecipados.

## 13. Exercícios Obrigatórios

### Exercício 1 — FizzBuzz

Escreva um programa que imprima números de 1 a 100:
- Se divisível por 3: imprima "Fizz"
- Se divisível por 5: imprima "Buzz"
- Se divisível por 3 e 5: imprima "FizzBuzz"
- Caso contrário: imprima o número

Use `for` com range.

### Exercício 2 — Fibonacci iterativo

Escreva uma função `fibonacci(n: u32) -> u64` que retorne o n-ésimo número de Fibonacci:
- fibonacci(0) = 0
- fibonacci(1) = 1
- fibonacci(n) = fibonacci(n-1) + fibonacci(n-2)

Use `loop` ou `while`. Teste com n = 10 (deve dar 55) e n = 20 (deve dar 6765).

### Exercício 3 — Função de potência

Escreva uma função `potencia(base: i64, exp: u32) -> i64` que calcule `base^exp` **sem usar `pow()`**. Use exponenciação rápida (binary exponentiation):

```
base^0 = 1
base^exp = base^(exp/2) * base^(exp/2)        se exp é par
base^exp = base * base^((exp-1)/2) * base^((exp-1)/2)  se exp é ímpar
```

Teste: `potencia(2, 10) = 1024`, `potencia(3, 0) = 1`, `potencia(5, 3) = 125`.

### Exercício 4 — Tabela de multiplicação

Escreva uma função `tabela(n: i32)` que imprima a tabuada de `n` (1 a 10). Cada linha no formato: `n x i = resultado`. Use `for` com range inclusivo.

### Exercício 5 — Verificador de número primo

Escreva uma função `eh_primo(n: u32) -> bool` que verifique se `n` é primo. Use `for` e `break` quando encontrar um divisor. Teste com: 2 (true), 7 (true), 10 (false), 1 (false), 97 (true).

### Exercício 6 — Expressão vs Statement

Explique por que este código compila:

```rust
fn main() {
    let x = {
        let a = 10;
        let b = 20;
        a + b
    };
    println!("{}", x);
}
```

E por que este NÃO compila:

```rust
fn main() {
    let x = {
        let a = 10;
        let b = 20;
        a + b;
    };
    println!("{}", x);
}
```

Qual é exatamente a diferença? O que `x` recebe em cada caso?

### Exercício 7 — GCD (Máximo Divisor Comum)

Escreva uma função `gcd(a: u64, b: u64) -> u64` usando o algoritmo de Euclides:
- Se b == 0, retorne a
- Senão, retorne gcd(b, a % b)

Use `loop` com `break`. Teste: `gcd(48, 18) = 6`, `gcd(100, 75) = 25`, `gcd(7, 13) = 1`.

Use as [pistas](exercicios/02-pistas.md) somente depois de tentar; consulte as [solucoes comentadas](exercicios/02-solucoes.md) apos entregar sua versao.
