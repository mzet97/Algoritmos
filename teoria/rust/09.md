## Objetivo da Aula

Dominar generics e traits — os mecanismos de abstração e polimorfismo de Rust. Entenderemos **generics** (como templates de C++, mas com verificação em tempo de compilação), **traits** (como interfaces, mas com poderes únicos), **trait bounds** (restricionar generics), **trait objects** (`dyn Trait` para despacho dinâmico), e como Rust alcança **polimorfismo sem herança**. Ao final, você saberá escrever código genérico, performático e reutilizável.

Esta aula é a base das abstrações reutilizáveis do Rust. Até aqui já usamos tipos e funções; agora vamos aprender a escrever código que funciona para muitos tipos diferentes sem perder segurança nem performance.

Mapa mental:

- **generics**: escrever uma lógica uma vez para vários tipos;
- **traits**: descrever capacidades e contratos comportamentais;
- **bounds**: declarar quais capacidades um tipo precisa ter;
- **trait objects**: abrir mão de parte do despacho estático quando precisamos de heterogeneidade.

## 1. Generics — Parametrização por Tipo

### 1.1 O problema sem generics

```rust
fn maior_i32(lista: &[i32]) -> &i32 {
    let mut maior = &lista[0];
    for item in &lista[1..] {
        if item > maior {
            maior = item;
        }
    }
    maior
}

fn maior_f64(lista: &[f64]) -> &f64 {
    let mut maior = &lista[0];
    for item in &lista[1..] {
        if item > maior {
            maior = item;
        }
    }
    maior
}

// Código duplicado! A lógica é idêntica, só muda o tipo.
```

### 1.2 Com generics

```rust
fn maior<T: std::cmp::PartialOrd>(lista: &[T]) -> &T {
    let mut maior = &lista[0];
    for item in &lista[1..] {
        if item > maior {
            maior = item;
        }
    }
    maior
}

fn main() {
    let nums = vec![3, 7, 1, 9, 4];
    println!("maior i32: {}", maior(&nums));

    let floats = vec![2.5, 8.1, 3.7, 9.9];
    println!("maior f64: {}", maior(&floats));

    let chars = vec!['a', 'z', 'm', 'b'];
    println!("maior char: {}", maior(&chars));
}
```

`<T>` é um **parâmetro de tipo genérico**. T é um placeholder para qualquer tipo. O `: std::cmp::PartialOrd` é um **trait bound** — exige que T possa ser comparado com `>`.

Vamos separar esses termos com cuidado:

- **Parâmetro de tipo genérico**: nome simbólico usado no lugar de um tipo concreto.
- **Placeholder**: marcador temporário; aqui, `T` não é um tipo real ainda, é uma posição que será preenchida pelo compilador.
- **Trait bound**: restrição que diz "só aceito tipos que implementem esta capacidade".

Por que generics existem?

- para evitar duplicação de código;
- para permitir reutilização sem custo de runtime;
- para mover restrições para o sistema de tipos em vez de depender de convenção informal.

### 1.3 Generics em structs

Generics não servem só para funções. Eles também permitem criar **tipos parametrizados**, isto é, tipos cuja forma lógica é fixa, mas cujos campos variam conforme o uso.

```rust
struct Par<T, U> {
    primeiro: T,
    segundo: U,
}

impl<T, U> Par<T, U> {
    fn novo(primeiro: T, segundo: U) -> Self {
        Par { primeiro, segundo }
    }

    fn trocar(self) -> Par<U, T> {
        Par {
            primeiro: self.segundo,
            segundo: self.primeiro,
        }
    }
}

// impl específico para tipos que são Copy + Debug
impl<T: std::fmt::Debug + Copy, U: std::fmt::Debug + Copy> Par<T, U> {
    fn descrever(&self) {
        println!("Par({:?}, {:?})", self.primeiro, self.segundo);
    }
}

fn main() {
    let p1 = Par::novo(42, "olá");              // Par<i32, &str>
    let p2 = Par::novo(3.14, true);              // Par<f64, bool>
    let p3 = Par::novo(String::from("a"), 'b'); // Par<String, char>

    p1.descrever();   // Par(42, "olá")
    p2.descrever();   // Par(3.14, true)
    // p3.descrever(); // ERRO: String não é Copy

    let trocado = p1.trocar();                   // Par<&str, i32>
    trocado.descrever();  // Par("olá", 42)
}
```

- **Impl específico**: implementação disponível apenas para instâncias genéricas que satisfaçam certos bounds.
- Isso permite liberar métodos extras apenas quando o tipo realmente suporta as operações necessárias.

### 1.4 Generics em enums

Já vimos `Option<T>` e `Result<T, E>` — ambos são enums genéricos:

```rust
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

Podemos criar nossos próprios:

```rust
enum Arvore<T> {
    Folha(T),
    No {
        valor: T,
        esquerda: Box<Arvore<T>>,
        direita: Box<Arvore<T>>,
    },
    Vazio,
}

impl<T: std::fmt::Debug> Arvore<T> {
    fn imprimir(&self, prefixo: &str) {
        match self {
            Arvore::Vazio => println!("{}(vazio)", prefixo),
            Arvore::Folha(v) => println!("{}Folha: {:?}", prefixo, v),
            Arvore::No { valor, esquerda, direita } => {
                println!("{}No: {:?}", prefixo, valor);
                esquerda.imprimir(&format!("{}  ", prefixo));
                direita.imprimir(&format!("{}  ", prefixo));
            }
        }
    }
}

fn main() {
    let arvore: Arvore<i32> = Arvore::No {
        valor: 10,
        esquerda: Box::new(Arvore::Folha(5)),
        direita: Box::new(Arvore::No {
            valor: 20,
            esquerda: Box::new(Arvore::Vazio),
            direita: Box::new(Arvore::Folha(30)),
        }),
    };
    arvore.imprimir("");
}
```

Esse exemplo mostra que generics também se combinam com estruturas recursivas. Ou seja, Rust permite expressar árvores, listas e outros formatos complexos mantendo tipos bem definidos.

### 1.5 Generics em funções — múltiplos parâmetros

```rust
fn envolver<T>(valor: T) -> Option<T> {
    Some(valor)
}

fn primeiro<T>(slice: &[T]) -> Option<&T> {
    slice.first()
}

fn trocar<T, U>(par: (T, U)) -> (U, T) {
    (par.1, par.0)
}

fn main() {
    let x = envolver(42);              // Option<i32>
    let y = envolver("olá");           // Option<&str>
    println!("{:?} {:?}", x, y);       // Some(42) Some("olá")

    let v = vec![10, 20, 30];
    println!("{:?}", primeiro(&v));     // Some(10)

    let t = trocar((1, "dois"));       // ("dois", 1)
    println!("{:?}", t);
}
```

### 1.6 Monomorphização — zero overhead

O compilador Rust **monomorfiza** generics: gera uma versão especializada do código para cada tipo concreto usado.

- **Monomorfização**: processo de transformar uma definição genérica em várias versões concretas especializadas durante a compilação.

Por que isso importa?

- porque explica por que generics em Rust normalmente têm custo zero em runtime;
- e também explica por que muitas especializações diferentes podem aumentar o tamanho do binário.

```rust
fn maior<T: PartialOrd>(lista: &[T]) -> &T { ... }

fn main() {
    let _ = maior(&[1, 2, 3]);        // gera maior_i32
    let _ = maior(&[1.0, 2.0, 3.0]);  // gera maior_f64
}
```

O compilador gera:
```rust
fn maior_i32(lista: &[i32]) -> &i32 { ... }
fn maior_f64(lista: &[f64]) -> &f64 { ... }
```

**Resultado:** generics em Rust são **zero-cost** — sem overhead virtual, sem box, sem indireção. Exatamente como templates de C++.

**Comparação com C++ templates:**
| Aspecto | C++ templates | Rust generics |
|---------|---------------|---------------|
| Especialização | Automática (monomorphização) | Automática (monomorphização) |
| Verificação | Instanciação (erros tardios) | Definição (erros antecipados com bounds) |
| Mensagens de erro | Incompreensíveis | Claras (trait bounds) |
| Duck typing | Sim (se compila, funciona) | Não (precisa declarar traits) |
| Overhead | Zero | Zero |

A diferença crucial: C++ verifica templates na instanciação (duck typing). Rust verifica generics na **definição** com trait bounds — se o tipo satisfaz o bound, compila. Erros são claros e imediatos.

- **Duck typing**: ideia de que "se o tipo parece suportar as operações, então serve", mesmo sem contrato formal explícito.
- Rust prefere contratos declarados com traits.

## 2. Traits — Contratos de Comportamento

### 2.1 O que é um trait

Trait é um **contrato** que define comportamento. Similar a interfaces em Java/Go, mas mais poderoso.

Essa é a ideia central:

- uma trait descreve **o que um tipo sabe fazer**, não **o que ele é**.

Por que traits existem?

- para modelar capacidades;
- para permitir polimorfismo sem herança;
- para servir de base para bounds, APIs genéricas e integração entre tipos diferentes.

```rust
trait Descrever {
    fn descricao(&self) -> String;

    // Método padrão (com implementação!)
    fn descricao_curta(&self) -> String {
        self.descricao()
    }
}
```

### 2.2 Implementando traits

```rust
trait Area {
    fn area(&self) -> f64;
}

trait Descrever {
    fn descricao(&self) -> String;
}

struct Circulo {
    raio: f64,
}

struct Retangulo {
    largura: f64,
    altura: f64,
}

struct Triangulo {
    base: f64,
    altura: f64,
}

// impl Trait for Tipo
impl Area for Circulo {
    fn area(&self) -> f64 {
        std::f64::consts::PI * self.raio * self.raio
    }
}

impl Area for Retangulo {
    fn area(&self) -> f64 {
        self.largura * self.altura
    }
}

impl Area for Triangulo {
    fn area(&self) -> f64 {
        0.5 * self.base * self.altura
    }
}

impl Descrever for Circulo {
    fn descricao(&self) -> String {
        format!("Círculo(raio={})", self.raio)
    }
}

impl Descrever for Retangulo {
    fn descricao(&self) -> String {
        format!("Retângulo({}x{})", self.largura, self.altura)
    }
}

fn main() {
    let formas: Vec<Box<dyn Area>> = vec![
        Box::new(Circulo { raio: 5.0 }),
        Box::new(Retangulo { largura: 3.0, altura: 4.0 }),
        Box::new(Triangulo { base: 6.0, altura: 3.0 }),
    ];

    for forma in &formas {
        println!("área: {:.2}", forma.area());
    }
}
```

`impl Trait for Tipo` significa que aquele tipo promete cumprir o contrato declarado pela trait.

### 2.3 Regra do Órfão (Orphan Rule)

Você pode implementar:
1. Um trait **seu** para qualquer tipo.
2. Um trait **da std** para seu tipo.
3. **NÃO** pode implementar um trait da std para um tipo da std.

Isso previne conflitos entre crates. Duas crates não podem implementar o mesmo trait para o mesmo tipo.

- **Crate**: unidade de compilação e distribuição em Rust.
- **Orphan Rule** existe para manter coerência global do ecossistema e evitar ambiguidades impossíveis de resolver.

### 2.4 Métodos padrão em traits

- **Método padrão**: método que já vem com implementação no próprio trait.
- Isso reduz repetição e permite que a trait ofereça comportamento comum além da interface mínima.

```rust
trait Imprimir {
    fn formato_completo(&self) -> String;

    // Método padrão — pode ser sobrescrito
    fn formato_curto(&self) -> String {
        self.formato_completo()
    }

    // Outro método padrão que usa os anteriores
    fn imprimir(&self) {
        println!("{}", self.formato_completo());
    }
}

struct Pessoa {
    nome: String,
    idade: u32,
}

impl Imprimir for Pessoa {
    fn formato_completo(&self) -> String {
        format!("{} ({} anos)", self.nome, self.idade)
    }

    // Sobrescreve o método padrão
    fn formato_curto(&self) -> String {
        self.nome.clone()
    }
}

fn main() {
    let p = Pessoa { nome: String::from("Alice"), idade: 30 };
    println!("Completo: {}", p.formato_completo());   // Alice (30 anos)
    println!("Curto: {}", p.formato_curto());          // Alice
    p.imprimir();                                       // Alice (30 anos)
}
```

## 3. Trait Bounds — Restringindo Generics

Sem bounds, o compilador não sabe quais operações pode permitir sobre um tipo genérico.

Em outras palavras, bounds respondem:

- "o que este tipo precisa saber fazer para que esta função faça sentido?"

### 3.1 Sintaxe de bounds

```rust
// Forma 1: inline
fn processar<T: Debug + Clone>(valor: T) { ... }

// Forma 2: where clause (preferida para bounds complexos)
fn processar<T>(valor: T)
where
    T: Debug + Clone,
{
    println!("{:?}", valor);
}

// Forma 3: múltiplos tipos
fn comparar<T, U>(a: &T, b: &U) -> bool
where
    T: PartialEq + Debug,
    U: Clone + Display,
{
    // ...
}
```

**`where` é preferido** quando:
- Há mais de 2 tipos genéricos.
- Bounds são complexos (múltiplos traits).
- A assinatura ficaria ilegível inline.

Isso é principalmente uma questão de legibilidade de API, algo muito importante em código genérico avançado.

### 3.2 Exemplos práticos

```rust
use std::fmt::{Debug, Display};

// T deve ser exibível e clonável
fn duplicar_e_mostrar<T: Display + Clone>(valor: &T) -> String {
    let copia = valor.clone();
    format!("{} {}", valor, copia)
}

// where clause para assinatura complexa
fn maior_de_tres<T>(a: T, b: T, c: T) -> T
where
    T: PartialOrd + Copy,
{
    let maior_ab = if a > b { a } else { b };
    if c > maior_ab { c } else { maior_ab }
}

// Múltiplos tipos genéricos com bounds
fn combinar<T, U>(primeiro: T, segundo: U) -> String
where
    T: Display,
    U: Display,
{
    format!("({}, {})", primeiro, segundo)
}

fn main() {
    println!("{}", duplicar_e_mostrar(&42));        // "42 42"
    println!("{}", duplicar_e_mostrar(&"olá"));     // "olá olá"

    println!("{}", maior_de_tres(3, 7, 5));          // 7
    println!("{}", maior_de_tres('a', 'z', 'm'));    // 'z'

    println!("{}", combinar(42, "texto"));            // "(42, texto)"
}
```

### 3.3 Bounds em structs

```rust
struct ParOrdenado<T>
where
    T: PartialOrd,
{
    menor: T,
    maior: T,
}

impl<T: PartialOrd> ParOrdenado<T> {
    fn novo(a: T, b: T) -> Self {
        if a <= b {
            ParOrdenado { menor: a, maior: b }
        } else {
            ParOrdenado { menor: b, maior: a }
        }
    }
}

impl<T: PartialOrd + Debug> ParOrdenado<T> {
    fn debug(&self) {
        println!("ParOrdenado {{ menor: {:?}, maior: {:?} }}", self.menor, self.maior);
    }
}

fn main() {
    let p = ParOrdenado::novo(42, 10);
    p.debug();  // ParOrdenado { menor: 10, maior: 42 }
}
```

### 3.4 impl Trait em parâmetros — sintaxe moderna

```rust
// Ao invés de:
fn processar<T: Display>(valor: T) { ... }

// Pode usar:
fn processar(valor: impl Display) {
    println!("{}", valor);
}

// Equivalente — mais conciso para casos simples
fn main() {
    processar(42);
    processar("olá");
    processar(3.14);
}
```

**Atenção:** `impl Trait` em parâmetros é equivalente a um generic com bound. Não é dynamic dispatch.

Essa distinção é crucial:

- `impl Trait` em parâmetro continua sendo estático;
- o tipo concreto ainda é conhecido pelo compilador em cada chamada;
- portanto ainda há monomorfização.

### 3.5 impl Trait em retorno

```rust
use std::iter::Iterator;

// Retorna um tipo que implementa Iterator<i32>
// O tipo concreto é gerado pelo compilador (opaco)
fn pares_ate(n: i32) -> impl Iterator<Item = i32> {
    (0..=n).filter(|x| x % 2 == 0)
}

fn main() {
    for par in pares_ate(10) {
        println!("{}", par);
    }
}
```

`impl Trait` em retorno esconde o tipo concreto — útil para closures e iterators complexos cujo tipo seria inescrivível.

- **Tipo opaco**: o chamador conhece as capacidades do retorno, mas não precisa conhecer seu tipo exato.
- Isso ajuda a encapsular detalhes internos de implementação.

## 4. Traits Importantes da Biblioteca Padrão

Na prática, aprender Rust idiomático é aprender a reconhecer essas traits e entender o que cada uma comunica semanticamente sobre um tipo.

### 4.1 Clone e Copy

```rust
// Clone — cópia explícita (.clone())
trait Clone {
    fn clone(&self) -> Self;
}

// Copy — cópia implícita (atribuição copia)
// Copy implica que a cópia é barata (bits na stack)
// Tipos que são Copy implementam Clone automaticamente
```

### 4.2 Debug e Display

```rust
use std::fmt;

// Debug — formatação para desenvolvedores ({:?})
// Display — formatação para usuários ({})

- **Debug**: representação voltada para inspeção técnica e diagnóstico.
- **Display**: representação voltada para exibição amigável.

struct Ponto { x: f64, y: f64 }

impl fmt::Display for Ponto {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

impl fmt::Debug for Ponto {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "Ponto {{ x: {}, y: {} }}", self.x, self.y)
    }
}

fn main() {
    let p = Ponto { x: 3.0, y: 4.0 };
    println!("Display: {}", p);      // (3.0, 4.0)
    println!("Debug: {:?}", p);      // Ponto { x: 3.0, y: 4.0 }
}
```

### 4.3 PartialEq e Eq

```rust
#[derive(PartialEq, Debug)]
struct Ponto { x: i32, y: i32 }

fn main() {
    let a = Ponto { x: 1, y: 2 };
    let b = Ponto { x: 1, y: 2 };
    println!("igual? {}", a == b);  // true
}
```

`PartialEq` = igualdade parcial (f64 tem NaN ≠ NaN). `Eq` = igualdade total (i32, String, etc.).

- **Igualdade parcial**: pode haver casos em que comparar um valor com ele mesmo não produz igualdade matemática total, como `NaN`.
- **Igualdade total**: todos os valores seguem regras completas e consistentes de igualdade.

### 4.4 PartialOrd e Ord

```rust
#[derive(PartialEq, Eq, PartialOrd, Ord, Debug)]
struct Versao {
    major: u32,
    minor: u32,
    patch: u32,
}

fn main() {
    let v1 = Versao { major: 1, minor: 2, patch: 3 };
    let v2 = Versao { major: 1, minor: 3, patch: 0 };
    let v3 = Versao { major: 2, minor: 0, patch: 0 };

    let mut versoes = vec![v3, v1, v2];
    versoes.sort();
    println!("{:?}", versoes);  // [1.2.3, 1.3.0, 2.0.0] — ordenado!
}
```

### 4.5 Default

- **Default**: valor padrão canônico de um tipo.
- Serve para construção incremental, configurações parciais e APIs mais ergonômicas.

```rust
#[derive(Debug, Default)]
struct Config {
    host: String,
    porta: u16,
    verbose: bool,
}

fn main() {
    let cfg = Config::default();
    println!("{:?}", cfg);
    // Config { host: "", porta: 0, verbose: false }

    let cfg_custom = Config {
        host: String::from("localhost"),
        porta: 8080,
        ..Default::default()   // preenche o resto com defaults
    };
    println!("{:?}", cfg_custom);
}
    // Config { host: "localhost", porta: 8080, verbose: false }
```

### 4.6 From e Into

```rust
struct Celsius(f64);
struct Fahrenheit(f64);

impl From<Celsius> for Fahrenheit {
    fn from(c: Celsius) -> Self {
        Fahrenheit(c.0 * 9.0 / 5.0 + 32.0)
    }
}

impl From<Fahrenheit> for Celsius {
    fn from(f: Fahrenheit) -> Self {
        Celsius((f.0 - 32.0) * 5.0 / 9.0)
    }
}

fn main() {
    let c = Celsius(100.0);
    let f: Fahrenheit = c.into();         // usa From automaticamente
    println!("100°C = {}°F", f.0);        // 212

    let f2 = Fahrenheit(32.0);
    let c2: Celsius = f2.into();
    println!("32°F = {}°C", c2.0);        // 0
}
```

**Regra:** Implementar `From<A> for B` dá automaticamente `Into<A>` for B.

Essa trait existe para conversões canônicas e seguras entre tipos, e aparece o tempo todo em APIs idiomáticas.

### 4.7 Iterator

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;

    // Dezenas de métodos padrão: map, filter, collect, fold, etc.
}

// Contador customizado
struct Contador {
    atual: u32,
    max: u32,
}

impl Contador {
    fn novo(max: u32) -> Self {
        Contador { atual: 0, max }
    }
}

impl Iterator for Contador {
    type Item = u32;

    fn next(&mut self) -> Option<Self::Item> {
        if self.atual < self.max {
            let val = self.atual;
            self.atual += 1;
            Some(val)
        } else {
            None
        }
    }
}

fn main() {
    let contador = Contador::novo(5);

    // Usa todos os métodos de Iterator!
    let soma: u32 = contador.sum();
    println!("Soma 0..5 = {}", soma);  // 10

    let contador2 = Contador::novo(5);
    let pares: Vec<u32> = contador2.filter(|x| x % 2 == 0).collect();
    println!("Pares: {:?}", pares);    // [0, 2, 4]
}
```

`Iterator` é uma das traits mais importantes do ecossistema.

Por que ela existe?

- para padronizar percursos sobre sequências;
- para permitir composição de operações como `map`, `filter`, `sum`, `collect`;
- para desacoplar algoritmos do tipo concreto da coleção.

## 5. Trait Objects — Despacho Dinâmico (`dyn Trait`)

### 5.1 Quando estática não basta

Generics + trait bounds = **despacho estático** (monomorphização). O tipo é conhecido em compilação. Mas às vezes você precisa de uma coleção heterogênea:

Aqui aparece uma distinção central:

- **Despacho estático**: a implementação exata é escolhida em compilação;
- **Despacho dinâmico**: a implementação exata é escolhida em runtime.

```rust
// Quero uma lista de formas DIFERENTES
// Generics NÃO permitem isso — Vec<Circulo> é diferente de Vec<Retangulo>
```

### 5.2 `dyn Trait` — despacho dinâmico

```rust
trait Area {
    fn area(&self) -> f64;
}

struct Circulo { raio: f64 }
struct Retangulo { largura: f64, altura: f64 }
struct Triangulo { base: f64, altura: f64 }

impl Area for Circulo {
    fn area(&self) -> f64 { std::f64::consts::PI * self.raio * self.raio }
}
impl Area for Retangulo {
    fn area(&self) -> f64 { self.largura * self.altura }
}
impl Area for Triangulo {
    fn area(&self) -> f64 { 0.5 * self.base * self.altura }
}

fn main() {
    // Vec de trait objects — tipos diferentes, mesma interface
    let formas: Vec<Box<dyn Area>> = vec![
        Box::new(Circulo { raio: 5.0 }),
        Box::new(Retangulo { largura: 3.0, altura: 4.0 }),
        Box::new(Triangulo { base: 6.0, altura: 3.0 }),
    ];

    for forma in &formas {
        println!("área: {:.2}", forma.area());
    }

    // Total
    let total: f64 = formas.iter().map(|f| f.area()).sum();
    println!("área total: {:.2}", total);
}
```

**Modelo mental:**

```
Stack (formas: Vec<Box<dyn Area>>):         Heap:
┌─────────────────┐
│ ptr ──────────────────────────→  ┌─────────────┐    ┌─────────────────────┐
│ len: 3           │               │ fat pointer  │ ──→│ Circulo { raio: 5 } │
│ cap: 3           │               │ (data ptr +  │    └─────────────────────┘
└─────────────────┘               │  vtable ptr) │
                                  ├─────────────┤    ┌──────────────────────┐
                                  │ fat pointer  │ ──→│ Retangulo { 3, 4 }   │
                                  │              │    └──────────────────────┘
                                  ├─────────────┤
                                  │ fat pointer  │ ──→│ Triangulo { 6, 3 }   │
                                  │              │    └──────────────────────┘
                                  └─────────────┘

Vtable para Circulo:
┌──────────────────┐
│ area() → fn ptr  │  ← despacho virtual (indireção)
└──────────────────┘
```

- **Trait object**: valor tratado através de uma trait, sem expor o tipo concreto.
- **Fat pointer**: ponteiro que carrega mais de uma informação; aqui, ponteiro para dados + ponteiro para vtable.
- **Vtable**: tabela de funções usada para descobrir qual implementação chamar em runtime.
- **Indireção**: custo extra de acessar algo por meio de ponteiros em vez de acesso direto.

**Custo:** `Box<dyn Trait>` adiciona:
- Indireção (ponteiro para heap).
- Despacho virtual (vtable lookup).
- Sem inlining.

Equivalente a classes abstratas / virtual em C++.

### 5.3 Estático vs Dinâmico

| Aspecto | Generics (estático) | dyn Trait (dinâmico) |
|---------|---------------------|----------------------|
| Resolução | Compilação | Runtime |
| Código gerado | Uma cópia por tipo | Uma cópia |
| Inlining | Possível | Não |
| Custo | Zero | Indireção + vtable |
| Tamanho | Conhecido | Fat pointer (16 bytes) |
| Coleção heterogênea | Não | Sim |
| Uso | Padrão | Quando precisa de heterogeneidade |

**Regra:** Prefira generics. Use `dyn Trait` apenas quando precisar de coleções heterogêneas ou quando o conjunto de tipos não é conhecido em compilação.

Essa é uma regra de engenharia importante: o padrão do Rust é privilegiar despacho estático; o dinâmico é usado quando a flexibilidade compensa o custo.

**Comparação com C++:**
| Rust | C++ |
|------|-----|
| Generics + bounds | Templates + concepts |
| `dyn Trait` | Classe abstrata + virtual |
| `Box<dyn Trait>` | `std::unique_ptr<Base>` |
| Sem herança | Herança múltipla |

## 6. Traits Associados (Associated Types)

```rust
trait Container {
    type Item;   // tipo associado

    fn adicionar(&mut self, item: Self::Item);
    fn obter(&self, indice: usize) -> Option<&Self::Item>;
    fn tamanho(&self) -> usize;
}

struct Pilha<T> {
    dados: Vec<T>,
}

impl<T> Container for Pilha<T> {
    type Item = T;   // associamos T ao tipo do trait

    fn adicionar(&mut self, item: T) {
        self.dados.push(item);
    }

    fn obter(&self, indice: usize) -> Option<&T> {
        self.dados.get(indice)
    }

    fn tamanho(&self) -> usize {
        self.dados.len()
    }
}

fn main() {
    let mut pilha: Pilha<i32> = Pilha { dados: Vec::new() };
    pilha.adicionar(10);
    pilha.adicionar(20);
    pilha.adicionar(30);

    println!("tamanho: {}", pilha.tamanho());   // 3
    println!("obter(1): {:?}", pilha.obter(1));  // Some(20)
}
```

- **Tipo associado**: tipo declarado dentro da trait e escolhido por quem a implementa.

Isso existe para expressar relações naturais entre comportamento e tipo produzido/consumido sem espalhar parâmetros genéricos por toda parte.

Tipos associados vs generics no trait:
- **Generic trait** `trait Container<T> { ... }`: um tipo pode implementar `Container<i32>` E `Container<String>`.
- **Associated type** `trait Container { type Item; ... }`: um tipo implementa o trait UMA VEZ com UM tipo associado.

`Iterator` usa tipos associados: `type Item;` — cada iterator tem um único tipo de saída.

## 7. Trait com operadores (Operator Overloading)

```rust
use std::ops;

#[derive(Debug, Clone, Copy)]
struct Vetor2D {
    x: f64,
    y: f64,
}

// Sobrecarga de +
impl ops::Add for Vetor2D {
    type Output = Vetor2D;

    fn add(self, rhs: Self) -> Self::Output {
        Vetor2D {
            x: self.x + rhs.x,
            y: self.y + rhs.y,
        }
    }
}

// Sobrecarga de -
impl ops::Sub for Vetor2D {
    type Output = Vetor2D;

    fn sub(self, rhs: Self) -> Self::Output {
        Vetor2D {
            x: self.x - rhs.x,
            y: self.y - rhs.y,
        }
    }
}

// Sobrecarga de * (escalar)
impl ops::Mul<f64> for Vetor2D {
    type Output = Vetor2D;

    fn mul(self, escalar: f64) -> Self::Output {
        Vetor2D {
            x: self.x * escalar,
            y: self.y * escalar,
        }
    }
}

// Sobrecarga de - unário (Neg)
impl ops::Neg for Vetor2D {
    type Output = Vetor2D;

    fn neg(self) -> Self::Output {
        Vetor2D { x: -self.x, y: -self.y }
    }
}

fn main() {
    let a = Vetor2D { x: 1.0, y: 2.0 };
    let b = Vetor2D { x: 3.0, y: 4.0 };

    let soma = a + b;
    println!("soma: {:?}", soma);          // Vetor2D { x: 4.0, y: 6.0 }

    let diferenca = b - a;
    println!("diferença: {:?}", diferenca); // Vetor2D { x: 2.0, y: 2.0 }

    let escalado = a * 3.0;
    println!("escalado: {:?}", escalado);   // Vetor2D { x: 3.0, y: 6.0 }

    let negativo = -a;
    println!("negativo: {:?}", negativo);   // Vetor2D { x: -1.0, y: -2.0 }
}
```

Operadores sobrecarregáveis via traits:
| Trait | Operador |
|-------|----------|
| `Add` | `+` |
| `Sub` | `-` |
| `Mul` | `*` |
| `Div` | `/` |
| `Rem` | `%` |
| `Neg` | `-` (unário) |
| `Not` | `!` |
| `BitAnd` | `&` |
| `BitOr` | `\|` |
| `Shl` | `<<` |
| `Shr` | `>>` |
| `Index` | `[]` |
| `Deref` | `*` (desreferência) |

## 8. Exemplo Completo — Biblioteca Genérica de Estatísticas

```rust
// aula9_generics.rs
// Compilar: rustc aula9_generics.rs
// Executar: ./aula9_generics

use std::fmt::{Debug, Display};
use std::ops::Add;

// === Trait customizado ===

trait Estatistica: PartialOrd + Copy + Debug + Add<Output = Self> + Default {
    fn zero() -> Self;
    fn to_f64(self) -> f64;
}

impl Estatistica for i32 {
    fn zero() -> Self { 0 }
    fn to_f64(self) -> f64 { self as f64 }
}

impl Estatistica for i64 {
    fn zero() -> Self { 0 }
    fn to_f64(self) -> f64 { self as f64 }
}

impl Estatistica for f64 {
    fn zero() -> Self { 0.0 }
    fn to_f64(self) -> f64 { self }
}

impl Estatistica for u32 {
    fn zero() -> Self { 0 }
    fn to_f64(self) -> f64 { self as f64 }
}

// === Struct genérica ===

#[derive(Debug)]
struct Serie<T> {
    nome: String,
    dados: Vec<T>,
}

impl<T> Serie<T>
where
    T: Estatistica,
{
    fn nova(nome: &str, dados: Vec<T>) -> Self {
        Serie { nome: nome.to_string(), dados }
    }

    fn media(&self) -> Option<f64> {
        if self.dados.is_empty() {
            return None;
        }
        let soma: T = self.dados.iter().copied().fold(T::zero(), |a, b| a + b);
        Some(soma.to_f64() / self.dados.len() as f64)
    }

    fn min(&self) -> Option<T> {
        self.dados.iter().copied().reduce(|a, b| if a < b { a } else { b })
    }

    fn max(&self) -> Option<T> {
        self.dados.iter().copied().reduce(|a, b| if a > b { a } else { b })
    }

    fn soma(&self) -> T {
        self.dados.iter().copied().fold(T::zero(), |a, b| a + b)
    }

    fn tamanho(&self) -> usize {
        self.dados.len()
    }

    fn resumo(&self) -> String {
        match (self.min(), self.max(), self.media()) {
            (Some(min), Some(max), Some(media)) => {
                format!(
                    "Serie '{}': {} elementos | min={:?} max={:?} média={:.2} soma={:?}",
                    self.nome, self.tamanho(), min, max, media, self.soma()
                )
            }
            _ => format!("Serie '{}': vazia", self.nome),
        }
    }
}

// === Trait Display para Serie ===

impl<T: Estatistica> Display for Serie<T> {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        write!(f, "{}", self.resumo())
    }
}

// === Trait objects para polimorfismo dinâmico ===

trait Resumivel {
    fn resumo_texto(&self) -> String;
}

impl<T: Estatistica> Resumivel for Serie<T> {
    fn resumo_texto(&self) -> String {
        self.resumo()
    }
}

// === Função genérica com múltiplos bounds ===

fn comparar_series<T, U>(a: &Serie<T>, b: &Serie<U>) -> String
where
    T: Estatistica,
    U: Estatistica,
{
    let media_a = a.media().unwrap_or(0.0);
    let media_b = b.media().unwrap_or(0.0);

    if media_a > media_b {
        format!("{} tem média maior ({:.2} > {:.2})", a.nome, media_a, media_b)
    } else if media_a < media_b {
        format!("{} tem média maior ({:.2} > {:.2})", b.nome, media_b, media_a)
    } else {
        format!("{} e {} têm a mesma média ({:.2})", a.nome, b.nome, media_a)
    }
}

fn main() {
    println!("=== Biblioteca Genérica de Estatísticas ===\n");

    // Serie de i32
    let notas = Serie::nova("Notas", vec![85, 92, 78, 95, 88, 72, 90]);
    println!("{}", notas);

    // Serie de f64
    let temperaturas = Serie::nova("Temperaturas", vec![22.5, 25.1, 19.8, 28.3, 21.7]);
    println!("{}", temperaturas);

    // Serie de u32
    let vendas = Serie::nova("Vendas", vec![150u32, 230, 180, 310, 275]);
    println!("{}", vendas);

    // Serie vazia
    let vazia: Serie<i32> = Serie::nova("Vazia", vec![]);
    println!("{}", vazia);

    // Comparação genérica
    println!("\n{}", comparar_series(&notas, &temperaturas));

    // Trait objects — coleção heterogênea
    println!("\n=== Trait Objects (coleção heterogênea) ===\n");

    let series: Vec<Box<dyn Resumivel>> = vec![
        Box::new(Serie::nova("A", vec![1i32, 2, 3])),
        Box::new(Serie::nova("B", vec![1.5f64, 2.5])),
        Box::new(Serie::nova("C", vec![100u32, 200, 300])),
    ];

    for serie in &series {
        println!("  {}", serie.resumo_texto());
    }

    // Operator overloading
    println!("\n=== Operator Overloading ===\n");

    use std::ops::Add;

    #[derive(Debug, Clone, Copy)]
    struct Ponto { x: f64, y: f64 }

    impl Add for Ponto {
        type Output = Ponto;
        fn add(self, rhs: Self) -> Self::Output {
            Ponto { x: self.x + rhs.x, y: self.y + rhs.y }
        }
    }

    let a = Ponto { x: 1.0, y: 2.0 };
    let b = Ponto { x: 3.0, y: 4.0 };
    println!("{:?} + {:?} = {:?}", a, b, a + b);

    // impl Trait em retorno
    println!("\n=== impl Trait em retorno ===\n");

    fn fibonacci() -> impl Iterator<Item = u64> {
        let (mut a, mut b) = (0u64, 1u64);
        std::iter::from_fn(move || {
            let proximo = a;
            (a, b) = (b, a + b);
            Some(proximo)
        })
    }

    for (i, fib) in fibonacci().take(15).enumerate() {
        println!("fib({}) = {}", i, fib);
    }
}
```

## 9. Erros Comuns

### Erro 1: Usar trait como tipo diretamente

```rust
// let x: Display = 42;  // ERRO: `Display` cannot be made into an object directly
let x: &dyn Display = &42;    // OK com &
let x: Box<dyn Display> = Box::new(42);  // OK com Box
```

### Erro 2: Esquecer trait bound

```rust
fn imprimir<T>(valor: T) {
    // println!("{}", valor);  // ERRO: `T` doesn't implement `Display`
}

fn imprimir<T: std::fmt::Display>(valor: T) {
    println!("{}", valor);  // OK
}
```

### Erro 3: Implementar trait de outra crate para tipo de outra crate

```rust
// impl Display for Vec<i32> {}  // ERRO: orphan rule
// nem o trait nem o tipo são seus
```

### Erro 4: Confundir impl Trait (genérico) com dyn Trait (dinâmico)

```rust
fn f1(x: impl Display) { }     // genérico — monomorfizado
fn f2(x: &dyn Display) { }     // dinâmico — vtable
// f1 é zero-cost, f2 tem indireção
```

### Erro 5: Usar trait object com trait que não é object-safe

```rust
trait MyTrait {
    fn foo<T>(&self, x: T);  // generic method
    // Box<dyn MyTrait>  // ERRO: não é object-safe
}
```

Traits são object-safe se não usam: métodos genéricos, `Self` no retorno, etc.

## 10. Comparação — C++ vs Rust (Abstração)

| Conceito | C++ | Rust |
|----------|-----|------|
| Genéricos | Templates | Generics |
| Polimorfismo estático | Templates + concepts | Generics + trait bounds |
| Polimorfismo dinâmico | Virtual + herança | `dyn Trait` |
| Interface | Abstract class / concepts | Traits |
| Herança | Múltipla | Não existe |
| Operator overloading | Global/-member functions | Traits (`Add`, `Mul`, etc.) |
| Especialização | Template specialization | Não (ainda) |
| Duck typing | Sim (templates) | Não (traits explícitos) |

Rust substitui herança por **composição + traits**. Em vez de "é um" (herança), Rust usa "comporta-se como" (traits). Isso elimina toda a complexidade de hierarquias de classes, diamond problem, e acoplamento frágil.
