# Aula 6 — Módulos, Organização de Arquivos e Crates

Um crate é uma decisão sobre o que é público, o que é detalhe e o que pode quebrar. Módulos e organização de arquivos em Rust são arquitetura em miniatura — e o compilador confere as fronteiras.

---

## Nesta aula

Dominar o sistema de módulos de Rust: como organizar código em **módulos** (`mod`), controlar **visibilidade** com `pub`, usar **paths** e `use`, estruturar projetos com **múltiplos arquivos**, e entender o que é uma **crate** (binária e de biblioteca). Você vai aprender a declarar módulos (`mod`), controlar visibilidade (`pub`, `pub(crate)`), importar com `use` e paths, dividir um projeto em múltiplos arquivos, e distinguir crate binária de crate de biblioteca.
---

## 1. O Problema que Módulos Resolvem

### 1.1 Em C/C++

Em C, você organiza código com **headers** (`.h`) e **implementações** (`.c`):

```c
// math_utils.h
#ifndef MATH_UTILS_H
#define MATH_UTILS_H
int fatorial(int n);
int fibonacci(int n);
#endif

// math_utils.c
#include "math_utils.h"
int fatorial(int n) { ... }
int fibonacci(int n) { ... }

// main.c
#include "math_utils.h"
int main(void) { ... }
```

Problemas:
- **Include guards** manuais (`#ifndef`) — se esquecer, redefinição.
- **Ordem de includes** importa — dependências cíclicas são pesadelo.
- Tudo que está no header é **público** — não há controle fino de visibilidade.
- O linker resolve símbolos depois da compilação — erros de linking são confusos.
- `#include` é **cópia de texto** — o pré-processador cola o conteúdo do `.h` no `.c`.

### 1.2 Em Rust

Rust não tem headers. Não tem pré-processador. Não tem cópia de texto. O sistema de módulos é **baseado em árvore** com visibilidade explícita:

- Cada arquivo é potencialmente um módulo.
- Tudo é **privado por padrão** — só é visível fora com `pub`.
- O compilador resolve tudo — sem linker manual para seus próprios módulos.
- Dependências são gerenciadas pelo Cargo — sem Makefiles.

Termos novos importantes:

- **Header**: arquivo de declaração em C/C++ normalmente incluído com `#include`.
- **Pré-processador**: etapa textual anterior à compilação, responsável por diretivas como `#include` e `#define`.
- **Visibilidade**: regra que determina de onde um item pode ser acessado.
- **Árvore de módulos**: organização hierárquica do código, em que módulos contêm submódulos e itens.

Por que Rust faz isso?

- para trocar montagem textual frágil por estrutura semântica real;
- para reduzir erros de linking, redefinição e acoplamento acidental;
- para permitir encapsulamento fino diretamente na linguagem.

## 2. Módulos Inline — `mod { }`

Antes de arquivos separados, podemos criar módulos **dentro do mesmo arquivo**:

- **Módulo inline**: módulo definido no próprio arquivo onde é declarado, em vez de ser carregado de outro arquivo.
- Isso é útil para exemplos pequenos, organização local ou testes.

```rust
// src/main.rs
mod saudacao {
    pub fn ola() {
        println!("Olá!");
    }

    fn segredo() {
        println!("Isto é privado!");
    }
}

fn main() {
    saudacao::ola();       // OK — pub
    // saudacao::segredo();  // ERRO: function `segredo` is private
}
```

**Regras:**
- `mod nome { ... }` cria um módulo com o nome dado.
- Itens dentro do módulo são **privados por padrão**.
- `pub` torna visível fora do módulo.
- Para acessar de fora: `nome_do_modulo::funcao()`.

- **Item**: nome genérico em Rust para funções, structs, enums, constantes, módulos, traits, etc.
- `::` é o operador de caminho, usado para navegar pela hierarquia de módulos e tipos.

## 3. Módulos em Arquivos Separados

### 3.1 Um arquivo = um módulo

Estrutura do projeto:
```
meu_projeto/
├── Cargo.toml
└── src/
    ├── main.rs
    └── matematica.rs       ← módulo "matematica"
```

`src/matematica.rs`:
```rust
pub fn fatorial(n: u64) -> u64 {
    if n <= 1 { 1 } else { n * fatorial(n - 1) }
}

pub fn fibonacci(n: u32) -> u64 {
    if n <= 1 { n as u64 } else { fibonacci(n - 1) + fibonacci(n - 2) }
}

fn interno() {
    // Esta função é privada — não acessível de fora
    println!("uso interno");
}
```

`src/main.rs`:
```rust
mod matematica;   // declara: "existe um módulo chamado matematica"
                  // o compilador busca src/matematica.rs

fn main() {
    println!("10! = {}", matematica::fatorial(10));
    println!("fib(10) = {}", matematica::fibonacci(10));
    // matematica::interno();  // ERRO: private
}
```

**Ponto crucial:** `mod matematica;` (com ponto-e-vírgula, sem corpo) diz ao compilador para buscar o conteúdo do módulo em outro lugar. O compilador procura:
1. `src/matematica.rs` — **arquivo**
2. `src/matematica/mod.rs` — **diretório com mod.rs**

Ou seja:

- `mod matematica { ... }` define o módulo ali mesmo;
- `mod matematica;` declara que o conteúdo real será carregado de outro arquivo.

Ambos são válidos. A primeira forma (arquivo `matematica.rs`) é o estilo moderno e preferido.

### 3.2 A diretiva `use` — importando paths

Sem `use`, o path completo é necessário:

```rust
fn main() {
    matematica::fatorial(5);
}
```

Com `use`, importamos o path:

```rust
use matematica::fatorial;
use matematica::fibonacci;

fn main() {
    println!("{}", fatorial(5));
    println!("{}", fibonacci(10));
}
```

Ou importar tudo do módulo (não recomendado para módulos grandes):

```rust
use matematica::*;  // glob import — traz tudo que é pub

fn main() {
    println!("{}", fatorial(5));
}
```

**Boa prática:** Importe o que precisa, explicitamente. `use modulo::funcao;` é preferível a `use modulo::*;`. O `*` é aceitável em testes ou quando o módulo é projetado para isso (como `prelude`).

- **Importar**: trazer um nome para o escopo local para não precisar escrever o path completo toda hora.
- **Escopo local**: região do código onde aquele nome está visível.
- **Glob import**: importação com `*`, trazendo todos os itens públicos de um módulo.

### 3.3 Múltiplos imports com mesma origem

```rust
use matematica::{fatorial, fibonacci};

// ou
use std::collections::{HashMap, HashSet, VecDeque};
```

### 3.4 Renomeando imports com `as`

```rust
use matematica::fatorial as fat;

fn main() {
    println!("{}", fat(5));
}
```

Útil para resolver conflitos de nomes.

- **Conflito de nomes**: quando dois itens diferentes têm o mesmo nome e ficaria ambíguo qual deles usar.

## 4. Hierarquia de Módulos — Submódulos

### 4.1 Estrutura com diretório

```
meu_projeto/
├── Cargo.toml
└── src/
    ├── main.rs
    └── rede/
        ├── mod.rs           ← módulo "rede"
        ├── tcp.rs           ← submódulo "rede::tcp"
        └── udp.rs           ← submódulo "rede::udp"
```

`src/rede/mod.rs`:
```rust
pub mod tcp;     // declara submódulo tcp (busca src/rede/tcp.rs)
pub mod udp;     // declara submódulo udp (busca src/rede/udp.rs)

pub fn descricao() {
    println!("Módulo de rede com TCP e UDP");
}
```

`src/rede/tcp.rs`:
```rust
pub fn conectar(host: &str, porta: u16) -> String {
    format!("Conectado TCP a {}:{} (simulado)", host, porta)
}

pub fn desconectar() {
    println!("TCP desconectado");
}
```

`src/rede/udp.rs`:
```rust
pub fn enviar(host: &str, porta: u16, dados: &[u8]) -> String {
    format!("Enviado {} bytes via UDP para {}:{}", dados.len(), host, porta)
}
```

`src/main.rs`:
```rust
mod rede;   // carrega src/rede/mod.rs

fn main() {
    rede::descricao();

    let conn = rede::tcp::conectar("127.0.0.1", 8080);
    println!("{}", conn);
    rede::tcp::desconectar();

    let msg = rede::udp::enviar("192.168.1.1", 9090, b"hello");
    println!("{}", msg);
}
```

### 4.2 Estilo alternativo (moderno) — sem mod.rs

Rust 2018+ suporta outra organização:

```
src/
├── main.rs
├── rede.rs           ← módulo "rede" (conteúdo do módulo)
└── rede/
    ├── tcp.rs        ← submódulo "rede::tcp"
    └── udp.rs        ← submódulo "rede::udp"
```

`src/rede.rs` (substitui `src/rede/mod.rs`):
```rust
pub mod tcp;
pub mod udp;

pub fn descricao() {
    println!("Módulo de rede");
}
```

Ambos os estilos funcionam. O estilo com `rede.rs` + `rede/` é o **padrão moderno** — evita a confusão de ter `mod.rs` em cada diretório. Use este estilo.

## 5. Visibilidade — `pub` e Privacidade

**Privado por padrão** é uma decisão central do Rust.

Por que isso existe?

- para obrigar o autor do módulo a escolher conscientemente o que faz parte da API pública;
- para reduzir acoplamento entre partes internas do projeto;
- para facilitar refatoração sem quebrar usuários do módulo.

### 5.1 Regras de visibilidade

| Declaração | Visibilidade |
|------------|-------------|
| Sem `pub` | Privado — só acessível dentro do módulo e submódulos |
| `pub` | Público — acessível de qualquer lugar |
| `pub(crate)` | Acessível dentro da crate atual |
| `pub(super)` | Acessível no módulo pai |
| `pub(in path)` | Acessível no path especificado |

Essas variações existem porque nem sempre "privado" ou "público para o mundo inteiro" são suficientes. Às vezes você quer expor algo só para a crate, só para o pai, ou só para uma subárvore específica.

### 5.2 Exemplo detalhado

```rust
mod banco_de_dados {
    pub struct Conexao {
        pub host: String,           // campo público
        porta: u16,                 // campo privado
        status_conexao: String,     // campo privado
    }

    impl Conexao {
        pub fn nova(host: &str, porta: u16) -> Conexao {
            Conexao {
                host: host.to_string(),
                porta,
                status_conexao: String::from("desconectado"),
            }
        }

        pub fn conectar(&mut self) {
            self.status_conexao = format!("conectado em {}:{}", self.host, self.porta);
            println!("{}", self.status_conexao);
        }

        pub fn status(&self) -> &str {
            &self.status_conexao
        }

        fn log_interno(&self) {
            println!("log: {}", self.status_conexao);
        }
    }

    pub fn versao() -> &'static str {
        "2.1.0"
    }

    fn funcao_interna() {
        // privada ao módulo
    }
}

fn main() {
    let mut conn = banco_de_dados::Conexao::nova("localhost", 5432);
    println!("host: {}", conn.host);           // OK — campo pub
    // println!("{}", conn.porta);             // ERRO: field `porta` is private
    println!("status: {}", conn.status());     // OK — método pub
    conn.conectar();

    println!("versão: {}", banco_de_dados::versao());
    // banco_de_dados::funcao_interna();       // ERRO: private
}
```

**Regras para structs:**
- A struct em si precisa ser `pub` para ser usada fora do módulo.
- Cada campo precisa ser `pub` individualmente para ser acessado fora.
- Construtores (funções associativas) devem ser `pub`.
- Métodos privativos ficam privados ao módulo.

### 5.3 Visibilidade de enums

```rust
mod formas {
    pub enum Forma {
        Circulo(f64),
        Retangulo { largura: f64, altura: f64 },
    }
    // Se o enum é pub, TODOS os variantes são automaticamente pub.
    // Não é possível ter enum pub com variantes privados.
}

fn main() {
    let c = formas::Forma::Circulo(5.0);  // OK
}
```

Enums são diferentes de structs: se o enum é `pub`, todos os variantes são `pub`.

Isso acontece porque o valor do enum é inseparável de suas variantes. Ao expor o tipo, Rust expõe também as formas válidas daquele tipo.

## 6. O caminho `self`, `super` e `crate`

Dentro de módulos, você pode referenciar caminhos relativos:

Essas palavras ajudam a navegar dentro da árvore de módulos:

- `self`: módulo atual;
- `super`: módulo pai;
- `crate`: raiz da crate atual.

Pense nelas como referências estruturais, não como caminhos de arquivo do sistema operacional.

```rust
mod alpha {
    pub fn funcao_alpha() {
        println!("alpha");
    }

    pub mod beta {
        pub fn funcao_beta() {
            super::funcao_alpha();       // super = módulo pai (alpha)
            self::funcao_beta_interna(); // self = módulo atual (beta)
        }

        fn funcao_beta_interna() {
            println!("interno de beta");
        }
    }
}

mod gamma {
    pub fn funcao_gamma() {
        crate::alpha::funcao_alpha();    // crate = raiz da crate
        crate::alpha::beta::funcao_beta();
    }
}

fn main() {
    alpha::funcao_alpha();
    alpha::beta::funcao_beta();
    gamma::funcao_gamma();
}
```

**Resumo:**
| Path | Significado |
|------|-------------|
| `crate::` | Raiz da crate atual |
| `super::` | Módulo pai (um nível acima) |
| `self::` | Módulo atual |

**Comparação com C:**
Em C, o equivalente seria:
- `crate::` → root do projeto (não existe em C — é relativo ao include path)
- `super::` → `../` (não existe — paths são baseados em strings de arquivo)
- `self::` → `./` atual

O sistema de Rust é baseado na **árvore de módulos**, não em caminhos de arquivo. O compilador garante que tudo está correto.

## 7. Crates — Binária e de Biblioteca

### 7.1 O que é uma crate

Uma **crate** é a unidade de compilação de Rust. É o equivalente a um "projeto" ou "library" em C/C++.

Essa é uma definição central do ecossistema:

- **crate** é a unidade que o compilador transforma de uma vez;
- também é a unidade básica de publicação e dependência no ecossistema Rust;
- um projeto Cargo pode conter uma ou mais crates.

Existem dois tipos:

| Tipo | Entrada | Produz | Análogo C |
|------|---------|--------|-----------|
| **Bin crate** | `src/main.rs` | Executável | Programa C |
| **Lib crate** | `src/lib.rs` | Biblioteca (`.rlib`) | `.a` / `.so` / `.dll` |

- **Bin crate**: gera programa executável.
- **Lib crate**: gera biblioteca reutilizável por outros códigos.

Um projeto Cargo pode ter **ambos**:

```
meu_projeto/
├── Cargo.toml
└── src/
    ├── main.rs     ← bin crate (pode usar a lib crate)
    └── lib.rs      ← lib crate (código compartilhado)
```

### 7.2 Lib crate — `src/lib.rs`

```rust
// src/lib.rs — a raiz da biblioteca
pub mod matematica;
pub mod rede;
```

Tudo que for `pub` em `lib.rs` fica disponível para:
- O bin crate (`main.rs`) do mesmo projeto
- Outros projetos que dependam desta crate

### 7.3 Bin crate usando Lib crate

```rust
// src/main.rs
use meu_projeto::matematica::fatorial;

fn main() {
    println!("5! = {}", fatorial(5));
}
```

Note: `meu_projeto` é o nome da crate (definido em `Cargo.toml`). O bin crate automaticamente tem acesso à lib crate do mesmo projeto.

### 7.4 Múltiplos binários

```
src/
├── lib.rs
└── bin/
    ├── servidor.rs    ← binário "servidor"
    └── cliente.rs     ← binário "cliente"
```

Em `Cargo.toml`:
```toml
[[bin]]
name = "servidor"
path = "src/bin/servidor.rs"

[[bin]]
name = "cliente"
path = "src/bin/cliente.rs"
```

Ou, sem configuração, coloque em `src/bin/` e o Cargo detecta automaticamente.

Compilar todos:
```bash
cargo build            # compila todos os binários
cargo run --bin servidor   # roda o binário "servidor"
cargo run --bin cliente    # roda o binário "cliente"
```

## 8. Dependências — `Cargo.toml`

### 8.1 Adicionando crates externas

```toml
[package]
name = "meu_projeto"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = { version = "1.0", features = ["derive"] }
serde_json = "1.0"
regex = "1"
clap = { version = "4", features = ["derive"] }
rand = "0.8"
```

Depois de editar `Cargo.toml`:
```bash
cargo build    # baixa e compila dependências
cargo update   # atualiza dentro das versões especificadas
```

**Comparação com C/C++:**
Em C/C++, gerenciar dependências é um pesadelo — vcpkg, conan, cmake ExternalProject, ou copiar manualmente. Em Rust, `Cargo.toml` resolve tudo.

- **Dependência**: crate externa usada pelo seu projeto.
- **Feature**: chave opcional que liga partes específicas de uma dependência.

Isso permite controlar tamanho do binário, funcionalidades ativas e compatibilidade sem precisar gerenciar manualmente dezenas de flags de build.

### 8.2 Usando crates externas

```rust
use rand::Rng;
use regex::Regex;

fn main() {
    // Número aleatório
    let mut rng = rand::thread_rng();
    let n: u32 = rng.gen_range(1..=100);
    println!("Número aleatório: {}", n);

    // Regex
    let re = Regex::new(r"\d+").unwrap();
    let texto = "abc 123 def 456";
    for cap in re.find_iter(texto) {
        println!("Encontrado: {}", cap.as_str());
    }
}
```

### 8.3 Comandos úteis do Cargo

```bash
cargo add serde              # adiciona dependência automaticamente
cargo add serde --features derive  # com feature
cargo rm serde               # remove dependência
cargo tree                   # mostra árvore de dependências
cargo outdated               # verifica dependências desatualizadas
cargo audit                  # verifica vulnerabilidades conhecidas
```

## 9. O Módulo `prelude`

Muitas crates fornecem um `prelude` — um módulo que re-exporta os tipos mais comuns:

- **Prelude**: conjunto de imports considerados básicos o suficiente para serem trazidos juntos ou automaticamente.
- A ideia é reduzir boilerplate sem esconder demais a origem dos tipos.

```rust
// A biblioteca padrão tem um prelude que é importado automaticamente
// É por isso que você pode usar Vec, String, Option, Result, etc. sem importar
// Equivalente a:
// use std::prelude::rust_2021::*;
```

Crates externas frequentemente pedem:
```rust
use serde::{Serialize, Deserialize};    // importação manual do prelude da crate
```

## 10. Re-exportando com `pub use`

Às vezes você quer reorganizar a API pública de um módulo:

- **Re-exportar**: expor publicamente um item que internamente mora em outro caminho.

Isso serve para separar:

- organização interna do código;
- formato externo da API que os usuários enxergam.

```rust
// src/lib.rs
pub mod matematica {
    pub mod aritmetica {
        pub fn soma(a: i32, b: i32) -> i32 { a + b }
        pub fn subtracao(a: i32, b: i32) -> i32 { a - b }
    }

    pub mod geometria {
        pub fn area_circulo(raio: f64) -> f64 {
            std::f64::consts::PI * raio * raio
        }
    }

    // Re-exporta para facilitar o acesso
    pub use aritmetica::{soma, subtracao};
    pub use geometria::area_circulo;
}

// Agora os usuários podem usar:
// meu_projeto::matematica::soma(1, 2)
// em vez de:
// meu_projeto::matematica::aritmetica::soma(1, 2)
```

`pub use` é fundamental para criar APIs limpas — esconde a estrutura interna dos módulos e expõe um caminho conveniente.

## 11. Atributos de Módulos

- **Atributo**: anotação especial iniciada com `#[]` que instrui o compilador a alterar comportamento, incluir/excluir código ou gerar implementações.

### 11.1 `#[cfg(test)]` — módulos de teste

```rust
pub fn soma(a: i32, b: i32) -> i32 {
    a + b
}

#[cfg(test)]    // só compila quando rodando testes
mod tests {
    use super::*;   // importa tudo do módulo pai

    #[test]
    fn teste_soma() {
        assert_eq!(soma(2, 3), 5);
        assert_eq!(soma(-1, 1), 0);
    }

    #[test]
    fn teste_soma_zero() {
        assert_eq!(soma(0, 0), 0);
    }
}
```

Rodar testes:
```bash
cargo test
```

Saída:
```
running 2 tests
test tests::teste_soma ... ok
test tests::teste_soma_zero ... ok

test result: ok. 2 passed; 0 failed; 0 ignored
```

### 11.2 `#[allow(...)]` — suprimir warnings

```rust
#[allow(dead_code)]
fn funcao_nao_usada() {
    // Não avisa que não é usada
}

#[allow(unused_variables)]
fn exemplo(x: i32) {
    // Não avisa que x não é usado
}
```

### 11.3 `#[warn(...)]` — ativar warnings

```rust
#[warn(unused_imports)]
use std::collections::HashMap;  // se não usar, gera warning
```

## 12. Projeto Completo — Organização Multi-Arquivo

Vamos criar um projeto completo com múltiplos módulos:

O objetivo desta parte é consolidar o modelo mental: módulos não são só "separar arquivos", mas sim desenhar fronteiras, visibilidade e API pública de forma consciente.

```bash
cargo new calculadora
cd calculadora
```

Estrutura final:
```
calculadora/
├── Cargo.toml
└── src/
    ├── main.rs
    ├── lib.rs
    ├── calculadora/
    │   ├── mod.rs
    │   ├── operacoes.rs
    │   └── historico.rs
    └── parser/
        ├── mod.rs
        └── tokenizer.rs
```

`Cargo.toml`:
```toml
[package]
name = "calculadora"
version = "0.1.0"
edition = "2021"
```

`src/lib.rs`:
```rust
pub mod calculadora;
pub mod parser;
```

`src/calculadora/mod.rs`:
```rust
pub mod operacoes;
pub mod historico;

pub use operacoes::{calcular, Operacao};
pub use historico::Historico;
```

`src/calculadora/operacoes.rs`:
```rust
#[derive(Debug, Clone, PartialEq)]
pub enum Operacao {
    Soma(f64, f64),
    Subtracao(f64, f64),
    Multiplicacao(f64, f64),
    Divisao(f64, f64),
}

#[derive(Debug, Clone, PartialEq)]
pub enum ErroCalculo {
    DivisaoPorZero,
}

pub fn calcular(op: &Operacao) -> Result<f64, ErroCalculo> {
    match op {
        Operacao::Soma(a, b) => Ok(a + b),
        Operacao::Subtracao(a, b) => Ok(a - b),
        Operacao::Multiplicacao(a, b) => Ok(a * b),
        Operacao::Divisao(_, b) if *b == 0.0 => Err(ErroCalculo::DivisaoPorZero),
        Operacao::Divisao(a, b) => Ok(a / b),
    }
}

pub fn nome_operacao(op: &Operacao) -> &'static str {
    match op {
        Operacao::Soma(_, _) => "+",
        Operacao::Subtracao(_, _) => "-",
        Operacao::Multiplicacao(_, _) => "*",
        Operacao::Divisao(_, _) => "/",
    }
}
```

```rust
use crate::calculadora::operacoes::Operacao;

pub struct Historico {
    entradas: Vec<String>,
}

impl Historico {
    pub fn novo() -> Self {
        Historico { entradas: Vec::new() }
    }

    pub fn registrar(&mut self, op: &Operacao, resultado: Result<f64, crate::calculadora::operacoes::ErroCalculo>) {
        let simbolo = crate::calculadora::operacoes::nome_operacao(op);
        let entrada = match op {
            Operacao::Soma(a, b)
            | Operacao::Subtracao(a, b)
            | Operacao::Multiplicacao(a, b)
            | Operacao::Divisao(a, b) => {
                format!("{} {} {} = ", a, simbolo, b)
            }
        };

        match resultado {
            Ok(val) => self.entradas.push(format!("{}{}", entrada, val)),
            Err(_) => self.entradas.push(format!("{}ERRO", entrada)),
        }
    }

    pub fn listar(&self) {
        if self.entradas.is_empty() {
            println!("Histórico vazio.");
            return;
        }
        println!("=== Histórico ===");
        for (i, entrada) in self.entradas.iter().enumerate() {
            println!("  {}: {}", i + 1, entrada);
        }
    }

    pub fn tamanho(&self) -> usize {
        self.entradas.len()
    }

    pub fn limpar(&mut self) {
        self.entradas.clear();
    }
}

impl Default for Historico {
    fn default() -> Self {
        Self::novo()
    }
}
```

```rust
#[derive(Debug, PartialEq)]
pub enum Token {
    Numero(f64),
    Operador(char),
    Desconhecido(String),
}

pub fn tokenizar(input: &str) -> Vec<Token> {
    let mut tokens = Vec::new();
    let mut buffer = String::new();

    for ch in input.chars() {
        match ch {
            '0'..='9' | '.' => buffer.push(ch),
            '+' | '-' | '*' | '/' => {
                if !buffer.is_empty() {
                    if let Ok(num) = buffer.parse::<f64>() {
                        tokens.push(Token::Numero(num));
                    }
                    buffer.clear();
                }
                tokens.push(Token::Operador(ch));
            }
            ' ' => {
                if !buffer.is_empty() {
                    if let Ok(num) = buffer.parse::<f64>() {
                        tokens.push(Token::Numero(num));
                    }
                    buffer.clear();
                }
            }
            _ => {
                buffer.push(ch);
            }
        }
    }

    if !buffer.is_empty() {
        if let Ok(num) = buffer.parse::<f64>() {
            tokens.push(Token::Numero(num));
        } else {
            tokens.push(Token::Desconhecido(buffer));
        }
    }

    tokens
}
```

```rust
use calculadora::calculadora::operacoes::{calcular, Operacao};
use calculadora::calculadora::historico::Historico;
use calculadora::parser::tokenizer::tokenizar;

fn avaliar_expressao(expr: &str) -> Option<Operacao> {
    let tokens: Vec<_> = tokenizar(expr)
        .into_iter()
        .filter(|t| !matches!(t, calculadora::parser::tokenizer::Token::Desconhecido(_)))
        .collect();

    if tokens.len() == 3 {
        use calculadora::parser::tokenizer::Token;
        if let (Token::Numero(a), Token::Operador(op), Token::Numero(b)) =
            (&tokens[0], &tokens[1], &tokens[2])
        {
            return Some(match op {
                '+' => Operacao::Soma(*a, *b),
                '-' => Operacao::Subtracao(*a, *b),
                '*' => Operacao::Multiplicacao(*a, *b),
                '/' => Operacao::Divisao(*a, *b),
                _ => return None,
            });
        }
    }
    None
}

fn main() {
    let mut historico = Historico::novo();

    let expressoes = [
        "3 + 4",
        "10 - 3",
        "6 * 7",
        "100 / 25",
        "10 / 0",
        "2 + abc",
    ];

    println!("=== Calculadora Modular ===\n");

    for expr in &expressoes {
        println!("Expressão: {}", expr);

        match avaliar_expressao(expr) {
            Some(op) => {
                let resultado = calcular(&op);

                match &resultado {
                    Ok(val) => println!("  = {:.4}\n", val),
                    Err(e) => println!("  ERRO: {:?}\n", e),
                }

                historico.registrar(&op, resultado);
            }
            None => println!("  Não consegui interpretar\n"),
        }
    }

    historico.listar();
    println!("\nTotal de operações: {}", historico.tamanho());
}
```

## 14. Erros Comuns

### Erro 1: Esquecer `mod` para o arquivo

Criou `src/matematica.rs` mas esqueceu `mod matematica;` em `main.rs` ou `lib.rs`:
```
erro: file not found for module `matematica`
```

**Solução:** Adicione `mod matematica;` no arquivo pai (onde o módulo deve ser visível).

### Erro 2: Esquecer `pub` no módulo

```rust
// lib.rs
mod calculadora;   // sem pub — outros projetos não podem usar!
```

**Solução:** `pub mod calculadora;` se quiser expor externamente.

### Erro 3: Esquecer `pub` em função/struct

```rust
pub mod matematica {
    fn fatorial(n: u64) -> u64 { ... }  // esqueceu pub!
}
```

```
erro: function `fatorial` is private
```

### Erro 4: Usar caminho relativo errado

```rust
// Dentro de src/rede/tcp.rs, tentando acessar src/rede/udp.rs:
// use udp::algo;     // ERRO — não funciona assim

use crate::rede::udp::algo;  // correto: path absoluto desde a raiz
use super::udp::algo;        // correto: path relativo ao pai
```

### Erro 5: Arquivo no lugar errado

O arquivo `tcp.rs` deve estar em `src/rede/tcp.rs` (não `src/tcp.rs`) quando declarado como `pub mod tcp` dentro de `src/rede/mod.rs`.

## 15. Comparação Final — C/C++ vs Rust (Organização)

| Conceito | C/C++ | Rust |
|----------|-------|------|
| Unidade de compilação | `.c` / `.cpp` | Crate |
| Declaração pública | Header `.h` | `pub` no código |
| Include | `#include "file.h"` (cópia textual) | `mod nome;` + arquivo |
| Importar | `using namespace` / `using` | `use path::to::item;` |
| Visibilidade | Tudo no header é público | `pub` / privado por padrão |
| Linker | Manual (-l, -L) | Cargo resolve tudo |
| Dependências | Copiar / vcpkg / conan | `Cargo.toml` |
| Guardas de inclusão | `#ifndef` manual | Não necessário |
| Namespace | `namespace` | Módulos (`mod`) |
| Testes | Framework externo | `cargo test` integrado |
