# Aula 14 — Async e Runtime Fundamentals

---

## Objetivo da Aula

Dominar o modelo de I/O assíncrono de Rust: **`async/await`**, o trait **`Future`**, o modelo **executor + reactor** (com tokio), **tasks**, **`select!`**, **timers**, e como Rust permite milhões de operações concorrentes com mínimo consumo de recursos. Entenderemos a diferença fundamental entre threads (Aula 13) e async tasks, por que async existe, quando usar cada um, e como o sistema de tipos de Rust ( ownership, `Pin`, `Send`) garante segurança mesmo em código assíncrono. Ao final, você saberá escrever programas async corretos e entender o que acontece por baixo do capô.

Esta aula introduz um segundo grande modelo de concorrência em Rust. Na Aula 13 usamos threads do sistema operacional; aqui vamos tratar tarefas leves voltadas principalmente para I/O concorrente.

Mapa mental:

- **async** não significa "mais rápido em tudo";
- **async** existe principalmente para lidar bem com espera de I/O;
- a unidade principal agora é a **task**, não a thread;
- o runtime coordena quando cada task anda ou pausa.

## 1. Por Que Async? O Problema de Escala

### 1.1 Threads não escalam para I/O

Na Aula 13 usamos threads nativas — cada thread custa ~1-8MB de stack. Para um servidor web com 100.000 conexões simultâneas:

```
100.000 threads × 1MB stack = ~100 GB de memória
```

Isso não escala. A maioria das conexões passa 99% do tempo **esperando** (I/O de rede, disco, banco de dados). Threads são desperdiçadas esperando.

### 1.2 O modelo async

Async usa **tarefas leves** que custam ~few KB cada e são gerenciadas em **user space** pelo runtime:

- **Task leve**: unidade de execução muito menor e mais barata que uma thread real.
- **User space**: código gerenciado no espaço de usuário, sem precisar que o kernel faça o agendamento fino de cada tarefa.

```
100.000 tasks × 4KB = ~400 MB de memória  ← viável!
```

| Aspecto | Thread | Async Task |
|---------|--------|------------|
| Stack | 1-8 MB (kernel) | ~few KB (user space) |
| Criação | Syscall (~μs-ms) | Alocação heap (~ns) |
| Troca de contexto | Kernel (registradores + stack) | User space (state machine) |
| Bloqueio | Thread inteira bloqueia | Apenas a task espera, executor roda outras |
| Escala | Milhares | Milhões |
| Melhor para | CPU-bound paralelo | I/O-bound concorrente |

### 1.3 O modelo Rust async vs outras linguagens

| Aspecto | Go | Rust | C# / JS |
|---------|----|------|---------|
| Runtime | Built-in (goroutines) | Externo (tokio, async-std) | Built-in (.NET / V8) |
| Modelo | M:N (green threads) | State machine + executor | State machine + executor |
| Memória | Stack dinâmico (cresce) | Size conhecido em compilação | Heap-allocated |
| Abordagem | `go func()` — simples | `async fn` + runtime — explícito | `async/await` — simples |
| Zero-cost | Não (runtime built-in) | Sim (sem runtime = sem custo) | Não |

**Diferença crucial:** Rust **não tem runtime async embutido**. A linguagem fornece `async/await` como syntax sugar para uma state machine. O runtime (executor + reactor) é uma crate separada — tipicamente **tokio**.

- **Syntax sugar**: sintaxe mais agradável que o compilador traduz para uma forma mais básica equivalente.
- **State machine**: estrutura que guarda em que ponto da execução a função parou e como deve continuar depois.
- **Runtime**: infraestrutura de execução que dá suporte ao modelo assíncrono.

## 2. Async/Await — Sintaxe

### 2.1 Função async

```rust
// async fn transforma a função em uma state machine que retorna Future
async fn saudar(nome: &str) -> String {
    format!("Olá, {}!", nome)
}

// Equivalente a:
fn saudar(nome: &str) -> impl Future<Output = String> {
    async move {
        format!("Olá, {}!", nome)
    }
}
```

`async fn` não executa nada — retorna um **`Future`** (valor preguiçoso). O corpo só executa quando o Future é **aguardado** (`.await`).

- **Future**: objeto que representa um valor que talvez ainda não esteja pronto, mas poderá ficar pronto depois.
- **Valor preguiçoso** (*lazy*): algo que descreve trabalho futuro sem executá-lo imediatamente.

### 2.2 `.await` — esperando o resultado

```rust
use tokio::time::{sleep, Duration};

async fn tarefa(nome: &str, segundos: u64) -> String {
    println!("{}: iniciando (vai esperar {}s)", nome, segundos);
    sleep(Duration::from_secs(segundos)).await;  // .await cede controle ao executor
    println!("{}: terminou", nome);
    format!("{} completou após {}s", nome, segundos)
}

#[tokio::main]
async fn main() {
    println!("Início");

    // Sequencial — cada tarefa espera a anterior
    let r1 = tarefa("A", 1).await;
    let r2 = tarefa("B", 2).await;
    println!("r1: {}, r2: {}", r1, r2);
    // Duração total: ~3 segundos (1 + 2)
}
```

**Modelo mental do .await:**

```
tarefa("A", 1).await:

1. Future começa a executar
2. sleep(1s) é chamado → registra timer no reactor
3. .await → SUSPENDE a task, devolve controle ao executor
4. Executor roda OUTRAS tasks enquanto espera
5. Timer dispara → reactor acorda a task
6. Task continua após o .await
7. Retorna o resultado
```

O ponto principal do `.await` é este:

- ele não bloqueia a thread como `sleep()` síncrono faria;
- ele suspende apenas a task atual;
- o executor aproveita esse tempo para rodar outras tasks prontas.

### 2.3 Concorrência com `tokio::join!` e `tokio::spawn`

```rust
use tokio::time::{sleep, Duration};

async fn tarefa(nome: &str, segundos: u64) -> String {
    println!("{}: iniciando", nome);
    sleep(Duration::from_secs(segundos)).await;
    println!("{}: terminou", nome);
    format!("{}", nome)
}

#[tokio::main]
async fn main() {
    // === join! — roda concorrentemente, espera TODAS terminarem ===
    println!("=== tokio::join! ===\n");

    let inicio = std::time::Instant::now();
    let (r1, r2, r3) = tokio::join!(
        tarefa("A", 1),
        tarefa("B", 2),
        tarefa("C", 1),
    );
    println!("Resultados: {}, {}, {}", r1, r2, r3);
    println!("Tempo com join!: {:.1}s\n", inicio.elapsed().as_secs_f64());
    // Tempo: ~2s (a mais longa) — não ~4s (soma)

    // === spawn — roda em background como task independente ===
    println!("=== tokio::spawn ===\n");

    let inicio = std::time::Instant::now();
    let handle1 = tokio::spawn(tarefa("X", 1));
    let handle2 = tokio::spawn(tarefa("Y", 2));
    let handle3 = tokio::spawn(tarefa("Z", 1));

    let r1 = handle1.await.unwrap();
    let r2 = handle2.await.unwrap();
    let r3 = handle3.await.unwrap();
    println!("Resultados: {}, {}, {}", r1, r2, r3);
    println!("Tempo com spawn: {:.1}s", inicio.elapsed().as_secs_f64());
    // Tempo: ~2s (a mais longa)
}
```

**Timeline com `join!`:**

```
Tempo:  0s       1s       2s
        |--------|--------|
Task A: |████████|done
Task B: |████████|████████|done
Task C: |████████|done
                             ↑ join! retorna quando TODAS terminam
```

### 2.4 `#[tokio::main]` — o que há por baixo

```rust
// O que você escreve:
#[tokio::main]
async fn main() {
    println!("olá async!");
}

// O que o compilador gera:
fn main() {
    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()
        .unwrap()
        .block_on(async {
            println!("olá async!");
        })
}
```

O runtime tokio:
1. Cria um **executor** (pool de threads — default = número de cores).
2. Cria um **reactor** (integra com epoll/io_uring/kqueue para I/O não-bloqueante).
3. Roda o Future principal com `block_on`.

Definições importantes:

- **Executor**: componente que decide qual task pronta será executada agora.
- **Reactor**: componente que espera eventos externos de I/O e acorda as tasks relevantes quando esses eventos acontecem.
- **block_on**: função que roda um future até conclusão, bloqueando o contexto chamador enquanto o runtime gerencia as tasks internas.

## 3. O Trait Future — Entendendo o Mecanismo

### 3.1 Definição

```rust
pub trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}

pub enum Poll<T> {
    Ready(T),    // valor pronto
    Pending,     // ainda não pronto — será acordado depois
}
```

- **Poll** é a linguagem formal do async em Rust:
  - `Ready(T)` = terminou e produziu `T`;
  - `Pending` = ainda não terminou; tente novamente mais tarde.

Cada `async fn` é transformada pelo compilador em uma **state machine** que implementa `Future`:

Isso explica por que async em Rust é zero-cost em essência: o compilador gera uma estrutura concreta especializada, em vez de depender de um runtime mágico da linguagem.

```rust
// O que você escreve:
async fn fetch_e_processar(url: &str) -> i32 {
    let dados = fetch(url).await;   // Ponto 1: suspensão
    let resultado = processar(&dados).await;  // Ponto 2: suspensão
    resultado
}

// O compilador gera (simplificado):
enum FetchProcessarState {
    Inicio { url: String },
    EsperandoFetch { url: String },
    EsperandoProcessar { dados: Vec<u8> },
    Done,
}

struct FetchProcessar {
    state: FetchProcessarState,
}

impl Future for FetchProcessar {
    type Output = i32;

    fn poll(mut self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<i32> {
        loop {
            match &mut self.state {
                FetchProcessarState::Inicio { url } => {
                    let future = fetch(url);
                    self.state = FetchProcessarState::EsperandoFetch { url: url.clone() };
                    // poll do fetch...
                }
                FetchProcessarState::EsperandoFetch { .. } => {
                    // poll do fetch future
                    // se Ready(dados) → muda para EsperandoProcessar
                    // se Pending → registra waker e retorna Pending
                }
                FetchProcessarState::EsperandoProcessar { .. } => {
                    // similar
                }
                FetchProcessarState::Done => panic!("poll after completion"),
            }
        }
    }
}
```

### 3.2 O ciclo poll → wake → poll

```
                ┌──────────────────────┐
                │     Executor          │
                │  (pool de threads)    │
                └──────┬───────────────┘
                       │
            poll(Future) → Pending
                       │
                       ├──→ Future registra Waker no Reactor
                       │    (ex: "acorde-me quando o socket tiver dados")
                       │
                ┌──────▼───────────────┐
                │     Reactor           │
                │  (epoll / io_uring)   │
                └──────┬───────────────┘
                       │
            Evento de I/O pronto (socket legível)
                       │
            wake() — acorda a task
                       │
            poll(Future) → Ready(resultado)
```

1. Executor chama `poll()` no Future.
2. Se `Pending`, o Future registra um **Waker** (callback) no reactor.
3. Reactor monitora eventos do SO (epoll, kqueue, io_uring).
4. Quando o evento ocorre, reactor chama `wake()`.
5. Executor põe a task de volta na fila e chama `poll()` novamente.
6. Quando `Ready(T)`, o valor é retornado.

- **Waker**: objeto que permite ao future avisar ao executor "me acorde quando eu puder continuar".
- Esse ciclo `poll -> pending -> wake -> poll` é o coração do modelo async de Rust.

### 3.3 Por que `Pin`?

`Pin<&mut Self>` impede que o Future seja movido na memória. Isso é necessário porque a state machine do async pode conter **auto-referências**:

- **Pin**: mecanismo que promete que um valor não será movido na memória depois de fixado.
- **Auto-referência**: situação em que parte da estrutura aponta para outra parte dela mesma.

Sem essa garantia, certas referências internas ficariam inválidas se o future mudasse de endereço após uma suspensão.

```rust
async fn exemplo() {
    let dados = vec![1, 2, 3];
    let referencia = &dados;  // referencia aponta para dados
    sleep(Duration::from_secs(1)).await;  // suspensão aqui!
    // Se o Future fosse movido na memória, referencia apontaria para lixo!
    println!("{:?}", referencia);
}
```

O `Pin` garante que o Future permanece no mesmo endereço de memória após a suspensão.

**Comparação:** Em C++, coroutines (C++20) usam um mecanismo similar (promise_type + coroutine handle), mas sem as garantias de segurança de Rust.

## 4. Tokio — O Runtime de Fato

### 4.1 Configuração

```toml
# Cargo.toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

`features = ["full"]` habilita: runtime multi-thread, I/O, timers, sync, macros. Para produção, selecione features individuais para reduzir tempo de compilação.

- **Feature**: opção de compilação de crate que liga ou desliga subconjuntos de funcionalidade.
- Isso existe para evitar dependências e tempo de compilação desnecessários.

### 4.2 Runtime flavors

```rust
// === Runtime multi-thread (padrão) ===
// Usa pool de threads (default = número de núcleos)
// Tasks migram entre threads (work-stealing)
#[tokio::main]
async fn main() {
    println!("Multi-thread runtime");
}

// === Runtime current-thread ===
// Tudo em uma única thread
// Mais eficiente para I/O leve (sem sincronização entre threads)
#[tokio::main(flavor = "current_thread")]
async fn main() {
    println!("Current-thread runtime");
}

// === Runtime configurado manualmente ===
fn main() {
    let rt = tokio::runtime::Builder::new_multi_thread()
        .worker_threads(4)          // 4 threads no pool
        .thread_name("tokio-worker")
        .enable_all()               // habilita I/O e timers
        .build()
        .unwrap();

    rt.block_on(async {
        println!("Runtime configurado manualmente");
    });
}
```

### 4.3 Tasks — a unidade de concorrência

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    // tokio::spawn cria uma task — roda concorrentemente
    // Retorna JoinHandle (equivalente a thread::JoinHandle)
    let handle = tokio::spawn(async {
        sleep(Duration::from_millis(100)).await;
        42
    });

    // .await no JoinHandle espera a task terminar
    let resultado = handle.await.unwrap();
    println!("Resultado: {}", resultado);  // 42

    // === Muitas tasks concorrentes ===
    let mut handles = Vec::new();

    for i in 0..1000 {
        handles.push(tokio::spawn(async move {
            sleep(Duration::from_millis(1)).await;
            i * 2
        }));
    }

    // Esperar todas
    let mut resultados = Vec::new();
    for h in handles {
        resultados.push(h.await.unwrap());
    }
    println!("Total de resultados: {}", resultados.len());  // 1000
}
```

**Task vs Thread:**

| Aspecto | Thread | Tokio Task |
|---------|--------|------------|
| Custo de criação | ~1μs + 1MB stack | ~200ns + ~256 bytes |
| Número prático | ~10.000 | ~1.000.000+ |
| Agendamento | Kernel (preemptivo) | Executor (cooperativo) |
| Bloqueio | OK (kernel troca) | **PROIBIDO** — bloqueia a thread inteira |
| Join | `handle.join()` | `handle.await` |

Essa tabela é importante porque mostra que async não substitui threads universalmente; ele resolve melhor um conjunto específico de problemas.

### 4.4 NUNCA bloqueie o executor

```rust
use tokio::time::{sleep, Duration};

// === ERRADO — bloqueia a thread do executor ===
async fn tarefa_ruim() {
    std::thread::sleep(Duration::from_secs(1));  // BLOQUEIA! Nenhuma outra task roda nesta thread!
}

// === CORRETO — cede controle ao executor ===
async fn tarefa_boa() {
    sleep(Duration::from_secs(1)).await;  // Cede controle — outras tasks podem rodar
}

// === Se PRECISA fazer CPU-bound, use spawn_blocking ===
async fn trabalho_cpu_intenso() -> u64 {
    tokio::task::spawn_blocking(|| {
        // Roda em thread separada — não bloqueia o executor
        let mut soma = 0u64;
        for i in 0..100_000_000 {
            soma = soma.wrapping_add(i);
        }
        soma
    }).await.unwrap()
}
```

**Regra de ouro async:** Nunca chame `std::thread::sleep`, I/O síncrono (`std::fs::*`, `std::net::*`), ou CPU-bound diretamente em código async. Use as versões async (tokio) ou `spawn_blocking`.

- **CPU-bound**: trabalho dominado por cálculo.
- **I/O-bound**: trabalho dominado por espera de rede, disco, banco, socket etc.

## 5. Canais Async — `tokio::sync`

### 5.1 mpsc channel async

Os canais async seguem a mesma ideia conceitual dos canais da aula anterior, mas agora a espera por mensagens não bloqueia a thread do executor.

```rust
use tokio::sync::mpsc;
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    // Canal com capacidade 32
    let (tx, mut rx) = mpsc::channel::<String>(32);

    // Produtor
    tokio::spawn(async move {
        for i in 0..10 {
            let msg = format!("mensagem {}", i);
            tx.send(msg).await.unwrap();  // .await — não bloqueia a thread!
            sleep(Duration::from_millis(100)).await;
        }
    });

    // Consumidor
    while let Some(msg) = rx.recv().await {  // .await — não bloqueia
        println!("Recebido: {}", msg);
    }
}
```

### 5.2 oneshot — valor único

```rust
use tokio::sync::oneshot;

#[tokio::main]
async fn main() {
    let (tx, rx) = oneshot::channel::<String>();

    tokio::spawn(async move {
        // Simula trabalho
        tokio::time::sleep(std::time::Duration::from_millis(100)).await;
        tx.send("resultado do trabalho".to_string()).unwrap();
    });

    let resultado = rx.await.unwrap();
    println!("Recebido: {}", resultado);
}
```

### 5.3 broadcast — múltiplos receptores

```rust
use tokio::sync::broadcast;

#[tokio::main]
async fn main() {
    let (tx, _) = broadcast::channel::<String>(16);

    // Cada subscribe() cria um receptor independente
    let mut rx1 = tx.subscribe();
    let mut rx2 = tx.subscribe();

    tokio::spawn(async move {
        while let Ok(msg) = rx1.recv().await {
            println!("Receptor 1: {}", msg);
        }
    });

    tokio::spawn(async move {
        while let Ok(msg) = rx2.recv().await {
            println!("Receptor 2: {}", msg);
        }
    });

    tx.send("olá todos!".to_string()).unwrap();
    tx.send("segunda mensagem".to_string()).unwrap();

    tokio::time::sleep(std::time::Duration::from_millis(50)).await;
}
```

### 5.4 Comparação de canais

| Canal | Produtores | Consumidores | Quando usar |
|-------|-----------|--------------|-------------|
| `mpsc` | Múltiplos | 1 | Pipeline, fan-in |
| `oneshot` | 1 | 1 | Resposta única (RPC, request/reply) |
| `broadcast` | 1 | Múltiplos | Eventos, notificações |
| `watch` | 1 | Múltiplos | Estado atual (último valor) |

- **oneshot**: canal de uso único, ideal para responder exatamente uma vez.
- **broadcast**: mesma mensagem pode ser observada por vários receptores independentes.
- **watch**: mantém principalmente o valor mais recente, útil para configuração e estado atual.

## 6. `tokio::select!` — Esperar Múltiplas Operações

### 6.1 Uso básico

```rust
use tokio::sync::mpsc;
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let (tx1, mut rx1) = mpsc::channel::<&str>(32);
    let (tx2, mut rx2) = mpsc::channel::<&str>(32);

    tokio::spawn(async move {
        sleep(Duration::from_millis(100)).await;
        tx1.send("do canal 1").await.unwrap();
    });

    tokio::spawn(async move {
        sleep(Duration::from_millis(50)).await;
        tx2.send("do canal 2").await.unwrap();
    });

    // select! espera QUALQUER ramo ficar pronto
    tokio::select! {
        msg = rx1.recv() => println!("Recebido do canal 1: {:?}", msg),
        msg = rx2.recv() => println!("Recebido do canal 2: {:?}", msg),
    }
    // "do canal 2" chega primeiro (50ms < 100ms)
}
```

### 6.2 select! com timeout

```rust
use tokio::time::{timeout, Duration};

#[tokio::main]
async fn main() {
    let resultado = timeout(
        Duration::from_millis(100),
        async {
            sleep(Duration::from_secs(5)).await;
            "nunca vai chegar"
        },
    ).await;

    match resultado {
        Ok(val) => println!("Resultado: {}", val),
        Err(_) => println!("Timeout — operação demorou demais!"),
    }
}
```

### 6.3 select! em loop com cancelamento

```rust
use tokio::sync::mpsc;
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel::<i32>(32);
    let mut contador = 0;

    // Produtor
    tokio::spawn(async move {
        for i in 0..20 {
            tx.send(i).await.unwrap();
            sleep(Duration::from_millis(100)).await;
        }
    });

    loop {
        tokio::select! {
            // Ramo 1: receber do canal
            Some(val) = rx.recv() => {
                contador += 1;
                println!("Recebido: {}", val);
            }

            // Ramo 2: timeout periódico
            _ = sleep(Duration::from_millis(350)) => {
                println!("Tick periódico — contador={}", contador);
            }

            // Ramo 3: ctrl+c
            _ = tokio::signal::ctrl_c() => {
                println!("Interrompido! Contador final: {}", contador);
                break;
            }
        }
    }
}
```

### 6.4 Cancelamento automático

`select!` cancela os ramos que não foram escolhidos. Isso é **cancelamento automático**:

- **Cancelamento automático**: futuros que perdem a corrida deixam de progredir naquele `select!` e são descartados, a menos que você os preserve externamente.

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    tokio::select! {
        _ = async {
            println!("Ramo A: antes do sleep");
            sleep(Duration::from_secs(10)).await;
            println!("Ramo A: depois do sleep");  // NÃO imprime se B ganhar
        } => println!("Ramo A venceu"),

        _ = sleep(Duration::from_millis(50)) => {
            println!("Ramo B venceu (timeout)");
        }
    }
    // Ramo A é CANCELADO automaticamente quando B vence
}
```

## 7. Mutex e RwLock Async

### 7.1 `tokio::sync::Mutex` vs `std::sync::Mutex`

```rust
use std::sync::Arc;
use tokio::sync::Mutex;  // Mutex ASYNC do tokio

#[tokio::main]
async fn main() {
    let contador = Arc::new(Mutex::new(0));

    let mut handles = Vec::new();

    for _ in 0..10 {
        let contador_clone = Arc::clone(&contador);
        handles.push(tokio::spawn(async move {
            // .await no lock — não bloqueia a thread!
            let mut num = contador_clone.lock().await;
            *num += 1;
            // lock liberado aqui
        }));
    }

    for h in handles {
        h.await.unwrap();
    }

    println!("Contador: {}", *contador.lock().await);  // 10
}
```

**Quando usar cada Mutex:**

| Mutex | Quando usar |
|-------|-------------|
| `std::sync::Mutex` | Locks curtos (não segura através de `.await`) — MAIS EFICIENTE |
| `tokio::sync::Mutex` | Locks longos que atravessam `.await` |

Essa distinção importa muito porque um mutex async não é simplesmente "sempre melhor". Ele resolve um problema específico e cobra custo por isso.

**Regra prática:** Prefira `std::sync::Mutex` (envolvido em `Arc`). Use `tokio::sync::Mutex` apenas se precisa segurar o lock através de `.await`.

## 8. I/O Assíncrono com Tokio

### 8.1 TCP echo server

```rust
use tokio::net::{TcpListener, TcpStream};
use tokio::io::{AsyncReadExt, AsyncWriteExt};

async fn handle_cliente(mut stream: TcpStream) -> tokio::io::Result<()> {
    let mut buffer = [0; 1024];

    loop {
        let n = stream.read(&mut buffer).await?;  // .await — não bloqueia
        if n == 0 {
            return Ok(());  // cliente desconectou
        }
        stream.write_all(&buffer[..n]).await?;  // ecoa de volta
    }
}

#[tokio::main]
async fn main() -> tokio::io::Result<()> {
    let listener = TcpListener::bind("127.0.0.1:8080").await?;
    println!("Echo server ouvindo em 127.0.0.1:8080");

    loop {
        let (stream, addr) = listener.accept().await?;
        println!("Conexão de: {}", addr);

        // Cada conexão vira uma task independente
        tokio::spawn(async move {
            if let Err(e) = handle_cliente(stream).await {
                println!("Erro em {}: {}", addr, e);
            }
        });
    }
}
```

**Modelo de execução:**

```
Thread pool (4 threads do executor):

Thread 1:  |── accept ──|── spawn task ──|── accept ──|── spawn task ──|...
Thread 2:  |── task A: read ──|── task A: write ──|── task C: read ──|...
Thread 3:  |── task B: read ──|── task B: write ──|── task D: read ──|...
Thread 4:  |── task E: read ──|── task E: write ──|── task F: read ──|...

Cada task: .await cede controle → executor roda outra task
Resulta em: milhares de conexões em apenas 4 threads
```

## 9. `Stream` — Iterators Assíncronos

### 9.1 O que é

`Stream` é o equivalente async de `Iterator` — produz valores ao longo do tempo:

- **Stream**: sequência assíncrona de itens, em que o próximo elemento pode ainda não estar pronto.
- Pense nele como "iterator + await entre os itens".

```rust
// Iterator (síncrono):
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;  // bloqueia até ter o próximo
}

// Stream (assíncrono):
trait Stream {
    type Item;
    fn poll_next(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Option<Self::Item>>;
}
```

### 9.2 Usando streams (com tokio-stream)

```toml
# Cargo.toml

futures = "0.3"
```

```rust
use tokio_stream::{self as stream, StreamExt};
use tokio::time::{sleep, Duration};

async fn main() {
    // Stream de intervalo
    let mut intervalo = stream::iter(0..5);

}
```

## 10. Padrões de Concorrência Async

### 10.1 Fan-out com tasks

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let urls = vec!["url1", "url2", "url3", "url4", "url5"];

    let inicio = std::time::Instant::now();

    // Fan-out: todas as requests em paralelo
    let mut handles = Vec::new();
    for url in urls {
        handles.push(tokio::spawn(async move {
            fetch_simulado(url).await
        }));
    }

    // Fan-in: coletar resultados
    let mut resultados = Vec::new();
    for handle in handles {
        resultados.push(handle.await.unwrap());
    }

    println!("Resultados: {:?}", resultados);
    println!("Tempo: {:.1}s", inicio.elapsed().as_secs_f64());
    // ~1s (todas em paralelo) em vez de ~5s (sequencial)
}

async fn fetch_simulado(url: &str) -> String {
    sleep(Duration::from_secs(1)).await;
    format!("dados de {}", url)
}
```

### 10.2 Rate limiting com semaphore

```rust
use tokio::sync::Semaphore;
use tokio::time::{sleep, Duration};
use std::sync::Arc;

#[tokio::main]
async fn main() {
    let semaforo = Arc::new(Semaphore::new(3));  // no máximo 3 concorrentes
    let mut handles = Vec::new();

    for i in 0..10 {
        let semaforo = Arc::clone(&semaforo);
        handles.push(tokio::spawn(async move {
            let _permit = semaforo.acquire().await.unwrap();  // espera vaga
            println!("Task {}: iniciando", i);
            sleep(Duration::from_secs(1)).await;
            println!("Task {}: terminando", i);
            // _permit dropado → libera vaga
        }));
    }

    for h in handles {
        h.await.unwrap();
    }
}
```

### 10.3 Graceful shutdown

```rust
use tokio::sync::mpsc;
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let (tx, mut rx) = mpsc::channel::<String>(32);
    let (shutdown_tx, mut shutdown_rx) = tokio::sync::broadcast::channel::<()>(1);

    // Worker
    let worker = tokio::spawn(async move {
        let mut shutdown = shutdown_rx;
        loop {
            tokio::select! {
                msg = rx.recv() => {
                    match msg {
                        Some(m) => println!("Processando: {}", m),
                        None => {
                            println!("Canal fechado, saindo...");
                            break;
                        }
                    }
                }
                _ = shutdown.recv() => {
                    println!("Shutdown recebido, finalizando...");
                    break;
                }
            }
        }
    });

    // Envia mensagens
    for i in 0..5 {
        tx.send(format!("mensagem {}", i)).await.unwrap();
        sleep(Duration::from_millis(100)).await;
    }

    // Sinal de shutdown
    let _ = shutdown_tx.send(());
    worker.await.unwrap();
    println!("Sistema finalizado graciosamente");
}
```

## 11. Exemplo Completo — Servidor de Chat Multi-Client

```rust
// aula14_async.rs
// Executar: cargo run (requer Cargo.toml com tokio)
//
// Cargo.toml:
// [package]
// name = "aula14_async"
// version = "0.1.0"
// edition = "2021"
//
// [dependencies]
// tokio = { version = "1", features = ["full"] }

use tokio::sync::broadcast;
use tokio::net::{TcpListener, TcpStream};
use tokio::io::{AsyncBufReadExt, AsyncWriteExt, BufReader};
use std::sync::Arc;
use std::sync::atomic::{AtomicUsize, Ordering};

struct EstadoCompartilhado {
    clientes_conectados: AtomicUsize,
    mensagens_enviadas: AtomicUsize,
}

async fn handle_cliente(
    stream: TcpStream,
    tx: broadcast::Sender<String>,
    estado: Arc<EstadoCompartilhado>,
) {
    let (reader, mut writer) = stream.into_split();
    let mut reader = BufReader::new(reader);
    let mut rx = tx.subscribe();

    let addr = writer.peer_addr().map(|a| a.to_string()).unwrap_or("???".into());

    let count = estado.clientes_conectados.fetch_add(1, Ordering::Relaxed) + 1;
    println!("Cliente conectado: {} (total: {})", addr, count);

    // Envia boas-vindas
    let _ = writer.write_all(format!("Bem-vindo ao chat! Você é o cliente #{}\n", count).as_bytes()).await;

    // Loop principal: ler do cliente E receber mensagens broadcast
    let mut linha = String::new();
    loop {
        tokio::select! {
            // Ler input do cliente
            result = reader.read_line(&mut linha) => {
                match result {
                    Ok(0) => {
                        // Cliente desconectou
                        println!("Cliente {} desconectou", addr);
                        let _ = tx.send(format!("[{}] saiu do chat", addr));
                        break;
                    }
                    Ok(_) => {
                        let msg = linha.trim().to_string();
                        if !msg.is_empty() {
                            let _ = tx.send(format!("[{}] {}", addr, msg));
                            estado.mensagens_enviadas.fetch_add(1, Ordering::Relaxed);
                        }
                        linha.clear();
                    }
                    Err(e) => {
                        println!("Erro lendo de {}: {}", addr, e);
                        break;
                    }
                }
            }

            // Receber mensagens de outros clientes
            result = rx.recv() => {
                match result {
                    Ok(msg) => {
                        if writer.write_all(msg.as_bytes()).await.is_err() {
                            break;  // não pode mais escrever
                        }
                        if writer.write_all(b"\n").await.is_err() {
                            break;
                        }
                    }
                    Err(broadcast::error::RecvError::Lagged(n)) => {
                        let _ = writer.write_all(format!("!! {} mensagens perdidas\n", n).as_bytes()).await;
                    }
                    Err(_) => break,
                }
            }
        }
    }

    estado.clientes_conectados.fetch_sub(1, Ordering::Relaxed);
}

#[tokio::main]
async fn main() -> tokio::io::Result<()> {
    let (tx, _) = broadcast::channel::<String>(100);
    let estado = Arc::new(EstadoCompartilhado {
        clientes_conectados: AtomicUsize::new(0),
        mensagens_enviadas: AtomicUsize::new(0),
    });

    let listener = TcpListener::bind("127.0.0.1:6379").await?;
    println!("=== Chat Server ===");
    println!("Ouvindo em 127.0.0.1:6379");
    println!("Conecte com: telnet 127.0.0.1 6379");
    println!("             ou: nc 127.0.0.1 6379");
    println!();

    loop {
        let (stream, addr) = listener.accept().await?;
        println!("Nova conexão de: {}", addr);

        let tx = tx.clone();
        let estado = Arc::clone(&estado);

        tokio::spawn(async move {
            handle_cliente(stream, tx, estado).await;
        });
    }
}
```

Compilar e executar:
```bash
cargo run
# Em outro terminal: telnet 127.0.0.1 6379
# Ou: nc 127.0.0.1 6379
```

**Arquitetura:**

```
                  ┌─────────────────────────────────────┐
                  │         Tokio Runtime                │
                  │  ┌──────────┐  ┌──────────┐         │
Cliente 1 ←───→  │  │ Task 1   │  │ Task 2   │  ←───→ Cliente 2
  telnet          │  │ read/write    read/write│         │  telnet
                  │  └────┬─────┘  └────┬─────┘         │
                  │       │             │                │
                  │       ▼             ▼                │
                  │  ┌─────────────────────────────┐    │
                  │  │    broadcast channel         │    │
                  │  │    (mensagens de todos)       │    │
                  │  └─────────────────────────────┘    │
                  │                                     │
                  │  ThreadPool (N worker threads)      │
                  └─────────────────────────────────────┘
```

## 12. Erros Comuns

### Erro 1: Bloquear o executor

```rust
// ERRADO — bloqueia a thread do executor
async fn ruim() {
    std::thread::sleep(Duration::from_secs(1));  // NENHUMA outra task roda nesta thread!
    let dados = std::fs::read_to_string("arquivo.txt").unwrap();  // Bloqueia I/O síncrono!
}

// CORRETO
async fn bom() {
    tokio::time::sleep(Duration::from_secs(1)).await;  // cede controle
    let dados = tokio::fs::read_to_string("arquivo.txt").await.unwrap();  // I/O async
}
```

### Erro 2: Segurar std::sync::Mutex através de .await

```rust
use std::sync::Mutex;

async fn perigo(dados: &Mutex<Vec<i32>>) {
    let mut guard = dados.lock().unwrap();
    // SE outra thread fizer panic enquanto este guard existe, o Mutex é envenenado
    // Pior: se .await suspende com guard ativo, NENHUMA task nesta thread pode pegar o lock
    tokio::time::sleep(Duration::from_secs(1)).await;  // guarda lock por 1 segundo!
    guard.push(42);
}
```

**Solução:** Solte o lock antes de `.await`, ou use `tokio::sync::Mutex`.

### Erro 3: Esquecer .await

```rust
async fn fetch(url: &str) -> String {
    format!("dados de {}", url)
}

async fn main_ruim() {
    fetch("http://example.com");  // NÃO EXECUTA! Future é criado e dropado
}

async fn main_bom() {
    let resultado = fetch("http://example.com").await;  // executa
}
```

### Erro 4: Criar runtime dentro de runtime

```rust
// ERRO: não pode criar runtime dentro de outro runtime
#[tokio::main]
async fn main() {
    // tokio::runtime::Runtime::new().unwrap().block_on(...);  // PANIC!
    // Use tokio::spawn em vez de criar outro runtime
}
```

### Erro 5: Usar async para CPU-bound

```rust
// INEFICIENTE — todas as tasks competem pelo mesmo pool
async fn cpu_bound_ruim() {
    for i in 0..1_000_000_000 {
        // computação pesada
    }
}

// CORRETO — roda em thread separada
async fn cpu_bound_bom() {
    tokio::task::spawn_blocking(|| {
        for i in 0..1_000_000_000 {
            // computação pesada em thread dedicada
        }
    }).await.unwrap()
}
```

## 13. Comparação — Go vs Rust vs C++ (Async)

| Conceito | Go | Rust (tokio) | C++20 (coroutines) |
|----------|----|----|------|
| Unidade | Goroutine (~4KB) | Task (~256B) | Coroutine frame (heap) |
| Runtime | Built-in | Crate (tokio) | Biblioteca customizada |
| Scheduler | M:N preemptivo | M:N cooperativo | Manual / biblioteca |
| I/O | net package (async) | tokio::net | asio / libuv |
| Seleção | `select` statement | `tokio::select!` | `when_any` (manual) |
| Cancelamento | context.Context | Drop do Future | manual |
| Memória | Stack cresce dinamicamente | Size fixo (Pin) | Heap (manual) |
| Overhead | Baixo | Muito baixo | Variável |
| Complexidade | Baixa (go func) | Média (Pin, Send) | Alta (manual tudo) |
| Debugging | pprof | tokio-console | Manual |

## 14. Tabela de Decisão — Threads vs Async

| Situação | Use |
|----------|-----|
| CPU-bound (computação pesada) | Threads (`std::thread`) |
| I/O-bound (rede, disco, DB) | Async (`tokio`) |
| Poucas tasks (<100) | Threads |
| Milhares+ de conexões | Async |
| Processamento paralelo de dados | Threads (rayon crate) |
| Servidor HTTP | Async |
| CLI tool simples | Threads ou síncrono |
| Mix CPU + I/O | Threads para CPU + async para I/O |
