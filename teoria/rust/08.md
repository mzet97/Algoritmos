# Aula 8 — Tratamento de Erros com Result e Option

---

## Nesta aula

Dominar o sistema de tratamento de erros de Rust: **`Option<T>`** (ausência de valor), **`Result<T, E>`** (sucesso ou erro), o **operador `?`**, propagação de erros, criar tipos de erro customizados, `From`/`Into` para conversão automática, e a filosofia central: **erros são valores, não exceções**. Você vai aprender a modelar ausência com `Option<T>` e falha com `Result<T, E>`, propagar erros com o operador `?`, converter tipos de erro com `From`/`Into`, e distinguir erros recuperáveis (valores) de bugs (pânico).
---

## 1. A Filosofia — Erros São Valores

### 1.1 O problema em C/C++

Em C, erros são tratados de formas inconsistentes e inseguras:

```c
// C — erros por código de retorno
FILE* f = fopen("arquivo.txt", "r");   // retorna NULL em erro
if (f == NULL) { /* tratar */ }

int result = printf("olá");             // retorna negativo em erro — quem verifica?

// C — erros por errno (global, não thread-safe por padrão)
errno = 0;
long pos = ftell(f);
if (errno != 0) { /* tratar */ }

// C — erros por return code
int fd = open("arquivo", O_RDONLY);    // -1 = erro
if (fd < 0) { perror("open"); }
```

Em C++, exceções adicionam complexidade invisível:

```cpp
// C++ — qualquer função pode lançar exceção
void processo() {
    auto dados = ler_arquivo();       // pode lançar?
    auto resultado = parsear(dados);  // pode lançar?
    salvar(resultado);                // pode lançar?
    // NENHUMA dessas funções declara que lança exceção
    // Você só descobre em runtime, se a exceção aparecer
}
```

Problemas do modelo de exceções:
- **Invisibilidade** — não se sabe quais funções podem lançar.
- **Non-local control flow** — o fluxo pula para um catch arbitrário.
- **Resource leaks** — esquecer RAII ou try/catch vaza recursos.
- **Performance** — tabelas de unwind, overhead em código que nunca lança.

Vamos fixar os termos:

- **Exceção**: mecanismo de runtime que interrompe o fluxo normal e procura um ponto de captura (`catch`).
- **Non-local control flow**: o fluxo não volta apenas para o chamador imediato; ele pode saltar vários níveis da pilha.
- **RAII**: padrão de C++ em que a aquisição e a liberação de recursos ficam atreladas à vida do objeto.
- **Unwind**: processo de desfazer a pilha de chamadas, executando destrutores no caminho.

### 1.2 Como Rust resolve

Rust **não tem exceções**. Em vez disso:

| Situação | Rust | C/C++ |
|----------|------|-------|
| Valor pode estar ausente | `Option<T>` | `null` / `nullptr` |
| Operação pode falhar | `Result<T, E>` | código de retorno / exceção |
| Erro irrecuperável | `panic!` | `abort()` / `assert()` |
| Propagação de erro | operador `?` | `throw` / return code manual |

**Regra de ouro:**
- **`Option<T>`** — quando a ausência de valor é uma possibilidade normal e esperada.
- **`Result<T, E>`** — quando a operação pode falhar por uma causa que o chamador deve tratar.
- **`panic!`** — quando algo está irremediavelmente quebrado (bug, invariant violado). Não deve ser usado para fluxo normal.

Isso existe para separar claramente três categorias diferentes:

- ausência esperada;
- falha recuperável;
- falha irrecuperável.

Misturar essas categorias é exatamente o que torna APIs confusas em C e C++.

## 2. Option<T> — Revisão Profunda

### 2.1 Definição

```rust
enum Option<T> {
    Some(T),   // tem valor
    None,      // não tem valor
}
```

`Option<T>` responde a uma pergunta simples: "pode haver um valor aqui ou não?"

Por que isso existe?

- para substituir `null` por algo tipado e explícito;
- para obrigar o chamador a lidar com a ausência;
- para tornar impossível esquecer, em código safe, que o valor pode não existir.

### 2.2 Combinators — a API completa

- **Combinator**: método que combina ou transforma valores encapsulados sem precisar abrir manualmente a estrutura com `match`.
- Eles existem para escrever código declarativo e encadeável, em vez de aninhar condicionais repetitivas.

```rust
fn main() {
    let x: Option<i32> = Some(42);
    let n: Option<i32> = None;

    // map — transforma o valor interno
    let dobado = x.map(|v| v * 2);         // Some(84)
    let n_dobado = n.map(|v| v * 2);       // None
    println!("map: {:?}, {:?}", dobado, n_dobado);

    // map_or — transforma com valor padrão
    let resultado = x.map_or(0, |v| v * 2);    // 84
    let resultado_n = n.map_or(0, |v| v * 2);  // 0
    println!("map_or: {}, {}", resultado, resultado_n);

    // map_or_else — transforma com closure para padrão
    let resultado = x.map_or_else(|| -1, |v| v * 2);  // 84
    println!("map_or_else: {}", resultado);

    // and_then — encadeia operações que retornam Option (flatMap)
    let encadeado = x.and_then(|v| {
        if v > 10 { Some(v * 100) } else { None }
    });
    println!("and_then: {:?}", encadeado);    // Some(4200)

    // or — fornece alternativa se None
    let alternativa = n.or(Some(99));
    println!("or: {:?}", alternativa);         // Some(99)

    // or_else — alternativa com closure
    let calc = n.or_else(|| Some(0));
    println!("or_else: {:?}", calc);            // Some(0)

    // unwrap — extrai, panic se None
    // println!("{}", n.unwrap());  // PANIC!

    // unwrap_or — extrai com padrão
    println!("unwrap_or: {}", n.unwrap_or(0));   // 0

    // unwrap_or_else — extrai com closure
    println!("unwrap_or_else: {}", n.unwrap_or_else(|| -1));  // -1

    // unwrap_default — extrai ou Default::default()
    println!("unwrap_default: {:?}", n.unwrap_or_default());   // 0

    // expect — como unwrap, mas com mensagem customizada
    // println!("{}", n.expect("deveria ter valor!"));
    // PANIC: deveria ter valor!

    // is_some / is_none
    println!("is_some: {}, is_none: {}", x.is_some(), n.is_none());  // true, true

    // filter — mantém Some apenas se o predicado for true
    let filtrado = x.filter(|&v| v > 50);
    println!("filter (>50): {:?}", filtrado);   // None

    // zip — combina dois Options em Option de tupla
    let a = Some(1);
    let b = Some("texto");
    let c: Option<&str> = None;
    println!("zip: {:?}", a.zip(b));            // Some((1, "texto"))
    println!("zip com None: {:?}", a.zip(c));   // None

    // transpose — converte Option<Result<T,E>> em Result<Option<T>,E>
    let opt_res: Option<Result<i32, &str>> = Some(Ok(42));
    let res_opt: Result<Option<i32>, &str> = opt_res.transpose();
    println!("transpose: {:?}", res_opt);        // Ok(Some(42))
}
```

- **Encadear** significa ligar operações de forma que cada etapa receba o valor produzido pela etapa anterior.
- **flatMap** é o nome funcional do padrão "transforma e evita criar Option<Option<T>>" ou Result<Result<T,E>,E>.

### 2.3 Encadeamento prático

```rust
fn main() {
    // Sem encadeamento — código aninhado (verboso)
    let texto = Some("42");
    let resultado_sem = match texto {
        Some(s) => match s.parse::<i32>() {
            Ok(n) => Some(n * 2),
            Err(_) => None,
        },
        None => None,
    };

    // Com encadeamento — limpo e expressivo
    let resultado = texto
        .and_then(|s| s.parse::<i32>().ok())   // Option<i32>
        .map(|n| n * 2);                       // Option<i32>

    println!("sem: {:?}", resultado_sem);  // Some(84)
    println!("com: {:?}", resultado);      // Some(84)
}
```

## 3. Result<T, E> — Sucesso ou Erro

### 3.1 Definição

```rust
enum Result<T, E> {
    Ok(T),     // sucesso com valor T
    Err(E),    // erro com valor E
}
```

`Result<T, E>` responde a outra pergunta: "a operação funcionou ou falhou?"

- `T` é o tipo do sucesso;
- `E` é o tipo do erro.

Por que isso existe?

- porque falha faz parte do fluxo normal de sistemas reais;
- porque o erro também carrega informação útil;
- porque o chamador precisa ver isso já na assinatura da função.

### 3.2 Uso básico

```rust
use std::fs;

fn main() {
    let resultado: Result<String, std::io::Error> = fs::read_to_string("arquivo.txt");

    match resultado {
        Ok(conteudo) => println!("Conteúdo: {}", conteudo),
        Err(erro) => println!("Erro: {}", erro),
    }
}
```

### 3.3 Criando seus próprios Results

```rust
#[derive(Debug)]
enum ErroDivisao {
    DivisaoPorZero,
    NumeradorInvalido,
}

fn dividir(a: f64, b: f64) -> Result<f64, ErroDivisao> {
    if b == 0.0 {
        Err(ErroDivisao::DivisaoPorZero)
    } else {
        Ok(a / b)
    }
}

fn main() {
    match dividir(10.0, 3.0) {
        Ok(resultado) => println!("10 / 3 = {:.4}", resultado),
        Err(ErroDivisao::DivisaoPorZero) => println!("Erro: divisão por zero"),
        Err(ErroDivisao::NumeradorInvalido) => println!("Erro: numerador inválido"),
    }

    match dividir(10.0, 0.0) {
        Ok(resultado) => println!("resultado = {}", resultado),
        Err(e) => println!("Erro: {:?}", e),
    }
}
```

### 3.4 Combinators de Result

Os combinators de `Result` seguem a mesma filosofia dos de `Option`, mas agora carregando explicitamente o caminho de falha.

```rust
use std::num::ParseIntError;

fn main() -> Result<(), ParseIntError> {
    let resultado: Result<i32, ParseIntError> = "42".parse();

    // map — transforma o valor Ok
    let dobrado = resultado.map(|n| n * 2);
    println!("dobrado: {:?}", dobrado);                    // Ok(84)

    // map_err — transforma o erro
    let texto: Result<i32, ParseIntError> = "abc".parse();
    let com_msg = texto.map_err(|e| format!("erro de parse: {}", e));
    println!("com_msg: {:?}", com_msg);                     // Err("erro de parse: ...")

    // and_then — encadeia operações Result (flatMap)
    let encadeado = "42".parse::<i32>().and_then(|n| {
        if n > 0 { Ok(n * 100) } else { Err("deve ser positivo".parse().unwrap_err()) }
    });

    // or / or_else — alternativa em caso de Err
    let alt1 = texto.or(Ok(0));
    println!("or: {:?}", alt1);                             // Ok(0)

    // unwrap / expect — extrai ou panic
    // let val = texto.unwrap();  // PANIC!
    let val = "42".parse::<i32>().unwrap();
    println!("unwrap: {}", val);                            // 42

    // unwrap_or / unwrap_or_else / unwrap_or_default
    println!("unwrap_or: {:?}", texto.unwrap_or(0));        // 0
    println!("unwrap_or_else: {:?}", texto.unwrap_or_else(|_| -1));  // -1

    // is_ok / is_err
    println!("is_ok: {}", resultado.is_ok());               // true
    println!("is_err: {}", texto.is_err());                  // true

    // ok() e err() — convertem para Option
    println!("ok(): {:?}", resultado.ok());                  // Some(42)
    println!("err(): {:?}", texto.err());                    // Some(ParseIntError)

    // as_ref / as_mut — empresta sem consumir
    let r: Result<String, &str> = Ok(String::from("olá"));
    let emprestado: Result<&String, &&str> = r.as_ref();
    println!("as_ref: {:?}", emprestado);                    // Ok("olá")

    Ok(())
}
```

## 4. O Operador `?` — Propagação Elegante

### 4.1 O problema sem `?`

```rust
use std::fs::File;
use std::io::{self, Read};

fn ler_arquivo_sem_ponto_interrogacao(caminho: &str) -> Result<String, io::Error> {
    let arquivo = match File::open(caminho) {
        Ok(f) => f,
        Err(e) => return Err(e),
    };

    let mut conteudo = String::new();
    match arquivo.read_to_string(&mut conteudo) {
        Ok(_) => Ok(conteudo),
        Err(e) => Err(e),
    }
}
```

Cada operação que pode falhar precisa de `match` para propagar o erro. Verboso e repetitivo.

- **Propagar erro**: não tratar o erro naquele ponto, mas devolvê-lo ao chamador para que ele decida.
- O operador `?` existe justamente para tornar essa estratégia legível.

### 4.2 Com o operador `?`

```rust
use std::fs::File;
use std::io::{self, Read};

fn ler_arquivo(caminho: &str) -> Result<String, io::Error> {
    let mut arquivo = File::open(caminho)?;             // propaga erro automaticamente
    let mut conteudo = String::new();
    arquivo.read_to_string(&mut conteudo)?;             // propaga erro automaticamente
    Ok(conteudo)
}
```

**O que o `?` faz:**
- Se o `Result` é `Ok(valor)`, extrai o valor e continua.
- Se o `Result` é `Err(e)`, **retorna `Err(e)` da função imediatamente**.
- Em `Option`: se `Some(valor)`, extrai. Se `None`, retorna `None`.

O ponto mais importante é este:

- `?` não "engole" erro;
- não transforma erro em sucesso;
- ele só encurta a passagem do erro adiante quando a função atual já retorna um tipo compatível.

**Equivalente a:**
```rust
match expressao {
    Ok(valor) => valor,
    Err(e) => return Err(e),
}
```

### 4.3 `?` encadeado

```rust
use std::fs;

fn ler_e_parsear(caminho: &str) -> Result<i32, Box<dyn std::error::Error>> {
    let conteudo = fs::read_to_string(caminho)?;   // io::Error propagado
    let numero: i32 = conteudo.trim().parse()?;     // ParseIntError propagado
    Ok(numero)
}
```

Ambos os erros (`io::Error` e `ParseIntError`) são propagados automaticamente. O `?` converte entre tipos de erro via `From` (veremos na seção 6).

Ou seja, `?` também conversa com o sistema de traits da linguagem. Ele não é mágica especial desconectada do resto do Rust.

### 4.4 `?` em `main`

Para usar `?` em `main`, declare o retorno como `Result`:

```rust
use std::error::Error;

fn main() -> Result<(), Box<dyn Error>> {
    let conteudo = std::fs::read_to_string("config.txt")?;
    println!("Config: {}", conteudo);
    Ok(())
}
```

Se ocorrer erro, `main` retorna o erro e o runtime imprime a mensagem.

### 4.5 `?` com Option

O operador `?` também funciona com `Option`:

```rust
fn ultimo_caractere(texto: &str) -> Option<char> {
    texto.chars().last()?;          // se vazio, retorna None
    Some(texto.chars().last()?)
}

fn main() {
    println!("{:?}", ultimo_caractere("olá"));    // Some('á')
    println!("{:?}", ultimo_caractere(""));        // None
}
```

## 5. Criando Tipos de Erro Customizados

### 5.1 O jeito simples — enum de erros

Criar um **tipo de erro customizado** significa modelar explicitamente as falhas possíveis da sua aplicação ou biblioteca.

Isso serve para:

- documentar as falhas no tipo;
- diferenciar causas distintas;
- preservar contexto e permitir tratamento específico.

```rust
#[derive(Debug)]
enum ErroApp {
    Io(std::io::Error),
    Parse(std::num::ParseIntError),
    Valido(String),
    NaoEncontrado(String),
}

// Implementar Display para mensagem humana
impl std::fmt::Display for ErroApp {
    fn fmt(&self, f: &mut std::fmt::Formatter) -> std::fmt::Result {
        match self {
            ErroApp::Io(e) => write!(f, "Erro de I/O: {}", e),
            ErroApp::Parse(e) => write!(f, "Erro de parse: {}", e),
            ErroApp::Valido(msg) => write!(f, "Erro de validação: {}", msg),
            ErroApp::NaoEncontrado(msg) => write!(f, "Não encontrado: {}", msg),
        }
    }
}

// Implementar std::error::Error para integração com o ecossistema

- **Display**: trait usada para exibição amigável ao usuário.
- **std::error::Error**: trait padrão que integra o tipo ao ecossistema de erros do Rust.
- **source()**: permite encadear a causa original de um erro.
impl std::error::Error for ErroApp {
    fn source(&self) -> Option<&(dyn std::error::Error + 'static)> {
        match self {
            ErroApp::Io(e) => Some(e),
            ErroApp::Parse(e) => Some(e),
            _ => None,
        }
    }
}

fn ler_idade(caminho: &str) -> Result<u32, ErroApp> {
    let conteudo = std::fs::read_to_string(caminho)
        .map_err(ErroApp::Io)?;

    let idade: u32 = conteudo.trim().parse()
        .map_err(ErroApp::Parse)?;

    if idade > 150 {
        return Err(ErroApp::Valido(format!("idade {} inválida", idade)));
    }

    Ok(idade)
}
```

### 5.2 O jeito idiomático — thiserror (crate)

Para projetos reais, a crate `thiserror` gera o boilerplate automaticamente:

```toml
# Cargo.toml
[dependencies]
thiserror = "2"
```

```rust
use thiserror::Error;

#[derive(Error, Debug)]
enum ErroApp {
    #[error("Erro de I/O: {0}")]
    Io(#[from] std::io::Error),

    #[error("Erro de parse: {0}")]
    Parse(#[from] std::num::ParseIntError),

    #[error("Idade inválida: {idade}")]
    IdadeInvalida { idade: u32 },

    #[error("Usuário '{nome}' não encontrado")]
    NaoEncontrado { nome: String },
}
```

`#[from]` gera automaticamente a implementação de `From`, permitindo usar `?` sem `.map_err()`.

- **Boilerplate**: código repetitivo e estrutural, necessário mas pouco informativo.
- `thiserror` existe justamente para reduzir esse custo sem perder tipos de erro bem modelados.

### 5.3 O jeito rápido — anyhow (crate)

Para aplicações (não bibliotecas), `anyhow` simplifica:

```toml
# Cargo.toml
[dependencies]
anyhow = "1"
```

```rust
use anyhow::{Context, Result};

fn ler_config(caminho: &str) -> Result<String> {
    let conteudo = std::fs::read_to_string(caminho)
        .with_context(|| format!("Falha ao ler '{}'", caminho))?;
    Ok(conteudo)
}

fn main() -> Result<()> {
    let config = ler_config("config.txt")?;
    println!("Config: {}", config);
    Ok(())
}
```

**Quando usar o quê:**
| Situação | Use |
|----------|-----|
| Biblioteca (crate de biblioteca) | `thiserror` — tipos de erro específicos |
| Aplicação (binário) | `anyhow` — erros flexíveis com contexto |
| Código simples/educacional | enum manual com `Display` + `Error` |

`anyhow` prioriza ergonomia em aplicações, enquanto `thiserror` prioriza tipos de erro explícitos e públicos. Essa distinção é muito importante em design de bibliotecas.

## 6. From/Into — Conversão Automática de Erros

### 6.1 A trait `From`

```rust
trait From<T> {
    fn from(valor: T) -> Self;
}
```

- **Conversão automática** aqui não significa implícita em todo lugar; significa que o ecossistema sabe como converter um tipo em outro quando a API pede isso.
- `From` expressa uma conversão canônica e sem ambiguidades.

Quando você implementa `From<SourceError> for MeuErro`, o operador `?` converte automaticamente:

```rust
#[derive(Debug)]
enum ErroApp {
    Io(std::io::Error),
    Parse(std::num::ParseIntError),
}

// Implementar From permite que ? converta automaticamente
impl From<std::io::Error> for ErroApp {
    fn from(e: std::io::Error) -> Self {
        ErroApp::Io(e)
    }
}

impl From<std::num::ParseIntError> for ErroApp {
    fn from(e: std::num::ParseIntError) -> Self {
        ErroApp::Parse(e)
    }
}

// Agora ? funciona sem .map_err()!
fn processar(caminho: &str) -> Result<i32, ErroApp> {
    let conteudo = std::fs::read_to_string(caminho)?;   // io::Error → ErroApp::Io automático
    let numero: i32 = conteudo.trim().parse()?;          // ParseIntError → ErroApp::Parse automático
    Ok(numero)
}
```

### 6.2 Como o `?` usa From

O operador `?` chama `From::from()` no erro antes de retornar:

```
expressao? expande para:

match expressao {
    Ok(v) => v,
    Err(e) => return Err(From::from(e)),  // ← conversão automática!
}
```

Isso é o que permite `?` funcionar com diferentes tipos de erro na mesma função.

## 7. Box<dyn Error> — Erro Genérico

Quando você não quer definir um tipo de erro específico:

```rust
use std::error::Error;

fn processar(caminho: &str) -> Result<String, Box<dyn Error>> {
    let conteudo = std::fs::read_to_string(caminho)?;       // io::Error → Box<dyn Error>
    let numero: i32 = conteudo.trim().parse()?;              // ParseIntError → Box<dyn Error>

    if numero < 0 {
        return Err(format!("número negativo: {}", numero).into());  // String → Box<dyn Error>
    }

    Ok(format!("Processado: {}", numero))
}

fn main() -> Result<(), Box<dyn Error>> {
    let resultado = processar("dados.txt")?;
    println!("{}", resultado);
    Ok(())
}
```

`Box<dyn Error>` aceita qualquer tipo que implemente `std::error::Error`. Útil para protótipos rápidos e scripts. Para código de produção, prefira tipos específicos.

Termos novos desta seção:

- **Box**: smart pointer dono para dados no heap;
- **`dyn Error`**: trait object, isto é, um valor cujo tipo concreto implementa `Error`, mas não é conhecido estaticamente naquele ponto;
- **Erro genérico**: abordagem em que você perde especificidade em troca de flexibilidade.

## 8. panic! — Erros Irrecuperáveis

`panic!` é para situações onde o programa não pode continuar:

**Panic** não é o mecanismo normal de erro em Rust.

Ele existe para:

- bugs do programador;
- invariantes quebradas;
- estados que não deveriam ser possíveis se o restante do programa estivesse correto.

```rust
fn main() {
    // panic! macro
    // panic!("algo terrível aconteceu!");

    // unwrap/expect em None ou Err
    let x: Option<i32> = None;
    // x.unwrap();              // PANIC: called `Option::unwrap()` on a `None` value
    // x.expect("deveria ter valor"); // PANIC: deveria ter valor

    // Array out of bounds
    let v = vec![1, 2, 3];
    // v[10];  // PANIC: index out of bounds

    // Integer overflow em debug
    let x: u8 = 255;
    // let y = x + 1;  // PANIC em debug (wrapping em release)

    // Divisão por zero inteira
    // let x = 1 / 0;  // PANIC: attempt to divide by zero
}
```

**Quando usar panic:**
- Exemplos e protótipos — onde você sabe que não vai falhar.
- Invariantes violados — `assert!`, `unreachable!`, `unimplemented!`.
- Testes — `assert_eq!` usa panic.

**Quando NÃO usar panic:**
- Entrada do usuário — use `Result`.
- I/O — use `Result`.
- Parsing — use `Result`.
- Qualquer situação recuperável — use `Result`.

**Comparação com C:**
```c
assert(p != NULL);  // C — abort() se falhar, sem stack unwind
```
```rust
assert!(p.is_some());  // Rust — panic, faz unwind da stack (libera recursos via Drop)
```

- **Invariante**: condição que deveria ser sempre verdadeira se a lógica do programa estiver correta.

## 9. Propagação vs Tratamento — Padrões

### 9.1 Tratar imediatamente com match

```rust
fn main() {
    match std::fs::read_to_string("config.txt") {
        Ok(conteudo) => println!("Config: {}", conteudo),
        Err(e) => {
            eprintln!("Aviso: não foi possível ler config ({})", e);
            println!("Usando configuração padrão...");
        }
    }
}
```

### 9.2 Propagar com ?

```rust
fn ler_config(caminho: &str) -> Result<String, std::io::Error> {
    let conteudo = std::fs::read_to_string(caminho)?;
    Ok(conteudo)
}
```

### 9.3 Fornecer valor padrão

```rust
fn main() {
    let porta: u16 = std::env::var("PORT")
        .ok()
        .and_then(|s| s.parse().ok())
        .unwrap_or(8080);

    println!("Porta: {}", porta);
}
```

### 9.4 Retentar

- **Retry**: tentar novamente uma operação que pode falhar temporariamente, como I/O ou rede.
- Isso é útil quando o erro não significa corrupção lógica, mas indisponibilidade momentânea.

```rust
fn ler_com_retry(caminho: &str, tentativas: u32) -> Result<String, std::io::Error> {
    let mut ultimo_erro = None;

    for i in 0..tentativas {
        match std::fs::read_to_string(caminho) {
            Ok(conteudo) => return Ok(conteudo),
            Err(e) => {
                println!("Tentativa {} falhou: {}", i + 1, e);
                ultimo_erro = Some(e);
            }
        }
    }

    Err(ultimo_erro.unwrap())
}
```

### 9.5 Coletar múltiplos erros

```rust
fn validar_campos(campos: &[&str]) -> Result<(), Vec<String>> {
    let erros: Vec<String> = campos
        .iter()
        .enumerate()
        .filter_map(|(i, campo)| {
            if campo.is_empty() {
                Some(format!("Campo {} está vazio", i))
            } else {
                None
            }
        })
        .collect();

    if erros.is_empty() {
        Ok(())
    } else {
        Err(erros)
    }
}

fn main() {
    match validar_campos(&["nome", "", "email", ""]) {
        Ok(()) => println!("Todos válidos!"),
        Err(erros) => {
            println!("Erros encontrados:");
            for erro in &erros {
                println!("  - {}", erro);
            }
        }
    }
}
```

## 10. Exemplo Completo — Pipeline de Processamento

```rust
// aula8_erros.rs
// Compilar: rustc aula8_erros.rs
// Executar: ./aula8_erros

use std::fmt;
use std::error::Error;
use std::num::ParseIntError;

// === Tipo de erro customizado ===

#[derive(Debug)]
enum ErroProcessamento {
    Io(std::io::Error),
    Parse(ParseIntError),
    Validacao(String),
    Vazio,
}

impl fmt::Display for ErroProcessamento {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ErroProcessamento::Io(e) => write!(f, "Erro I/O: {}", e),
            ErroProcessamento::Parse(e) => write!(f, "Erro parse: {}", e),
            ErroProcessamento::Validacao(msg) => write!(f, "Validação: {}", msg),
            ErroProcessamento::Vazio => write!(f, "Dados vazios"),
        }
    }
}

impl Error for ErroProcessamento {
    fn source(&self) -> Option<&(dyn Error + 'static)> {
        match self {
            ErroProcessamento::Io(e) => Some(e),
            ErroProcessamento::Parse(e) => Some(e),
            _ => None,
        }
    }
}

impl From<std::io::Error> for ErroProcessamento {
    fn from(e: std::io::Error) -> Self { ErroProcessamento::Io(e) }
}

impl From<ParseIntError> for ErroProcessamento {
    fn from(e: ParseIntError) -> Self { ErroProcessamento::Parse(e) }
}

// === Funções do pipeline ===

fn parsear_numeros(texto: &str) -> Result<Vec<i32>, ErroProcessamento> {
    if texto.trim().is_empty() {
        return Err(ErroProcessamento::Vazio);
    }

    let numeros: Result<Vec<i32>, ErroProcessamento> = texto
        .split(',')
        .map(|s| s.trim().parse::<i32>().map_err(ErroProcessamento::from))
        .collect();   // collect sobre Iterator<Result<T,E>> → Result<Vec<T>, E>

    numeros
}

fn validar_numeros(numeros: &[i32]) -> Result<(), ErroProcessamento> {
    if numeros.is_empty() {
        return Err(ErroProcessamento::Vazio);
    }
    for &n in numeros {
        if n < 0 {
            return Err(ErroProcessamento::Validacao(
                format!("número negativo encontrado: {}", n)
            ));
        }
        if n > 1000 {
            return Err(ErroProcessamento::Validacao(
                format!("número {} excede limite de 1000", n)
            ));
        }
    }
    Ok(())
}

fn calcular_estatisticas(numeros: &[i32]) -> (f64, i32, i32) {
    let media = numeros.iter().sum::<i32>() as f64 / numeros.len() as f64;
    let min = *numeros.iter().min().unwrap();
    let max = *numeros.iter().max().unwrap();
    (media, min, max)
}

fn processar_pipeline(dados: &str) -> Result<String, ErroProcessamento> {
    // Pipeline com propagação automática via ?
    let numeros = parsear_numeros(dados)?;          // pode falhar (parse, vazio)
    validar_numeros(&numeros)?;                       // pode falhar (validação)

    let (media, min, max) = calcular_estatisticas(&numeros);

    Ok(format!(
        "Resultados: {} números | média={:.1} | min={} | max={}",
        numeros.len(), media, min, max
    ))
}

// === Demo ===

fn main() {
    println!("=== Pipeline de Processamento com Result ===\n");

    let casos = [
        "10, 20, 30, 40, 50",       // OK
        "10, abc, 30",                // Erro de parse
        "10, -5, 30",                 // Erro de validação
        "10, 2000, 30",               // Erro de validação (limite)
        "",                           // Vazio
        "100",                        // OK (único número)
    ];

    for caso in &casos {
        println!("Input: \"{}\"", caso);
        match processar_pipeline(caso) {
            Ok(resultado) => println!("  ✓ {}\n", resultado),
            Err(e) => println!("  ✗ {}\n", e),
        }
    }

    // === Demonstração de encadeamento de Option ===
    println!("=== Encadeamento de Option ===\n");

    let dados: Vec<Option<i32>> = vec![Some(10), None, Some(30), Some(40), None];

    // Coletar apenas os Some
    let validos: Vec<i32> = dados.iter().filter_map(|&x| x).collect();
    println!("Válidos: {:?}", validos);               // [10, 30, 40]

    // Soma dos Some
    let soma: i32 = dados.iter().filter_map(|&x| x).sum();
    println!("Soma dos válidos: {}", soma);           // 80

    // Primeiro Some
    let primeiro = dados.iter().find_map(|&x| x);
    println!("Primeiro válido: {:?}", primeiro);      // Some(10)

    // === unwrap vs expect vs match ===
    println!("\n=== Padrões de tratamento ===\n");

    let resultado: Result<i32, &str> = Ok(42);

    // match — sempre seguro
    match resultado {
        Ok(v) => println!("match: {}", v),
        Err(e) => println!("erro: {}", e),
    }

    // if let — quando só importa o Ok
    if let Ok(v) = resultado {
        println!("if let: {}", v);
    }

    // unwrap_or — valor padrão
    let valor = resultado.unwrap_or(0);
    println!("unwrap_or: {}", valor);

    // map — transformar
    let dobrado = resultado.map(|v| v * 2);
    println!("map: {:?}", dobrado);
}
```

## 11. Erros Comuns

### Erro 1: Usar unwrap em código de produção

```rust
let x: Option<i32> = None;
x.unwrap();  // PANIC em produção — inaceitável para servidor
```

**Solução:** Use `?`, `unwrap_or`, `match`, ou `map`.

### Erro 2: Ignorar erros com `let _ =`

```rust
let _ = std::fs::remove_file("tmp.txt");  // ignora completamente
// Pode estar falhando silenciosamente
```

**Solução:** Se importa, trate. Se não, documente: `let _ = ...; // intencionalmente ignorado`.

### Erro 3: Usar `?` em função sem retorno Result

```rust
fn main() {  // retorna (), não Result
    // let f = File::open("a.txt")?;  // ERRO: `?` in a function that returns `()`
}
```

**Solução:** Mude o retorno para `Result<(), Box<dyn Error>>` ou trate o erro.

### Erro 4: Box<dyn Error> sem std::error::Error

```rust
struct MeuErro;  // não implementa Error
// fn foo() -> Result<(), Box<dyn Error>> {
//     Err(Box::new(MeuErro))  // ERRO: MeuErro não é Error
// }
```

**Solução:** Implemente `Display` e `Error` para seu tipo.

### Erro 5: Confundir Option e Result

```rust
fn buscar(id: u32) -> Option<Usuario> { ... }   // ausência normal
fn buscar(id: u32) -> Result<Usuario, Erro> { ... }  // falha que deve ser tratada
```
- `Option` — "pode não existir, e isso é normal".
- `Result` — "a operação pode falhar, e o chamador deve decidir o que fazer".

## 12. Comparação — C/C++ vs Rust (Erros)

| Conceito | C/C++ | Rust |
|----------|-------|------|
| Ausência de valor | `NULL` / `nullptr` | `Option<T>` |
| Erros recuperáveis | Código de retorno / exceções | `Result<T, E>` |
| Erros irrecuperáveis | `abort()` / `assert()` | `panic!` |
| Propagação | `throw` / return code manual | `?` automático |
| Stack unwind | C++ (exceções) | `panic!` (não para Result) |
| Tipos de erro | Livre (int, string, classe) | Tipados (implementam `Error`) |
| Checagem | Nenhuma em tempo de compilação | Compilador obriga a tratar |
| Overhead | C: nenhum; C++: tables | Rust: zero (Result é um enum) |
| Exceções | `try/catch` (invisível) | Não existe — erros são explícitos |

struct Config { host: String; porta: u16; debug: bool; }

### Exercício 5 — Retentativa genérica

### Exercício 6 — Conversor de temperatura com erros

### Exercício 7 — Coletor de erros

Escreva uma função `validar_usuario(nome: &str, email: &str, idade: &str) -> Result<Usuario, Vec<String>>` que valide todos os campos e retorne **todos** os erros de uma vez (não pare no primeiro). Use `filter_map` para coletar erros.
